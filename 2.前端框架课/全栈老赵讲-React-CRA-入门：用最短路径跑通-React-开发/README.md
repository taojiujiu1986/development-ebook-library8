# 第1章 先别慌：React 到底是干啥的，为什么前端都在学它

## 开篇引入：你现在要学的，不是“一个新语法”，而是一种写页面的方式

如果你已经会一点 HTML、CSS、JavaScript，那学 React 最容易踩的坑就是：一上来就盯着“语法新不新”“API 记不记得住”。

其实不用急。

按老赵的说法，React 不是让你重新学前端，而是给你一套更顺手的方式去搭页面、管状态、拆组件。你可以把它理解成：**页面一复杂，React 就帮你从“手动改 DOM”切换到“用数据驱动页面”**。

这一章先不急着敲代码，先把方向搞明白：React 到底解决什么问题，为什么会火，以及你接下来要建立的“组件拼页面”的直觉是什么。  
你先把这个底层感觉立住，后面学 CRA、JSX、组件、props、state，脑子就不会散。

## 一、React 是什么：它在前端开发里扮演什么角色？

先回答最直接的问题：**React 是什么？**

你可以先把它理解成一个前端 UI 库。它主要负责两件事：

1. 帮你拆页面
2. 帮你把数据和界面关联起来

也就是说，React 不是浏览器，也不是框架大全。它更像一个“页面组织工具”。

### 它在前端开发里干什么

传统写法里，你可能会这么干：

- 页面有一个标题
- 点按钮后，数字加 1
- 列表里多一条数据
- 表单输入后，页面显示结果

这些事原生 JS 都能做，但页面一复杂，代码就容易乱：

- 哪些 DOM 该改，得自己找
- 状态变了，手动同步页面
- 逻辑和结构混在一起
- 后面维护的人看着头大

React 的思路就不一样：  
**你先描述“页面长什么样”，再让数据变化去驱动页面变化。**

这就是它最核心的价值。

### 你可以把它想成什么

如果你以前写原生页面像“一个个节点去修”，那 React 更像“先搭模型，再让模型自动更新”。

比如你有一个购物车：

- 原生写法：先找到数量节点，再找到总价节点，再找到列表节点，分别更新
- React 写法：你只管改购物车数据，界面显示交给组件去渲染

这样一来，代码思路会清楚很多。你关注的是“数据变了什么”，不是“这个节点该怎么找”。

---

## 二、为什么不用传统 DOM 思路写复杂页面？

这部分很关键。因为很多人一开始会问：  
“原生 JS 不是也能做吗？为什么非得学 React？”

答案很简单：**能做，不代表好维护。**

### 1. 传统 DOM 思路，越写越像在修机器

刚开始页面简单时，原生 JS 很顺手，比如点击按钮改个数字：

```html
<button id="btn">点我</button>
<p id="count">0</p>
```

```js
let count = 0;
btn.onclick = () => {
  count++;
  document.getElementById('count').innerText = count;
};
```

这没问题。

但页面一旦复杂，比如同时有搜索框、筛选、列表、弹窗、表单校验，你就得频繁操作 DOM：

- 找节点
- 改内容
- 控样式
- 绑事件
- 处理联动

最后很容易变成：**代码能跑，但谁也不敢轻易改。**

### 2. 问题不在“能不能写”，而在“好不好管”

传统 DOM 思路最大的痛点，不是语法麻烦，而是**状态和界面之间的关系容易失控**。

比如你手动改了一个地方，忘了同步另一个地方：

- 数量变了，列表没变
- 输入值变了，提示没清
- 切换选项了，按钮状态没刷新

页面一复杂，就像一堆线缠在一起，最后你自己都不知道哪根线连着哪块。

React 就是来解决这个问题的：**让页面变化跟着数据走，而不是你满屏幕去找节点改节点。**

### 3. React 让你少碰“细枝末节”

React 不是说你完全不用管页面，而是把很多琐碎的 DOM 操作收起来了。  
你只需要关心：

- 当前数据是什么
- 页面应该显示什么
- 用户点了之后数据怎么变

这对做项目特别有用。因为真实开发里，最费时间的往往不是“写页面本身”，而是“页面各种联动关系怎么管”。

## 三、React 的核心思想：组件化和声明式

这部分是 React 的灵魂，建议你先把这两个词记成“使用习惯”，别急着背定义。

### 1. 组件化：把页面拆成一块一块的

组件化很像搭积木。

一个完整页面，不是一个巨大的文件写到底，而是拆成很多小块：

- 顶部导航
- 搜索框
- 商品列表
- 商品卡片
- 底部版权

每一块都可以单独写、单独调、单独复用。

比如“商品卡片”这个东西，你页面里可能出现 20 次。  
如果你手写 20 份 HTML，后面改样式就很痛苦。  
但如果它是一个组件，你只要写一份模板，传不同数据进去就行。

这就是 React 组件思维的第一步：  
**页面不是一整坨，而是很多可组合的零件。**

### 2. 声明式：你告诉 React“我想要什么”，它帮你更新页面

传统方式偏“命令式”：

- 先找到按钮
- 再找到文本
- 再修改内容
- 再判断状态

React 更偏声明式：

- 我想让页面显示什么
- 我想让数据是什么
- 数据变了，页面自己跟着变

你可以把它理解为：

> 不是你一条条指挥浏览器干活，而是你把结果描述出来，React 负责把过程安排好。

这也是为什么 React 很适合做交互复杂的页面。你关心的是“状态是什么”，而不是“每次怎么精确改 DOM”。

### 3. 一个最小例子：用组件拼页面，感觉会更直观

比如你要做一个首页，内容其实就三块：

- 头部标题
- 中间欢迎语
- 底部按钮

如果用组件思路来想，就不是“写一个大页面”，而是：

- `Header` 负责头部
- `Main` 负责中间内容
- `Footer` 负责底部

最后把它们拼起来就行。  
这时候你会发现，React 不是逼你写新东西，而是逼你先问一句：

**“这个页面能不能拆？”**

能拆，就能更好维护，也更容易复用。  
这就是组件化最实在的地方。

## 四、前端基础和 React 学习之间，怎么衔接最顺？

很多读者会担心：  
“我基础倒是会一点，但 React 会不会门槛很高？”

别慌。你已经会的前端基础，正好能接上 React。

### 1. HTML、CSS、JS 是地基，不是白学

React 页面最终还是要落回 HTML 结构、CSS 样式、JS 逻辑。  
只不过在 React 里，这三样的组织方式变了。

你可以这样理解：

- HTML：页面结构的思路还在
- CSS：样式写法还在
- JS：事件、数据、逻辑还在
- React：帮你把这些东西按组件组织起来

所以学 React，不是抛弃基础，而是把基础“装进组件里”。

### 2. 你已经具备最重要的起点：会用 JavaScript 思考

React 里最常见的事，基本都离不开 JS：

- 数组遍历
- 条件判断
- 函数传参
- 事件回调
- 对象和数组的更新

所以如果你会一点 JavaScript，就已经有很好的起跑线了。  
接下来只是把“操作页面”的方式，从原生 DOM 切换到 React 的组件和状态模型。

### 3. 学 React 的正确姿势：边搭边学

别一上来就想把所有概念吃透。  
正确顺序是：

1. 先知道 React 是拿来干什么的
2. 再学怎么创建项目
3. 再看 JSX 怎么写页面
4. 再学组件和 props
5. 再处理事件、状态、列表、表单
6. 最后做个小项目把这些串起来

这样学，脑子不会散，也不会学完一堆名词却不知道怎么落地。

## 五、先建立“用组件拼页面”的直觉

这一节最重要。你只要把这个直觉建立起来，后面学 React 就顺很多。

### 1. 先别盯着页面，先看“页面可以拆成几块”

比如做一个简单的首页，你可以先拆成：

- Header：顶部区域
- Banner：头图区域
- CardList：卡片列表
- Footer：底部区域

每一块单独做成一个组件，最后组合在一起。

这就是 React 最常见的落地方式：  
**先拆，再拼。**

### 2. 组件之间怎么配合

组件不是孤立的。  
有些组件负责展示，有些组件负责接收数据，有些组件负责处理交互。

比如：

- 父组件负责准备数据
- 子组件负责展示一条卡片
- 点击按钮后，父组件更新数据
- 子组件根据新数据重新显示

你现在不用死记这些关系，先有感觉就行：  
**组件像零件，数据像螺丝，页面像装好的机器。**

### 3. 这个思路后面会怎么用上

你先把这个“拆页面”的直觉记住，后面学 CRA 的时候就有用了。  
因为下一章我们会先把 React 项目跑起来，看看一个标准的 CRA 项目长什么样，目录怎么认、文件怎么改、页面怎么显示。  
等你把项目起起来，再回头看组件拆分，就会非常顺。

# 第2章 JSX 其实没那么吓人：语法规则和页面写法一次讲透

## 开篇引入：你以为在写 HTML，其实是在写 React 的页面说明书

刚接触 React，很多人看到 JSX 会犯怵：

“这不就是 HTML 吗？怎么还夹着 JS 变量、表达式，甚至条件判断？”

别急，这一章老赵就带你把 JSX 掰开揉碎讲明白。

先记住一句话：**JSX 不是新的模板语言，它是 React 写页面的基本语法**。你可以把它理解成“看起来像 HTML 的 JavaScript 写法”。React 推荐你用 JSX，不是为了增加门槛，而是为了让你更自然地把“页面结构”和“数据逻辑”写在一起。

你可以把它理解成：

- **HTML** 负责页面骨架；
- **JavaScript** 负责数据和行为；
- **JSX** 让你把这两件事顺手放在一起写。

这也是 React 组件思维的起点：**不是先数页面里有多少标签，而是先想这个页面要展示什么数据、哪些地方会变化。**

这一章我们就抓住四件事：

1. 搞清楚 JSX 到底是什么；
2. 掌握 JSX 最重要的规则；
3. 知道怎么写变量、表达式和简单条件；
4. 最后用 JSX 直接搭一个完整的小页面。

---

## 1. JSX 是什么，和 HTML 的关系到底是什么？

### 1.1 JSX 不是 HTML，但长得像 HTML

JSX 全称是 JavaScript XML。它本质上是 **React 组件返回 UI 的写法**。

比如：

```jsx
const title = <h1>欢迎来到 React 世界</h1>;
```

它长得像 HTML，但浏览器并不直接认识它。React 会把它转换成真正的 JavaScript 调用，再渲染成页面。

所以你写 JSX 的时候，脑子里要切换一下：

- 不是在写静态标签
- 而是在写“组件返回的 UI 描述”

你可以把 HTML 理解成直接盖房子，JSX 更像先画施工图。你写的是页面长什么样，React 负责把它变成最后的页面。

### 1.2 为什么 React 爱用 JSX？

因为 JSX 最实用的地方，就是**页面结构和数据逻辑能放在一起看**。

比如：

```jsx
const username = "老赵";
const element = <h2>你好，{username}</h2>;
```

如果用原生 DOM 操作，你得创建元素、设置文本、拼接逻辑，代码会碎很多。JSX 的好处就是：**页面写法更接近你脑子里想的样子，读起来也更顺。**

这对后面学组件、props、state 都很重要，因为 React 的核心就是：**用数据驱动页面**。

### 1.3 JSX 适合什么场景？

在 React 里，几乎所有页面都会用 JSX 来写：

- 首页布局
- 列表展示
- 表单
- 弹窗
- 条件提示

所以你可以把它看成 React 入门最重要的一把钥匙。JSX 没整明白，后面组件、props、state、路由都会学得有点飘。

---

## 2. JSX 的核心规则：单根节点、className、{} 表达式

这一节是重点中的重点，后面写 JSX 基本都绕不开。

### 2.1 为什么 JSX 必须有单根节点？

错误写法：

```jsx
return (
  <h1>标题</h1>
  <p>副标题</p>
);
```

JSX 要求：**一个组件返回的内容必须包在一个根节点里**。

正确写法有两种：

#### 写法 1：外层包一个 div

```jsx
return (
  <div>
    <h1>标题</h1>
    <p>副标题</p>
  </div>
);
```

#### 写法 2：用 Fragment

```jsx
return (
  <>
    <h1>标题</h1>
    <p>副标题</p>
  </>
);
```

简单记：

- 有明确容器需求时，用 `div`
- 不想多加一层标签时，用 `<>...</>`

### 2.2 为什么 class 要写成 className？

HTML 里你会写：

```html
<div class="box"></div>
```

但 JSX 里要写成：

```jsx
<div className="box"></div>
```

原因很简单：`class` 在 JavaScript 里是保留关键字，React 统一用了 `className`。

记住一句就够了：

> **JSX 里类名用 `className`，不要写 `class`。**

### 2.3 JSX 里的 {} 到底是干嘛的？

`{}` 是 JSX 里插入 JavaScript 表达式的入口。

比如：

```jsx
const name = "老赵";
return <h1>你好，{name}</h1>;
```

这里 `{name}` 会把变量值放到页面里。

再比如：

```jsx
const age = 18;
return <p>年龄：{age + 1}</p>;
```

这里还能放表达式。

记住一个判断标准：

- **能算出结果的表达式**，通常可以放进 `{}` 里
- **语句**一般不行，比如 `if`、`for` 不能直接塞进去

比如下面这样不行：

```jsx
return (
  <div>
    {if (isLogin) {
      <p>已登录</p>
    }}
  </div>
);
```

这个先记着，后面条件渲染会告诉你更合适的写法。

## 3. 在 JSX 里写变量、字符串、表达式和简单条件

这一节讲的是：JSX 怎么真正“活”起来。

### 3.1 写变量：最常见的用法

```jsx
const title = "React 入门";
const author = "老赵";

return (
  <div>
    <h1>{title}</h1>
    <p>作者：{author}</p>
  </div>
);
```

这就是 JSX 最基础的用法：**先在组件里准备数据，再在页面里渲染数据**。

### 3.2 写字符串：能直接写就直接写

字符串可以直接写：

```jsx
return <p>你好，React</p>;
```

也可以放进 `{}`：

```jsx
return <p>{"你好，React"}</p>;
```

一般来说，**能直接写就直接写，没必要绕一层 `{}`**。花括号更适合放变量或表达式。

### 3.3 写表达式：让页面跟着数据算

比如：

```jsx
const price = 99;
return <p>折后价：{price * 0.8} 元</p>;
```

再比如：

```jsx
const firstName = "全栈";
const lastName = "老赵";
return <h2>{firstName + lastName}</h2>;
```

你可以把 JSX 理解成“页面 + 简单计算”的结合体。复杂逻辑别硬塞进去，先在上面算好，再拿结果渲染。

### 3.4 写简单条件：页面内容可以按情况变化

JSX 里最常见的条件写法是三元表达式：

```jsx
const isLogin = true;

return (
  <div>
    {isLogin ? <p>欢迎回来，老赵</p> : <p>请先登录</p>}
  </div>
);
```

再比如：

```jsx
const count = 0;

return (
  <div>
    {count > 0 ? <span>有消息</span> : <span>暂无消息</span>}
  </div>
);
```

入门阶段你先把三元表达式吃透，基本就够用了。后面学条件渲染时，再扩展 `&&` 和提前返回。

## 4. JSX 中常见坑：注释、样式、属性写法

新手写 JSX，最容易的问题就是：**写得像 HTML，却忘了自己在写 JavaScript 里的语法**。

### 4.1 注释怎么写？

HTML 注释是：

```html
<!-- 这是注释 -->
```

JSX 里不能这么写，要写成：

```jsx
return (
  <div>
    {/* 这是 JSX 注释 */}
    <h1>标题</h1>
  </div>
);
```

记住：

> **JSX 注释必须写在 `{/* ... */}` 里面。**

### 4.2 样式怎么写？

JSX 里写行内样式，不是字符串，而是对象：

```jsx
return <div style={{ color: "red" }}>红色文字</div>;
```

这里两个大括号别慌：

- 外层 `{}` 是 JSX 语法
- 内层 `{}` 是 JavaScript 对象

也可以先定义样式对象：

```jsx
const boxStyle = {
  color: "white",
  backgroundColor: "black",
  padding: "12px"
};

return <div style={boxStyle}>黑底白字</div>;
```

注意 CSS 属性名要写成驼峰式：

- `background-color` → `backgroundColor`
- `font-size` → `fontSize`

### 4.3 属性写法有哪些要注意的？

除了 `className`，还有一些属性写法也和 HTML 略有区别。

比如：

```jsx
<input disabled />
```

这种布尔属性可以直接写。  
如果要传变量，就写成：

```jsx
const isDisabled = true;
<input disabled={isDisabled} />
```

先抓住两个核心点就够了：

1. HTML 属性名在 JSX 里可能会变；
2. 变量、对象、表达式通常都要放进 `{}`。

## 5. 用 JSX 直接搭一个完整页面：从“会看”到“会写”

这一节直接上手，看看 JSX 怎么落地。我们不只写几个零散标签，而是直接拼一个可以拿来练手的小页面。

### 5.1 先定页面目标

我们做一个简单介绍页，包含：

- 标题
- 简介
- 用户名
- 状态提示
- 一个技能列表
- 一个根据条件变化的小提示

### 5.2 示例：一个完整的 JSX 页面

```jsx
function App() {
  const title = "React 入门第一页";
  const user = {
    name: "老赵",
    role: "前端带教",
    desc: "带你用最短路径跑通 React 开发",
  };
  const isOnline = true;
  const skills = ["HTML", "CSS", "JavaScript", "React"];

  return (
    <div className="page">
      <h1>{title}</h1>
      <p>欢迎你，{user.name}</p>
      <p>身份：{user.role}</p>
      <p>介绍：{user.desc}</p>

      <div className="status">
        {isOnline ? <span>当前在线</span> : <span>当前离线</span>}
      </div>

      <h2>技能清单</h2>
      <ul>
        <li>{skills[0]}</li>
        <li>{skills[1]}</li>
        <li>{skills[2]}</li>
        <li>{skills[3]}</li>
      </ul>

      <p>{skills.length > 3 ? "技能还挺多" : "技能还可以继续补"}</p>
    </div>
  );
}

export default App;
```

你已经能看到 JSX 的核心玩法了：

- 用 `className`
- 用 `{}` 插变量
- 用三元表达式做条件渲染
- 用数组取值渲染列表
- 用对象把页面数据收拢起来

这就是 React 组件思维的雏形：**先准备数据，再按数据渲染界面。**

### 5.3 再看一眼错误写法，别在坑里摔两次

下面这段代码是新手特别容易写出来的：

```jsx
function Demo() {
  const name = "老赵";

  return (
    <div class="box">
      <h1>{name}</h1>
      <!-- 这是注释 -->
      <p style="color: red;">你好</p>
    </div>
  );
}
```

我们来快速改对：

```jsx
function Demo() {
  const name = "老赵";

  return (
    <div className="box">
      <h1>{name}</h1>
      {/* 这是注释 */}
      <p style={{ color: "red" }}>你好</p>
    </div>
  );
}
```

这几个点你要形成条件反射：

- `class` 改 `className`
- HTML 注释改成 JSX 注释
- `style` 不能写字符串，要写对象

## 6. JSX 入门检查清单：写之前先过一遍

以后每次写 JSX，先扫一遍这几个点：

- 有没有**单根节点**
- `class` 有没有写成 `className`
- 变量和表达式有没有放进 `{}`
- 条件渲染是不是用三元表达式
- 注释是不是写成 `{/* ... */}`
- 样式是不是对象写法
- 属性名有没有符合 JSX 规则

刚开始不用追求写得多高级，先追求**写得对、写得稳、写得出来**。

# 第3章 组件和 props：把页面拆开写，React 组件思维真正落地

## 开篇引入：别再把 React 当“写页面的新语法”了

很多同学刚学 React，最容易犯的毛病就是还是“一个页面一个 HTML 文件”的思路。结果一上来就写一个巨大的 `App`，标题、列表、按钮、表单全堆进去，后面自己都不敢改。

React 真正厉害的地方，不是“能写页面”，而是它提供了一种更舒服的写法：

> **把页面拆成一个个小组件，再像搭积木一样拼起来。**

这章老赵带你把这个事落地。你会学到：

- 组件是什么
- 为什么页面要拆组件
- 函数组件怎么写
- 组件怎么组合成页面
- `props` 怎么把数据从父组件传给子组件
- `props` 的常见写法和解构写法
- 用一个小案例把卡片、标题、按钮拆出来

先记住一句话：

> **React 不是让你少写代码，而是让你把代码写得更好维护。**

页面一复杂，不拆组件就是灾难：改一处，崩一片；加一个需求，整个文件都得翻。拆开之后，哪里管哪里，思路会清楚很多。

## 一、什么是 React 组件，为什么页面要拆组件

### 1.1 组件就是“可复用的页面零件”

React 组件可以理解成一个**带结构、带逻辑、可复用的小模块**。比如页面里常见的标题栏、用户卡片、按钮、商品列表、导航栏，都很适合做成组件。

如果每个页面都重复写，后面改样式、改文案、改交互都会很痛苦。所以 React 的思路是：**把这些独立、重复、逻辑清晰的部分拆出去，变成组件。**

你可以把组件想成乐高积木。每块不大，但拼起来就是完整页面。

### 1.2 为什么要拆组件

拆组件不是为了“看起来高级”，而是为了更实在的几个好处：

- **更好维护**：按钮样式统一改一次，所有地方一起变
- **更好复用**：同一个卡片可以在多个页面重复用
- **更清晰**：一眼能看懂页面结构
- **更利于协作**：多人开发时，各管各的组件，互不干扰

### 1.3 什么时候该拆组件

老赵给你一个简单判断：

- **一块内容反复出现**，拆
- **一块内容逻辑独立**，拆
- **一块内容太长太乱**，拆
- **一块内容未来大概率会变**，拆

别过度拆分。页面只有几行代码，你拆成一堆组件，那就是给自己添堵。

一个很好用的标准是：**页面上能不能用一句话描述这个区域在干嘛？**  
如果能，比如“这是标题”“这是商品卡”“这是用户头像”，那它就适合拆出来。

## 二、函数组件的基本写法

### 2.1 函数组件长什么样

CRA 里最常见的就是函数组件，它本质上就是一个 JavaScript 函数，返回一段 JSX。

```jsx
function Hello() {
  return <h1>你好，React！</h1>;
}

export default Hello;
```

也可以写成箭头函数：

```jsx
const Hello = () => {
  return <h1>你好，React！</h1>;
};

export default Hello;
```

### 2.2 组件名为什么要大写

组件名通常首字母大写，比如 `Hello`、`UserCard`、`Header`。不要写成小写。React 会根据首字母判断它是普通标签还是自定义组件，你自己写的组件，一律大写开头。

### 2.3 组件的核心规则

#### 规则 1：返回 JSX
组件最终要返回页面内容，不返回就没东西显示。

#### 规则 2：一个组件一个职责
别让一个组件既管布局，又管数据，又管交互，太重了。

#### 规则 3：首字母大写
这是 React 组件的基本习惯。

#### 规则 4：通常一个文件一个组件
文件名和组件名对应起来，后面找代码也方便。

---

## 三、组件如何组合成一个完整页面

### 3.1 组件不是单独存在的

React 不是“写很多散装组件”，而是把组件组合成页面。

比如：

- `App`：页面总入口
- `Header`：顶部标题
- `UserCard`：用户信息卡片
- `ActionButton`：按钮

组合起来就是：

```jsx
import Header from "./Header";
import UserCard from "./UserCard";
import ActionButton from "./ActionButton";

function App() {
  return (
    <div>
      <Header />
      <UserCard />
      <ActionButton />
    </div>
  );
}

export default App;
```

这就是 React 最核心的感觉：**每个组件各干各的，再拼成页面。**

### 3.2 父组件和子组件

组件组合里经常会出现两个概念：

- **父组件**：负责组织页面，往下传数据
- **子组件**：负责展示局部内容

比如 `App` 是父组件，`UserCard` 是子组件。父组件把用户名、头像、价格这些数据传给子组件，子组件负责渲染。

这就引出了本章最重要的内容：**props**。

---

## 四、props 的作用：父组件给子组件传数据

### 4.1 props 是干什么的

一句话讲明白：

> **props 就是组件之间传数据的方式，最常见的是父组件给子组件传。**

比如：

```jsx
function UserCard(props) {
  return <h2>{props.name}</h2>;
}
```

父组件这样传：

```jsx
<UserCard name="老赵" />
```

子组件就能拿到 `name` 这个值。

### 4.2 props 的基本特点

#### 特点 1：只读
子组件拿到 props 后，不能直接改它，只能用。

#### 特点 2：单向流动
通常是父到子，数据流更清楚。

#### 特点 3：可以传各种值
不只是字符串，还可以传数字、布尔值、数组、对象、函数。

### 4.3 props 传数据的一个小例子

```jsx
function UserCard(props) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>年龄：{props.age}</p>
    </div>
  );
}

function App() {
  return <UserCard name="老赵" age={30} />;
}
```

注意，数字要写成 `age={30}`，字符串可以直接写在引号里。你只要记住一个动作就行：

> **父组件负责给，子组件负责拿。**

### 4.4 常见传值形式对照一下

实际写代码时，props 经常不是只传一个字段，而是一次传多个字段。

```jsx
<UserCard name="老赵" age={30} city="北京" />
```

子组件里就可以这样取：

```jsx
function UserCard(props) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>年龄：{props.age}</p>
      <p>城市：{props.city}</p>
    </div>
  );
}
```

如果数据是对象，也可以直接传对象：

```jsx
<UserCard user={{ name: "老赵", job: "前端讲师" }} />
```

如果数据是数组，也照样能传：

```jsx
<TagList tags={["React", "CSS", "JavaScript"]} />
```

props 不挑数据类型，关键是你会不会拆、会不会用。

---

## 五、props 的常见写法和解构写法

### 5.1 直接通过 props.xxx 取值

这是最直白的写法：

```jsx
function UserCard(props) {
  return (
    <div>
      <h2>{props.name}</h2>
      <p>{props.city}</p>
    </div>
  );
}
```

优点是好懂，适合刚上手。

### 5.2 解构写法：更常用、更清爽

更常见的写法是直接解构：

```jsx
function UserCard({ name, city }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{city}</p>
    </div>
  );
}
```

字段少的时候更舒服，字段多的时候也更清楚。

### 5.3 什么时候用哪种写法

- **学习阶段**：先用 `props.xxx`
- **实战开发**：大多数时候用解构

别纠结高级不高级，先把数据正确传进去、正确展示出来最重要。

### 5.4 props 里传对象和数组

#### 传对象

```jsx
function UserCard({ user }) {
  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.job}</p>
    </div>
  );
}

function App() {
  return <UserCard user={{ name: "老赵", job: "前端讲师" }} />;
}
```

#### 传数组

```jsx
function TagList({ tags }) {
  return (
    <ul>
      {tags.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}
```

先记住：**props 不只是传一个字，它能传结构化数据。** 后面做组件通信时会经常用到。

## 六、用一个小案例拆出卡片、标题、按钮组件

我们做一个最小化实战：一个“课程介绍卡片”。

### 6.1 先看页面需求

页面包括：

- 标题：`React 入门训练营`
- 一张卡片，显示课程信息
- 一个按钮：`立即学习`

如果全写在 `App` 里：

```jsx
function App() {
  return (
    <div>
      <h1>React 入门训练营</h1>
      <div>
        <h2>课程简介</h2>
        <p>带你用最短路径跑通 React 开发</p>
      </div>
      <button>立即学习</button>
    </div>
  );
}
```

能跑，但不够清爽。现在拆开。

### 6.2 拆成三个组件

#### 1）标题组件

```jsx
function Title({ text }) {
  return <h1>{text}</h1>;
}

export default Title;
```

#### 2）卡片组件

```jsx
function Card({ title, desc }) {
  return (
    <div style={{ border: "1px solid #ddd", padding: "12px", marginTop: "12px" }}>
      <h2>{title}</h2>
      <p>{desc}</p>
    </div>
  );
}

export default Card;
```

#### 3）按钮组件

```jsx
function Button({ text }) {
  return <button>{text}</button>;
}

export default Button;
```

### 6.3 在父组件里组合起来

```jsx
import Title from "./Title";
import Card from "./Card";
import Button from "./Button";

function App() {
  return (
    <div>
      <Title text="React 入门训练营" />
      <Card title="课程简介" desc="带你用最短路径跑通 React 开发" />
      <Button text="立即学习" />
    </div>
  );
}

export default App;
```

这样一拆，结构就很清楚了：

- `App` 负责组织页面
- `Title` 负责标题
- `Card` 负责内容展示
- `Button` 负责按钮

### 6.4 这个案例里你要真正学会的东西

你不是只学会“拆组件”，而是要学会一种思考方式：

1. 先看页面有哪些独立区域
2. 再看哪些区域能复用
3. 用 props 把数据传进去
4. 父组件负责组合，子组件负责展示

以后你做页面，哪怕是一个后台列表页，也都是这套思路：**先拆，再传，再组合。**

## 七、常见误区：很多人组件写乱就是因为这几个坑

### 7.1 误区一：组件拆得太碎

一行代码一个组件，没必要。拆组件的目的是让代码更清楚，不是比赛。

### 7.2 误区二：把所有东西都写死在子组件里

如果标题、文案、按钮文字都写死，这个组件就没法复用了。应该尽量通过 props 传进来。

```jsx
function Button({ text }) {
  return <button>{text}</button>;
}
```

比起写死文本，这种写法更通用。

### 7.3 误区三：只会复制，不会组合

React 的核心不是复制粘贴，而是组合。看到一个页面，先想“有哪些块能抽出来”。

### 7.4 误区四：搞不清谁是父组件谁是子组件

最简单的判断：

- 谁在外层组织布局，谁就是父组件
- 谁被包在里面，谁就是子组件

再简单一点：**传数据的一般是父，接数据的一般是子。**

## 八、从今天开始，你要养成的组件写法习惯

### 8.1 先画草图

先别急着敲代码，先想页面分区：

- 顶部
- 中间内容
- 底部按钮

### 8.2 再拆模块

问自己三个问题：

- 哪些地方会重复？
- 哪些地方逻辑独立？
- 哪些地方以后最可能变化？

满足其中一两个，就值得拆。

### 8.3 再设计 props

先列出子组件需要的数据：

- 标题
- 描述
- 图片
- 按钮文字

这样写组件时不会乱。

### 8.4 最后在父组件里拼起来

# 第4章 事件处理：按钮一点就动，React 交互从这里开始

前面几章我们把 React 的“骨架”搭起来了：会写组件，会看 JSX，也知道页面不是一大坨 HTML 直接堆上去，而是拆成一个个组件来拼。

但静态页面只是展示，真正让页面“活起来”的，是**事件处理**。

你点按钮要有反应，输入框要能输入，列表项要能选中，弹窗要能开关，这些动作都离不开事件。也就是说，**React 的交互入口，通常就是事件处理**。这一章咱们先把最常见的几个场景跑通：按钮点击、输入框变化、事件函数传参、拿到事件对象，再做两个小交互案例。

你可以先把它理解成一句话：**让页面从“展示信息”变成“能回应用户操作”**。后面学 `useState`、表单、列表交互，本质上都是围绕事件展开的。

## 5.1 先搞清楚：React 事件和原生 DOM 事件有什么区别

原生 DOM 里，通常是先找到元素，再手动绑事件：

```html
<button id="btn">点我</button>
<script>
  const btn = document.getElementById('btn')
  btn.addEventListener('click', function () {
    console.log('clicked')
  })
</script>
```

React 里，不用自己 `getElementById`，直接在 JSX 里写：

```jsx
function App() {
  function handleClick() {
    console.log('clicked')
  }

  return <button onClick={handleClick}>点我</button>
}
```

你先记住这几个点：

- 原生 DOM 常用 `addEventListener`
- React 直接写 `onClick`、`onChange`、`onSubmit`
- 事件名用驼峰写法，比如 `onClick`，不是 `onclick`
- 事件属性里放的是**函数引用**，不是函数执行结果

也就是说，这句是对的：

```jsx
<button onClick={handleClick}>点我</button>
```

这句是错的：

```jsx
<button onClick={handleClick()}>点我</button>
```

因为第二种会在渲染时立刻执行，不是点击时执行。

你可以把 React 事件理解成：**我在 JSX 里直接告诉你，这个按钮点了以后该干嘛**。这很符合 React 的组件思维：结构、数据、行为尽量放在一起看。

---

## 5.2 最常用的两个：onClick 和 onChange

这两个你后面会天天见，先把写法练熟。

### 1）onClick：按钮点击

```jsx
function App() {
  function handleClick() {
    alert('按钮被点了')
  }

  return <button onClick={handleClick}>点一下</button>
}
```

这是最基础的点击事件。后面你做切换、删除、提交、弹窗，基本都从它开始。

### 2）onChange：输入框变化

```jsx
function App() {
  function handleChange(e) {
    console.log(e.target.value)
  }

  return <input type="text" onChange={handleChange} />
}
```

输入框一变化，就会触发 `handleChange`，然后你可以从事件对象里拿到当前输入值。

### 3）常用事件先混个脸熟

- `onClick`：点击
- `onChange`：输入变化
- `onSubmit`：表单提交
- `onFocus`：获得焦点
- `onBlur`：失去焦点

入门阶段，先把 `click`、`change`、`submit` 这三个用顺，已经能做不少页面交互了。

## 5.3 事件处理函数怎么写？怎么传参？

事件处理本质上就两件事：

1. 函数怎么定义
2. 需要传值时怎么写

### 1）先写一个单独的处理函数

```jsx
function App() {
  function handleClick() {
    console.log('点击了按钮')
  }

  return <button onClick={handleClick}>提交</button>
}
```

这样写最清楚，函数单独放出来，逻辑一眼能看懂。

### 2）需要传参时，用箭头函数包一层

比如你想点不同按钮打印不同名字：

```jsx
function App() {
  function handleClick(name) {
    console.log('点击的是：', name)
  }

  return (
    <div>
      <button onClick={() => handleClick('按钮A')}>按钮A</button>
      <button onClick={() => handleClick('按钮B')}>按钮B</button>
    </div>
  )
}
```

这个写法要记牢：

- `onClick={() => handleClick('按钮A')}` 是对的
- `onClick={handleClick('按钮A')}` 是错的

后者会在渲染时立刻执行。

### 3）什么时候直接传函数名，什么时候包一层？

很简单：

- **不传参**：直接写函数名
- **要传参**：包箭头函数

```jsx
<button onClick={handleClick}>不传参</button>
<button onClick={() => handleClick(id)}>传参</button>
```

后面做删除、编辑、切 tab、点列表项，这个写法都会反复出现。

---

## 5.4 事件对象和当前输入值，怎么拿最方便？

这一节是输入框和表单的基础，别跳过。

### 1）什么是事件对象 `e`

事件函数里通常会接收一个参数，常写成 `e`：

```jsx
function handleClick(e) {
  console.log(e)
}
```

这个 `e` 就是事件对象，里面带着这次事件的信息。

### 2）输入框当前值怎么拿

```jsx
function App() {
  function handleChange(e) {
    console.log(e.target.value)
  }

  return <input type="text" onChange={handleChange} />
}
```

链路很清楚：

- `e`：事件对象
- `e.target`：触发事件的元素
- `e.target.value`：输入框当前内容

以后做搜索框、昵称输入、登录框，基本都是这个套路。

### 3）别直接瞎猜 value 在哪

很多新手会这么写：

```jsx
function handleChange() {
  console.log(value)
}
```

如果你没自己定义 `value`，当然拿不到。更稳的办法就是直接从事件对象里拿：

```jsx
function handleChange(e) {
  console.log(e.target.value)
}
```

先记成一句最实用的话：

**用户输入后，值就在事件对象的 `target.value` 里。**

## 5.5 先做个最小交互：按钮点一下，数字加一

光看不练没用，咱们直接做一个最经典的小案例：**点击按钮，数字加一**。

### 1）需求很简单

页面上显示一个数字，初始是 0。每点一次按钮，数字加 1。

### 2）完整代码

```jsx
import { useState } from 'react'

function App() {
  const [count, setCount] = useState(0)

  function handleAdd() {
    setCount(count + 1)
  }

  return (
    <div style={{ padding: '20px' }}>
      <h1>当前数字：{count}</h1>
      <button onClick={handleAdd}>+1</button>
    </div>
  )
}

export default App
```

### 3）这个案例里，事件扮演什么角色？

- 点击按钮，触发 `onClick`
- `handleAdd` 被执行
- 调用 `setCount(count + 1)`
- 页面上的数字跟着变化

你会发现，React 的交互不是“手动改页面内容”，而是：

**先触发事件，再更新状态，最后让页面自动重渲染。**

这一点先有个感觉就行，后面学 `useState` 的时候会更顺。

## 5.6 再做一个输入框：输入什么，就显示什么

这个例子比按钮再进一步，也更贴近日常需求。

```jsx
import { useState } from 'react'

function App() {
  const [text, setText] = useState('')

  function handleChange(e) {
    setText(e.target.value)
  }

  return (
    <div style={{ padding: '20px' }}>
      <input type="text" value={text} onChange={handleChange} />
      <p>你输入的是：{text}</p>
    </div>
  )
}

export default App
```

这个例子里，你已经能看到一点受控组件的影子了，但现在先别急着上概念，先把流程吃透：

- 输入框里输入内容
- `onChange` 触发
- 从 `e.target.value` 拿到新值
- `setText` 更新状态
- 页面上的文字同步变化

这就是 React 里很常见的闭环：

**用户操作 → 事件触发 → 更新状态 → 页面刷新**

后面做表单、做搜索、做筛选，都离不开这个套路。

## 5.7 表单提交：记得先拦住默认刷新

这个坑很常见。你一写 `form`，浏览器默认就会想着“提交并刷新页面”。

### 1）默认行为是什么

如果你不管它，表单提交时页面可能直接刷新，刚输入的内容也跟着没了。

### 2）React 里正确写法

```jsx
function App() {
  function handleSubmit(e) {
    e.preventDefault()
    console.log('表单提交了')
  }

  return (
    <form onSubmit={handleSubmit}>
      <input type="text" />
      <button type="submit">提交</button>
    </form>
  )
}
```

### 3）这里注意两点

- `onSubmit` 绑在 `form` 上，不是只绑在按钮上
- 一定要写 `e.preventDefault()`

你可以先记住一句最实用的话：

**表单提交先拦默认刷新，再写自己的业务逻辑。**

这句话后面做登录、搜索、发布内容时都会用到。

## 5.8 来个稍微完整点的例子：点赞按钮切换

上面都是基础操作，现在咱们做一个更像真实页面的小交互：**点赞切换**。

### 1）需求描述

页面上有一个按钮，初始显示“未点赞”。点击后变成“已点赞”，颜色也变一下，再点一次切回来。

### 2）代码实现

```jsx
import { useState } from 'react'

function App() {
  const [liked, setLiked] = useState(false)

  function handleLike() {
    setLiked(!liked)
  }

  return (
    <div style={{ padding: '20px' }}>
      <button
        onClick={handleLike}
        style={{
          backgroundColor: liked ? 'hotpink' : '#eee',
          color: liked ? '#fff' : '#333',
          border: 'none',
          padding: '8px 16px',
          cursor: 'pointer'
        }}
      >
        {liked ? '已点赞' : '未点赞'}
      </button>
    </div>
  )
}

export default App
```

### 3）这个案例的关键点

点击按钮，触发事件，修改状态，页面样式和文字一起变。

这就是 React 最常见的交互方式。不是你去手动改按钮文字，而是状态变了，页面自然跟着变。

## 5.9 再加一个列表点击：点谁就打印谁

这个场景也很常见，尤其是后面做分类、菜单、标签页的时候。

```jsx
function App() {
  const list = ['前端', '后端', '测试']

  function handleItemClick(item) {
    console.log('点击了：', item)
  }

  return (
    <div style={{ padding: '20px' }}>
      <ul>
        {list.map((item) => (
          <li key={item} onClick={() => handleItemClick(item)}>
            {item}
          </li>
        ))}
      </ul>
    </div>
  )
}

export default App
```

这里顺手强调两个点：

- `map` 渲染列表时，每一项都要有 `key`
- 点击列表项时，如果要把当前项传进去，就用箭头函数包一下

`key` 最好用稳定、唯一的值，不要随便拿下标顶，尤其是列表会增删改的时候。

这一段虽然简单，但它已经把**列表渲染 + 事件处理**连起来了。后面你做文章列表、商品列表、菜单列表，基本就是这个思路。

## 5.10 事件处理里最常见的几个坑，先给你避掉

### 误区 1：把事件函数写成执行结果

错误：

```jsx
<button onClick={handleClick()}>点我</button>
```

正确：

```jsx
<button onClick={handleClick}>点我</button>
```

### 误区 2：事件名写错

错误：

```jsx
<button onclick={handleClick}>点我</button>
```

正确：

```jsx
<button onClick={handleClick}>点我</button>
```

### 误区 3：拿输入框值时不看 `e.target.value`

错误思路：

```jsx
function handleChange() {
  console.log(value)
}
```

正确方式：

```jsx
function handleChange(e) {
  console.log(e.target.value)
}
```

### 误区 4：想传参，结果把逻辑全塞进 JSX

如果事件里做的事情很多，别硬堆在标签里。能拆函数就拆函数：

```jsx
function handleDelete(id) {
  console.log('删除：', id)
}
```

```jsx
<button onClick={() => handleDelete(1)}>删除</button>
```

### 误区 5：事件处理和页面结构混成一团

新手很容易把按钮、输入、提示、列表都写成一锅粥。你先记个原则：**事件函数负责行为，JSX 负责展示**。这样代码更清楚，后面拆组件也更轻松。

### 误区 6：表单提交忘了阻止默认刷新

如果你写了 `form`，又没写 `e.preventDefault()`，页面一提交就刷新，状态全没了。这个坑先提前避开，省得你后面调半天。

## 5.11 这一章你要形成的思路，不是零散语法

这一章最重要的，不是背多少事件名，而是把流程想顺。

你以后看到交互需求，脑子里先过一遍：

1. 是点击还是输入？
2. 用 `onClick` 还是 `onChange`？
3. 处理函数要不要传参？
4. 要不要拿事件对象？
5. 最后是不是要更新 state？

把这条链路记住：

**用户操作 → 触发事件 → 执行函数 → 读取事件对象或参数 → 更新状态 → 页面重渲染**

这就是 React 组件思维里很关键的一步：  
**不是“我去操作 DOM”，而是“我通过事件驱动状态变化，再让界面自己刷新”。**

如果你这一步能顺了，后面学 `useState`、表单受控组件，基本就是顺水推舟。

- React 事件不是原生 DOM 的 `addEventListener` 写法，而是在 JSX 里直接写 `onClick`、`onChange`
- 事件处理函数要传“函数”，不要直接执行
- 不需要传参时直接写函数名，需要传参时用箭头函数包一层
- 事件对象 `e` 很重要，输入框当前值基本都从 `e.target.value` 里拿

- 表单提交时记得 `e.preventDefault()`，避免页面刷新
- 列表渲染时别忘了 `key`
- 最后都要落到一个结果：更新 state，让页面重新渲染

这一章先把“点一下、变一下”的思路练熟。下一章咱们就把这个结果真正存进状态里，正式把 `useState` 和 `setState` 的那套路子讲明白。

# 第5章 state 入门：从 setState 到 useState，页面状态终于会变了

## 开篇引入：页面不“动”，多半是因为你还没把状态接上

前面我们把 React 的基本骨架搭起来了，这一章终于轮到最关键的东西：**state**。

很多刚上手 React 的同学都会卡在这儿：

- 我把变量改了，页面怎么没变？
- 按钮都点了，为什么内容不刷新？
- 为什么在 React 里，“数据变了，页面自动变”这么重要？

老赵先给你一句最直白的话：**React 里的页面能不能动，核心就看你有没有把“变化的数据”放进 state 里。**

你可以把 state 理解成组件自己的“记忆本”。  
凡是会变化、而且变化后会影响页面展示的东西，比如数字、开关、输入框内容、列表数据、展开状态，都适合放进 state。

这一章咱们直接把这件事讲透：

1. state 是什么，为什么组件需要状态  
2. 类组件里的 setState 先做认知过渡  
3. 函数组件里的 useState 基础写法  
4. useState 返回值到底是什么  
5. 数字、文本、对象、数组这些状态怎么改  
6. 用计数器和开关案例把状态变化跑通  

学完这一章，你至少要能做到一件事：**看到一个页面需求，能判断哪些东西该放 state，怎么让它跟着用户操作变。**

## 一、state 是什么，为什么组件需要状态

### 1. state 不是普通变量，但很像“会触发页面更新的变量”

普通变量变了，页面不一定变；**state 变了，React 会帮你重新渲染组件**。

比如：

```jsx
function App() {
  let count = 0;

  const add = () => {
    count++;
    console.log(count);
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={add}>加一</button>
    </div>
  );
}
```

你点按钮时，`count` 确实变了，但页面上的数字大概率还是 `0`。  
原因很简单：`count` 只是普通变量，React 不知道它变了，自然不会主动刷新页面。

所以你记住这个判断标准就行：

> **如果一个数据变化后，页面需要跟着变化，那它大概率应该放到 state 里。**

---

### 2. 哪些东西适合放进 state

别一上来什么都往 state 里塞，先学会判断。

常见适合放 state 的数据有：

- 计数值：`count`
- 开关状态：`isOpen`、`isShow`
- 输入框内容：`keyword`、`username`
- 列表数据：`list`
- 当前选中项：`activeTab`
- 弹窗显示状态：`modalVisible`
- 请求回来的数据：`data`

简单说：

**state 主要管“会变，而且变了要影响页面”的东西。**

---

### 3. React 组件思维：先想“页面要展示什么状态”

这就是 React 最核心的组件思维。

以前你写原生 JS，更多是“先搭 DOM，再操作 DOM”。  
React 更像是：

- 先想页面有哪些状态
- 再根据状态决定页面长什么样
- 用户操作以后，只改状态，不直接乱戳 DOM

比如一个商品详情页，你先想：

- 商品标题有没有
- 价格是多少
- 是否已收藏
- 详情是否展开

这些都是状态。  
把状态想清楚，页面大体就出来了。  
这就是 React 的路子：**先状态，后视图。**

---

## 二、先认识一下 setState：老写法不用深学，但要知道它在干啥

### 1. 为什么要先看 class 的 setState

现在项目里很多新代码都在用函数组件和 Hooks，但你还是得认识一下 `setState`。原因很简单：

- 你会在旧代码里看到
- 它能帮你理解“状态更新”这个动作本身
- 以后看别人项目不会一脸懵

不用死背，但至少要知道：**React 的状态更新，最早就是从这套机制来的。**

---

### 2. 类组件的基本写法

类组件里，状态一般放在 `state` 里，更新时用 `setState`。

```jsx
import React from "react";

class App extends React.Component {
  state = {
    count: 0,
  };

  add = () => {
    this.setState({
      count: this.state.count + 1,
    });
  };

  render() {
    return (
      <div>
        <p>{this.state.count}</p>
        <button onClick={this.add}>加一</button>
      </div>
    );
  }
}

export default App;
```

你只要看懂三件事：

1. `state` 是组件自己的状态对象  
2. `setState` 是修改状态的方法  
3. `setState` 执行后，组件会重新渲染  

记住这句就够了：

**类组件改状态，用 `setState`；不要直接改 `this.state`。**

### 3. 先把它和 useState 对上号

你现在不用纠结类组件写法多不多，重点是把它和函数组件连起来看：

- 类组件：`this.state` + `this.setState`
- 函数组件：`useState` + `setXxx`

它们做的是同一件事，都是**改状态、触发页面更新**。  
只是现在我们更常用函数组件，所以你把 `setState` 当成“老路子认知过渡”就行，真正上手还是看下一节的 `useState`。

---

## 三、函数组件里的 useState：现在才是主角

### 1. 为什么现在大家更常用 useState

函数组件配合 Hooks，是现在 React 开发的主流写法。  
而 `useState` 就是函数组件里最常用的状态工具。

它让函数组件也能拥有状态能力，而且写法更直接，不用再写一堆 `class`、`this`。

---

### 2. useState 的基础写法，先拆成两步看

很多人第一次见 `useState`，会觉得这东西像语法糖，记不住。  
老赵建议你拆开看，就两步：

```jsx
const [count, setCount] = useState(0);
```

这句的意思是：

- `count`：当前状态值
- `setCount`：修改这个状态的方法
- `0`：初始值

完整例子如下：

```jsx
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  const add = () => {
    setCount(count + 1);
  };

  return (
    <div>
      <p>{count}</p>
      <button onClick={add}>加一</button>
    </div>
  );
}

export default App;
```

你可以把这个模板记成标准写法：

```jsx
const [xxx, setXxx] = useState(初始值);
```

后面写表单、切换、列表交互，都会一直用到它。

---

### 3. useState 返回值到底是什么

`useState` 返回的是一个二元数组：

```jsx
[状态值, 修改状态的方法]
```

比如：

```jsx
const [name, setName] = useState("老赵");
const [visible, setVisible] = useState(false);
```

这就是后面写 React 的高频模板。

---

## 四、状态更新到底怎么改：数字、文本、对象、数组

### 1. 数字状态：最简单，直接加减就行

```jsx
const [count, setCount] = useState(0);

const add = () => setCount(count + 1);
const minus = () => setCount(count - 1);
```

最小闭环就是：

- 页面显示一个数字
- 点击按钮
- 调用修改函数
- 数字变了，页面也跟着变

这就是 state 的第一课。

---

### 2. 文本状态：常用于输入框、标题、搜索词

```jsx
const [keyword, setKeyword] = useState("");
```

修改时：

```jsx
setKeyword("React");
```

常见场景就是搜索框、表单字段、按钮文案切换等。

比如页面上显示：

```jsx
<p>当前输入：{keyword}</p>
```

你一改 `keyword`，页面就会跟着刷新，这就是文本状态最常见的用法。

---

### 3. 对象状态：一组相关数据放一起

```jsx
const [user, setUser] = useState({
  name: "老赵",
  age: 18,
});
```

修改对象里的某个字段时，通常这样写：

```jsx
setUser({
  ...user,
  age: 19,
});
```

意思是：

- 先把原对象展开
- 再覆盖你要改的字段

记住一句话：

> **对象状态更新，通常要“拷贝一份，再改一项”。**

比如：

```jsx
setUser({
  ...user,
  city: "广州",
});
```

这样更稳妥，也更符合 React 的更新习惯。

---

### 4. 数组状态：列表、商品、选项卡都离不开它

```jsx
const [todos, setTodos] = useState(["吃饭", "睡觉"]);
```

新增一项：

```jsx
setTodos([...todos, "敲代码"]);
```

删除一项：

```jsx
setTodos(todos.filter((item) => item !== "睡觉"));
```

高频操作就两个：

- **新增：`[...旧数组, 新元素]`**
- **删除：`filter`**

#### 列表 key 先顺手记一下

如果你拿数组去渲染列表，别忘了 `key`：

```jsx
{
  todos.map((item, index) => (
    <li key={index}>{item}</li>
  ))
}
```

更推荐用稳定的唯一值做 `key`。  
你现在先记住底线：**列表渲染一定要写 key**。

---

### 5. 常见误区：不要把 state 当成“随便改的容器”

#### 误区一：直接改对象或数组

```jsx
user.age = 20;
setUser(user);
```

或者：

```jsx
todos.push("新任务");
setTodos(todos);
```

这种写法不推荐。因为你是在原地修改原数据，React 不一定好判断变化。

#### 误区二：以为 setState/setXxx 是立刻同步生效

```jsx
setCount(count + 1);
console.log(count);
```

你会发现打印出来的值不一定是最新的。  
先记住一句：

> **不要指望刚 set 完，下一行立刻拿到新值。**

---

## 五、用计数器和开关案例把状态变化跑通

### 1. 计数器案例：理解“改状态 -> 页面自动更新”

```jsx
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  const add = () => setCount(count + 1);
  const minus = () => setCount(count - 1);

  return (
    <div style={{ padding: 20 }}>
      <h2>计数器：{count}</h2>
      <button onClick={add}>加一</button>
      <button onClick={minus} style={{ marginLeft: 8 }}>
        减一
      </button>
    </div>
  );
}

export default App;
```

这个例子里，你只要盯住一条线：

1. 页面显示 `count`
2. 点击按钮
3. 调用 `setCount`
4. 组件重新渲染
5. 页面数字更新

这就是 React 状态驱动页面变化的完整闭环。

---

### 2. 开关案例：理解布尔值状态

```jsx
import { useState } from "react";

function App() {
  const [isOpen, setIsOpen] = useState(false);

  const toggle = () => setIsOpen(!isOpen);

  return (
    <div style={{ padding: 20 }}>
      <button onClick={toggle}>{isOpen ? "关闭" : "打开"}</button>

      {isOpen && <p>你看到我了，因为开关是开着的。</p>}
    </div>
  );
}

export default App;
```

你要学会一个判断：

- **`true / false` 类型的状态，特别适合表示开关**
- 页面内容是否展示，往往就靠它控制

弹窗、菜单、折叠面板，本质上也是这个套路。

---

## 六、从 useState 往后怎么接：下一章就用状态做渲染切换

这一章你已经把“状态”这个核心工具摸到了。  
但状态本身不是终点，真正有意思的是：**状态一变，页面怎么跟着变花样。**

接下来下一章我们就会讲：

- 条件渲染：`true` 的时候显示，`false` 的时候隐藏
- 列表渲染：一组数据怎么批量生成页面
- `key` 为什么必须写
- 状态变化后，页面怎么自动切换不同内容

你可以提前记住一句话：

> **state 负责变化，条件渲染和列表渲染负责把变化变成页面。**

## 赵老师小结

这一章你最该拿走的，不是语法，而是 **React 的状态思维**。

重点给你捋一下：

1. **state 是组件里会影响页面更新的数据**
2. **普通变量变了不一定刷新页面，state 变了会触发重新渲染**
3. **类组件里通过 `setState` 更新状态，函数组件里通过 `useState` 声明和修改状态**
4. **`useState` 返回两个东西：状态值和修改函数**
5. **数字、文本、对象、数组都能作为状态，但更新方式不一样**
6. **对象和数组更新时，尽量拷贝后再改，不要原地乱改**
7. **计数器和开关是理解 state 最好的入门案例**
8. **列表渲染时别忘了 key，这个习惯后面会一直用到**

你只要把这章吃透，后面学条件渲染、列表渲染、表单、父子组件通信，都会顺很多，因为那些东西本质上都是在管理状态、使用状态、响应状态变化。

# 第6章 条件渲染和列表渲染：让页面按数据自动切换和生成

前面我们已经把组件、props、事件和 `useState` 搭起来了。到了这一章，就进入真正“页面会动起来”的部分了。

真实项目里，页面大多不是写死的，而是根据数据变化来显示不同内容。比如：

- 登录了就显示头像和退出按钮，没登录就显示登录入口
- 有待办事项就展示列表，没数据就显示“暂时没有任务”
- 商品接口返回多少条，就渲染多少个商品卡片
- 某个按钮要不要显示，也得看当前状态

在 React 里，这些事主要靠两件事解决：

1. **条件渲染**：满足某个条件就显示，不满足就不显示
2. **列表渲染**：把数组里的每一项自动变成页面元素

你可以先把这章记成一句话：

> React 页面不是靠“硬写 DOM”堆出来的，而是靠“数据 + 判断 + 映射”自动生成出来的。

这一章你要重点抓住两件事：页面怎么按条件切换；数组怎么变成列表。只要这两块吃透了，后面做表单、做通信、做项目实战，都会顺很多。

---

## 一、条件渲染到底是干什么的？

说白了，**条件渲染就是按情况显示不同内容**。

传统前端里，我们常常要判断状态，然后改 `innerHTML`、切换显示隐藏。React 里也是这个思路，只不过你是在 JSX 里直接写判断逻辑。

### 1.1 最常见的三种写法

#### 写法一：三元表达式

适合“二选一”的场景。

```jsx
function LoginStatus() {
  const isLogin = true

  return (
    <div>
      {isLogin ? <p>欢迎回来，老铁！</p> : <p>请先登录</p>}
    </div>
  )
}
```

它适合这种场景：

- 登录 / 未登录
- 选中 / 未选中
- 有数据 / 没数据
- 加载中 / 加载完成

比如：

```jsx
{isLoading ? <p>加载中...</p> : <p>加载完成</p>}
```

#### 写法二：逻辑与 `&&`

适合“满足条件才显示”的场景。

```jsx
function Notice() {
  const showTip = true

  return <div>{showTip && <p>这里是提示信息</p>}</div>
}
```

它常用在：

- 有消息才显示提示
- 有权限才显示按钮
- 有未读数才显示角标
- 有错误才显示报错信息

比如：

```jsx
{error && <p className="error">{error}</p>}
```

#### 写法三：提前返回

逻辑复杂时，这种方式最清楚。

```jsx
function UserPanel() {
  const isLogin = true

  if (!isLogin) {
    return <p>请先登录</p>
  }

  return <p>欢迎回来</p>
}
```

如果组件里判断多、嵌套多，老赵建议优先用这种写法，别把 JSX 写成逻辑大杂烩。

### 1.2 什么时候用哪种写法？

直接记规则：

- **要么显示 A，要么显示 B**：用三元表达式
- **只有满足条件才显示一块内容**：用 `&&`
- **逻辑复杂，先判断再返回**：用提前 `return`

比如：

```jsx
{isLoading ? <p>加载中...</p> : <p>加载完成</p>}
```

这是二选一。

```jsx
{error && <p>请求失败，请稍后再试</p>}
```

这是有条件才显示。

```jsx
function UserStatus() {
  const isLogin = true
  const isVip = false

  if (!isLogin) return <p>请先登录</p>
  if (isVip) return <p>VIP 用户，欢迎你</p>

  return <p>普通用户，欢迎回来</p>
}
```

这个写法朴素，但很稳。

### 1.3 条件渲染的小提醒

新手常把条件写得太复杂，最后 JSX 乱成一锅粥。老赵建议你记住：

> JSX 里可以做判断，但别把它写成大型逻辑现场。

如果判断太多，先在 `return` 前把变量算好，再拿结果去渲染：

```jsx
function UserPanel() {
  const isLogin = true
  const isVip = false

  let content = <p>请登录</p>

  if (isLogin && isVip) {
    content = <p>VIP 用户，欢迎你</p>
  } else if (isLogin) {
    content = <p>普通用户，欢迎回来</p>
  }

  return <div>{content}</div>
}
```

这样更清楚，也更适合入门阶段。

### 1.4 空状态：没数据的时候别让页面发呆

条件渲染在真实项目里最常见的用途之一，就是处理**空状态**。

比如待办列表还没数据、商品接口还没返回、搜索结果为空，这时候页面不能啥都不说，最好给一个提示。

```jsx
function EmptyStateDemo() {
  const list = []

  return (
    <div>
      {list.length > 0 ? (
        <ul>
          {list.map((item) => (
            <li key={item.id}>{item.name}</li>
          ))}
        </ul>
      ) : (
        <p>当前没有数据，先去添加一条吧</p>
      )}
    </div>
  )
}
```

这个场景特别实用。你以后做列表页、搜索页、订单页，都会反复碰到。

---

## 二、列表渲染的基本思路：数组映射成页面

React 另一个核心能力，就是把数组数据直接变成页面元素。

### 2.1 列表渲染本质是什么？

一句话：

> **数组里的每一项，都是页面上的一个小块。**

比如待办数组：

```jsx
const todos = ['学 React', '写页面', '提交作业']
```

用 `map()` 就能渲染成列表：

```jsx
function TodoList() {
  const todos = ['学 React', '写页面', '提交作业']

  return (
    <ul>
      {todos.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  )
}
```

核心就是：

- 遍历数组
- 每一项返回一个 JSX
- React 自动拼成页面

### 2.2 实际项目里更常见的是对象数组

比如：

```jsx
const products = [
  { id: 1, name: '键盘', price: 199 },
  { id: 2, name: '鼠标', price: 99 },
  { id: 3, name: '显示器', price: 1299 }
]
```

渲染时这样写：

```jsx
function ProductList() {
  const products = [
    { id: 1, name: '键盘', price: 199 },
    { id: 2, name: '鼠标', price: 99 },
    { id: 3, name: '显示器', price: 1299 }
  ]

  return (
    <div>
      {products.map((item) => (
        <div key={item.id}>
          <h3>{item.name}</h3>
          <p>价格：{item.price} 元</p>
        </div>
      ))}
    </div>
  )
}
```

这就是 React 的典型套路：

- 数据放数组里
- `map()` 遍历
- 每条数据渲染成一个结构块
- 数据变，页面就变

你以后做资讯列表、商品卡片、用户列表、评论列表，基本都靠这条路。

### 2.3 列表渲染别忘了空数据处理

实际开发里，数组经常为空，比如接口还没返回，或者当前确实没内容。别直接渲染空列表，最好加兜底提示：

```jsx
function TodoList() {
  const todos = []

  return (
    <div>
      {todos.length > 0 ? (
        <ul>
          {todos.map((item) => (
            <li key={item}>{item}</li>
          ))}
        </ul>
      ) : (
        <p>当前没有待办事项</p>
      )}
    </div>
  )
}
```

页面不是“有内容就展示”，还得考虑“没内容时怎么办”。

## 三、列表渲染为什么一定要写 key？

这个点特别重要，但很多人入门时会忽略。

### 3.1 `key` 是干什么的？

你可以把 `key` 理解成：

> **列表里每一项的身份证号。**

React 更新列表时，需要知道：

- 哪一项是新来的
- 哪一项被删了
- 哪一项只是位置变了
- 哪一项内容改了

没有 `key`，React 就不容易判断，更新效率会差，某些情况下还会渲染错位。

所以，**只要是列表渲染，基本都要写 `key`**。

### 3.2 标准写法

最推荐用稳定且唯一的字段，比如数据库里的 `id`：

```jsx
{products.map((item) => (
  <div key={item.id}>{item.name}</div>
))}
```

### 3.3 别随手拿下标当 key

很多新手爱写：

```jsx
{list.map((item, index) => (
  <div key={index}>{item.name}</div>
))}
```

这不是绝对不能用，但有风险。尤其当列表会增删、排序、插入、拖拽调整位置时，`index` 会变，身份就不稳定了。

### 3.4 什么时候 index 勉强能用？

如果列表：

- 静态展示
- 顺序不变
- 不会增删改排序

那 `index` 可以临时顶一下。但只要能用稳定 id，就尽量别用 `index`。

### 3.5 key 的几个误区

#### 误区一：key 写在组件内部没用

```jsx
{list.map((item) => (
  <TodoItem item={item} />
))}
```

这样不行，外层要写：

```jsx
{list.map((item) => (
  <TodoItem key={item.id} item={item} />
))}
```

`key` 要写在 `map()` 返回的最外层元素上。

#### 误区二：key 不会传给 props

`key` 是 React 内部使用的特殊字段，不会像普通 props 一样传给子组件。

#### 误区三：别用随机数当 key

```jsx
{list.map((item) => (
  <div key={Math.random()}>{item.name}</div>
))}
```

这个非常不推荐。因为每次渲染 key 都变，React 会认为每一项都是新元素，反而更乱。

记住一句话：

> **key 要稳定、唯一、可重复使用。**

## 四、实战：做一个待办列表，把条件渲染和列表渲染串起来

光看概念不够，得落地。我们来做一个最常见的小案例：**待办列表**。

这个例子会用到：

- 条件渲染
- 列表渲染
- `key`
- `useState`

### 4.1 需求拆解

页面要实现三件事：

1. 输入待办内容
2. 点击按钮添加到列表
3. 当列表为空时显示提示

写页面前，先把数据、状态和交互想清楚，别一上来就敲。

### 4.2 完整示例

```jsx
import { useState } from 'react'

function TodoApp() {
  const [inputValue, setInputValue] = useState('')
  const [todos, setTodos] = useState([
    { id: 1, text: '学 React' },
    { id: 2, text: '练习列表渲染' }
  ])

  const addTodo = () => {
    if (!inputValue.trim()) return

    const newTodo = {
      id: Date.now(),
      text: inputValue
    }

    setTodos([...todos, newTodo])
    setInputValue('')
  }

  return (
    <div>
      <h2>待办列表</h2>

      <input
        value={inputValue}
        onChange={(e) => setInputValue(e.target.value)}
        placeholder="请输入待办事项"
      />
      <button onClick={addTodo}>添加</button>

      {todos.length > 0 ? (
        <ul>
          {todos.map((item) => (
            <li key={item.id}>{item.text}</li>
          ))}
        </ul>
      ) : (
        <p>暂时没有待办事项</p>
      )}
    </div>
  )
}

export default TodoApp
```

### 4.3 这个案例里你要看懂的点

#### 第一，输入框是受控思路的延伸

`value` 绑定状态，`onChange` 更新状态，这样输入框和数据同步了。你现在不用纠结“受控组件”这个词，先把这种写法记住。后面讲表单的时候，我们还会把它捋顺。

#### 第二，新增数据不要直接改原数组

```jsx
setTodos([...todos, newTodo])
```

这是 React 里常见写法，意思是生成一个新数组，再更新状态。旧数据不动，基于旧数据复制一份，然后把新项加进去。

#### 第三，列表项用 `id` 当 key

这比用下标稳得多，也更符合实际项目习惯。

#### 第四，空数组时给提示

这就是条件渲染的典型场景。列表不是永远有数据，页面也不能永远空着。

## 六、这一章你真正该带走的页面思维

学完条件渲染和列表渲染，你要形成一个很实用的 React 思路：

### 6.1 页面不是“写出来”的，而是“算出来”的

你不要先想着“我得写多少个 div”，而是先想：

- 当前有啥数据
- 哪些内容需要显示
- 什么条件下显示
- 一条数据对应一个什么组件

这就是 React 的组件思维和数据驱动思维。

### 6.2 先判断，再渲染；先组织数据，再映射页面

可以记成这几个步骤：

1. 准备数据
2. 判断要不要显示某块内容
3. 用 `map()` 把数组变成列表
4. 给每项加稳定 `key`
5. 空数据时做兜底提示

这个流程你以后会反复用，几乎所有基础页面都绕不开。

### 6.3 别把 React 写成“硬编码页面”

如果你发现自己在重复写很多结构差不多的 `div`，就该想想：

- 这是不是应该用数组渲染？
- 这是不是应该拆成一个小组件？
- 这是不是应该先判断再显示？

这几个问题问一遍，通常能少走很多弯路。

这一章其实就干了两件大事：

- **条件渲染**：决定页面显示什么
- **列表渲染**：决定页面有多少个内容块

你只要记住这些关键点就够了：

- 二选一就用三元表达式

说白了，React 页面大多数时候就是在做一件事：**根据数据，把该显示的显示出来。**

这也是你后面写表单、写通信、写项目时最常用的底层套路。页面不用死写，数据一变，页面跟着变，这才是 React 的味道。

# 第7章 表单处理：受控组件、输入联动和提交数据怎么写

表单在前端里几乎天天见：登录、注册、搜索、编辑资料、下单、留言、筛选条件，只要用户要“填点什么”，基本都绕不开它。

在 React 里，表单最核心的一件事不是“怎么拿值”，而是**谁来管值**。标准答案很简单：**让 state 作为数据源，输入框跟着 state 走**。这就是本章主角——**受控组件**。

你先记住一句话：

**输入框里显示什么，由 React 的 state 决定；用户输入以后，再把新值写回 state。**

这样写的好处也很直接：

- 数据好管
- 输入联动方便
- 校验容易加
- 提交逻辑清楚
- 清空和回显都很顺手

后面做项目，只要不是特别特殊，表单优先按这个思路写，基本稳。

---

## 一、为什么 React 表单要重点学受控组件？

### 1.1 什么叫“受控”

在 React 里，如果一个表单元素的值由组件状态控制，它就是受控组件。

可以直接理解成：

- **state 是唯一数据源**
- 输入框只是展示 state 的窗口
- 用户输入时，通过事件把新值写回 state
- state 一变，页面自动更新

### 1.2 为什么要这样写

受控组件最适合这些场景：

- 实时校验
- 输入联动
- 条件提交
- 表单重置
- 编辑数据回显

一句话：**让表单可控、可预测、可维护**。复杂表单更是离不开它。

### 1.3 判断是不是受控组件，看这三条

1. 有没有用 state 保存字段值  
2. 输入框有没有绑定 `value`  
3. 输入变化时有没有用 `onChange` 写回 state  

这三条齐了，基本就是受控组件。

### 1.4 常见坑

- `value` 写了，没写 `onChange`，输入框会变只读
- state 里存的是数字，input 里却直接当数字处理
- 每个字段都单独写一个 `setXxx`，代码容易散
- 只会 `e.target.value`，遇到 checkbox、radio、select 就卡住
- 提交只绑按钮点击，不走 `form onSubmit`，回车提交也失效

记住：**受控组件不是为了复杂，而是为了让复杂有章法。**

### 赵老师小结

React 里的表单，重点不是“怎么读 DOM”，而是“谁来管数据”。  
受控组件就是让 **React 管值**。这样不管是联动、校验、提交还是清空，都能顺着一套逻辑往下写。

## 二、input、textarea、select 的受控写法怎么写？

`input`、`textarea`、`select` 写法不一样，但套路一样：**value 绑定 state，onChange 更新 state**。

### 2.1 input

```jsx
import { useState } from "react";

function LoginForm() {
  const [username, setUsername] = useState("");

  return (
    <div>
      <input
        type="text"
        value={username}
        onChange={(e) => setUsername(e.target.value)}
        placeholder="请输入用户名"
      />
      <p>当前输入：{username}</p>
    </div>
  );
}

export default LoginForm;
```

### 2.2 textarea

```jsx
import { useState } from "react";

function CommentBox() {
  const [content, setContent] = useState("");

  return (
    <textarea
      value={content}
      onChange={(e) => setContent(e.target.value)}
      placeholder="写点什么吧"
    />
  );
}
```

### 2.3 select

```jsx
import { useState } from "react";

function CitySelect() {
  const [city, setCity] = useState("beijing");

  return (
    <select value={city} onChange={(e) => setCity(e.target.value)}>
      <option value="beijing">北京</option>
      <option value="shanghai">上海</option>
      <option value="shenzhen">深圳</option>
    </select>
  );
}
```

注意：

- `select` 上放 `value`
- `option` 里放的是提交值，不是显示文本
- `textarea` 在 React 里也走 `value`，别按原生写法来

### 赵老师小结

`input`、`textarea`、`select` 的受控写法本质一样：**value 绑 state，onChange 改 state**。  
先把这个基本模型吃透，后面所有表单都能照着套。

## 三、onChange 配合 state，怎么实现输入联动？

### 3.1 什么叫输入联动

输入联动就是：一个输入动作，带动页面其他地方一起变。比如：

- 输入用户名，下方实时显示“欢迎你，xxx”
- 输入价格，另一个字段自动计算结果
- 勾选“同意协议”，按钮才可点击
- 选择城市后，提示当前配送范围

这类需求 React 很适合做，因为它天然就是**数据变，界面跟着变**。

### 3.2 最基本的联动

```jsx
import { useState } from "react";

function LivePreview() {
  const [name, setName] = useState("");

  return (
    <div>
      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="请输入姓名"
      />
      <p>你好，{name || "朋友"}！</p>
    </div>
  );
}
```

### 3.3 多字段表单怎么写更顺

字段一多，别每个都单独写一套 `useState`，更稳的做法是：**用一个对象统一管理**。

```jsx
import { useState } from "react";

function ProfileForm() {
  const [formData, setFormData] = useState({
    name: "",
    email: "",
  });

  const handleChange = (e) => {
    const { name, value } = e.target;
    setFormData({
      ...formData,
      [name]: value,
    });
  };

  return (
    <div>
      <input
        name="name"
        value={formData.name}
        onChange={handleChange}
        placeholder="姓名"
      />
      <input
        name="email"
        value={formData.email}
        onChange={handleChange}
        placeholder="邮箱"
      />
    </div>
  );
}
```

关键点就三个：

- 给输入框加 `name`
- 用 `e.target.name` 找到字段名
- 用 `[name]` 更新对应字段

### 3.4 联动时常见问题

- 更新对象时忘了展开旧数据，别的字段被覆盖
- state 结构没规划好，后面越写越乱
- 临时变量和 state 混着用，自己都分不清谁才是真数据源

记住：**联动的前提是关键数据都放进 state。**

### 赵老师小结

输入联动的核心就一句：**输入变化 → 更新 state → 页面重新渲染**。  
多字段表单建议用一个对象统一管理，靠 `name + value` 做通用处理，代码更整齐，也更适合真实项目。

## 四、表单提交时，preventDefault 到底怎么用？

### 4.1 为什么点击提交会刷新页面

原生表单一提交，浏览器默认会刷新或跳转。  
但在 React 单页应用里，这通常不是你想要的。我们更希望：

- 拿到表单数据
- 做校验
- 发请求
- 处理成功失败
- 保持当前页面状态

所以要先阻止默认提交行为。

### 4.2 正确写法

```jsx
function handleSubmit(e) {
  e.preventDefault();
  console.log("开始提交表单");
}
```

再绑定到表单上：

```jsx
<form onSubmit={handleSubmit}>
  <button type="submit">提交</button>
</form>
```

注意：

- 提交事件写在 `form` 上，不是只写在按钮上
- `preventDefault()` 用来阻止浏览器默认刷新
- 提交逻辑统一放到 `handleSubmit`

### 4.3 提交流程一般做什么

基础提交流程通常是：

1. 阻止默认行为
2. 做简单校验
3. 读取 state 里的表单数据
4. 发请求或模拟提交
5. 成功后清空表单
6. 失败后提示错误

比如：

```jsx
const handleSubmit = (e) => {
  e.preventDefault();

  if (!formData.name.trim()) {
    alert("姓名不能为空");
    return;
  }

  console.log("提交数据：", formData);
};
```

### 4.4 只绑按钮点击行不行

可以，但不推荐当主方案。  
`form onSubmit` 能同时支持按钮点击和回车提交，逻辑更统一，也更符合语义。

### 赵老师小结

表单提交优先走 `form` 的 `onSubmit`，别只盯着按钮点击。  
提交前记得 `preventDefault()`，不然页面刷新会把你的状态直接冲掉。

### 老赵带你练一练

1. 写一个带提交按钮的表单，点击后不刷新页面。  
2. 提交前检查用户名是否为空。  
3. 试试按回车键提交，看看能不能正常触发。

## 五、表单校验和简单清空逻辑，怎么做最顺手？

### 5.1 校验先从简单的来

入门阶段先把最实用的判断做好：

- 不能为空
- 长度够不够
- 邮箱格式像不像
- 是否选了某个选项

比如：

```jsx
if (!formData.email.includes("@")) {
  alert("邮箱格式不对");
  return;
}
```

核心就一句：**提交前拦住错误数据**。

### 5.2 清空表单很简单

受控组件的好处之一，就是清空特别方便。  
把 state 重新设回初始值就行。

```jsx
const initialForm = {
  name: "",
  email: "",
  city: "beijing",
};

const [formData, setFormData] = useState(initialForm);

const handleReset = () => {
  setFormData(initialForm);
};
```

字段多的时候，建议把默认值单独抽成 `initialForm`，后面重置、初始化、回显都方便。

### 5.3 错误提示怎么放

入门阶段可以先用最直接的方式：

- `alert`
- 页面显示红字
- 提交按钮下方提示错误信息

比如：

```jsx
const [error, setError] = useState("");

const handleSubmit = (e) => {
  e.preventDefault();

  if (!formData.name.trim()) {
    setError("姓名不能为空");
    return;
  }

  setError("");
};
```

页面里再渲染：

```jsx
{error && <p style={{ color: "red" }}>{error}</p>}
```

### 赵老师小结

校验和清空都不复杂，核心就是：**校验看 state，清空也改 state**。  
受控组件的价值就在这儿，表单整个生命周期都能被你控制住。

### 老赵带你练一练

1. 给表单加“姓名不能为空”的校验。  
2. 提交成功后，把表单恢复初始值。  
3. 页面上显示一个简单错误提示，不要只用 `alert`。

## 六、做一个可提交的基础表单案例

下面把前面的内容拼起来，做一个完整点的例子：**用户信息登记表**。  
包含：

- 姓名输入框
- 自我介绍 textarea
- 城市 select
- 提交按钮
- 校验
- 清空

### 6.1 完整代码

```jsx
import { useState } from "react";

const initialForm = {
  name: "",
  intro: "",
  city: "beijing",
};

function UserForm() {
  const [formData, setFormData] = useState(initialForm);
  const [error, setError] = useState("");

  const handleChange = (e) => {
    const { name, value } = e.target;
    setFormData({
      ...formData,
      [name]: value,
    });
  };

  const handleSubmit = (e) => {
    e.preventDefault();

    if (!formData.name.trim()) {
      setError("姓名不能为空");
      return;
    }

    if (!formData.intro.trim()) {
      setError("自我介绍不能为空");
      return;
    }

    setError("");
    console.log("提交成功：", formData);
    alert("提交成功");
    setFormData(initialForm);
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <label>姓名：</label>
        <input
          name="name"
          value={formData.name}
          onChange={handleChange}
          placeholder="请输入姓名"
        />
      </div>

      <div>
        <label>自我介绍：</label>
        <textarea
          name="intro"
          value={formData.intro}
          onChange={handleChange}
          placeholder="简单介绍一下自己"
        />
      </div>

      <div>
        <label>城市：</label>
        <select name="city" value={formData.city} onChange={handleChange}>
          <option value="beijing">北京</option>
          <option value="shanghai">上海</option>
          <option value="shenzhen">深圳</option>
        </select>
      </div>

      {error && <p style={{ color: "red" }}>{error}</p>}

      <button type="submit">提交</button>
    </form>
  );
}

export default UserForm;
```

### 6.2 这套套路怎么记

以后做类似表单，基本按这个流程来：

#### 第一步：先定初始数据
把表单字段写成一个对象，默认值准备好。

#### 第二步：用 state 管住整个表单
`useState(initialForm)` 保存表单数据。

#### 第三步：写通用 handleChange
靠 `name + value` 统一更新字段。

#### 第四步：提交前先校验
别急着发请求，先看关键字段有没有问题。

#### 第五步：提交成功后清空或重置
直接把 state 改回初始值。

### 6.3 接真实接口时怎么接

后面学到请求之后，这个提交函数就可以改成：

- 先校验
- 再 `await` 提交接口
- 成功后重置表单
- 失败后显示错误提示

也就是说，**今天这个基础案例，就是后面接 API 的地基**。  
地基打稳了，后面做登录页、注册页、编辑页、搜索栏、筛选器，本质都只是换字段和接口，不换思路。

## 七、把表单值传给别的组件，提前感受一下后面要学的通信

表单写到这里，下一步常见问题就来了：**表单里的值，不只自己要用，还要给别的组件看。**

比如：

- 你输入用户名，旁边的头像卡片要跟着变
- 你选了城市，底部提示条要显示当前城市

这时候就不能只让当前组件自己闷头写了，得把数据往外传，或者把外面的数据传进来。  
这就是下一章要讲的 **组件通信**，尤其是 **父子组件通信**。

你先记一句很实在的话：

**表单写在子组件里没问题，但只要别的组件也要用这个值，就得考虑通信。**

表单不难，难的是你有没有用对方式。

# 第8章 组件通信：父子组件怎么配合，数据怎么来回传

做 React，组件写多了，绕不开一个问题：**页面一复杂，数据就得在组件之间流动。**  
这一章老赵带你把最常用的通信方式讲明白：**父子组件怎么传数据，子组件怎么把信息传回父组件，兄弟组件怎么先建立思路。** 这章吃透了，后面做表单、列表、弹窗、小项目，基本就不会乱。

这一章的重点很明确：**先把父子组件配合玩明白。**

## 一、先搞清楚：React 里数据往哪走

React 里最常见的通信场景就三种：

1. **父传子**
2. **子传父**
3. **兄弟组件通信**

先别急着背名词，先记住最实用的一条：

> **谁负责管理数据，谁就更像父组件；谁只负责展示或触发操作，谁就更像子组件。**

你后面写页面，不是先想高级模式，而是先想：**这个数据放哪儿，谁来管，谁来用，谁来改。**

### 1. 为什么要分父子？

因为 React 里，组件最好别互相乱改数据。  
比如顶部要显示用户名，列表项要点删除，表单输入后要统一提交，如果每个组件都自己存一份，最后很容易出现：

- 状态散乱
- 数据不同步
- 改一个地方，别的地方一起炸

所以 React 更常见的方式是：

- **父组件保存重要数据**
- **父组件通过 props 传给子组件**
- **子组件想通知父组件，就调用父组件传下来的函数**

这个模式非常常用，后面做项目基本离不开。

### 2. 一个简单的心智模型

你可以把 React 组件理解成一家小店：

- 父组件像老板，负责记账、管库存、定规则
- 子组件像店员，负责展示商品、接收操作
- 子组件不能直接改库存，要先告诉老板

这个比喻不高大上，但很好用。  
**谁掌握数据，谁就负责最终决策。**

---

## 二、父传子：通过 props 传数据和函数

### 1. 父传子最常见的是什么？

最常见就两类：

- **普通数据**：字符串、数字、对象、数组
- **函数**：让子组件以后“反向通知”父组件

先看最简单的传数据。

```jsx
// 父组件 App.jsx
function App() {
  const userName = "老赵";
  return <Hello name={userName} age={18} />;
}
```

```jsx
// 子组件 Hello.jsx
function Hello(props) {
  return (
    <div>
      <p>你好，{props.name}</p>
      <p>年龄：{props.age}</p>
    </div>
  );
}
```

这里要记住：

- 父组件在 JSX 上写属性
- 子组件通过 `props` 接收
- 子组件不能直接改父组件传下来的值

如果把前面学过的 JSX 规则串起来理解，就会很自然：**标签上写属性，组件里用 `props` 接。** 这就是 React 组件之间最基础的配合方式。

### 2. props 的几个实战用法

#### 传字符串

```jsx
<Title text="React 入门课" />
```

#### 传数字

```jsx
<Price value={99} />
```

#### 传对象

```jsx
<UserCard user={{ name: "老赵", job: "全栈" }} />
```

#### 传数组

```jsx
<List items={["React", "Vue", "Angular"]} />
```

#### 传函数

```jsx
<Button onClick={handleSave} />
```

你会发现，`props` 不只是传文字，它其实是**组件之间的接口**。  
所以做组件时，别急着写页面，先想清楚这个组件需要什么输入。

### 3. 为什么要传函数？

父组件为什么要把函数传给子组件？因为子组件往往不知道数据最终要保存到哪里。比如：

- 点击“保存”后要提交表单
- 点击“删除”后要更新列表
- 点击“切换状态”后要修改父组件里的 state

这时候子组件只负责触发动作，真正的数据处理交给父组件。  
这就叫：**父组件下发能力，子组件按需调用。**

### 4. props 使用时的注意点

#### 注意点 1：props 是只读的

子组件里不要直接改 props。

```jsx
function Hello(props) {
  props.name = "别乱改";
}
```

这个思路不对。props 是父组件传来的输入，子组件只管用，不管改。

#### 注意点 2：别把所有东西都往 props 里塞

新手常见问题是：既然能传，那我全传进去。  
别这么干。传太多说明组件职责可能乱了。更好的做法是：**一个组件只负责一件事，传它真正需要的部分。**

#### 注意点 3：命名要清楚

比如：

```jsx
<UserCard user={userInfo} onEdit={handleEdit} />
```

一看就知道：

- `user` 是数据
- `onEdit` 是事件回调

别写成 `a1`、`fn2`、`data3`，那不是开发，是挖坑。

## 三、子传父：通过回调函数把信息传回去

### 1. 子组件怎么把信息传给父组件？

核心办法就一个：**父组件先传一个函数给子组件，子组件调用这个函数，并把自己的信息带回去。**

```jsx
function App() {
  const handleMsg = (msg) => {
    console.log("父组件收到：", msg);
  };

  return <Child onSend={handleMsg} />;
}
```

```jsx
function Child(props) {
  return (
    <button onClick={() => props.onSend("我是子组件发来的消息")}>
      发送消息
    </button>
  );
}
```

流程很简单：

1. 父组件定义处理函数 `handleMsg`
2. 父组件通过 props 传给子组件
3. 子组件需要时调用 `props.onSend(...)`
4. 父组件收到后自己决定怎么处理

这就是 React 里很常见的“反向通知”模式。

### 2. 子传父最常见的场景

- 子组件按钮点击后，通知父组件打开弹窗
- 子组件表单输入后，把值交给父组件统一保存
- 子组件列表项删除时，通知父组件更新列表

子组件不需要知道最终怎么处理，它只要把事情发出去就行。  
**它负责触发，父组件负责落地。**

### 3. 标准写法

#### 父组件

```jsx
function Parent() {
  const handleChildData = (data) => {
    console.log("收到子组件数据：", data);
  };

  return <Child onChangeData={handleChildData} />;
}
```

#### 子组件

```jsx
function Child(props) {
  return (
    <button onClick={() => props.onChangeData("子组件的数据")}>
      发送
    </button>
  );
}
```

这个结构很适合做：

- 新增
- 删除
- 编辑
- 提交表单
- 选择某个选项后通知父组件

### 4. 一个更完整的父子联动案例：留言板

这个案例把父传子、子传父、列表 key、受控组件一起串起来。

#### 需求

我们做一个留言板：

- 上面有输入框
- 输入留言后点击“添加”
- 父组件把留言保存到列表
- 子组件把输入内容传给父组件
- 列表里每条留言可以删除

#### 父组件：统一管理留言数据

```jsx
import { useState } from "react";
import MessageForm from "./MessageForm";
import MessageList from "./MessageList";

function App() {
  const [messages, setMessages] = useState([
    { id: 1, text: "第一条留言" },
    { id: 2, text: "第二条留言" },
  ]);

  const handleAddMessage = (text) => {
    const newMsg = {
      id: Date.now(),
      text,
    };
    setMessages([...messages, newMsg]);
  };

  const handleDeleteMessage = (id) => {
    setMessages(messages.filter((item) => item.id !== id));
  };

  return (
    <div>
      <h1>留言板</h1>
      <MessageForm onAdd={handleAddMessage} />
      <MessageList items={messages} onDelete={handleDeleteMessage} />
    </div>
  );
}

export default App;
```

父组件很清楚：

- `messages` 是主数据
- `handleAddMessage` 负责新增
- `handleDeleteMessage` 负责删除

也就是说，**真正的数据中心在 App 里**。

#### 输入组件：只负责收集内容并上报

```jsx
import { useState } from "react";

function MessageForm(props) {
  const [value, setValue] = useState("");

  const handleSubmit = () => {
    if (!value.trim()) return;
    props.onAdd(value);
    setValue("");
  };

  return (
    <div>
      <input
        value={value}
        onChange={(e) => setValue(e.target.value)}
        placeholder="请输入留言"
      />
      <button onClick={handleSubmit}>添加留言</button>
    </div>
  );
}

export default MessageForm;
```

这里顺手复习一下受控组件：

- 输入框的值来自 state
- 输入变化时更新 state
- 点击按钮时把值交给父组件

这就是标准表单组件写法。  
**子组件不保存最终结果，只负责采集和传递。**

#### 列表组件：负责展示和删除

```jsx
function MessageList(props) {
  return (
    <ul>
      {props.items.map((item) => (
        <li key={item.id}>
          {item.text}
          <button onClick={() => props.onDelete(item.id)}>删除</button>
        </li>
      ))}
    </ul>
  );
}

export default MessageList;
```

这里还能顺手记住一个重点：**列表渲染必须写 `key`。**  
`key` 最好稳定、唯一，别乱用随机值。

这个例子就是一个完整的父子联动闭环：

- 父组件传数据和函数给子组件
- 子组件通过回调把输入传回来
- 父组件更新 state
- 子组件再根据新的 props 显示结果

这就是基础项目最常见的落地方式。

## 四、兄弟组件通信：先点到为止，先找共同父组件

### 1. 兄弟组件怎么通信？

兄弟组件不能直接面对面对话。  
在 React 里，**兄弟组件通信通常要借助共同的父组件做中转站。**

也就是说：

- A 组件把数据传给父组件
- 父组件再传给 B 组件

或者反过来：

- B 要修改 A 依赖的数据
- 先通知父组件
- 父组件更新后再分发给 A

### 2. 为什么先记住这个就够了？

因为你现在是入门阶段，不需要一上来就上更复杂的状态管理。  
先记住一句话就行：

> **兄弟组件不直接通话，先找共同父组件。**

以后你做“筛选列表”“表格搜索”“商品搜索页”，本质都是这个套路。

### 3. 一个简单例子

假设有两个兄弟组件：

- `SearchBar`：输入搜索关键字
- `ProductList`：展示搜索结果

它们的父组件 `App` 里保存 `keyword` 和 `list`。

流程是：

1. `SearchBar` 输入内容，调用父组件函数
2. 父组件更新 `keyword`
3. 父组件把 `keyword` 传给 `ProductList`
4. `ProductList` 根据关键字渲染

这就是最基础的兄弟通信思路。  
这一段先理解就行，不用展开太深。后面做完整项目时，你会发现很多页面都还是这个中转逻辑。

## 五、把组件通信放进一个小项目场景里练习

光看例子不够，咱们再把思路总结成一个小项目流程。  
如果你要从零做一个小页面，一般可以这么走：

### 1. 先拆组件，再想数据

先别急着写代码，先把页面拆一下：

- 哪些地方是展示区
- 哪些地方是输入区
- 哪些地方是列表区
- 哪些数据要统一管理

这一步很重要。React 的组件思维不是“一个页面写到底”，而是“先拆，再组”。

### 2. 再定谁管数据

一般来说：

- 父组件管主数据
- 子组件管输入和展示
- 子组件需要修改数据时，通过回调通知父组件

这就是最稳的落地方式。

### 3. 再定 props 的内容

你可以先问自己三件事：

- 子组件要展示什么？——传数据
- 子组件要触发什么动作？——传函数
- 子组件是否需要把输入结果传回来？——传回调

这样一套下来，组件之间的关系就清楚了。

### 4. 这章和前面知识怎么接上

你会发现，这一章不是孤立的，它会把前面学过的东西全串起来：

- **JSX**：组件标签怎么写
- **state / useState**：数据放哪里
- **表单受控组件**：输入框怎么管
- **列表渲染**：怎么显示一堆数据
- **列表 key**：为什么必须写
- **组件通信**：数据怎么在父子之间流动

所以你别把它当成单独的一章。  
它其实是在帮你建立一个最核心的 React 习惯：**先拆组件，再理数据流。**

## 六、实战里最容易踩的坑

### 1. 组件之间“谁管数据”不清楚

最常见的混乱是：输入框自己存一份，列表又存一份，父组件还存一份。  
最后三份数据不同步。

记住一句话：

> **数据尽量只放一处，谁负责修改，谁就管理。**

一旦出现“改了 A，B 没变”，先查是不是多头管理了。

### 2. 忘记给列表项加 key

列表渲染时一定要写 `key`：

```jsx
{items.map((item) => (
  <li key={item.id}>{item.text}</li>
))}
```

`key` 最好稳定、唯一，后面如果要增删改排序，更要认真写。

### 3. 回调函数命名太随意

比如：

- `aaa`
- `handle1`
- `fun`

这种名字会让通信逻辑很难读。  
建议直接用：

- `onAdd`
- `onDelete`
- `onChange`
- `onSubmit`

### 4. 只想着“传值”，忘了“传行为”

父传子不只是传文本，也可以传函数。  
很多时候，真正重要的不是“传什么内容”，而是“把什么能力交给子组件”。

# 第9章 useEffect 基础：什么时候该做副作用，什么时候该请求数据

## 开篇引入：先别把 useEffect 想复杂了

前面我们已经把 `useState` 搞明白了：页面上的数据一变，组件就重新渲染。  
但实际开发里，光会“改页面里的状态”还不够，还经常要做一些**不直接写在 JSX 里的事**，比如：

- 页面刚打开时请求数据
- 监听某个状态变化，顺手改浏览器标题
- 开一个定时器，过一会儿自动更新
- 组件离开页面时，把定时器清掉

这些事，通常就交给 `useEffect`。

你先把它记成一句话：

> **组件渲染完了，或者某个数据变了，我再去做点别的事。**

这“别的事”，就叫副作用。别被术语吓住，它不是说代码有问题，而是说这件事不是单纯算 UI，而是会影响外部环境，比如请求网络、改标题、开定时器、做清理。

入门阶段你先记住最常见的场景：

- 页面先显示出来
- 然后去拉数据
- 拉到数据后再更新页面

这个流程，基本就是 `useEffect` 的主场。

## 一、useEffect 是干什么的？适合解决什么问题？

### 1.1 先搞清楚：什么叫副作用

你不用死磕概念，只要记住：  
**只要它不是“根据 state 直接渲染页面”的事，很多时候就可以考虑用 `useEffect`。**

常见场景：

- **请求数据**：页面加载后拉列表
- **同步外部状态**：比如改 `document.title`
- **监听事件**：窗口大小、滚动事件
- **定时器**：`setInterval`、`setTimeout`
- **清理工作**：组件卸载时清掉定时器、取消监听

你可以把它理解成 React 里的“启动工具”和“善后工具”。

比如做列表页，通常是：

1. 页面先渲染
2. `useEffect` 里请求接口
3. 接口返回后，把数据塞进 `state`
4. 页面根据 `state` 重新渲染

这就是后面做项目时最常见的套路。

### 1.2 不要乱用：不是所有逻辑都往 useEffect 塞

很多初学者喜欢把所有逻辑都写进 `useEffect`，结果代码就绕晕了。  
简单判断一下：

- **能直接算出来的内容**，优先写在组件里
- **要等渲染后做的事**，或者**会影响页面外部环境的事**，再考虑 `useEffect`

比如：

```jsx
const fullName = firstName + " " + lastName;
```

这种直接拼字符串，没必要进 `useEffect`。  
但如果你要：

```jsx
document.title = fullName;
```

那就适合放进 `useEffect`。

再比如按钮点击后更新数字：

```jsx
const [count, setCount] = useState(0);
```

这类页面状态，直接用 `useState` 就行。  
但如果你想让浏览器标签页也跟着变化，那就用 `useEffect` 同步一下。

### 1.3 入门阶段最常用的三种用途

先抓住这三个就够了：

1. **首次渲染后执行一次**：页面初始化请求
2. **某个值变化后执行**：比如搜索词变化后重新请求
3. **组件卸载时清理**：比如清掉定时器

做项目时，先问自己一句：

> 这件事是不是要在页面显示之后再做？  
> 是不是要跟某个状态绑定？  
> 是不是要记得收尾？

如果答案里有一个“是”，那就值得考虑 `useEffect`。

## 二、首次渲染、依赖变化、卸载清理分别是什么意思？

### 2.1 首次渲染：页面第一次出来的时候做一次

如果你希望某个逻辑**只在组件第一次挂载时执行一次**，最常见的写法就是：

```jsx
useEffect(() => {
  console.log("组件第一次渲染完成");
}, []);
```

这里的空数组 `[]` 很关键，表示这个 effect 没有依赖项，所以只在首次渲染后执行一次。

这个场景最常见的用途就是：

- 初始化数据请求
- 初始化标题
- 初始化第三方库

比如商品列表页一打开就请求数据：

```jsx
useEffect(() => {
  console.log("页面打开，开始请求列表数据");
}, []);
```

以后把 `console.log` 换成真实请求就行。

### 2.2 依赖变化：某个状态变了，就重新执行

如果你希望某个逻辑在 `count` 变化时执行：

```jsx
useEffect(() => {
  console.log("count 变了，现在是：", count);
}, [count]);
```

这表示：  
**只要 `count` 变了，`useEffect` 就重新跑一遍。**

可以把依赖数组理解成“观察名单”。  
谁在名单里，谁变了，effect 就跟着动。

比如搜索词变化后重新处理，或者筛选条件切换后重新请求，都适合这么写。

### 2.3 没有依赖数组：每次渲染都执行

如果你这样写：

```jsx
useEffect(() => {
  console.log("每次渲染后都会执行");
});
```

那就是**每次组件重新渲染，都会执行**。  
这个写法不是不能用，但入门阶段先知道有这回事就行。大多数时候更常见的是：

- `[]`：只执行一次
- `[某个值]`：值变了再执行

没有依赖数组的写法容易绕进循环里，所以先别滥用。

### 2.4 卸载清理：组件走了，善后别忘了

有些副作用需要收尾，比如定时器、监听器。  
如果不清理，组件虽然没了，但任务还在跑，容易出问题。

例子：

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log("每秒打印一次");
  }, 1000);

  return () => {
    clearInterval(timer);
  };
}, []);
```

这里 `return` 出来的函数，就是清理函数。  
它会在**组件卸载时执行**，也会在依赖变化、effect 重新运行前先清理旧副作用。

记住一句：

> **凡是“开了之后要关掉”的东西，useEffect 里通常都要写 cleanup。**

像这些都算：

- 定时器要清掉
- 事件监听要取消
- 轮询要停掉

## 三、useEffect 的基础写法和依赖数组怎么用？

### 3.1 标准写法

最基础的结构是这样：

```jsx
useEffect(() => {
  // 副作用逻辑
  return () => {
    // 清理逻辑
  };
}, [依赖项]);
```

三个核心部分：

- `useEffect(() => { ... })`：执行副作用
- `return () => { ... }`：清理副作用
- `[依赖项]`：决定什么时候重新执行

### 3.2 三种最常见写法

#### 写法一：只执行一次

```jsx
useEffect(() => {
  console.log("只在首次渲染后执行");
}, []);
```

适合初始化、首屏请求、设置默认值。

#### 写法二：依赖某个 state

```jsx
useEffect(() => {
  console.log("搜索词变化了：", keyword);
}, [keyword]);
```

适合输入联动、筛选变化、标题更新。

#### 写法三：清理副作用

```jsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log("定时执行");
  }, 1000);

  return () => clearInterval(timer);
}, []);
```

适合定时器、监听器、订阅取消。

### 3.3 依赖数组别乱写，尤其别漏写

新手常见问题是：  
“我明明用了 `count`，为什么只写 `[]` 也能跑？”

能跑不代表对。  
如果 effect 里用到了某个变量，却没把它放进依赖数组，后面这个变量变了，effect 可能不会按你想的重新执行。

所以先记一个很朴素的原则：

> **effect 里用到哪个外部变量，通常就把它放进依赖数组。**

比如：

```jsx
useEffect(() => {
  console.log("当前用户名：", username);
}, [username]);
```

这个就很自然。  
先按这个原则写，基本不会离谱。

## 四、用一个小例子看懂：标题变化、定时器、简单联动

### 4.1 例子一：让浏览器标题跟着 count 变化

```jsx
import React, { useEffect, useState } from "react";

function CounterTitle() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `当前点击次数：${count}`;
  }, [count]);

  return (
    <div>
      <p>当前次数：{count}</p>
      <button onClick={() => setCount(count + 1)}>点我加 1</button>
    </div>
  );
}

export default CounterTitle;
```

这个例子把 `useState` 和 `useEffect` 连起来了：

- `useState` 管数据
- `useEffect` 负责“数据变了以后做点事”

你点击按钮，`count` 变了，组件重新渲染，`useEffect` 再把标题改掉。  
这就是最基础的状态联动副作用。

### 4.2 例子二：定时器自动更新

```jsx
import React, { useEffect, useState } from "react";

function Clock() {
  const [now, setNow] = useState(new Date().toLocaleTimeString());

  useEffect(() => {
    const timer = setInterval(() => {
      setNow(new Date().toLocaleTimeString());
    }, 1000);

    return () => clearInterval(timer);
  }, []);

  return <h2>现在时间：{now}</h2>;
}

export default Clock;
```

这个例子有两个重点：

- `useEffect` 只执行一次，启动定时器
- 组件卸载时，清理定时器

`useEffect` 很适合做这种“先启动、后维护、最后清理”的事情。  
实际项目里还会用在轮询、倒计时、自动轮播这些场景。

记住一句经验：  
只要你用了 `setInterval`，脑子里就要立刻冒出一句话——**记得清理**。

### 4.3 例子三：输入联动——关键词变了就重新处理

```jsx
import React, { useEffect, useState } from "react";

function SearchBox() {
  const [keyword, setKeyword] = useState("");

  useEffect(() => {
    if (!keyword) return;
    console.log("准备根据关键词处理数据：", keyword);
  }, [keyword]);

  return (
    <div>
      <input
        value={keyword}
        onChange={(e) => setKeyword(e.target.value)}
        placeholder="输入关键词"
      />
    </div>
  );
}

export default SearchBox;
```

这个写法很典型：

- 输入框改值
- `keyword` 更新
- `useEffect` 监听 `keyword`
- 关键词变化后触发联动逻辑

以后把 `console.log` 换成真实请求，就是标准的搜索联动模式。  
这里顺手加个判断：`keyword` 为空时直接返回，别让空值触发无意义操作。

## 五、useState 和 useEffect 怎么配合才顺手？

### 5.1 先后顺序要记住

可以这么理解：

- `useState` 负责“我有什么数据”
- `useEffect` 负责“数据变了以后我要干啥”

这俩经常一起出现，尤其是页面初始化和用户交互的时候。

### 5.2 常见组合模式一：初始化后请求数据

```jsx
import React, { useEffect, useState } from "react";

function ListPage() {
  const [list, setList] = useState([]);

  useEffect(() => {
    const mockData = ["React", "Vue", "Svelte"];
    setList(mockData);
  }, []);

  return (
    <ul>
      {list.map((item) => (
        <li key={item}>{item}</li>
      ))}
    </ul>
  );
}

export default ListPage;
```

这里 `useEffect` 负责初始化拿数据，`useState` 负责把数据存起来并展示。

顺手注意一下列表渲染里的 `key`：最好用稳定、唯一的值。这里示例里直接用字符串本身，图省事可以；真实项目里更常见的是 `id`。

### 5.3 常见组合模式二：状态变化触发副作用

```jsx
const [name, setName] = useState("");

useEffect(() => {
  console.log("name 变了：", name);
}, [name]);
```

输入内容、切换筛选条件、点按钮改状态，都可以带动 effect 跑起来。

### 5.4 常见组合模式三：先更新状态，再根据状态做事

这里要注意一个小坑：  
`setState` 不是你写完就立刻改值，它更像是“发起一次更新”。  
所以别指望刚 `setCount(1)`，下一行 `count` 就马上变成 1。

如果要在状态变化后做事，**更适合交给 `useEffect`**。  
很多人刚开始会写成这样：

```jsx
setCount(count + 1);
console.log(count);
```

然后发现打印的还是旧值。  
这不是 React 不听话，而是更新时机还没到。  
这种情况，等状态真正变了之后再处理，`useEffect` 就很顺手。

## 六、一个更贴近项目的小场景：页面初始化、标题、数据联动一起上

真实项目里，`useEffect` 很少只做一件事。  
它更常见的状态是：**页面一打开，先初始化，再联动一些提示。**

比如你做一个简单的文章列表页，需求可能是这样：

- 进入页面时拉一次列表
- 列表加载成功后改一下标题
- 用户切换关键词时，列表跟着变化

这个流程可以拆成：

1. `useState` 存列表、关键词、加载状态
2. `useEffect([])` 负责首次进入页面时初始化
3. `useEffect([keyword])` 负责关键词变化后的联动
4. 必要时在清理函数里收尾

你先别急着把它想成复杂架构。  
入门阶段只要记住：**状态交给 `useState`，状态变化后的动作交给 `useEffect`**。  
这俩分工清楚，代码就不会乱。

## 七、入门阶段最容易踩的几个坑

### 7.1 把所有逻辑都塞进 useEffect

不对。  
纯计算、纯渲染，直接写在组件里就行。

比如：

```jsx
const total = price * amount;
```

这种完全没必要放进 `useEffect`。  
越是把简单逻辑塞进去，后面越难看懂代码到底在干啥。

### 7.2 忘了依赖数组

如果你希望只执行一次，写 `[]`。  
如果你依赖某个值变化，就把它放进去。  
别模模糊糊地不写，不然页面行为会很怪。

### 7.3 定时器不清理

这个很常见。  
组件切走了，定时器还在跑，容易报错或者浪费资源。  
凡是定时器、监听器，基本都要想到清理函数。

### 7.4 在 effect 里无脑改 state，造成循环

比如：

```jsx
useEffect(() => {
  setCount(count + 1);
}, [count]);
```

这个写法会导致 `count` 一变，effect 就执行，然后又改 `count`，接着又执行……  
很容易进入循环。

所以你要记住：

> **useEffect 里可以改 state，但要先想清楚依赖关系。**

### 7.5 只看代码能不能跑，不看逻辑对不对

入门时最容易犯这个错。  
代码能运行，不代表写法合理。  
你要多问一句：

- 这件事为什么要放到 effect 里？
- 它是不是只需要执行一次？
- 它会不会反复触发？
- 有没有清理逻辑？

这几个问题想明白，`useEffect` 基本就不会把你绕晕。

---

## 赵老师小结

这一章你只要抓住三件事：

1. **useEffect 是干副作用的**，主要负责渲染之后的事情。
2. **依赖数组决定执行时机**：  
   - `[]`：首次渲染后执行一次  
   - `[某个值]`：这个值变化时执行
3. **副作用要善后**：定时器、监听器这类东西，记得写清理函数。

再直白一点：  
以后你做页面初始化请求、标题更新、定时刷新、输入联动，这些事大概率都会碰到 `useEffect`。  
它不是高深技巧，就是你写 React 时很常用的工具。

另外，咱们这章还有一个很重要的连接点：  
**`useState` 管数据，`useEffect` 管数据变了之后的动作**。  
这个组合你先吃透，后面做表单联动、父子组件通信、页面初始化请求，都会越来越顺。

下一章我们就要开始接触**简单路由**了。  
你会看到一个更完整的页面拆分方式：怎么让一个项目不只是一页，而是能切到不同页面。  
这一步，会直接把咱们往项目实战推进一大截。

# 第10章 简单路由：把页面分出来，做出一个像样的小应用

## 开篇引入：为什么你明明只做个小项目，也最好上路由？

前面我们已经把组件、state、表单、列表这些基础摸了一遍。现在你会碰到一个很现实的问题：**页面一多，代码就开始乱。**

比如一个小应用，常见就会有这些页面：

- 首页：展示推荐内容
- 列表页：展示所有数据
- 详情页：点进去看单条内容
- 关于页：放一些说明
- 登录页：处理用户登录

如果都堆在一个组件里，通常会变成：

- `App.jsx` 越写越长
- 条件渲染层层嵌套
- 改一个地方，别的页面也容易受影响
- 以后再加“返回上一页”“收藏页”“个人中心”，脑子直接打结

所以哪怕是小项目，也建议尽早把页面拆开，用路由把它们组织起来。  
你可以先把路由理解成：**根据地址栏变化，决定渲染哪个页面组件。**

这一章咱们就干一件事：**把几个页面分出来，再用导航串起来，做出一个像样的小应用。**  
先别想着把路由学全，先把最短路径跑通：

1. 知道为什么要路由
2. 会安装 React Router
3. 会写最基础的页面切换
4. 会做一个带参数的详情页
5. 能把前面学过的列表、组件、`key` 一起用起来

## 一、为什么小项目也需要路由？

### 1.1 一个页面不等于一个组件树

很多新手会想：“我是不是直接在 `App` 里用条件渲染切页面就行？”

当然能跑，但不够像样。

如果只是首页和详情页简单切一下，临时写写可以。  
但只要你开始有这些需求：

- 直接通过地址访问某个页面
- 刷新后还能停在原来的页面
- 复制链接给别人，别人能直接打开同一个页面
- 切页面时，地址栏也跟着变

那路由就必须上了。

### 1.2 路由解决的是“页面组织问题”

React 的核心思路是组件化。  
路由做的事，就是把“页面”也按组件的方式组织起来。

可以简单理解为：

- `App` 负责总布局
- `Home` 负责首页
- `List` 负责列表页
- `Detail` 负责详情页
- `About` 负责关于页

然后由路由决定：**当前地址对应哪个组件显示。**

这样一来，页面结构就清楚了，后面加导航、加详情页、加用户中心，都不会乱。

### 1.3 小项目为什么也值得学

路由不只是大项目才需要。入门阶段学路由，最大的价值是：

- 提前建立“多页面应用”的思维
- 让页面按职责拆分，而不是一坨写到底
- 为后面的项目实战打底

一句话：**不是为了炫技，是为了把项目写得更像样。**

### 赵老师小结

路由不是可有可无的东西，而是小应用变成正常应用的关键一步。只要项目里开始出现多个页面，或者需要通过地址切换内容，就该考虑路由了。

## 二、React Router 的基础安装和使用

### 2.1 先把库装上

在 CRA 项目里，通常直接用 `react-router-dom`。

```bash
npm install react-router-dom
```

或者：

```bash
yarn add react-router-dom
```

装完就能开始写路由了。入门阶段别急着研究太多进阶写法，先把“页面能切换”跑通最重要。

### 2.2 基础思路：用路由包住页面

常见写法是先把整个应用包到路由容器里，再写具体规则。

```jsx
import { BrowserRouter, Routes, Route } from "react-router-dom";
import Home from "./pages/Home";
import About from "./pages/About";

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
      </Routes>
    </BrowserRouter>
  );
}

export default App;
```

先记住这几个角色：

- `BrowserRouter`：给整个应用套上路由能力
- `Routes`：路由规则集合
- `Route`：一条具体规则
- `path`：地址
- `element`：对应显示的页面组件

### 2.3 最小可运行步骤

#### 第一步：创建页面组件

`src/pages/Home.jsx`

```jsx
function Home() {
  return <h2>这是首页</h2>;
}

export default Home;
```

`src/pages/About.jsx`

```jsx
function About() {
  return <h2>这是关于页</h2>;
}

export default About;
```

#### 第二步：配置路由

把 `App.jsx` 改成上面的写法。

#### 第三步：浏览器访问

打开：

- `http://localhost:3000/`
- `http://localhost:3000/about`

就能看到不同页面。

### 2.4 一个判断标准

判断路由有没有跑通，看两点：

- 地址栏变了
- 页面内容也跟着变了

如果只是页面变了，地址栏没变，那通常还不是标准路由切换。  
如果刷新后页面挂了，说明路由配置还不完整。

### 赵老师小结

React Router 入门不用整复杂。先记住这条链：**安装库 → 包住应用 → 写 Route → 对应页面显示。** 这套跑通了，你就已经能开始做像样的小应用了。

## 三、路由、页面组件和导航，先把骨架搭出来

### 3.1 页面组件怎么拆

路由一上来，第一件事不是写复杂逻辑，而是先把页面拆开。

建议目录这样放：

```bash
src/
  pages/
    Home.jsx
    About.jsx
    List.jsx
    Detail.jsx
  components/
    Header.jsx
    Footer.jsx
```

原则很简单：

- **pages**：放页面级组件
- **components**：放可复用的小组件

页面级组件一般直接对应路由。比如 `Home` 是首页，`About` 是关于页；`Header`、`Footer` 这种公共内容，放 `components` 更合适。

### 3.2 导航怎么写

页面有了，用户怎么跳？这时就要用 `Link`。

```jsx
import { Link } from "react-router-dom";

function Header() {
  return (
    <nav>
      <Link to="/">首页</Link> | <Link to="/about">关于</Link> | <Link to="/list">列表</Link>
    </nav>
  );
}

export default Header;
```

你可以把它理解成：`Link` 就是 React Router 的“内部跳转按钮”，切页面时不会整页刷新。

### 3.3 `Link` 和普通 `a` 标签的区别

#### 普通 `a`

```html
<a href="/about">关于</a>
```

它会触发整页刷新，浏览器重新请求页面。单页应用里这样不够顺手。

#### `Link`

```jsx
<Link to="/about">关于</Link>
```

它会在不整页刷新的前提下切换路由。  
只要是自己项目里的页面，尽量用 `Link`；外部网站再用 `a`。

### 3.4 一个最小页面结构

```jsx
function App() {
  return (
    <BrowserRouter>
      <Header />
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/list" element={<List />} />
      </Routes>
    </BrowserRouter>
  );
}
```

这样就很像一个正常的小应用了：

- 顶部导航固定
- 中间页面内容切换
- 用户通过链接浏览不同页面

### 3.5 常见误区

#### 误区一：把所有页面都写在 `App` 里

这样会越来越乱。`App` 负责组织路由，不负责把所有页面逻辑塞进去。

#### 误区二：导航还在用 `a`

除非跳外部网站，否则尽量用 `Link`。

#### 误区三：页面里重复写公共内容

头部、底部这种公共部分，最好抽出来复用。

### 赵老师小结

路由不是单独存在的，它要和页面组件、导航一起配合。先把“页面拆分”和“导航跳转”做好，应用骨架就出来了。

## 四、参数路由：列表点进去，详情页就该跟着变

### 4.1 为什么需要参数路由

做列表页时，经常会遇到这种需求：

- 点某一项进入详情页
- 每个详情页地址不同
- 通过地址就能知道当前看的是哪条数据

这时候就需要参数路由。

比如：

- `/detail/1`
- `/detail/2`
- `/detail/100`

最后那个数字就是参数。

### 4.2 基本写法

```jsx
function Detail() {
  return <h2>这是详情页</h2>;
}

export default Detail;
```

路由配置：

```jsx
<Route path="/detail/:id" element={<Detail />} />
```

这里的 `:id` 就表示参数位置。

### 4.3 在页面里拿到参数

可以用 `useParams` 获取参数。

```jsx
import { useParams } from "react-router-dom";

function Detail() {
  const params = useParams();

  return <h2>详情页 ID：{params.id}</h2>;
}

export default Detail;
```

访问 `/detail/1` 显示 `1`，访问 `/detail/99` 显示 `99`。这就完成了最基础的“通过 URL 带数据”。

### 4.4 参数路由最小实践：列表跳详情

```jsx
import { Link } from "react-router-dom";

const data = [
  { id: 1, title: "React 入门" },
  { id: 2, title: "React Router" },
  { id: 3, title: "组件拆分" },
];

function List() {
  return (
    <div>
      <h2>列表页</h2>
      <ul>
        {data.map((item) => (
          <li key={item.id}>
            <Link to={`/detail/${item.id}`}>{item.title}</Link>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default List;
```

这里有两个重点：

1. `to={`/detail/${item.id}`}`：把 id 拼到路径里
2. `key={item.id}`：列表渲染别忘了 key

顺手再说一句：`map` 渲染数组时，`key` 不是摆设，它会影响 React 判断哪些内容变了。入门阶段先记住：**只要是列表，就尽量写稳定的 key，优先用 id。**

### 4.5 参数路由的判断标准

问自己两个问题：

- 我是不是需要让每个页面地址都唯一？
- 我是不是要根据 URL 中的信息展示不同内容？

如果答案是“是”，那参数路由就很适合。

### 4.6 常见误区

#### 误区一：参数只能拿来显示文字

不是，它通常还会用来请求数据，比如根据 `id` 拉详情。

#### 误区二：不区分列表页和详情页

列表页展示多个条目，详情页展示单个条目，这两个职责别混。

#### 误区三：列表忘记写 key

只要是 `map` 渲染数组，就养成写 `key` 的习惯。

### 赵老师小结

参数路由是入门阶段最实用的能力之一。它能把“列表 → 详情”的页面切换串起来，也能让项目更像一个真正的应用。

## 五、先把导航串起来，再谈项目结构

### 5.1 先把小应用结构想清楚

现在我们做一个最小版本的小应用，只追求跑通，不追求花哨。

页面规划如下：

- `/`：首页
- `/list`：列表页
- `/detail/:id`：详情页
- `/about`：关于页

再加一个顶部导航：

- 首页
- 列表
- 关于

这样用户就能在几个页面之间来回切换了。

### 5.2 推荐的落地流程

这一段很重要，因为它就是你后面做项目时最常用的“落地顺序”：

#### 第一步：先搭页面文件
页面组件先建好，哪怕先只写一句话。

#### 第二步：把路由配置好
先让地址能对应到页面。

#### 第三步：加导航
用 `Link` 把页面串起来。

#### 第四步：补参数页
让列表页能进入详情页。

#### 第五步：整理页面内容
把每个页面补成“像样的样子”。

这个流程很适合新手，因为每一步都能看到结果，不容易乱。  
而且你会慢慢形成一个很关键的习惯：**先搭骨架，再填内容。**

### 5.3 一个完整的最小示例

```jsx
import { BrowserRouter, Routes, Route, Link, useParams } from "react-router-dom";

function Home() {
  return <h2>欢迎来到首页</h2>;
}

function About() {
  return <h2>这里是关于页</h2>;
}

function List() {
  const data = [
    { id: 1, title: "React 入门" },
    { id: 2, title: "路由基础" },
  ];

  return (
    <div>
      <h2>文章列表</h2>
      <ul>
        {data.map((item) => (
          <li key={item.id}>
            <Link to={`/detail/${item.id}`}>{item.title}</Link>
          </li>
        ))}
      </ul>
    </div>
  );
}

function Detail() {
  const { id } = useParams();
  return <h2>当前文章 ID：{id}</h2>;
}

function Header() {
  return (
    <nav>
      <Link to="/">首页</Link> | <Link to="/list">列表</Link> | <Link to="/about">关于</Link>
    </nav>
  );
}

function App() {
  return (
    <BrowserRouter>
      <Header />
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/list" element={<List />} />
        <Route path="/about" element={<About />} />
        <Route path="/detail/:id" element={<Detail />} />
      </Routes>
    </BrowserRouter>
  );
}

export default App;
```

这段代码已经把当前阶段最需要的内容都串起来了：

- 页面拆分
- 路由配置
- 导航跳转
- 参数路由
- 列表 key
- 页面切换

### 5.4 项目落地时的检查清单

写完后检查这几项：

- 地址栏变了，页面也变了
- 导航能正常跳转
- 列表点击能进入详情
- 刷新页面不报错
- 列表 `key` 没遗漏
- 页面组件没有全堆在一个文件里

如果这些都没问题，说明你已经把最基础的路由流程吃透了。

### 赵老师小结

这一章最重要的不是记住多少 API，而是能把几个页面串起来，做出一个能点、能切、能跳的小应用。路由一通，后面做真实项目时，脑子里就不会只剩“一坨页面”的思路了。

## 六、往后怎么接：把路由放进你的基础项目里

## 一、先别急着写代码：项目需求怎么拆？

做 React 项目，第一步不是打开编辑器狂敲，而是先想清楚：**页面要长什么样，功能要做什么，数据从哪来，状态怎么走。**

很多新手一上来就想写组件，结果写着写着发现：这个状态不知道放哪，那个按钮不知道谁来管，最后 `App.jsx` 越堆越大，自己都看不懂。所以咱们先把需求掰开揉碎。

这次做一个很基础的“任务管理页”，可以理解成简化版待办事项应用。

### 1. 页面结构

页面拆三块就行：

- 顶部标题区：显示项目名，比如“我的任务板”
- 中间操作区：输入框 + 新增按钮
- 底部列表区：展示任务列表，支持完成/删除

如果想更像真实项目，再加一个筛选区：

- 全部
- 已完成
- 未完成

这个结构很朴素，但很适合练手，因为它把页面展示、表单输入、列表渲染、状态切换都串起来了。

### 2. 功能清单

先做最核心的几个：

- 能看到任务列表
- 能新增任务
- 能标记任务完成
- 能删除任务
- 能按状态筛选任务

这几个功能，已经足够覆盖入门阶段大部分常用写法了。

### 3. 数据结构

项目顺不顺，关键看数据结构。比如任务可以这样设计：

```js
[
  { id: 1, text: "学习 React", done: false },
  { id: 2, text: "整理笔记", done: true }
]
```

这里最常见的三个字段：

- `id`：列表渲染用，后面 `key` 要靠它
- `text`：任务内容
- `done`：是否完成

很多人写项目卡住，不是不会语法，而是数据结构没想明白。结构一清楚，后面组件怎么拆、状态怎么放，基本就有方向了。

### 赵老师小结

项目实战第一步，不是写代码，而是拆需求。先定页面结构，再定功能清单，最后定数据结构。这样你写 React 的时候，脑子不会乱，代码也更容易往下接。

试着把你平时最常用的一个页面拆成三部分：

1. 页面结构  
2. 功能清单  
3. 数据结构  

写完后，你会发现项目思路一下清楚很多。

## 二、先把 CRA 项目跑起来，再看目录怎么分工

真正开始之前，先把项目初始化好。CRA 的好处就是省心，环境搭起来快，适合咱们先把 React 开发流程跑通。

### 1. 创建项目与启动

先创建项目：

```bash
npx create-react-app task-board
cd task-board
npm start
```

跑起来后，先别急着删文件，先看它默认给你的结构。这个动作很重要，因为**CRA 项目结构**就是你后面写代码的地基。

### 2. CRA 目录结构怎么看

一个 CRA 项目最常见的结构大概是这样：

```bash
src/
  App.js
  index.js
  components/
  pages/
  assets/
```

不一定非要完全照抄，但这个思路要有：

- `index.js`：把 React 应用挂到页面上
- `App.js`：项目主入口页面
- `components/`：放通用组件，比如输入框、任务项、筛选栏
- `pages/`：放页面级组件，比如首页、关于页
- `assets/`：放图片、样式资源

初学阶段先记住一句就够了：**组件按职责分，页面按功能分。**  
这样后面找代码、改代码都方便。

### 3. 先明确每个文件干什么

你做项目时，最好一开始就给文件定好职责：

- `App.js`：负责组装页面
- `TaskForm.jsx`：负责新增任务
- `TaskFilter.jsx`：负责筛选条件
- `TaskList.jsx`：负责列表展示
- `TaskItem.jsx`：负责单条任务渲染
- `pages/Home.jsx`：如果后面要加路由，可以放首页

这个步骤看着简单，但特别关键。因为很多人项目乱，不是不会写，而是文件职责没分开，最后所有逻辑都堆到一个地方。

### 赵老师小结

CRA 先帮你把环境搭好，目录结构先帮你把骨架搭好。项目一开始就把文件职责理顺，后面写起来会非常顺。

## 三、项目从哪开始写：先搭页面骨架，再补逻辑

项目实战最怕的就是一上来就写业务逻辑。老赵建议你按这个顺序来：

1. 先搭页面结构  
2. 再拆组件  
3. 再接状态  
4. 再做交互  
5. 最后整理代码

这个顺序很适合入门，因为你每一步都能看到页面变化，不会写着写着迷路。

### 1. 先把页面摆出来

先在 `App` 里把这些组件摆起来：

```jsx
function App() {
  return (
    <div>
      <h1>我的任务板</h1>
      <TaskForm />
      <TaskFilter />
      <TaskList />
    </div>
  );
}
```

先让页面跑起来，再慢慢补逻辑。  
这就是 React 开发很实用的习惯：**先搭结构，再补数据和交互。**

### 2. 组件怎么拆

按这个项目，可以拆成几个小组件：

- `TaskForm`：负责新增任务
- `TaskFilter`：负责筛选任务
- `TaskList`：负责展示列表
- `TaskItem`：负责单个任务项

这就是 React 组件思维：**一个组件只干一件事。**

比如：

- 表单只负责输入和提交
- 筛选只负责切换显示条件
- 列表只负责把数据渲染出来
- 单个任务项只负责展示一条任务和按钮

这样拆完后，页面更清楚，后面维护也省事。以后你要改样式、加功能、排 bug，都不会一头雾水。

### 赵老师小结

组件拆得好，项目就好维护。别一上来就把所有逻辑写在一个文件里。先拆出表单、列表、筛选、任务项，再慢慢补功能，写起来会顺很多。

### 老赵带你练一练

## 四、核心功能实现：列表展示、表单新增、状态管理、条件切换

这一部分是项目核心，因为它把 `useState`、受控组件、列表渲染、条件渲染全串起来了。

### 1. 列表展示：先把数据渲染出来

先把任务数据放在 `App` 的 state 里：

```jsx
const [tasks, setTasks] = useState([
  { id: 1, text: "学习 React", done: false },
  { id: 2, text: "整理笔记", done: true }
]);
```

然后用 `map` 渲染：

```jsx
{tasks.map(item => (
  <TaskItem key={item.id} task={item} />
))}
```

这里一定要注意：**列表渲染必须有 key。**  
这个 `key` 最好用稳定的 `id`，别随便拿数组下标顶上去。因为列表一旦增删排序，`index` 容易乱，React 也不好判断哪个项变了。

### 2. 表单新增：受控组件怎么做

新增任务的输入框，推荐用受控组件。也就是输入框的值交给 state 管。

```jsx
const [input, setInput] = useState("");

<input
  value={input}
  onChange={(e) => setInput(e.target.value)}
/>
```

点击按钮后，把新任务加进列表：

```jsx
const addTask = () => {
  if (!input.trim()) return;

  setTasks([
    ...tasks,
    { id: Date.now(), text: input, done: false }
  ]);
  setInput("");
};
```

这一步里你会看到几个实战要点：

- 输入框为空时别提交
- 新数据要放到原数组后面
- 添加后清空输入框

这就是最常见的表单处理套路。你以后做搜索框、登录表单、评论框，思路都差不多。

### 3. 状态管理：别乱放，放对地方

这个项目里，`tasks` 和 `input` 都可以放在 `App` 里。  
原因很简单：它们都要参与页面交互，而且会影响多个子组件。

判断标准可以记一句：

- **谁控制数据，谁就放 state**
- **多个组件都要用的数据，往上提**

比如输入框的值，表单要用；新增按钮也要用；任务列表也要受它影响，那它就适合放到上层统一管理。

### 4. 条件切换：完成状态和筛选

任务完成后，可以切换样式，比如加删除线：

```jsx
<p style={{ textDecoration: task.done ? "line-through" : "none" }}>
  {task.text}
</p>
```

筛选任务时，可以根据 `filter` 状态决定显示哪些项：

```jsx
const visibleTasks = tasks.filter(task => {
  if (filter === "done") return task.done;
  if (filter === "active") return !task.done;
  return true;
});
```

这就是条件渲染的典型用法：**不同状态，显示不同内容。**

React 很多地方都在围着“状态变化后页面跟着变”转。你只要把状态管住，页面就好办。

### 赵老师小结

这一节你要记住三件事：列表要有 `key`，表单最好用受控组件，状态别乱放。只要把这三件事弄顺，React 页面的大部分交互你就能上手了。

给任务列表加一个“完成/未完成”切换按钮；再给输入框加一个“回车提交”的功能，练一下表单和状态联动。

## 五、把组件通信和 `useEffect` 接进来，让项目更像真的

前面咱们已经把页面做出来了，接下来就该让组件之间真正“说上话”，再顺手补一个 `useEffect` 的实际落点。这个时候你会发现，前面学的知识不是散的，它们在项目里都是有位置的。

### 1. 父子组件通信怎么做

父组件把数据和方法传给子组件，子组件负责展示和触发事件。

比如父组件把单个任务传给 `TaskItem`：

```jsx
<TaskItem
  key={item.id}
  task={item}
  onToggle={handleToggle}
  onDelete={handleDelete}
/>
```

子组件里收到后直接用：

```jsx
function TaskItem({ task, onToggle, onDelete }) {
  return (
    <div>
      <span>{task.text}</span>
      <button onClick={() => onToggle(task.id)}>完成</button>
      <button onClick={() => onDelete(task.id)}>删除</button>
    </div>
  );
}
```

这就是最常见的父子通信方式：**父传子用 props，子传父用回调函数。**

你可以把它理解成一条很朴素的规则：

- 父组件负责管总数据
- 子组件负责展示局部内容
- 子组件想改父组件的数据，就调用父组件传下来的方法

### 2. `useEffect` 在这个项目里干什么

`useEffect` 不是拿来“显得高级”的，它最常见的作用就是处理副作用，比如页面加载后读取本地存储、监听数据变化后保存数据。

比如你可以在页面加载时，从本地存储恢复任务：

```jsx
useEffect(() => {
  const saved = localStorage.getItem("tasks");
  if (saved) {
    setTasks(JSON.parse(saved));
  }
}, []);
```

再比如，当任务列表变化时，把它存回本地：

```jsx
useEffect(() => {
  localStorage.setItem("tasks", JSON.stringify(tasks));
}, [tasks]);
```

这样一来，刷新页面任务还在。这个场景特别实用，也很适合新手理解 `useEffect` 的基础用法。

### 3. 为什么它适合放在这里

因为它刚好承接前面的状态管理。  
你已经会用 `useState` 管数据了，接下来再用 `useEffect` 处理“数据变化后要做什么”，这个链路就完整了。

### 赵老师小结

父子通信是 React 里非常重要的一环。父组件管数据，子组件管展示和触发动作；`useEffect` 则负责处理一些“状态之外的事”，比如读取和保存数据。把这两件事接进去，你的项目就更像一个完整的小应用了。

### 老赵带你练一练

## 六、项目收尾：怎么整理代码，怎么继续扩展？

项目做到这里，别急着关编辑器。最后一步很关键：**整理代码，回顾流程，想清楚下一步怎么扩展。**

### 1. 整理代码

检查这几件事：

- 组件有没有拆太碎
- state 有没有乱放
- 重复代码能不能抽一下
- `key` 有没有写对
- 表单有没有受控
- 交互逻辑有没有清晰
- `useEffect` 的依赖有没有写对

如果你发现某个组件又长又乱，通常就说明它职责太多了。这个时候别硬撑，拆开会更舒服。

### 2. 回顾整个流程

你可以按这个顺序回忆：

1. 用 CRA 创建项目  
2. 看懂目录结构  
3. 拆页面和组件  
4. 用 JSX 写页面骨架  
5. 用 props 传数据  
6. 用 `useState` 管状态  
7. 用受控组件处理表单  
8. 用 `map` 渲染列表，补上 `key`  
9. 用父子通信处理增删改  
10. 用 `useEffect` 做数据持久化  
11. 用简单路由扩展页面  

这条链路，就是你入门 React 最短路径里的核心路线。以后再接别的项目，基本也能照这个思路往下推。

### 3. 下一步怎么扩展

如果你想继续练，可以加这些功能：

- 本地存储，刷新不丢数据
- 编辑任务
- 搜索任务
- 多页面路由
- 接后端接口

这些功能不难，关键是你已经有了 React 的基本骨架，后面就是不断加功能。你会越来越清楚：React 不是背出来的，是一层层做出来的。

### 赵老师小结

项目做完，不只是“跑起来了”就完事。你要能回头复盘：哪里用了 state，哪里用了 props，哪里用了受控组件，哪里用了列表 `key`，哪里用了 `useEffect`。这样你才算真正把 React 的开发流程走了一遍。

## 七、简单路由怎么接进来：让项目有点“多页面”的样子

如果你想把这个小项目再往前推一步，可以加一个简单路由。  
实际项目里，路由通常负责不同页面切换，不负责具体业务逻辑。

比如：

- `/`：任务列表页
- `/about`：项目说明页
- `/help`：使用说明页

这样一来，项目就更像一个完整的小应用了。你以后做活动页、管理后台、内容页，也都是这个套路：不同页面负责不同内容，路由负责把它们切过去。

### 1. 路由在这里的作用

路由的作用很简单：

- 首页放主要功能
- 说明页放辅助信息
- 以后想加更多页面，也不用重构整个项目

你不需要一开始就把路由做得很复杂，先会“切页面”就够了。这个阶段的目标不是造轮子，而是把 React 的完整开发流程串通。

### 2. 把路由和前面的内容连起来

路由本身不复杂，难的是和项目业务结合。  
你可以把列表页放在首页，把任务说明放到关于页。这样你就能一边练组件，一边练页面组织，思路会更接近真实开发。

### 赵老师小结

简单路由的作用，就是让你的项目从“单页练习”往“多页面应用”迈一步。别把它想复杂，先把页面切换跑通就行。
