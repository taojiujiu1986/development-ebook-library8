# 第1章 先别慌：前端新手最常见的报错从哪来

你是不是也遇到过这种情况：代码明明照着教程写了，页面却不对；控制台一片红字，心里先“咯噔”一下，然后开始乱改，越改越乱。别急，这很正常。前端新手最容易卡住的，往往不是复杂原理，而是那些特别细、特别容易漏的小错误。

这本书不是系统教材，它更像你的“前端查错小抄”。你遇到问题时，不用从头读到尾，先看现象，再去对应章节找“错误示例—原因—正确写法—排查步骤”，效率会高很多。

## 为什么前端新手总是卡在细节错误上？

前端错误有个特点：**问题不大，影响很大**。一个标签没闭合，页面结构可能就乱了；一个图片路径写错，图片就不显示；一个选择器优先级没算对，样式看起来就像没写一样。还有些问题更隐蔽，比如 JS 条件判断写反了，页面不报错，但功能就是不工作。

新手常卡住，通常是因为这三个习惯：

1. **只看结果，不看现象**
2. **一出问题就乱改**
3. **不知道该从 HTML、CSS 还是 JavaScript 哪一层查**

所以你要记住：前端排错不是“猜”，而是先判断问题属于哪一类，再去对应位置找原因。你越慌，越容易把一个小问题改成一堆大问题。

## 这本书怎么用？先按“现象”找，再按分类查

你可以把本书当成一个随手翻的查错工具。

### 先看现象
比如：

- 页面内容不见了
- 样式不生效
- 按钮点了没反应
- 控制台报错
- 图片加载失败

先把症状说清楚，别急着猜原因。症状越具体，越容易定位。

### 再去对应章节查
按这个顺序最省事：

- **HTML 常见错误**：标签闭合与嵌套、路径写错、图片/链接不显示
- **CSS 常见错误**：样式不生效、选择器优先级混乱、盒模型理解错误、元素不显示、定位异常
- **JavaScript 常见错误**：变量作用域误解、条件判断写错、循环死循环、事件绑定失效、DOM 获取为空、类型转换问题

### 最后再对照修复
不要一上来就改十处。先定位一处，再验证一处。你每改一行，都要知道自己为什么改、改完会产生什么变化。

## HTML 常见错误：先查结构，再查路径

#### 1. 标签闭合与嵌套错误

**错误示例**
```html
<p>欢迎来到前端学习
<div>这里是内容</div>
```

**错误原因**  
`p` 标签没闭合，浏览器会自动修，但结果可能和你想的不一样。嵌套顺序乱了，也会让结构看起来很怪。

**正确写法**
```html
<p>欢迎来到前端学习</p>
<div>这里是内容</div>
```

**老赵式排查步骤**
1. 先看标签是不是成对出现。
2. 再看嵌套顺序对不对，别把 `div`、`p`、`ul`、`li` 乱套。
3. 结构一怪，先怀疑 HTML，不要先怪 CSS。

**避免再次犯错的方法**
- 写完一个标签，顺手补闭合
- 复杂结构先缩进对齐
- 页面布局乱了，先检查 HTML 结构

#### 2. 路径写错

**错误示例**
```html
<img src="img/a.png">
```

**错误原因**  
图片实际在 `images/` 里，但你写成了 `img/`，浏览器当然找不到资源。

**正确写法**
```html
<img src="images/a.png" alt="示例图片">
```

**老赵式排查步骤**
1. 先看文件夹里真实路径。
2. 再核对文件名大小写。
3. 打开开发者工具，看是不是 404。

**避免再次犯错的方法**
- 手写路径前先看目录结构
- 图片、链接不显示，优先查路径
- 别凭记忆写目录名

## CSS 常见错误：先查有没有选中，再查有没有被覆盖

#### 1. 样式不生效

**错误示例**
```css
.box { display: flex; }
```

但页面没变化。

**错误原因**  
可能不是 `display: flex` 没用，而是这个选择器根本没选中元素，或者后面有更高优先级的样式把它覆盖了。

**正确写法**
```css
.box {
  display: flex;
}
```

并确认 HTML 里真的有：

```html
<div class="box"></div>
```

**老赵式排查步骤**
1. 先检查类名、id 名是不是写对了。
2. 再看样式有没有被后面的代码覆盖。
3. 打开 Elements 面板，看最终生效的是哪条样式。

**避免再次犯错的方法**
- HTML 和 CSS 一起核对
- 先写最简单的样式验证是否生效
- 不要只看自己写的代码，要看浏览器最终用了什么

#### 2. 选择器优先级混乱、盒模型理解错误

你是不是也遇到过：明明写了样式，结果被别的规则盖住了？这多半就是优先级问题。还有盒模型，新手最容易把“内容宽度”和“整体宽度”混在一起。

**错误示例**
```css
.box { width: 200px; padding: 20px; border: 1px solid #000; }
```

**错误原因**  
你以为盒子是 200px，实际上加上 `padding` 和 `border` 后整体会变大，布局就可能挤坏。优先级混乱时，可能你写的规则根本不是最终生效的那条。

**正确写法**
```css
.box {
  width: 200px;
  padding: 20px;
  border: 1px solid #000;
  box-sizing: border-box;
}
```

**老赵式排查步骤**
1. 看最终生效的样式是不是你写的那条。
2. 检查有没有更高优先级规则覆盖。
3. 看盒模型是否需要 `box-sizing: border-box;`。

**避免再次犯错的方法**
- 先记住：浏览器最后显示的才算数
- 布局不对时，先查盒模型
- 遇到覆盖问题，先用开发者工具看“最终结果”

#### 3. 元素不显示、定位异常

**错误示例**
```css
.item { display: none; position: absolute; top: 100px; left: 100px; }
```

**错误原因**  
元素可能被隐藏了，也可能定位参考对象不对，导致位置跑偏。

**正确写法**
```css
.item {
  display: block;
  position: absolute;
  top: 100px;
  left: 100px;
}
```

**老赵式排查步骤**
1. 先看是不是 `display: none`、`visibility: hidden`、`opacity: 0`。
2. 再看定位方式有没有写对。
3. 如果位置怪，检查父元素有没有设置定位。

**避免再次犯错的方法**
- 元素不显示，先查隐藏属性
- 定位异常，先看父元素和参考坐标
- 不要一口气改很多定位参数

## JavaScript 常见错误：先看变量，再看条件和事件

#### 1. 变量作用域误解、条件判断写错

**错误示例**
```js
if (num = 10) {
  console.log("成立");
}
```

**错误原因**  
这里不是判断，而是赋值。`=` 是赋值，`===` 才是比较。新手很容易把它们混在一起。

**正确写法**
```js
if (num === 10) {
  console.log("成立");
}
```

**老赵式排查步骤**
1. 先看控制台有没有报错。
2. 再确认变量是不是在当前作用域内。
3. 条件判断里先检查运算符是“赋值”还是“比较”。

**避免再次犯错的方法**
- 写 `if` 时先默念：我是比较，不是赋值
- 先打印变量值，再判断
- 别在局部作用域外乱用变量

#### 2. 循环死循环、事件绑定失效、DOM 获取为空、类型转换问题

**错误示例**
```js
const btn = document.querySelector(".btn");
btn.addEventListener("click", () => {
  console.log("点击了");
});
```

如果页面里没有 `.btn`，这里就会出问题。

**错误原因**  
`querySelector` 没选到元素时会返回 `null`。另外，事件没绑定上，可能是 DOM 还没生成，或者选择器写错了。类型转换没处理好时，字符串和数字混着算，也会出怪问题。循环写错的话，还可能直接死循环，把页面卡住。

**正确写法**
```js
const btn = document.querySelector(".btn");
console.log(btn);

if (btn) {
  btn.addEventListener("click", () => {
    console.log("点击了");
  });
}
```

**老赵式排查步骤**
1. 先打印 DOM，看看是不是 `null`。
2. 再确认选择器和页面元素是否一致。
3. 事件没反应时，先加 `console.log` 验证有没有触发。
4. 循环卡住时，检查终止条件。
5. 涉及计算时，看看是不是字符串没转成数字。

**避免再次犯错的方法**
- 取 DOM 前，先确认页面里真的有这个元素
- 事件绑定后先打日志
- 循环一定要有出口
- 做加减乘除前，先检查类型

## 记住这一个小口诀

**先看现象，再找分类；先查 HTML，再查 CSS，最后看 JS。**

你不用一上来就把所有原理背熟。新手阶段最重要的，是知道问题大概率出在哪一层，然后快速翻到对应地方查“错误示例—原因—正确写法—排查步骤”。

## 小结：别慌，先定位，再修复

以后你遇到前端报错，先别急着乱试。先把问题归到 HTML、CSS、JavaScript 里，再按“现象—原因—正确写法”去查。这本书不是让你死记硬背的，而是让你在卡住的时候，能马上找到该看哪里。

从这一章开始，你要练的不是“会写更多代码”，而是“更快找到错在哪”。

# 第2章 HTML 常见错误：标签闭合、嵌套和路径写错

你是不是也遇到过：**代码没明显报错，页面却不对劲**？图片不显示、样式没加载、文字跑偏，甚至整页结构乱掉。新手在 HTML 阶段最常踩的坑，往往不是“不会写”，而是几个细节反复出错。

这一章，老赵只讲三类高频问题：**标签没闭合或闭合顺序错了、标签嵌套乱了、路径写错了**。你学完后，至少能做到：页面一异常，马上知道先查什么。

## 一、标签闭合错误：少一个符号，页面就可能跑偏

### 你是不是也写过这种代码？

```html
<div>
  <p>这是第一段
  <span>这是强调文字</p>
</span>
</div>
```

或者：

```html
<div>
  <p>内容1
<div>
  <p>内容2</p>
</div>
```

看着差不多，浏览器却不一定按你的意思理解。

### 错误原因是什么？

HTML 是按结构解析的，不是按“感觉差不多”解析的。  
**标签不闭合**，浏览器会帮你补，但补法不一定对；  
**闭合顺序错了**，比如先开 `p` 再开 `span`，却先关 `p` 再关 `span`，浏览器可能自动重排，导致后面一大片内容都被带歪。

### 正确写法

```html
<div>
  <p>这是第一段 <span>这是强调文字</span></p>
</div>
```

```html
<div>
  <p>内容1</p>
</div>
<div>
  <p>内容2</p>
</div>
```

### 老赵式排查步骤

1. **先看缩进**：缩进乱，结构大概率也乱。  
2. **从外往里对闭合**：开了哪个标签，就对应关掉哪个。  
3. **重点查成对标签**：`div`、`p`、`span`、`ul/li` 最容易漏。  
4. **刷新页面看表现**：某块内容突然跑位，先怀疑结构。  
5. **看 Elements 面板**：浏览器真实解析后的 DOM，往往直接暴露问题。

### 怎么避免再犯？

- 写完一个结构就补齐闭合标签
- 一层一缩进，别乱缩
- 用编辑器自动补全
- 每次保存后刷新检查结构有没有跑偏

## 二、标签嵌套错误：`div`、`p`、`span` 为什么总是乱套？

### 你是不是也觉得“能套进去就行”？

新手很容易把标签“随便包一包”。但有些标签不适合乱嵌套，尤其是 `p` 和块级元素混着写的时候。

### 错误示例

```html
<p>
  这是一段文字
  <div>这里放了一个 div</div>
</p>
```

```html
<span>
  <div>这个写法也不对</div>
</span>
```

### 错误原因是什么？

`p` 标签里通常不应该直接放 `div` 这类块级元素。浏览器遇到这种情况，往往会**自动拆结构**。  
你以为内容包在一起了，实际 DOM 早就变了。很多时候不是 CSS 的问题，而是 HTML 结构先乱了。

### 正确写法

```html
<div>
  <p>这是一段文字</p>
  <div>这里放一个 div</div>
</div>
```

```html
<span>这是行内文字</span>
<div>这是独立块</div>
```

### 老赵式排查步骤

1. **先判断标签类型**：这是段落、独立区块，还是行内内容？  
2. **检查有没有把块级元素塞进不合适的容器里**，尤其是 `p`。  
3. **看浏览器解析后的 DOM**，别只看源码。  
4. **布局异常时，先怀疑嵌套，再怀疑 CSS**。

### 避免再次犯错的方法

- 先搭大结构，再填内容
- 不确定能不能嵌套时，拆开写更稳
- 多看浏览器最终解析结果
- 记住：**HTML 是结构，不是随便包起来就行**

## 三、路径写错：图片、CSS、JS 为什么死活加载不出来？

### 你是不是也遇到过这些情况？

- 图片明明在文件夹里，页面却裂图
- CSS 写好了，但样式完全没生效
- JS 文件引入了，页面就是没反应

这类问题最烦，因为代码“看起来没问题”，但浏览器就是不认。

### 错误示例

```html
<img src="images/logo.png" alt="logo">
<link rel="stylesheet" href="css/style.css">
<script src="js/main.js"></script>
```

如果你的真实结构是：

```text
project/
  assets/
    images/
    css/
    js/
```

那上面的路径就很可能不对。

### 错误原因是什么？

路径错，常见就这几种：

- 文件夹名写错
- 文件名大小写错了
- 相对路径层级不对
- 把 HTML 文件所在位置想错了
- 以为“文件在项目里”就等于“路径能找到”

特别注意：很多环境里**大小写是敏感的**，`Logo.png` 和 `logo.png` 不是一回事。  
路径一定是从**当前 HTML 文件的位置**出发去算，不是从你脑子里的“项目大概位置”去算。

### 相对路径和绝对路径，别混了

#### 1）相对路径常见坑

如果 `index.html` 和 `assets` 文件夹在同一层级，应该这样写：

```html
<img src="./assets/images/logo.png" alt="logo">
<link rel="stylesheet" href="./assets/css/style.css">
<script src="./assets/js/main.js"></script>
```

如果少写了一层，或者多写了一层，浏览器就会找不到文件。

#### 2）绝对路径常见坑

```html
<img src="/assets/images/logo.png" alt="logo">
```

这个写法不是一定错，但它表示的是**从网站根目录开始找**。  
如果你是本地直接打开 HTML 文件，或者部署路径不是站点根目录，这种写法也可能失效。

### 正确写法示例

先确认结构：

```text
project/
  index.html
  assets/
    images/logo.png
    css/style.css
    js/main.js
```

再写：

```html
<img src="./assets/images/logo.png" alt="logo">
<link rel="stylesheet" href="./assets/css/style.css">
<script src="./assets/js/main.js"></script>
```

### 老赵式排查步骤

1. **先确认 HTML 文件在哪里**，别凭感觉。  
2. **按实际文件树写路径**，从当前 HTML 文件出发去找。  
3. **核对文件名、后缀名、大小写**，一个字母都别猜。  
4. **打开控制台和 Network 面板**，看是不是 404。  
5. **直接对照真实路径**，别只看你“觉得应该对”。

### 避免再次犯错的方法

- 统一资源目录结构，别乱放
- 路径尽量用编辑器补全
- 改文件名后，立刻检查所有引用
- 保存后刷新，第一时间看图片、样式、脚本有没有加载成功

## 四、老赵给你的统一排查模板：先结构，再路径，再看浏览器

以后排 HTML 问题，你可以直接这样查，别一上来就瞎改。

### 1. 检查结构
- 标签有没有闭合
- 闭合顺序对不对
- 嵌套层级有没有乱
- `p`、`div`、`span` 有没有放错位置

### 2. 检查路径
- 图片、CSS、JS 路径对不对
- 文件名是否一致
- 大小写是否匹配
- 相对路径层级是否正确
- 有没有把相对路径和根路径搞混

### 3. 检查浏览器表现
- 页面是不是局部乱了
- 图片是不是裂了
- 样式是不是没加载
- 控制台是否有 404

### 4. 回到源码和 DOM
- 源码不等于浏览器最终解析结果
- 重点看 Elements 和 Network
- 别只盯着你“以为写对了”的代码

这个顺序很重要：**先查结构，再查路径，最后看浏览器反馈**，效率最高。

## 五、练习题纠错：你可以拿这几个小例子自测

### 题 1：这段代码为什么页面乱了？

```html
<div>
  <p>欢迎你
  <span>来学习前端</p>
</span>
</div>
```

**问题点**：闭合顺序错了。  
**修正**：

```html
<div>
  <p>欢迎你 <span>来学习前端</span></p>
</div>
```

### 题 2：为什么图片不显示？

```html
<img src="img/logo.png" alt="logo">
```

如果你的目录实际是 `assets/images/logo.png`，那就是路径写错了。  
**修正**：

```html
<img src="./assets/images/logo.png" alt="logo">
```

### 题 3：为什么 `div` 放进 `p` 里后布局怪怪的？

```html
<p>
  这里是一段介绍
  <div>按钮区域</div>
</p>
```

**问题点**：嵌套不合理。  
**修正**：

```html
<p>这里是一段介绍</p>
<div>按钮区域</div>
```

## 六、新手学习路线建议：先把这几个坑养成“条件反射”

HTML 阶段别贪多，先把最容易出错的几件事练熟：

1. **每写完一个标签块，立刻检查闭合是否完整**
2. **页面一乱，先怀疑 HTML 结构**
3. **图片、CSS、JS 不生效，先查路径**
4. **多用编辑器自动补全和缩进提示**
5. **每次保存后都刷新看结果，不要攒到最后一起查**

你可以把本章当成随手查的清单：  
**结构有没有问题？路径有没有问题？浏览器有没有报错？**

只要你养成这个习惯，HTML 里最常见的坑，基本都能提前拦住。

## 本章小结

记住一句话就够了：**HTML 出问题，先看结构，再看路径。**

- **标签没闭合**：浏览器会自动补，但可能补歪，页面就跑偏了  
- **嵌套乱套**：`div`、`p`、`span` 放错位置，DOM 会变得很怪

# 第3章 HTML 进阶一点的坑：语义标签、属性写法和页面显示异常

你是不是也遇到过这种情况：HTML 明明写了，页面就是“不对劲”——图片不出来、链接点了没反应、表单提交不上去、结构一团乱。更麻烦的是，浏览器还不一定直接报错，新手很容易先怀疑 CSS 或 JS，其实问题往往就藏在 HTML 里。

这一章不讲大而全的 HTML 教科书，只盯住那些**新手最容易忽略、但最影响页面表现**的坑。你可以把它当成一份 HTML 排错清单，哪里怪就来这里对照。

## 1. 属性名写错、属性值漏引号、重复属性：为什么页面就是不按你想的来？

你是不是也写过这种代码？

```html
<img scr="logo.png" alt=logo>
<a href='https://example.com' href="https://baidu.com">去看看</a>
<input type=text placeholder=请输入姓名>
```

看起来像能跑，其实问题不少。新手最容易犯的就是：觉得“差不多就行”，结果浏览器根本不按你的意思执行。

### 错误示例

```html
<img scr="logo.png" alt=logo>
<input type=text placeholder=请输入姓名>
<a href="a.html" href="b.html">跳转</a>
```

### 错误原因

- `scr` 应该是 `src`，属性名拼错，浏览器直接不认。
- 属性值没加引号，简单值有时勉强能过，但一旦有空格、特殊字符就容易出问题。
- 同一个属性重复写，后面的可能覆盖前面的，结果不稳定。

### 正确写法

```html
<img src="logo.png" alt="logo">
<input type="text" placeholder="请输入姓名">
<a href="a.html">跳转</a>
```

### 老赵式排查步骤

1. 先看属性名有没有拼错，`src`、`href`、`alt`、`type` 最容易出错。  
2. 再看属性值是否规范，尽量都加引号。  
3. 检查有没有重复属性，复制粘贴后特别容易多出来。  
4. 打开开发者工具，看元素实际渲染结果，不要只看源码。  

### 避免再次犯错的方法

- 写完标签后，固定做“拼写、引号、重复”三连检。
- 新手阶段尽量别省引号。
- 复制代码时，重点看属性有没有重复带进去。
- 页面不对劲时，先查 HTML，再怀疑别的。

---

## 2. 语义标签乱用，为什么页面结构会“看着像对，实际上很乱”？

你是不是也有这种习惯：看到一个块就随手套个 `<div>`，想强调就乱用 `<strong>`，想表示标题就到处塞 `<h1>`？这就是很多新手页面“能看，但不规范”的根源。

### 错误示例

```html
<h1>登录按钮</h1>
<div>这是页面主标题</div>
<strong>这是一个普通说明文字</strong>
```

表面上能显示，实际上语义已经乱了。

### 错误原因

- `h1-h6` 是标题层级，不是“把字变大”的工具。
- `strong`、`em` 这类标签表示语义，不是专门做样式。
- 语义乱了，后面做样式、结构维护、搜索识别都会更麻烦。

### 正确写法

```html
<h1>页面主标题</h1>
<p>登录按钮</p>
```

```html
<p class="note">这是普通说明文字</p>
```

```css
.note {
  font-weight: bold;
  color: blue;
}
```

### 老赵式排查步骤

1. 先问自己：这个标签是在表达意思，还是在偷懒做样式？  
2. 有没有滥用 `h1`、`strong`、`em`、`b`、`i`？  
3. 页面层级是否一眼能看懂：标题、段落、列表、图片区块、表单区块是否清楚？  
4. 如果删掉样式，结构还是否合理？  

### 避免再次犯错的方法

- 记住一句话：**HTML 管结构，CSS 管外观。**
- 别把语义标签当装饰标签。
- 写完后从“别人能不能看懂结构”这个角度检查一遍。
- 先看语义对不对，再看好不好看。

---

## 3. 页面显示异常：图片不显示、链接失效、表单不工作，先别慌

这是新手最常见、也最容易抓狂的一类问题。你是不是也经历过：图片路径明明写了，页面就是空白；链接点了没反应；表单看着正常，一提交就不工作。

---

### 3.1 图片不显示：先查标签，再查路径

#### 错误示例

```html
<img scr="images/logo.png">
<img src="img/logo.pn">
```

### 错误原因

- `src` 写成 `scr`，浏览器直接不认。
- 路径写错了，文件夹名、文件名、后缀名错一个都不行。
- 图片文件根本不在那个位置，或者大小写不一致。

### 正确写法

```html
<img src="./images/logo.png" alt="网站 logo">
```

### 老赵式排查步骤

1. 先确认标签和属性是不是对的，尤其是 `img` 和 `src`。  
2. 去文件夹里找图片，别靠感觉。  
3. 把图片地址直接复制到浏览器地址栏试一下。  
4. 看控制台有没有加载失败提示。  

### 避免再次犯错的方法

- 路径别猜，按目录结构写。
- 文件名和后缀逐字核对。
- 新手阶段尽量统一命名，别中英文混着来。
- 图片不显示时，先别怀疑 CSS，先查 `src` 和路径。

---

### 3.2 链接失效：不是没点到，就是写错了地址

#### 错误示例

```html
<a herf="about.html">关于我们</a>
<a href="about.htmll">关于我们</a>
<a href="">关于我们</a>
```

### 错误原因

- `href` 拼错成 `herf`，浏览器直接忽略。
- 文件名或后缀写错。
- `href=""` 为空，行为容易异常。
- 外链少写协议或地址不完整，也会跳不出去。

### 正确写法

```html
<a href="./about.html">关于我们</a>
```

### 老赵式排查步骤

1. 先确认是不是 `a` 标签，`href` 是否拼对。  
2. 检查目标文件是否真的存在。  
3. 本地跳转尽量统一用相对路径。  
4. 外链直接复制到地址栏测试。  

### 避免再次犯错的方法

- 链接写完立刻点一次。
- 复制粘贴后重点看文件名和后缀。
- 不要随手留空 `href`。
- “点了没反应”时，先查 `href`。

---

### 3.3 表单不工作：很多时候不是表单坏了，而是属性不对

#### 错误示例

```html
<form action="/login" methd="post">
  <input type="text" name="username">
  <button>提交</button>
</form>
```

### 错误原因

- `method` 拼错成 `methd`。
- `action` 地址可能不对。
- 输入框缺少 `name`，后端收不到数据。
- 按钮类型不明确，提交行为可能异常。

### 正确写法

```html
<form action="/login" method="post">
  <input type="text" name="username">
  <button type="submit">提交</button>
</form>
```

### 老赵式排查步骤

1. 先检查 `action` 和 `method`。  
2. 再检查输入框有没有 `name`。  
3. 看按钮是不是 `type="submit"`。  
4. 如果接了接口，就看请求有没有真正发出去。  

### 避免再次犯错的方法

- 记住表单三要素：**action、method、name**。
- 别只看页面像不像表单，要看能不能提交数据。
- 做表单时，先测试提交，再继续往下写。

---

## 4. 老赵式排错思路：先验证标签，再看属性和资源引用

HTML 出问题，别一上来就怀疑 CSS 和 JS。先按这个顺序查，效率最高。

### 第一步：先看标签本身有没有写对
- 标签名是不是拼错了？
- 起始标签和结束标签有没有成对？
- 嵌套顺序对不对？

比如：

```html
<p><div>内容</p></div>
```

这就是明显的嵌套错误。浏览器可能会自动修正，但结果往往不是你想要的。

**正确写法：**
```html
<div><p>内容</p></div>
```

### 第二步：再看属性有没有问题
- 属性名拼对了吗？
- 属性值有引号吗？
- 有没有重复属性？
- 该写在 `a` 上的属性有没有写到别的标签上？

### 第三步：检查资源引用
- 图片路径对不对？
- 链接地址对不对？
- 表单提交地址对不对？

### 第四步：看浏览器实际效果
不要只盯着代码脑补。浏览器是最终裁判，页面展示、控制台提示、元素是否存在，都是线索。

### 第五步：看渲染后的结构有没有被浏览器“自动修正”
有些 HTML 错误不会直接报错，但浏览器修正后，结构已经变了。  
所以遇到显示异常时，别只看源码，还要看**渲染后的 DOM 结构**。

## 5. 练习题纠错：你是不是也会在这里踩坑？

### 题目：修复下面这段 HTML

```html
<div>
  <h1>欢迎来到我的网站</h1>
  <img scr="images/banner.jpg" alt=banner>
  <a herf="about.html">关于我们</a>
  <p><strong>联系我们</p></strong>
</div>
```

### 问题在哪里？

1. `img` 的 `src` 写错成了 `scr`。  
2. `alt` 没加引号。  
3. `a` 的 `href` 写错成了 `herf`。  
4. `<p>` 和 `<strong>` 的嵌套顺序错了。  

### 正确答案示例

```html
<div>
  <h1>欢迎来到我的网站</h1>
  <img src="images/banner.jpg" alt="banner">
  <a href="about.html">关于我们</a>
  <p><strong>联系我们</strong></p>
</div>
```

### 这道题想提醒你什么？

不是所有“页面能打开”的代码都算对。很多 HTML 错误不会直接让页面崩掉，但会让内容显示异常、行为失效、结构混乱。新手最容易在这种“看起来差不多”的地方掉坑。

### 老赵式做题方法

1. 先扫标签名对不对。  
2. 再看属性名和属性值。  
3. 检查有没有漏引号、写错拼写。  
4. 看嵌套顺序是否正确。  
5. 路径、链接、资源地址是否真实存在。  

这个顺序一旦养成，后面你排错会快很多。

## 6. 新手怎么避免反复掉进这些坑？

给你一个很实用的习惯清单，照着做，能少走很多弯路。

### 1）写完先做“三查”
- 查标签名
- 查属性名和属性值
- 查路径和资源

### 2）不要只看代码，要看浏览器效果
页面显示不对，先问自己：**浏览器到底认没认这段 HTML？**

### 3）对照文档和实际效果
你不需要一开始背所有属性，但至少要知道：这个标签有什么标准属性，哪个是必需的，哪个是可选的。

### 4）养成最小化排查习惯
页面出问题时，先删掉多余内容，只保留最小结构，看看问题还在不在。这样你很快能判断：是 HTML 问题、CSS 问题，还是 JS 问题。

### 5）别怕“麻烦”，怕的是重复踩坑
新手阶段最值钱的不是“写得快”，而是“少出错”。你每次多检查十秒，可能就少卡半小时。

## 小结：HTML 的坑，很多都不是“大错”，而是“细节错”

这一章你要记住的核心其实很简单：

- **标签要写对，嵌套要顺。**
- **属性要拼对，值要规范。**
- **路径要真实，资源要能找到。**
- **语义标签别乱用，HTML 管结构，CSS 管样式。**
- **先查标签，再查属性，再查资源引用。**

如果你以后遇到“页面看起来怪怪的”，别急着怀疑前端框架，先回来翻这一章。很多时候，问题就藏在一个小小的拼写错误、一个漏掉的引号、一个写错的路径里。

你可以把这一章当成 HTML 的“现场排查表”：先看标签，再看属性，再看资源；先看结构，再看表现，最后再去怀疑别的东西。这样你排错会快很多，也不会一上来就被细节绊住。

# 第4章 CSS 常见错误：样式不生效、选择器优先级和盒模型

你是不是也遇到过这种情况：HTML 明明写好了，CSS 也写了，页面就是不听话。按钮不变色、文字不居中、盒子总跑偏。新手学 CSS，最烦的往往不是“不会写”，而是“我以为写对了，但它就是不生效”。

这一章老赵不绕概念，直接讲几个高频坑：**样式不生效、选择器优先级混乱、盒模型理解错误、元素不显示、定位异常**。记住一句话：**CSS 排错不是靠猜，是靠一层一层确认。**

---

## 一、样式不生效：先别急着怀疑人生，先查这几件事

你是不是也写过这种代码，结果页面一点反应都没有？

```html
<link rel="stylesheet" href="style.css">
```

```css
.box {
  color: red;
}
```

页面还是黑的。别急，**样式不生效**最常见的原因，通常不是 CSS 语法，而是下面这几类。老赵建议你按顺序查：**没引入、写错、被覆盖、没选中**。

### 1.1 没引入成功

**错误示例：**

```html
<link rel="stylesheet" href="style.csss">
```

文件名多了一个 `s`，或者路径写错了。

**错误原因：**  
浏览器根本没找到 CSS 文件，自然不会生效。很多新手以为是选择器写错了，其实压根没加载到样式文件。

**正确写法：**

```html
<link rel="stylesheet" href="./style.css">
```

**老赵式排查步骤：**
1. 先看 `link` 标签有没有写。
2. 再看 `href` 路径对不对。
3. 打开开发者工具，在 Network 里看 CSS 有没有加载成功。
4. 如果 404 了，先修路径，别急着改样式。

**避免再次犯错的方法：**
- 文件名、后缀、路径统一小写。
- 新手阶段尽量少用太深的相对路径。
- 写完就刷新检查，别只看代码不看页面。

---

### 1.2 样式写错了，自己还没发现

**错误示例：**

```css
titel {
  color: red;
}
```

```html
<div class="title">标题</div>
```

**错误原因：**  
CSS 里写的是 `titel`，HTML 里是 `title`。这种拼写一错，浏览器就当你没写。还有一种常见情况是属性名写错，比如 `font-szie`、`colr`。

**正确写法：**

```css
.title {
  color: red;
}
```

**老赵式排查步骤：**
1. 先把选择器和属性名逐个看一遍，别只看大概。
2. 对照 HTML，确认 class 或 id 拼写一致。
3. 打开开发者工具，看这条规则有没有出现在 Styles 里。
4. 如果连规则都没出现，八成就是写错了。

**避免再次犯错的方法：**
- 写完马上肉眼核对一遍。
- 新手别一口气复制太多代码，容易把错也一起复制过去。
- 不生效时，先查拼写，再查逻辑。

---

### 1.3 被别的样式覆盖了

**错误示例：**

```css
p {
  color: red;
}
.text {
  color: green;
}
```

```html
<p class="text">你好</p>
```

结果显示绿色。

**错误原因：**  
`.text` 比 `p` 更具体，所以把前面的覆盖了。很多时候不是“没生效”，而是“生效了，但输了”。

**正确写法：**  
想让某条样式稳定生效，就用更明确的选择器，避免冲突规则互相打架。

**老赵式排查步骤：**
1. 打开开发者工具，选中元素。
2. 看 Styles 里哪条规则被划掉了。
3. 找到最终生效的那条样式，确认是谁覆盖了谁。
4. 先定位冲突源头，再决定改哪里。

**避免再次犯错的方法：**
- 学会看“被划掉的样式”。
- 不要随手写一堆重复规则。
- 同一属性尽量只保留一个主要来源。

---

### 1.4 样式没选中元素

**错误示例：**

```css
.box .title {
  font-size: 20px;
}
```

```html
<div class="box">
  <h2>标题</h2>
</div>
```

**错误原因：**  
`.box .title` 表示 `.box` 里面有一个 `class="title"` 的元素，但 HTML 里根本没有这个类。选择器看起来很完整，实际一个都没选中。

**正确写法：**

```css
.box h2 {
  font-size: 20px;
}
```

**老赵式排查步骤：**
1. 看选择器是不是写得太长、太复杂。
2. 对照 HTML 结构，确认层级关系。
3. 先用简单选择器验证，再逐步加复杂度。

**避免再次犯错的方法：**
- 新手阶段先别写太长的层级选择器。
- 选不中时先缩短选择器，逐步测试。
- 先让样式生效，再谈“写得优雅”。

---

## 二、选择器优先级混乱：为什么你写的样式总是输给别人

你是不是也有这种感觉：明明后来写了样式，为什么还是没赢？这就是选择器优先级的问题。新手最容易犯的错，不是不会写，而是不知道谁更有权力。

一般来说，优先级更强的，往往是：
- `id`
- `class`
- 标签选择器
- 通配符 `*`

### 2.1 先记住一个最小规则

**错误示例：**

```css
div {
  color: red;
}

.box {
  color: blue;
}
```

```html
<div class="box">文字</div>
```

结果显示蓝色。

**错误原因：**  
`.box` 比 `div` 更具体，所以赢了。不能只看“谁写在下面”，还要看“谁更具体”。很多新手以为“后写的就一定赢”，其实不是。

**正确写法：**  
关键样式尽量用更明确的类选择器，少靠标签选择器硬撑。

**老赵式排查步骤：**
1. 先看是不是多个选择器同时作用于同一个元素。
2. 看开发者工具里哪条规则优先级更高。
3. 先理解冲突来源，再考虑怎么改。

**避免再次犯错的方法：**
- 少用标签选择器控制关键样式。
- 多用类选择器做业务样式。
- 遇到冲突先找来源，不要直接乱加复杂选择器。

---

### 2.2 最小示例看懂“为什么总输”

**错误示例：**

```css
.box {
  color: red;
}

div.box {
  color: green;
}
```

```html
<div class="box">我是文字</div>
```

如果你本来想让 `.box` 的红色生效，但结果却被别的规则改掉了，问题就出在更具体的选择器上。

**错误原因：**  
选择器越具体，优先级通常越强。`div.box` 比 `.box` 更具体，所以更容易赢。

**正确写法：**  
别让同一个元素同时被多套风格打架。尽量统一一层样式来源，或者把冲突规则整理掉。

**老赵式排查步骤：**
1. 看最终生效的是哪一条。
2. 找到比它更强的规则。
3. 判断是该删掉冲突，还是该调整结构。

**避免再次犯错的方法：**
- 给同类组件用统一命名。
- 别在很多地方重复改同一个属性。
- 开发者工具是你最好的“裁判”。

---

### 2.3 `!important` 不是万能药

**错误示例：**

```css
.box {
  color: red !important;
}
```

**错误原因：**  
你可能只是想临时压住别的样式，但很容易越写越多，最后项目里全是 `!important`，后面谁都不好改。

**正确写法：**  
尽量通过合理选择器和层级关系解决，而不是滥用 `!important`。

**老赵式排查步骤：**
1. 先问自己：这条样式为什么要强行压制？
2. 看是不是选择器写得太弱。
3. 看是不是样式结构本来就乱了。

**避免再次犯错的方法：**
- 把 `!important` 当最后手段，不当常规手段。
- 先整理结构，再谈覆盖。

---

## 三、盒模型理解错误：为什么宽高对不上，布局总差一点

新手最容易犯的错就是：我写了 `width: 200px`，为什么页面看起来不是 200px？

### 3.1 宽高不等于最终占位

**错误示例：**

```css
.box {
  width: 200px;
  padding: 20px;
  border: 10px solid #000;
}
```

你以为盒子总宽度还是 200px，结果页面却明显更宽，甚至把父容器撑开了。

**错误原因：**  
`width` 只管内容区域，`padding` 和 `border` 会继续往外加。也就是说，最终占位会比你写的 `width` 更大。很多布局错位、超出容器、左右不对齐的问题，本质都在这里。

**正确写法：**

```css
.box {
  width: 200px;
  box-sizing: border-box;
  padding: 20px;
  border: 10px solid #000;
}
```

**老赵式排查步骤：**
1. 先看有没有 `padding` 和 `border`。
2. 再看有没有设置 `box-sizing`。
3. 用开发者工具看实际尺寸，不要只看自己写的 width。
4. 如果父盒子被撑开了，先别急着怪布局，先算盒模型。

**避免再次犯错的方法：**
- 记住：`width` 不一定等于最终宽度。
- 新手常用 `box-sizing: border-box;`，能少很多误差。
- 做布局时先养成“看实际尺寸”的习惯。

---

### 3.2 元素不显示，不一定是“没写”，可能是“被藏起来了”

**错误示例：**

```css
.box {
  display: none;
}
```

或者：

```css
.box {
  visibility: hidden;
}
```

**错误原因：**  
元素还在，但被隐藏了。还有可能是宽高为 0、颜色和背景色一样，或者被其他元素盖住。

**正确写法：**  
确认你是真的要隐藏；调试时先把隐藏属性去掉。

**老赵式排查步骤：**
1. 检查 `display` 和 `visibility`。
2. 看元素有没有宽高。
3. 看文字颜色是不是和背景撞色。
4. 看是不是被定位层盖住了。

**避免再次犯错的方法：**
- 调试时给元素加明显边框：
  ```css
  border: 1px solid red;
  ```
- 看不见时先判断它是“没了”还是“藏了”。

---

### 3.3 定位异常：明明定位了，怎么还是跑偏

**错误示例：**

```css
.parent {
  position: relative;
}

.child {
  position: absolute;
  top: 0;
  left: 0;
}
```

但你以为它会出现在想要的位置，结果偏了。

**错误原因：**  
绝对定位会相对最近的定位祖先元素定位。如果父级没弄对，位置就会跑。还有一种常见情况是：你以为参考的是整个页面，其实参考的是某个局部容器。

**正确写法：**  
先确认谁是定位参考系，再设置 `top/left/right/bottom`。

**老赵式排查步骤：**
1. 看父元素有没有 `position: relative;`。
2. 看子元素是不是 `absolute`。
3. 检查是否被外层布局影响。
4. 用边框标记父子盒子，观察参考关系。

**避免再次犯错的方法：**
- 先搞清楚“相对谁定位”。
- 定位之前先把结构理顺，不要一上来全靠 `absolute` 硬摆。

---

## 四、错误示例、错误原因、正确写法：一眼看懂的对照

### 示例 1：路径错了，样式没加载

**错误：**
```html
<link rel="stylesheet" href="css/stlye.css">
```

**原因：** 拼写错误。

**正确：**
```html
<link rel="stylesheet" href="css/style.css">
```

---

### 示例 2：选择器写错，选不中

**错误：**
```css
#btn { color: red; }
```

```html
<button class="btn">提交</button>
```

**原因：** id 和 class 混用了。

**正确：**
```css
.btn { color: red; }
```

---

### 示例 3：盒模型算错，盒子变大

**错误：**
```css
.card {
  width: 300px;
  padding: 20px;
  border: 5px solid #000;
}
```

**原因：** 没考虑 `padding` 和 `border`。

**正确：**
```css
.card {
  box-sizing: border-box;
  width: 300px;
  padding: 20px;
  border: 5px solid #000;
}
```

## 五、老赵式排错步骤：先加载，再命中，再覆盖，再算盒子

以后遇到 CSS 问题，别乱猜，直接按这个顺序来。

### 第一步：先确认样式有没有加载
- CSS 文件路径对不对
- `link` 标签有没有写
- 浏览器 Network 里有没有 404

### 第二步：再确认有没有命中元素
- 选择器和 HTML 是否匹配
- class、id 有没有写错
- 层级关系对不对

### 第三步：再确认有没有被覆盖
- 看哪条样式最终生效
- 看有没有更高优先级的规则
- 看有没有 `!important`、内联样式、后写规则

### 第四步：确认是不是盒模型和定位问题
- 宽高是不是被 padding/border 撑大了
- 元素是不是被隐藏了
- 定位参照系是不是弄错了

**记住：** 新手最怕的就是一上来就改代码，改半天发现是路径错了。

## 六、练习题纠错：你可以这样自己查

### 题目 1：按钮颜色没变

**题目代码：**
```html
<button class="btn">点我</button>
```

```css
#btn {
  background: blue;
  color: #fff;
}
```

**你先判断什么错了？**  
这里是 `class` 和 `id` 混用了。

**正确答案：**
```css
.btn {
  background: blue;
  color: #fff;
}
```

**排查提醒：**
- 先看 HTML，再看 CSS。
- 先找“选没选中”，再找“为什么没覆盖”。

### 题目 2：卡片宽度总超出父容器

**题目代码：**
```css
.card {
  width: 100%;
  padding: 20px;
  border: 1px solid #ccc;
}
```

**你先判断什么错了？**  
`width: 100%` 已经占满父容器，再加上 `padding` 和 `border`，就容易超出。

**正确答案：**

```css
.card {
  box-sizing: border-box;
  width: 100%;
  padding: 20px;
  border: 1px solid #ccc;
}
```

**排查提醒：**
- 先算盒模型，再怪布局。

### 题目 3：文字明明写了却看不见

**题目代码：**

```css
  color: white;
  background: white;
}
```

**你先判断什么错了？**  
这不是没显示，是颜色和背景色一样了。

**正确答案：**
```css
.tip {
  color: #333;
  background: white;
}
```

**排查提醒：**
- 看不见不等于没生效。
- 先给它加边框，看看是不是还在。

## 七、避免再次犯错的方法：学会看开发者工具

老赵最想提醒你的，其实就一句：**别靠猜，学会看浏览器给你的答案。**

### 你要重点看三样东西
1. **Styles 面板**：哪条样式生效了，哪条被划掉了。
2. **Computed 面板**：最终结果到底是多少。
3. **元素结构**：你写的选择器到底有没有选中它。

### 新手照着做的步骤
1. 打开页面，按 F12 或右键检查。
2. 点选你要看的元素。
3. 看 Styles 里有没有你写的那条 CSS。
4. 如果没有，先查路径和选择器。
5. 如果有但被划掉了，说明被覆盖了。
6. 如果样式生效了但布局还不对，再查盒模型和定位。

### 新手养成三个习惯
- 写完样式先刷新确认。
- 出问题先用边框和背景色测试。
- 遇到冲突先删减选择器，不要先加复杂度。

### 一个很实用的判断标准
如果你不知道问题在哪，就按这个顺序问自己：
- 样式文件加载了吗？
- 选择器命中了吗？
- 有没有被覆盖？
- 是盒模型问题还是定位问题？

---

## 八、小结：CSS 新手最该记住的不是“写更多”，而是“查更准”

CSS 的坑，很多都不是大问题，而是小地方没对上：路径错一个字母，选择器少一个点，优先级判断错一步，盒模型少算了 padding。前端排错最值钱的能力，不是背更多属性，而是**快速定位问题**。

以后你遇到“样式不生效”，先别急着改十遍。记住老赵这句话：

**先看有没有加载，再看有没有选中，再看有没有被覆盖，最后再看盒模型和定位。**

你只要把这套顺序养成习惯，CSS 就会从“玄学”变成“可排查的问题”。

# 第5章 CSS 布局高频坑：元素不显示、定位异常和常见排版翻车

你是不是也遇到过这种情况：  
明明写了个 `div`，页面上就是看不见；  
明明设了 `position: absolute`，结果元素飞到不知道哪儿去了；  
明明只是想做个简单排版，最后却“叠罗汉”“跑偏”“塌成一团”。

别慌，这类问题通常都有明确原因。老赵今天就带你专门拆这几个 CSS 布局高频坑。你不用先把布局体系学全，先学会“看见问题、定位问题、修掉问题”就够了。

---

## 一、元素为什么不显示？先从最常见的 4 个点查起

### 1. `display: none`：元素直接没了

**错误示例：**
```css
.box {
  display: none;
}
```

**错误原因：**  
`display: none` 会让元素直接从布局里消失，不占位置，也看不见。新手最常见的情况就是：前面写过隐藏逻辑，后面忘了改回来。

**正确写法：**
```css
.box {
  display: block;
}
```

**老赵式排查步骤：**
1. 打开开发者工具，选中这个元素；
2. 看计算样式里有没有 `display: none`；
3. 查是不是别的规则覆盖了它；
4. 如果是 JS 控制的，再看是不是被切到隐藏状态了。

**避免再次犯错的方法：**  
先确认元素“存在且可见”，再做切换、动画和交互。别一上来就写隐藏逻辑。

---

### 2. `visibility: hidden`：看不见，但还占位

**错误示例：**
```css
.box {
  visibility: hidden;
}
```

**错误原因：**  
它不是删除元素，而是把元素藏起来，所以页面会空出一块位置，但元素本身还在。

**正确写法：**
```css
.box {
  visibility: visible;
}
```

**老赵式排查步骤：**
1. 看元素是不是“占着位置但看不见”；
2. 优先检查 `visibility`；
3. 如果还能点到但看不到，再查透明度或遮挡。

**避免再次犯错的方法：**  
记住：`display` 管“在不在布局里”，`visibility` 管“看不看得见”。

---

### 3. `opacity: 0`：透明到像没了

**错误示例：**
```css
.box {
  opacity: 0;
}
```

**错误原因：**  
元素还在，只是完全透明。结构没问题，但视觉上看不到。

**正确写法：**
```css
.box {
  opacity: 1;
}
```

**老赵式排查步骤：**
1. 看元素有没有占位；
2. 检查透明度是不是 0；
3. 如果鼠标能碰到、眼睛却看不到，优先查它。

**避免再次犯错的方法：**  
只要你发现“像消失了，但又不像真没了”，先查 `opacity`。

---

### 4. 尺寸为 0：盒子太小，肉眼看不见

**错误示例：**
```css
.box {
  width: 0;
  height: 0;
}
```

**错误原因：**  
宽高为 0，内容没有展示空间，看起来就像没渲染。空盒子、图片容器、绝对定位小图标最容易中招。

**正确写法：**
```css
.box {
  width: 200px;
  height: 100px;
}
```

**老赵式排查步骤：**
1. 看盒子有没有尺寸；
2. 看内容能不能把它撑开；
3. 如果是空盒子，记得显式给宽高。

**避免再次犯错的方法：**  
先给关键盒子加临时边框：
```css
.box { border: 1px solid red; }
```
先把盒子“看见”，再谈美化。

---

## 二、定位为什么总是跑偏？先搞清楚参照系

### 1. `absolute` 不是随便放，它要找父级定位参考

**错误示例：**
```css
.parent {}
.child {
  position: absolute;
  top: 0;
  left: 0;
}
```

**错误原因：**  
如果父元素没有定位，`absolute` 会继续往上找参考点，结果常常不是你以为的那个容器。你本来想让它贴在卡片角落，最后却跑到页面左上角去了。

**正确写法：**
```css
.parent {
  position: relative;
}
.child {
  position: absolute;
  top: 0;
  left: 0;
}
```

**老赵式排查步骤：**
1. 先问自己：它该相对谁定位？
2. 给那个父级加 `position: relative`；
3. 再看 `top / left` 是否生效；
4. 如果还不对，再往外层找干扰。

**避免再次犯错的方法：**  
只要用 `absolute`，先养成习惯：**先定参照系，再写偏移量。**

---

### 2. `fixed`、`sticky`、`relative` 别混着乱用

**错误示例：**
```css
.header {
  position: sticky;
  top: 0;
}
```
但你以为它会像 `fixed` 一样一直钉死在顶部。

**错误原因：**  
`sticky` 是“滚到某个位置后粘住”，不是从头到尾固定；`fixed` 才是相对浏览器窗口固定。`relative` 则主要是“先占着原来的位置，再做偏移参考”。

**正确写法：**
```css
.header {
  position: fixed;
  top: 0;
}
```
或
```css
.header {
  position: sticky;
  top: 0;
}
```

**老赵式排查步骤：**
1. 先确认你要的是“吸顶”还是“一直固定”；
2. 再看父元素是否影响 `sticky`；
3. 检查 `top` 有没有写；
4. 看页面有没有足够滚动空间。

**避免再次犯错的方法：**  
`sticky` 是“条件固定”，不是“绝对固定”。先想清楚效果，再写代码。

---

## 三、为什么布局会塌？浮动这块最容易翻车

### 1. 浮动后父元素高度塌陷

**错误示例：**
```css
.left {
  float: left;
}
.right {
  float: left;
}
```

**错误原因：**  
浮动元素会脱离普通文档流，父元素可能感知不到高度，于是背景没了、边框没了、下面内容还往上顶，看起来像整个盒子“塌了”。

**正确写法：**
```css
.parent::after {
  content: "";
  display: block;
  clear: both;
}
```

**老赵式排查步骤：**
1. 看子元素是不是用了 `float`；
2. 看父元素是不是突然没高度了；
3. 给父元素清除浮动；
4. 再观察布局是否恢复。

**避免再次犯错的方法：**  
新手阶段尽量少用浮动做整体布局。能用 `flex`，先用 `flex`。

---

## 四、常见排版翻车：间距不对、层级不对、位置跑偏

### 1. 间距不对：别一上来就疯狂加 `margin`

**错误示例：**
```css
.card {
  margin-top: 60px;
}
```

**错误原因：**  
你可能把父子关系、兄弟关系、默认外边距全混了。尤其是 `body` 默认 `margin` 没去掉时，页面会莫名多出一圈空白。

**正确写法：**
```css
body {
  margin: 0;
}
```

**老赵式排查步骤：**
1. 先清浏览器默认样式；
2. 看间距来自 `margin` 还是 `padding`；
3. 检查是不是多个元素叠加出了空白；
4. 用开发者工具直接看盒模型。

**避免再次犯错的方法：**  
别只盯着视觉上的空白，要看它到底是哪一层撑出来的。

---

### 2. 层级不对：元素明明在那儿，就是被盖住了

**错误示例：**
```css
.modal {
  position: absolute;
  z-index: 1;
}
.header {
  position: relative;
  z-index: 10;
}
```

**错误原因：**  
`z-index` 不是随便写大就赢，它还要看定位方式和层叠上下文。新手常见的感觉就是：我明明加了 `z-index`，怎么还是被挡住了？

**正确写法：**
```css
.modal {
  position: fixed;
  z-index: 9999;
}
```

**老赵式排查步骤：**
1. 先确认元素有没有 `position`；
2. 再看它是不是被父级层叠环境限制了；
3. 检查有没有别的元素层级更高；
4. 临时把问题元素抬到最上层验证一下。

**避免再次犯错的方法：**  
别迷信“数字越大越赢”，先看它处在哪个层级环境里。

---

### 3. 位置跑偏：通常是参照错了，不是你眼花了

**错误示例：**
```css
.badge {
  position: absolute;
  top: 10px;
  right: 10px;
}
```

**错误原因：**  
你以为它贴着卡片，实际它贴着页面。通常还是父级没设对定位，参照系跑偏了。

**正确写法：**
```css
.card {
  position: relative;
}
.badge {
  position: absolute;
  top: 10px;
  right: 10px;
}
```

**老赵式排查步骤：**
1. 找到它应该贴着谁；
2. 给那个容器加 `position: relative`；
3. 再调 `top/right/bottom/left`；
4. 必要时给容器加边框辅助观察。

**避免再次犯错的方法：**  
只要用绝对定位，先把参照容器定下来，再去调偏移。

---

## 五、老赵式排查顺序：别乱改，按这个来

以后遇到布局问题，就按这个顺序来：

1. **看元素是否存在**  
   开发者工具里有没有这个节点？

2. **看元素是否占位**  
   是 `display: none`，还是尺寸为 0？

3. **看元素是否被覆盖**  
   有没有被别的层压住？

4. **看元素是否脱离文档流**  
   有没有用了 `float`、`absolute`、`fixed`？

5. **看参照系是否正确**  
   定位父级有没有设置好？

很多新手一上来就猛改 `margin`，其实真正的问题是元素根本没显示出来。老赵建议你养成一个习惯：**先定位现象，再动手改样式。**

---

## 六、避免再次翻车：先写最小布局，再逐步加效果

老赵给你一个特别实用的习惯：

### 1. 先写最小布局
先把结构搭出来，只保留最基础的 `div`、标题、按钮、图片。

### 2. 先让它“看得见”
加边框、背景色、固定宽高，确认每个盒子都能找到。

### 3. 再处理布局
先定主结构，再上定位、浮动、层级。

### 4. 最后才加装饰和复杂效果
比如阴影、动画、悬浮、遮罩、交互效果。

### 5. 每次只改一个变量
别一次改十个属性，不然你根本不知道是哪一项把页面改坏的。

---

## 小结：布局翻车，大多不是能力问题，是排查顺序问题

CSS 布局里最常见的坑，基本就这几类：

- 元素不显示：`display`、`visibility`、`opacity`、尺寸为 0  
- 定位异常：`relative`、`absolute`、`fixed`、`sticky` 用错  
- 浮动塌陷：父元素高度没撑住  
- 排版翻车：间距、层级、参照系搞混  

你只要记住一句话：**先确认元素在哪儿、在不在、占不占位、有没有被盖住、是不是脱离文档流。**  
这样你以后看到“页面不对劲”，就不会第一反应是“我是不是不适合学前端”了。

别急，前端新手最需要的不是一次写对，而是每次都能快速找到错在哪。

# 第6章 JavaScript 常见错误：变量、条件判断和循环写错

你是不是也遇到过这种情况：代码明明照着写了，页面却没反应；按钮一点就报错；甚至一刷新，浏览器直接卡住。  
新手阶段最常见的 JS 问题，往往不是“语法多高级”，而是**变量、判断、循环**这三块基础逻辑写歪了。

这一章，老赵就带你抓几个高频坑：**变量作用域误解、条件判断写错、循环死循环**。先别急着背原理，先学会“看到问题就能顺藤摸瓜查出来”。

---

## 一、变量作用域误解：为什么外面能用、里面不能用、改了没反应？

### 你是不是也写过这种代码？

```javascript
function test() {
  let score = 100;
}
console.log(score);
```

你会纳闷：`score` 明明写了，为什么外面拿不到？

再比如：

```javascript
let num = 10;
function add() {
  let num = 20;
}
add();
console.log(num);
```

你以为改的是外面的变量，结果输出还是 `10`。

### 错误原因是什么？

这是**作用域**的问题。

最常见的记法就一句：

- 函数里声明的变量，通常只能在函数里用
- 块级作用域里的变量，出了这个块可能就访问不到
- 同名变量会遮住外层变量，你以为改了外层，其实改的是里面

很多 `undefined`、拿不到值、修改没效果的问题，本质都是：**变量不在你以为的那个范围里**。

### 正确写法是什么？

如果要让外面能用，就把变量放到合适的位置：

```javascript
let score;

function test() {
  score = 100;
}

test();
console.log(score);
```

如果只是函数内部用，就把值传进去：

```javascript
function add(num) {
  console.log(num + 10);
}
add(20);
```

块级作用域也要留意：

```javascript
if (true) {
  let msg = "你好";
  console.log(msg);
}
// console.log(msg); // 这里访问不到
```

### 老赵式排查步骤

1. 先看变量是在哪里声明的  
2. 再看你使用它的位置，是不是超出作用域了  
3. 再看有没有同名变量把外层变量遮住了  
4. 最后确认你改的是不是同一个变量

### 避免再次犯错的方法

- 变量尽量“在哪用，就在哪附近声明”
- 不要乱用重复名字
- 函数之间传值，优先用参数
- 写完先问自己：**谁能访问它？**

---

## 二、条件判断写错：if、else、比较运算符和赋值运算符混淆

### 你是不是也写过这种判断？

```javascript
let age = 18;
if (age = 18) {
  console.log("可以进入");
}
```

看起来像在判断，其实已经悄悄把 `age` 赋值成 18 了。  
还有一种常见情况：你明明想判断“相等”，结果分支总是不对，最后半天找不到原因。

### 错误原因是什么？

这里最常见的坑就三个：

- 把 `=` 当成判断
- 把 `==` 和 `===` 搞混
- `if / else if / else` 的顺序写乱

你要记住：

- `=` 是赋值
- `==` 是比较值
- `===` 是比较值和类型

JS 只要语法没错，代码就会跑，但跑出来的结果可能完全不是你想要的。

### 正确写法是什么？

```javascript
let age = 18;
if (age === 18) {
  console.log("可以进入");
}
```

再看一个常见分数判断：

```javascript
let score = 75;

if (score >= 90) {
  console.log("优秀");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
```

这里要注意顺序：范围大的先写，范围小的后写，不然条件容易被前面的分支“抢走”。

### 老赵式排查步骤

1. 先看条件里有没有把 `=` 写进去  
2. 再看你要比的是“值相等”还是“连类型也要一致”  
3. 再看 `if / else if / else` 的顺序有没有乱  
4. 最后代入一个具体值，手动走一遍分支

### 避免再次犯错的方法

- 写条件前先用中文说一遍逻辑
- 优先使用 `===`
- 遇到字符串和数字比较时，多留个心眼
- 每次写完都问一句：**这个条件真的和我想的一样吗？**

---

## 三、循环死循环：for、while 写错导致页面卡死或浏览器无响应

### 你是不是也碰到过：页面突然卡住？

这通常不是浏览器坏了，而是你写了一个**不会结束的循环**。

比如：

```javascript
let i = 1;
while (i <= 5) {
  console.log(i);
}
```

看着像在数数，其实 `i` 根本没变，循环条件永远成立，页面就会一直跑下去。  
还有一种是你写了循环，但边界写反了，结果循环压根不执行，表面没报错，实际上逻辑已经歪了。

### 错误原因是什么？

循环出问题，常见就两种：

- **循环变量没有变化**
- **终止条件写错了**

比如这个：

```javascript
for (let i = 0; i >= 10; i++) {
  console.log(i);
}
```

你本来想让它从 0 到 10，结果条件写成了 `i >= 10`，第一次就不成立，循环根本不执行。

再比如边界条件写错：

```javascript
let n = 10;
while (n > 0) {
  console.log(n);
  n++;
}
```

你本来想倒着减，结果却在加，条件永远不会变成假，这就很危险。

### 正确写法是什么？

```javascript
let i = 1;
while (i <= 5) {
  console.log(i);
  i++;
}
```

```javascript
for (let i = 0; i < 10; i++) {
  console.log(i);
}
```

循环能不能正常跑，关键不是“我写了循环”，而是你有没有把**起点、条件、步长、终点**理顺。

### 老赵式排查步骤

1. 先看循环变量有没有更新  
2. 再看条件是不是朝着“结束”在变化  
3. 再看边界值，比如 `<=` 和 `<` 有没有写错  
4. 如果页面卡死，先停下来查循环，别乱刷新

### 避免再次犯错的方法

- 写循环前先想清楚：**什么时候结束**
- 先写伪代码，再翻成 JS
- 每个循环都要有出口
- 调试时先少量打印，别一上来就跑大循环

---

## 四、老赵式排错顺序：先变量，再判断，再循环

新手排 JS 错误，别东一榔头西一棒子。老赵建议你按这个顺序来：

### 1. 先看变量作用域

问自己：这个变量是不是在当前地方真的能访问？  
很多 `undefined`、拿不到值的问题，先从这里查。

### 2. 再看条件判断

问自己：这个 `if` 到底判断对了没有？  
有没有把 `=` 写进去？有没有把边界写错？

### 3. 最后看循环终止条件

问自己：它到底会不会停？  
循环变量有没有变？条件有没有反着写？

这个顺序很重要，因为很多新手一出错就先怀疑框架、浏览器、电脑，其实大多数时候都是基础逻辑错了。

---

## 五、练习题纠错：你来找问题，老赵来帮你修

### 例 1：为什么打印不出来？

```javascript
function showName() {
  let name = "小赵";
}
showName();
console.log(name);
```

**问题**：`name` 定义在函数内部，外面访问不到。  
**改法**：

```javascript
let name = "小赵";
function showName() {
  console.log(name);
}
showName();
```

### 例 2：为什么判断总是成立？

```javascript
let pass = 60;
if (pass = 60) {
  console.log("通过");
}
```

**问题**：用了赋值号 `=`。  
**改法**：

```javascript
if (pass === 60) {
  console.log("通过");
}
```

如果你想判断“是否大于等于 60”，就直接写 `pass >= 60`。

### 例 3：为什么页面卡死？

```javascript
let n = 0;
while (n < 3) {
  console.log(n);
}
```

**问题**：`n` 没有递增。  
**改法**：

```javascript
while (n < 3) {
  console.log(n);
  n++;
}
```

### 例 4：为什么循环根本不执行？

```javascript
for (let i = 5; i < 5; i++) {
  console.log(i);
}
```

**问题**：起点和终止条件一样，第一次就不成立。  
**改法**：

```javascript
for (let i = 0; i < 5; i++) {
  console.log(i);
}
```

## 六、新手最稳的学习路线：先写伪代码，再检查边界条件

你想少踩坑，最有效的方法其实很朴素：

### 1. 先写伪代码

先别急着敲 JS，先用中文想清楚：

- 变量从哪来
- 条件什么时候成立
- 循环什么时候结束

### 2. 再翻成代码

把中文逻辑一句一句翻成代码，不要一口气全写完。  
这样你更容易发现：到底是变量没定义，还是条件写错，还是循环漏了更新。

### 3. 最后检查边界条件

重点检查这几个点：

- 变量是否在作用域内
- 条件是不是写成了赋值
- 比较符号是否正确
- 循环有没有出口
- 边界值有没有漏掉

如果你能养成这个习惯，很多 JS 错误其实都能在写出来之前就被你自己拦住。

**先看变量作用域，再看判断条件，再看循环终止条件。**

记住一句话：  
**新手排错，不是拼谁会背，而是拼谁会查。**

# 第7章 JavaScript 事件与 DOM：绑定失效、获取为空、页面没反应

你是不是也遇到过这种情况：代码明明写了，按钮就是没反应；`querySelector` 拿到的是 `null`；页面点来点去，像“装死”一样。别慌，这类问题很常见。老赵先给你一句结论：**先查元素在不在，再查选择器对不对，再查事件绑没绑上，最后查执行时机。**

---

## 一、事件绑定失效：为什么你写了 `addEventListener` 还是没用？

### 1. 常见错误示例

```js
const btn = document.querySelector('.btn');
btn.addEventListener('click', function () {
  alert('点到了');
});
```

如果页面里没有 `.btn`，或者代码执行时按钮还没生成，这段代码就会失效。还有一种情况是：事件名写错，或者绑的不是你真正点击的那个元素。

### 2. 错误原因

- **绑定对象不对**：选到空值，或者选错元素。
- **事件名写错**：比如把 `click` 写成 `clik`。
- **执行时机太早**：DOM 还没出来，代码先跑了。

### 3. 正确写法

```js
document.addEventListener('DOMContentLoaded', function () {
  const btn = document.querySelector('.btn');
  if (btn) {
    btn.addEventListener('click', function () {
      alert('点到了');
    });
  }
});
```

或者把 `<script>` 放到 `body` 最后，先让元素加载出来。

### 4. 老赵式排查步骤

1. `console.log(btn)`，先看有没有拿到元素。
2. 如果是 `null`，回 HTML 找这个元素。
3. 核对选择器有没有写错。
4. 检查事件名有没有拼错。
5. 看脚本是不是执行得太早。

### 5. 避免再次犯错的方法

- 涉及 DOM 操作，尽量先包一层 `DOMContentLoaded`。
- 写完选择器，先对照 HTML 确认。
- 绑定事件前，先确认变量不是空的。
- 养成先打印、再处理的习惯。

---

## 二、DOM 获取为空：为什么 `querySelector` 拿到的是 `null`？

### 1. 典型错误示例

```js
const box = document.querySelector('#box');
box.innerHTML = '你好';
```

如果页面里没有 `id="box"`，这里就会报错，因为 `box` 是 `null`。

### 2. 错误原因

- **选择器写错**：比如页面是 `.box`，你却写成了 `#box`。
- **元素还没加载**：代码跑早了。
- **节点根本不存在**：HTML 里压根没写这个元素。

### 3. 正确写法

```js
const box = document.querySelector('.box');
if (box) {
  box.innerHTML = '你好';
}
```

新手阶段别嫌判空麻烦，它能挡掉很多低级报错。

### 4. 老赵式排查步骤

- 先回 HTML 看元素在不在。
- 再核对 `#` 和 `.` 有没有写对。
- 再看代码是不是执行太早。
- 最后补上空值判断。

### 5. 避免再次犯错的方法

- 看到 `null`，先找 HTML，不要先乱改 JS。
- `querySelector` 写完先 `console.log`。
- 选择器尽量写准确，别凭感觉猜。

---

## 三、点击无反应、输入框没变化：为什么页面像没听见你说话？

### 1. 点击无反应的常见情况

#### 情况一：事件根本没绑上

```js
btn.onclick = function () {
  console.log('clicked');
};
```

如果 `btn` 是空的，这句当然没用。

#### 情况二：绑错了元素
页面上有多个按钮，你点的是 B，结果只给 A 绑了事件。

#### 情况三：被别的层挡住了
这不一定是 JS 问题，也可能是 CSS 把元素盖住了，导致你根本点不到。

### 2. 输入框没变化的常见情况

```js
const input = document.querySelector('input');
input.value = 'abc';
```

如果你想改的是某个特定输入框，却选得太宽泛，或者页面上有多个 `input`，就很容易看起来“没变化”。

### 3. 正确写法

```js
const input = document.querySelector('#username');
if (input) {
  input.value = 'abc';
}
```

选元素时尽量具体一点，别一上来就用太宽的选择器。

### 4. 排查思路

- 先确认是不是点到了正确元素。
- 再确认事件是否真的绑定成功。
- 再看控制台有没有报错。
- 如果还是不对，顺手看看是不是 CSS 挡住了点击。

### 5. 避免再次犯错的方法

- 给关键按钮加一句 `console.log('按钮触发了')`。
- 页面“没反应”时，先确认事件有没有执行。
- 不要只看界面表象，要看控制台。
- 先验证“有没有触发”，再谈“逻辑对不对”。

## 四、`DOMContentLoaded` 到底什么时候用？新手最容易搞混的地方

你是不是也会问：**我到底啥时候该等页面加载完，再去操作 DOM？** 老赵告诉你，只要你要做这些事，就很适合放进 `DOMContentLoaded` 里：

- 获取页面元素
- 绑定点击事件
- 修改文本、样式、输入框值
- 给列表项、按钮、卡片加交互

### 错误示例

```js
const btn = document.querySelector('.btn');
btn.addEventListener('click', fn);
```

如果这段脚本写在 `<head>` 里，元素还没出来，就容易出问题。

### 正确写法

```js
document.addEventListener('DOMContentLoaded', function () {
  const btn = document.querySelector('.btn');
  if (btn) {
    btn.addEventListener('click', fn);
  }
});
```

### 老赵式判断口诀

- **先有 DOM，再操作 DOM**
- **先有元素，再绑事件**
- **先确认页面加载完，再去查询**

如果你不确定脚本放哪儿，初学阶段先用 `DOMContentLoaded`，最稳。

## 五、错误示例、错误原因、正确写法对照

### 示例 1：选择器写错

```js
document.querySelector('#btn').addEventListener('click', fn);
```

**错误原因**：页面实际是 `.btn`，不是 `#btn`。  
**正确写法**：

```js
document.querySelector('.btn').addEventListener('click', fn);
```

---

### 示例 2：执行时机太早

```js
const btn = document.querySelector('.btn');
btn.addEventListener('click', fn);
```

**错误原因**：脚本先执行，元素还没渲染出来。  
**正确写法**：

```js
document.addEventListener('DOMContentLoaded', function () {
  const btn = document.querySelector('.btn');

```

### 示例 3：忘了判空

```js
const title = document.querySelector('.title');
title.innerHTML = '新标题';
```

**错误原因**：`title` 可能是 `null`。  
**正确写法**：

```js
if (title) title.innerHTML = '新标题';
```

# 第8章 JavaScript 数据与类型：类型转换、比较和逻辑判断的坑

## 开篇引入：你是不是也遇到过“看着对，结果就是不对”？

新手学 JavaScript，最容易卡住的地方之一，不是语法，而是**数据类型和运算规则**。

你是不是也遇到过这种情况：

- 输入框里明明填了“18”，结果一加变成了“181”？
- 明明写了 `if (a == 0)`，却发现别的值也能进来？
- 判断“有值没值”时，结果跟你想的不一样？
- 代码没报错，但输出就是怪怪的？

别急，这一章老赵就帮你把这些坑捋顺。你先记住一句话：**JavaScript 很灵活，但也很容易“自动帮你转换”，然后把你带沟里。**

---

## 一、类型转换问题：字符串、数字、布尔值混用，最容易把结果带偏

### 1. 典型错误示例

```javascript
let a = "10";
let b = 5;
console.log(a + b); // "105"
```

你以为是 15，结果是 `"105"`。

再看一个：

```javascript
let isLogin = "false";
if (isLogin) {
  console.log("已登录");
}
```

你以为会进不去，结果它偏偏进去了。

### 2. 错误原因

核心问题是：**类型不统一**。

- `"10"` 是字符串
- `5` 是数字
- `"false"` 也是字符串，不是布尔值 `false`

JavaScript 会做**隐式类型转换**，但规则对新手不友好。尤其是 `+` 号，既可能表示加法，也可能表示字符串拼接。

还有一个常见误区：**你看到的内容，不一定是你以为的类型。**  
输入框、接口返回值、`localStorage` 取出来的数据，很多时候默认都是字符串。

### 3. 正确写法

做数字运算时，先转成数字：

```javascript
let a = Number("10");
let b = 5;
console.log(a + b); // 15
```

做布尔判断时，确保是真正的布尔值：

```javascript
let isLogin = false;
if (isLogin) {
  console.log("已登录");
}
```

不确定类型时，先打印：

```javascript
console.log(typeof a);
```

### 4. 老赵式排查步骤

- 先 `console.log(变量)` 看值
- 再 `console.log(typeof 变量)` 看类型
- 检查有没有把字符串和数字混着用
- 看是不是被 `+` 号带偏，变成拼接了

### 5. 避免再次犯错的方法

- 读输入框、接口、表单值时，先想清楚类型
- 只要参与计算，就先转数字
- 只要参与判断，就先确认是不是布尔值
- 不确定时先打印，别靠猜

---

## 二、宽松比较和严格比较：`==` 和 `===` 到底怎么选？

### 1. 典型错误示例

```javascript
console.log(1 == "1");   // true
console.log(1 === "1");  // false
```

很多新手会懵：明明不一样，为什么还能相等？

再看一组对比：

```javascript
console.log(false == 0); // true
console.log(false === 0); // false
console.log("" == 0);     // true
console.log("" === 0);    // false
```

### 2. 错误原因

`==` 是**宽松比较**，会先做类型转换；  
`===` 是**严格比较**，类型和值都必须一致。

问题就在于，`==` 太“热心”了，常常让你误判。

### 3. 正确写法

新手阶段，老赵建议你：**默认用 `===`，默认用 `!==`。**

```javascript
if (age === 18) {
  console.log("成年");
}
```

如果确实需要比较转换后的值，先手动转换，不要把责任交给 `==`。

### 4. 老赵式排查步骤

- 先看是不是用了 `==`
- 再看左右两边类型是否一致
- 再判断是不是自动转换导致结果异常
- 条件怪怪的，就把两边都打印出来

### 5. 避免再次犯错的方法

- 新手少用 `==`，优先用 `===`
- 只有非常清楚转换规则时，才考虑宽松比较
- 比较前先问自己：左右两边类型一样吗？

---

## 三、输入框取值、数字计算、拼接字符串：最容易踩的三连坑

### 1. 输入框取值为什么总是“字符串”？

```javascript
let val = document.querySelector("#age").value;
console.log(val + 1);
```

哪怕你输入的是 `18`，`value` 拿到的也是字符串 `"18"`，所以结果可能变成 `"181"`。

### 2. 错误原因

很多新手以为“输入的是数字，拿出来也应该是数字”。  
但表单输入拿到的值通常都是**字符串**。

### 3. 正确写法

```javascript
let val = Number(document.querySelector("#age").value);
console.log(val + 1); // 19
```

如果要更明确地处理整数：

```javascript
let val = parseInt(document.querySelector("#age").value, 10);
```

### 4. 拼接字符串的误区

```javascript
let score = 90;
console.log("你的分数是：" + score + 10); // "你的分数是：9010"
```

因为一旦前面出现字符串，后面很容易一路变成拼接。

如果想做加法，先算完再拼接：

```javascript
console.log("你的分数是：" + (score + 10)); // "你的分数是：100"
```

### 5. 老赵式排查步骤

- 看数据是不是从输入框拿来的
- 看有没有 `.value`
- 看 `+` 号两边是不是字符串
- 复杂表达式先拆开写，别一行塞太满

### 6. 避免再次犯错的方法

- 表单值默认当字符串处理
- 计算前先转数字
- 拼接前先算清楚，别让 `+` 同时干两件事
- 复杂表达式拆开写，更容易查错

---

## 四、判断逻辑为什么总不按预期走？

### 1. 典型错误示例

```javascript
let count = "0";
if (count) {
  console.log("有值");
}
```

很多人会想：`0` 不就是没值吗？  
但这里的 `"0"` 是字符串，它是**真值**，所以条件成立。

再看一个常见误区：

```javascript
let num = 0;
if (num) {
  console.log("有值");
}
```

这里反而不会进，因为数字 `0` 是假值。

### 2. 错误原因

JavaScript 里有“真值”和“假值”的概念。常见假值有：

- `false`
- `0`
- `""`
- `null`
- `undefined`
- `NaN`

但注意：**字符串 `"0"` 不是数字 `0`**，它不是假值。

所以你如果想判断“有没有输入内容”，和“数值是不是 0”，其实是两回事。

### 3. 正确写法

判断“数字是否为 0”：

```javascript
let count = Number(input.value);
if (count === 0) {
  console.log("数量为 0");
}
```

判断“有没有输入内容”：

```javascript
if (input.value.trim() !== "") {
  console.log("有输入");
}
```

### 4. 老赵式排查步骤

- 先看变量类型
- 再确认你是在判断“值存在”还是“数值比较”
- 如果条件总是成立，把条件单独打印出来看

### 5. 避免再次犯错的方法

- 判断前先问自己：我到底在判断什么？
- 不要混着用字符串判断和数字判断
- `0`、`"0"`、`""` 这三个一定分清
- 条件判断别图省事，越模糊越容易错

## 五、老赵式通用排错法：先看类型，再看运算符，再看输出

这一类问题，老赵建议你固定三步走。

### 第一步：先看数据类型

```javascript
console.log(typeof a);
console.log(typeof b);
```

先别急着改代码，先确认它们到底是什么。很多“看着像数字”的值，其实是字符串。

### 第二步：再看运算符

重点盯这些：

- `+`
- `==`
- `===`
- `&&`
- `||`

很多坑都出在这里。尤其是 `+`，它最爱一会儿当加法，一会儿当拼接。

### 第三步：再看输出结果

不要只看“结果不对”，要看：

- 是不是字符串拼接了
- 是不是比较规则变了
- 是不是逻辑判断走偏了
- 是不是某个变量根本没转类型

### 老赵提醒

排错时别一上来就猜。  
**先打印，先验证，再修改。**  
很多问题不是代码太难，而是你没看清变量的真实面目。

# 第9章 老赵式通用排错方法：从现象到原因再到验证

你是不是也遇到过这种情况：代码明明改了，页面却没反应；控制台一片红，心里发慌；或者你一急，连续改了好几个地方，结果问题更乱了？  
别慌，这一章老赵不讲虚的，就给你一套**通用排错流程**。以后不管是 HTML、CSS 还是 JavaScript 出问题，你都能按这个顺序查，不用靠猜。后面各章的坑，基本都能套进去。

---

## 一、先看现象：问题到底表现在哪一层？

排错第一步，不是急着改代码，而是**先看问题表现在哪**。新手最容易犯的错，就是“看见不显示，就以为一定是 JS 坏了”。其实问题可能在 HTML、CSS，甚至路径。

你先问自己四个问题：

- 页面是**完全不显示**？
- 还是**显示了，但位置、样式、内容不对**？
- 控制台有没有红色报错？
- 网络资源有没有加载成功？

### 1）页面现象：是“没了”，还是“变样了”？

比如：

```html
<div class="box">hello</div>
```

你发现页面上根本没有 `.box`。这时候别先怪 JavaScript，先看是不是：

- 标签没闭合
- 被 CSS 设成了 `display: none`
- 父元素布局把它挤没了
- 路径错了，页面根本没加载到这段代码

如果是“显示了但不对”，就重点看颜色、大小、位置是不是被别的规则改了。很多问题不是“坏了”，而是“被覆盖了”。

### 2）控制台现象：有没有红色报错？

控制台是新手最该养成习惯看的地方。  
如果页面不工作，先打开控制台，看有没有：

- `Uncaught TypeError`
- `Cannot read properties of null`
- 语法错误
- 路径加载失败提示

**老赵提醒你：**只要有红色报错，先别乱改别的，优先看报错里的文件名、行号、对象名。很多时候，答案已经写在报错里了。

### 3）网络现象：资源有没有加载成功？

如果图片、CSS、JS、接口数据不出来，去看网络面板：

- 文件是不是 404
- 图片路径是不是写错了
- JS 有没有真正加载
- 接口请求有没有失败

比如：

```html
<img src="images/logo.png">
```

结果图片不显示，常见原因不是标签错，而是路径写成了 `image/`、`imgs/` 之类。还有一种坑：文件名大小写不一致，本地看着没事，换环境就炸。

### 4）交互现象：点击、输入、切换有没有响应？

如果按钮点了没反应，先别急着怀疑逻辑：

- 事件有没有绑上
- 元素是不是动态生成的
- 代码是不是根本没执行到
- DOM 获取是不是空了

很多“没反应”，其实不是逻辑错，而是根本没找到那个元素。

---

## 二、再定位层级：先分 HTML、CSS、JS，不要上来就全局乱查

很多问题查不出来，是因为你一上来就“全局乱查”。老赵建议你按层拆：先判断问题在哪一层，再往下挖。

### 1）先判断是 HTML、CSS 还是 JS

你可以这样想：

- **HTML 问题**：结构、标签、路径、内容是否正确
- **CSS 问题**：样式有没有生效、被谁覆盖了、布局是否异常
- **JS 问题**：逻辑有没有执行、变量有没有拿错、事件有没有绑定成功

举个例子：一个按钮看不见。

- HTML 里根本没有这个按钮，是结构问题。
- HTML 有，但被 CSS 隐藏了，是样式问题。
- 页面渲染后被 JS 改没了，是脚本问题。

### 2）按“最小单位”排查

你可以按这个顺序查：

1. HTML 里有没有这个元素？
2. CSS 有没有把它隐藏？
3. JS 有没有在渲染后又改掉它？
4. 控制台有没有报错？
5. 路径有没有问题？

这个顺序很重要，因为它是从最基础、最容易确认的地方开始查。别一上来就怀疑最复杂的逻辑。

### 3）先别乱改代码

老赵特别提醒你一句：**先别乱改代码。**  
新手最爱一边改 HTML，一边改 CSS，再顺手改 JS。结果本来只要修一个地方，最后完全不知道到底哪一步起作用了。

正确做法是：一次只改一个点，改完马上验证。这样你才知道“到底是谁导致了变化”。

---

## 三、验证假设：每次只改一个点，别一次乱改一堆

排错不是凭感觉装修，而是像侦探一样验证。

### 错误示例

你发现按钮没反应，于是同时改了：

- class 名
- HTML 结构
- 事件绑定方式
- CSS 样式

最后按钮好了，但你完全不知道到底是哪个修改起作用的。下次再坏，还是不会查。

### 正确写法

应该这样做：

1. 先确认按钮元素是否存在
2. 再确认事件有没有绑定成功
3. 再确认回调函数有没有执行
4. 最后确认执行后的结果是否符合预期

### 老赵式排查步骤

- 在关键位置加一句 `console.log("到了这里")`
- 每次只改一个地方
- 改完立刻刷新验证
- 如果问题消失，回头确认到底是哪一改生效了

### 避免再次犯错的方法

养成一个习惯：**改代码前先想清楚“我这次只验证什么”**。  
如果你这次想确认事件有没有绑上，就别顺手改样式；如果你想确认路径对不对，就别同时改逻辑。这样才不会把问题越改越大。

---

## 四、调试工具入门：控制台、元素面板、网络面板怎么用？

新手不需要一下子学会所有 DevTools 功能，先会这三个就够了。

### 1）控制台：看报错、打日志

控制台主要做两件事：

- 看报错
- 看 `console.log`

例如：

```js
console.log("按钮点击了");
```

如果你点了按钮却看不到这句话，说明代码没执行到。那你就继续往前查：是不是事件没绑上？是不是选择器选错了？是不是 JS 文件根本没加载？

### 2）元素面板：看结构和样式

元素面板特别适合查这些问题：

- 标签闭合错了没有
- 嵌套是不是乱了
- 样式到底有没有生效
- 被哪个样式覆盖了

比如你写了：

```css
.box { color: red; }
```

但页面还是黑色，就去元素面板看这个样式是不是被别的选择器覆盖了。很多“样式不生效”，不是没写，而是优先级不够。

### 3）网络面板：看文件和接口

网络面板适合查：

- CSS、JS、图片是不是加载失败
- 接口是不是返回 404、500
- 请求有没有发出去

**老赵提示：**如果你改了代码没效果，先看是不是浏览器缓存、文件路径错误、资源没加载成功。尤其是 JS 和 CSS，没加载就是没执行，页面当然没变化。

---

## 五、记录错误：把踩过的坑记下来，形成自己的错误清单

很多新手的问题，不是不会，而是同一个坑反复掉。  
所以你要学会记录错误。

### 你可以这样记

每次出错时，写下这四项：

- 现象：页面发生了什么
- 原因：最后查出来是什么
- 解决：你怎么修好的
- 提醒：下次怎么避免

比如：

- 现象：按钮点击没反应
- 原因：`querySelector` 选不到元素
- 解决：把选择器改成正确 class
- 提醒：先确认 DOM 存在再绑定事件

再比如：

- 现象：图片不显示
- 原因：`src` 路径写错
- 解决：改成正确相对路径
- 提醒：先检查文件名和层级，再检查后缀

### 为什么这招特别管用？

因为以后你再遇到类似问题，不用重新猜。  
你自己的“错误清单”，比任何系统教材都更适合你。它不是抄笔记，而是帮你建立“问题—原因—解决”的反射。

这章不是只给你一个“通用说法”，而是给你一个以后每次都能复用的查错模板。你后面遇到具体问题时，可以直接按这个顺序走：

- **HTML 出错**：先看标签闭合、嵌套、路径，再看页面结构和加载结果

你不用每次都重学一遍，直接套这个框架就行。  
说白了，排错的核心不是“记住所有答案”，而是“知道先查什么、后查什么”。

## 七、避免再次犯错：建立“先判断、后修改、再验证”的习惯

这才是通用排错方法真正要你养成的能力。

### 1）先判断

先判断问题属于哪一层：

- HTML
- CSS
- JavaScript
- 路径
- 浏览器环境

别急着动手，先把方向弄清楚。方向错了，越修越远。

### 2）后修改

别一口气改太多。  
每次只改一个点，方便验证。  
你只要记住一句话：**改得越少，越容易知道真相。**

### 3）再验证

改完就看结果：

- 页面有没有变化
- 控制台有没有新报错
- 网络请求有没有正常
- 交互有没有恢复

如果没变，就继续查下一层；如果变了，就说明你找对方向了。

### 老赵给你的最终口诀

你可以记成一句话：

**先看现象，后分层；先缩小范围，再验证；先改一个点，最后复盘。**

## 一、HTML 纠错练习：标签、路径、属性问题快速判断

### 题 1：标签闭合与嵌套错误

**错误示例：**
```html
<div>
  <p>欢迎来到前端学习
  <span>一起进步</p>
</div>
```

你是不是也见过这种写法？看着缩进挺像那么回事，但其实标签已经乱套了。

**错误原因：**  
`p` 和 `span` 的闭合顺序不对。HTML 标签要**先开后关、后开先关**，不能交叉嵌套。浏览器有时会“帮你修”，但页面结构可能已经变形，后面的样式和布局也会跟着出问题。

**正确写法：**
```html
<div>
  <p>欢迎来到前端学习 <span>一起进步</span></p>
</div>
```

**老赵式排查步骤：**
1. 先看标签有没有都闭合。
2. 再看嵌套顺序对不对，尤其是 `div`、`p`、`span`。
3. 页面显示怪，先别怀疑 CSS，先查 HTML 结构。
4. 用编辑器自动格式化，层级乱没乱一眼就知道。

**避免再次犯错的方法：**
- 写完一小段就检查闭合。
- 养成缩进对齐的习惯。
- 复杂结构先分块写，不要一口气堆完。

---

### 题 2：路径写错，图片不显示

**错误示例：**
```html
<img src="images/banner.jpg" alt="banner">
```
但图片就是不出来。

**错误原因：**  
可能是路径写错、文件夹名拼错、文件名大小写不一致，或者实际位置不对。新手最容易把相对路径想当然。比如文件叫 `Banner.jpg`，你写成 `banner.jpg`，本地可能没事，换环境就挂。

**正确写法：**
```html
<img src="./images/banner.jpg" alt="banner">
```

**老赵式排查步骤：**
1. 先确认图片文件真的存在。
2. 再确认路径和文件名是否完全一致。
3. 看看是不是少了 `./`、`../`，目录层级有没有搞错。
4. 打开开发者工具看是不是 404。
5. 直接把图片地址复制到浏览器里试一下，最直观。

**避免再次犯错的方法：**
- 文件名、文件夹名尽量统一用小写。
- 改资源路径后全局检查。
- 分清当前目录和上一级目录，别凭感觉写。

## 二、CSS 纠错练习：样式不生效、优先级、盒模型、定位问题综合判断

### 题 3：样式不生效，到底为啥？

**错误示例：**
```css
.title {
  color: red;
}
```
```html
<h1 class="titel">标题</h1>
```

**错误原因：**  
类名拼错了。CSS 里写的是 `.title`，HTML 里写成了 `titel`，当然匹配不上。浏览器只认精确匹配，差一个字母都不行。

**正确写法：**
```html
<h1 class="title">标题</h1>
```

**老赵式排查步骤：**
1. 先看 HTML 和 CSS 的选择器名字是不是一致。
2. 再看 CSS 文件有没有正确引入。
3. 用浏览器检查元素，看样式有没有命中。
4. 如果样式被划掉，说明不是没写，而是被覆盖了。

**避免再次犯错的方法：**
- 类名命名统一规范。
- 用开发者工具确认选择器是否命中。
- 先排查写没写对，再排查有没有被覆盖。

---

### 题 4：选择器优先级混乱

**错误示例：**
```css
p {
  color: blue;
}
.text {
  color: green;
}
#main p {
  color: red;
}
```
```html
<div id="main">
  <p class="text">你好</p>
</div>
```

你是不是也遇到过：明明写了样式，但显示的却是别的颜色？

**错误原因：**  
这是**优先级**在起作用。`#main p` 比 `.text` 和 `p` 更具体，所以最后生效的是红色。很多新手一着急就加 `!important`，结果问题没解决，代码还更乱。

**正确写法：**
```css
#main .text {
  color: red;
}
```
或者只保留一条明确规则，别让多个选择器互相打架。

**老赵式排查步骤：**
1. 看元素命中了哪些规则。
2. 看哪条规则被划掉。
3. 判断是选择器更具体，还是后写的规则覆盖了前面的。
4. 别一上来就乱加 `!important`。

**避免再次犯错的方法：**
- 选择器写得简洁明确。
- 少用层层嵌套。
- 先理解“谁更具体谁优先”。

---

### 题 5：盒模型理解错误，宽度怎么超了？

**错误示例：**
```css
.box {
  width: 200px;
  padding: 20px;
  border: 10px solid #333;
}
```

**错误原因：**  
你可能以为 `width: 200px` 是最终总宽度，其实默认盒模型下，内容宽度、内边距、边框会继续往外加，最后整体比 200px 大，布局就被撑开了。

**正确写法：**
```css
.box {
  width: 200px;
  padding: 20px;
  border: 10px solid #333;
  box-sizing: border-box;
}
```

**老赵式排查步骤：**
1. 先确认是不是盒模型问题。
2. 看元素实际占用的总宽度，不要只盯着 `width`。
3. 检查有没有设置 `box-sizing: border-box;`。
4. 布局总超宽，优先怀疑盒模型。

**避免再次犯错的方法：**
- 做布局时优先习惯 `border-box`。
- 不要只看 `width`，要看总占位。
- 用浏览器检查盒模型区域，养成看总宽度的习惯。

---

### 题 6：元素不显示、定位异常

**错误示例：**
```css
.box {
  display: none;
  position: absolute;
  top: 20px;
  left: 20px;
}
```

**错误原因：**  
元素已经 `display: none`，直接“隐身”了，后面的定位再写也没用。还有一种常见情况是：父元素没设相对定位，子元素 `absolute` 后乱跑，看起来像“定位失效”。

**正确写法：**
```css
.parent {
  position: relative;
}
.box {
  display: block;
  position: absolute;
  top: 20px;
  left: 20px;
}
```

**老赵式排查步骤：**
1. 先看是不是被隐藏了：`display: none`、`visibility: hidden`、`opacity: 0`。
2. 再看定位依赖的父元素有没有设置参考定位。
3. 检查 `top/right/bottom/left` 是否写错。
4. 看元素是不是跑到视野外了。
5. 实在找不到，给元素加个边框，先确认它到底存不存在。

**避免再次犯错的方法：**
- 隐藏和定位问题分开排查。
- 绝对定位前先确认参考系。
- 不确定时先给元素加边框，看它到底在哪。

---

## 三、JavaScript 纠错练习：变量、判断、循环、事件、DOM、类型问题综合判断

### 题 7：变量作用域误解

**错误示例：**
```javascript
if (true) {
  let msg = '你好';
}
console.log(msg);
```

**错误原因：**  
`let` 是块级作用域，`if` 里面定义的变量，外面拿不到。很多新手会觉得“我明明定义了啊”，其实是作用域范围不对。

**正确写法：**
```javascript
let msg;
if (true) {
  msg = '你好';
}
console.log(msg);
```

**老赵式排查步骤：**
1. 看变量是不是定义在当前作用域里。
2. 看是不是 `let` / `const` 的块级作用域问题。
3. 报错“未定义”时先查作用域，不要先怀疑浏览器。
4. 变量尽量就近使用，但别放错地方。

**避免再次犯错的方法：**
- 先画清楚变量在哪一层定义。
- 少把变量写在临时块里却想外面用。
- 理解“能访问到”比“写出来了”更重要。

---

### 题 8：条件判断写错

**错误示例：**
```javascript
let age = 18;
if (age = 20) {
  console.log('成年');
}
```

**错误原因：**  
这里把 `=` 写成了赋值，不是比较。结果不是判断，而是把 `age` 改成了 20。这个错误很隐蔽，代码不一定立刻报错，但逻辑已经错了。

**正确写法：**
```javascript
if (age === 20) {
  console.log('成年');
}
```

**老赵式排查步骤：**
1. 先看是赋值还是比较。
2. 判断语句里优先检查 `=`、`==`、`===`。
3. 逻辑不对时，先打印变量值看看是不是被改了。
4. 写完判断句后读一遍。

**避免再次犯错的方法：**
- 条件判断尽量用 `===`。
- 看见 `if` 先检查等号数量。
- 写完后把整句念出来，很多错误会立刻暴露。

---

### 题 9：循环死循环

**错误示例：**
```javascript
let i = 0;
while (i < 5) {
  console.log(i);
}
```

**错误原因：**  
`i` 没有自增，条件永远成立，程序就一直转下去，页面甚至会卡死。

**正确写法：**
```javascript
let i = 0;
while (i < 5) {
  console.log(i);
  i++;
}
```

**老赵式排查步骤：**
1. 看循环条件会不会变化。
2. 看循环体里有没有更新计数器。
3. 一旦页面卡住，优先怀疑死循环。
4. 先在纸上模拟几次，再跑代码。

**避免再次犯错的方法：**
- 每次写循环都问自己：退出条件靠什么触发？
- 先写小循环测试。
- 不确定时用 `for` 代替 `while`，更直观。

### 题 10：事件绑定失效、DOM 获取为空、类型转换问题

**错误示例：**
```javascript
const btn = document.querySelector('.btn');
btn.addEventListener('click', function () {
  alert('点击了');
});

const num = '10';
console.log(num + 1);
```

**错误原因：**  
如果页面里根本没有 `.btn`，`btn` 就是 `null`，事件当然绑不上。`'10' + 1` 也不是数学加法，而是字符串拼接。这里一个是 DOM 没拿到，一个是类型没转对，都是新手高频坑。

**正确写法：**
```javascript
const btn = document.querySelector('.btn');
if (btn) {
  btn.addEventListener('click', function () {
    alert('点击了');
  });
}

const num = Number('10');
console.log(num + 1);
```

**老赵式排查步骤：**
1. 先确认 DOM 元素有没有真的选到。
2. 打印 `btn` 看是不是 `null`。
3. 看代码执行时机是不是太早了，元素还没渲染出来。
4. 涉及数字运算时，先确认类型是不是字符串。
5. 遇到 `+`，先想清楚是拼接还是相加。

**避免再次犯错的方法：**
- 绑定事件前先判断元素是否存在。
- 脚本放底部，或者等 DOM 加载完成再执行。
- 遇到 `+`，先判断它是“拼接”还是“相加”。

## 四、老赵式做题思路：先别急着改，先说出错在哪

做纠错题，最怕两种人：一种是上来就乱改，改半天没结果；另一种是只会说“就是不对”，但说不出为什么不对。

老赵建议你用这个顺序：

1. **先定位类型**：这是 HTML、CSS 还是 JavaScript 的问题？  
2. **再看现象**：是显示不出来、样式没生效，还是逻辑不执行？  
3. **再找最可疑点**：路径、类名、优先级、作用域、类型转换。  
4. **最后再动手改**：一次只改一个点，别同时改一堆。  
5. **改完再验证**：代码改了不算，跑一下才算数。

这个顺序特别适合新手，因为你现在最缺的不是会背，而是会查。你每次做题，都尽量先说出“这题像哪种坑”，再开始动手。

## 五、练习题复盘清单：做完就按这个模板总结

你做完一题，别只记答案，最好顺手写下这 5 句：

- 这题错在 **哪一类**？
- 表面现象是 **什么**？
- 我是怎么找到错的？
- 正确写法是什么？
- 下次怎么避免再犯？

比如你今天做的是图片不显示，那就记成：**路径写错 + 文件名不一致 + 先查资源地址再看页面**。  
如果是按钮点不动，那就记成：**DOM 获取为空 + 元素还没渲染 + 先判断是否存在再绑定事件**。

你会发现，题做多了之后，真正拉开差距的不是谁会背，而是谁能把错误归类、把经验复用。

## 六、新手学习路线建议：把“会做题”变成“会排错”

如果你现在还在基础阶段，老赵建议你按这个顺序练：

1. **先练 HTML**：标签闭合、嵌套、路径、属性别写错。  
2. **再练 CSS**：样式不生效、优先级、盒模型、定位、元素显示问题。  
3. **最后练 JS**：作用域、判断、循环、事件、DOM、类型转换。  
4. **每做一题都复盘**：把坑记成标签，比如“路径”“优先级”“作用域”。  
5. **不要只看答案**：一定要自己说出错因和排查步骤。

你不用一口气变成高手，你只要比昨天少踩一个坑，就已经在进步了。

这一章你要记住的不是某一个答案，而是一种习惯：**先识别错误类型，再按步骤排查，最后总结成自己的坑位清单**。  
HTML 先看标签、路径、属性；CSS 先看选择器、盒模型、定位；JavaScript 先看作用域、判断、循环、事件、DOM 和类型。

# 第11章 新手学习路线建议：少踩坑、少回头、学得更稳

你是不是也有这种感觉：HTML 刚看懂一点，CSS 又卡住了；好不容易开始写 JS，又被报错和空值狠狠干一把。很多新手不是学不会，而是**顺序乱了、目标大了、复盘少了**。这一章老赵不讲大道理，就讲：怎么学得更稳，怎么少走回头路，怎么把书用成工具。

## 一、HTML、CSS、JavaScript 的基础学习顺序怎么安排更合理？

最稳的顺序，老赵建议你按这个来：

### 1. 先学 HTML：先把“骨架”搭明白
先别急着搞炫酷页面，先把常用标签、表单、图片、链接、列表弄熟。重点不是背标签，而是先盯住这几件事：

- 标签有没有闭合
- 嵌套是不是乱了
- 图片、CSS、JS 路径有没有写对

**为什么先学它？**  
因为 HTML 是页面基础，后面的 CSS 和 JS 都围着它转。页面结构没搭稳，后面样式再漂亮、交互再复杂，也容易一改就崩。

### 2. 再学 CSS：把“长相”和布局搞清楚
学 CSS 时，先别一上来就钻高级技巧。先把这些学扎实：

- 选择器怎么写
- 样式为什么不生效
- 盒模型是什么
- 定位和布局怎么影响元素位置

你是不是也遇到过：明明写了 `color: red;`，页面就是不变色？或者元素明明在代码里，屏幕上却像“人间蒸发”？这类问题先别怪浏览器，先回头看选择器、层级和盒模型。

### 3. 最后学 JavaScript：让页面“动起来”
JS 别急着猛冲语法大全，先把最常用的掌握住：

- 变量
- 条件判断
- 循环
- 函数
- DOM 获取和事件绑定
- 基本类型转换

这个顺序的好处很简单：**先能看懂页面，再让页面变好看，最后再让页面动起来。**  
这样学，不容易乱，也更容易定位问题。

## 二、为什么新手不要一开始就追求大而全？

你是不是也想过：我要一次性把 HTML、CSS、JS、Vue、React 全学会？  
老赵劝你一句：**别急，真的别急。**

### 常见误区
新手最容易犯的错就是：

- 今天看一点 HTML
- 明天跳去 CSS 布局
- 后天又跑去学 JavaScript 框架
- 结果每一块都只认识一点点，遇到问题还是不会查

这样学的结果，往往是“看过很多，能写很少”。

### 正确思路
基础阶段最重要的不是“学得多”，而是“学得稳”。  
你只要先把下面这些解决掉，就已经领先很多人了：

- HTML 能搭页面
- CSS 能让页面正常显示
- JS 能处理基本交互
- 遇到报错知道从哪里下手

**记住：先会用，再补原理。**  
比如你先知道 `display: none` 会隐藏元素，再慢慢理解它为什么会影响布局；先知道 `==` 和 `===` 不一样，再去研究它们的区别。别一开始就钻太深，容易把自己绕晕。

## 三、如何边学边查：把错误当成知识入口，而不是失败？

你写代码出错，很正常。新手最怕的不是错，而是**错了不知道从哪看**。

### 你可以这样做
遇到问题时，别先怀疑自己笨，先按这个顺序查：

1. 看报错信息，先找关键词  
2. 判断是 HTML、CSS 还是 JS 的问题  
3. 注释掉一部分代码，确认出错范围  
4. 去查对应知识点，比如“样式不生效”“DOM 获取为空”“变量作用域”  
5. 修完后记录下来，下次直接翻笔记

### 举个例子
比如按钮点了没反应，先别急着改十遍代码。你先看：

- 按钮元素有没有真正渲染出来
- 事件绑定写在了哪里
- `document.querySelector` 有没有拿到空值
- 控制台有没有报错

很多时候不是逻辑错得多离谱，而是某一个小环节没接上。

### 老赵式提醒
错误不是失败，错误是入口。  
你每次卡住一次，实际上都是在帮你定位一个知识盲区。关键是别硬扛，先定位，再修正。

## 四、如何整理自己的高频错误清单和复盘笔记？

别小看这个动作，它特别管用。

### 你可以建一个“高频错误本”
每次出错，记录四项就够了：

- **问题表现**：页面哪里不对、报什么错
- **错误原因**：路径错、选择器优先级错，还是变量作用域错
- **正确写法**：把修正后的代码贴上去
- **下次提醒**：一句话总结，比如“先看控制台，再看 DOM 是否为空”

### 示例
比如你总是把按钮事件绑失效，那就记：

- 问题：点击没反应
- 原因：DOM 还没渲染就绑定了事件
- 正确写法：先获取元素，确认元素存在后再绑定
- 提醒：先查元素是否获取成功

再比如 CSS 样式总是不生效，也可以记成：

- 问题：文字颜色没变
- 原因：选择器写错，或者被更高优先级覆盖
- 正确写法：检查选择器和优先级
- 提醒：先看是否命中元素，再看是否被覆盖

这样记几次，你会发现很多坑其实是重复的。

## 五、给自己一张“写代码前先检查”的清单

新手最怕“这个错我上次也犯过”。想避免这种情况，最有效的方法不是靠记性，而是靠清单。你以后遇到问题，先回到对应章节查一遍，再对着清单排。

### HTML 自查
- 标签有没有闭合
- 嵌套顺序对不对
- 路径有没有写错

### CSS 自查
- 样式有没有写到正确元素上
- 选择器优先级是否冲突
- 盒模型有没有影响尺寸
- 元素是不是被隐藏了
- 定位是否写乱了

### JS 自查
- 变量作用域对不对
- 条件判断有没有写反
- 循环会不会死循环
- 事件绑定对象是不是存在
- DOM 获取是不是为空
- 类型转换有没有遗漏

### 老赵式小习惯
你可以给自己加一个“提交前检查”动作：  
写完一小段代码，先别急着往下堆，先跑一遍页面，打开控制台，看有没有报错，再继续写。  
这样做不是慢，反而是快。因为你越早发现问题，改起来越省事。
