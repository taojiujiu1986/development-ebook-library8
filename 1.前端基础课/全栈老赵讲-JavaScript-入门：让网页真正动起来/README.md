# 第1章 第1章：先认识 JavaScript——它到底能让网页做什么

## 开篇引入：网页为什么会“动”？

你打开很多网页时，会发现它们像“静态海报”：能看、能读，但一点击没反应，输错了内容也没人提醒。  
JavaScript 的作用，就是给网页装上“神经”和“手脚”，让它能听懂你的操作，并马上回应。

比如：

- 点一下按钮，弹出提示框；
- 输入框里输错内容，立刻提醒；
- 点击“展开”，隐藏内容马上出现；
- 切换菜单，局部内容跟着变化。

这些功能看似简单，却是网页从“能看”走向“能用”的关键一步。  
**HTML 负责结构，CSS 负责外观，JavaScript 负责互动。**

如果把网页比作一间房子：

- **HTML** 是骨架和家具；
- **CSS** 是装修和配色；
- **JavaScript** 就是电路、开关和智能设备，让房子真正“活起来”。

---

## JavaScript 到底能做什么？

先记住最常见的几种能力就够了：

1. **提示用户**：弹窗、提醒、消息提示。  
2. **响应点击**：按钮点一下，页面立刻反应。  
3. **读取输入**：拿到输入框里的内容。  
4. **检查数据**：判断用户名、密码有没有填对。  
5. **修改页面内容**：让文字变化，或者显示、隐藏某个区域。  

### 小案例：点按钮弹一句话

一个网页上有个按钮，点击后弹出“你好，JavaScript！”。

这个例子说明了最基础的网页思维：  
**先有页面元素，再让 JavaScript 盯住它，最后在用户操作时做出反应。**

**老赵提醒：**  
JavaScript 最常见的本领，不是写“大而全”的系统，而是先把这些小交互做好。别小看它们，网页好不好用，往往就看这些细节。

## JavaScript 和 HTML、CSS 是什么关系？

很多新手容易把三者混在一起，其实它们分工很清楚。

### 1. HTML：负责“有什么”
HTML 像说明书，告诉浏览器页面里有哪些东西：标题、段落、输入框、按钮。

### 2. CSS：负责“长什么样”
CSS 像化妆和穿衣服，负责颜色、大小、间距、布局。

### 3. JavaScript：负责“怎么动”
JavaScript 像按钮和开关，负责交互、判断、变化。

你可以把它们理解成一组搭档：  
**HTML 搭台，CSS 打扮，JavaScript 演戏。**

### 小案例预览

一个“点我一下”的按钮：

- HTML 先把按钮摆出来；
- CSS 让按钮更好看；
- JavaScript 让按钮点击后弹出一句话。

所以，用户感觉“网页在回应我”，通常靠的就是 JavaScript。

**老赵提醒：**  
这三样不是互相替代，而是各干各的活。新手先学会它们怎么配合，比纠结“谁最重要”更有用。

## 本书会怎么带你学？

别担心，我们不会一上来就丢一堆看不懂的代码。  
这本书会按“从能看懂，到能写出，再到能做交互”的顺序来学。

你可以把学习路线想成爬楼梯：

### 第一步：认识基础语法
先学会变量、字符串、数字、布尔值、运算符这些最常见的东西。  
这是你和 JavaScript 打招呼的方式。

### 第二步：学会做判断和重复执行
接着学习 `if/else`、`switch`、`for`、`while`。  
这部分像是给程序装上“如果……就……”和“重复做”的思维。

### 第三步：学会封装成函数
函数就像把常用动作打包成一个按钮，哪里需要哪里调用。

### 第四步：接触数组、对象、DOM 和事件
这一步开始，你就能真正碰到网页了。  
比如获取按钮、读取输入框、点击后改内容，这些都离不开它们。

### 第五步：做简单交互和表单校验
比如检查用户名有没有填、密码够不够长、点击按钮后显示提示。

**老赵提醒：**  
学编程像学做饭，不是先学满汉全席，而是先会洗菜、切菜、开火。一步一步来，反而更稳。

## 新手常见误区：JavaScript 真的那么难吗？

很多初学者一看到代码就紧张，觉得“这东西只有大神才会”。  
其实，刚开始学 JavaScript，最重要的不是记住所有知识点，而是建立一种感觉：

- 代码不是天书，它只是按顺序执行的命令；
- 每一段代码都在解决一个小问题；
- 先会写简单脚本，再慢慢变复杂。

还有一个误区是：**一定要一开始就学很深的内容**。  
其实完全没必要。你先把基础语法、判断、循环、函数、事件搞明白，就已经能做很多小项目了。

你可以把编程想成搭积木：

- 先认识基础形状；
- 再学怎么拼成小房子；
- 最后才是城堡。

只要愿意动手，JavaScript 并没有想象中那么吓人，它更像一门“越练越顺”的手艺。

## 一个最简单的网页交互小案例预览

先看一个非常小的例子：点击按钮后弹出提示。

```html
<button id="btn">点我一下</button>

<script>
  const btn = document.getElementById('btn');

  btn.addEventListener('click', function () {
    alert('你好，JavaScript！');
  });
</script>
```

这里发生了三件事：

1. 页面上先有一个按钮；
2. JavaScript 找到这个按钮；
3. 给按钮绑定“点击事件”，一点击就弹出提示。

你现在不用急着完全记住，只要先理解：  
**JavaScript 可以监听用户动作，并让网页做出回应。**

这就是“网页动起来”的起点。以后你会学到更多类似的能力，比如读取输入框内容、判断用户是否填写、显示隐藏元素等，今天这一步就是打基础。

# 第2章 第2章：把 JavaScript 放进网页里——三种引入方式入门

上一章我们认识了 JavaScript 是什么，这一章就开始真正“点火”。

你可以把 HTML 想成房子的框架，CSS 想成外观装修，JavaScript 则像电路、开关和遥控器：**没有它，网页很多地方只能看，不能动**。本章要做的事很明确——把 JS 放进网页里、跑起来、看到结果。对新手来说，最重要的不是一上来写多复杂，而是先建立一个感觉：**“我写的代码，浏览器真的会执行。”**

## 2.1 JavaScript 能放到哪里？三种引入方式是什么？

把 JavaScript 放进网页里，常见有三种方式。你可以把它们理解成三种“说话方式”：有的直接在现场喊，有的写在屋里，有的单独记在小本子上。

### 1）内联写法：直接写在标签事件里

比如按钮被点击时，直接执行一小段代码：

```html
<button onclick="alert('你好！')">点我</button>
```

这像是把说明写在开关上。优点是**简单、直接**，适合第一次体验“点击有反应”。

但缺点也很明显：  
- 代码一多就乱  
- 页面结构和逻辑混在一起  
- 后面不好维护  

所以它更适合：
- 临时测试  
- 很短的小效果  
- 学习阶段快速体验交互  

---

### 2）内部脚本：写在 `<script>` 标签里

把 JavaScript 直接写在 HTML 文件内部：

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>内部脚本</title>
</head>
<body>
  <button id="btn">点我</button>

  <script>
    alert('页面加载完成');
  </script>
</body>
</html>
```

这种方式像是把“控制台”放在房子里，学习和练习都很方便。优点是：
- 方便学习  
- 方便调试  
- 适合小练习  

缺点是文件一大就容易乱，不适合复杂项目。

---

### 3）外部脚本：把 JS 单独放到 `.js` 文件里

这是最常见、也最推荐尽早掌握的方式。HTML 负责结构，JS 负责逻辑，分工清楚。

**index.html**

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>外部脚本</title>
</head>
<body>
  <button id="btn">点我</button>

  <script src="main.js"></script>
</body>
</html>
```

**main.js**

```javascript
alert('我是外部脚本');
```

这种方式像把电路图单独整理好，优点是：
- 清晰  
- 好维护  
- 适合正式项目  
- 代码越多越有优势  

---

### 老赵提醒

新手阶段不用纠结“哪种最高级”，先记住一个实用原则：

- **练习时**：内部脚本最方便  
- **正式项目**：外部脚本最常用  
- **内联写法**：能看懂就行，不建议长期大量使用  

先让代码“跑起来”，比一开始追求规范更重要。

---

## 2.2 `script` 标签放哪里最合适？

`script` 标签的作用很简单：**告诉浏览器，这里开始执行 JavaScript。**

它放的位置，会影响代码能不能找到页面上的元素。

### 放在 `body` 末尾

```html
<body>
  ...
  <script src="main.js"></script>
</body>
```

这是新手最稳妥的方式之一。因为页面元素先加载，JS 再去找它们，就不容易“找不到人”。你可以理解成：**先让同学都进教室，再开始点名。**

### 放在 `head` 中

也可以放在 `head` 里，但如果 JS 要操作按钮、输入框等元素，太早执行就可能报错。

所以刚开始学习时，最推荐的做法是：  
**把 `script` 放到 `body` 最后面。**

---

## 2.3 怎么在浏览器里查看运行结果？

学 JS 很重要的一步，不是“写完就算了”，而是要学会**看结果**。代码就像做菜，写完不代表熟了，得尝一口才知道对不对。

### 1）页面直接看

```javascript
document.body.innerHTML = 'Hello JavaScript';
```

执行后页面内容发生变化，你能直接看见效果。适合观察“网页变没变”。

### 2）使用浏览器控制台查看

控制台像浏览器的“小黑板”，可以看输出、看报错、看程序有没有跑起来。

常见打开方式：
- 右键页面 → 检查  
- 按 `F12`  
- 切到 Console（控制台）

比如：

```javascript
console.log('代码运行了');
```

你会在控制台看到这句话。很多时候页面没变化，但控制台会告诉你程序到底有没有执行。

---

### 小案例：先输出，再确认

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>查看结果</title>
</head>
<body>
  <script>
    console.log('Hello，浏览器！');
    alert('我已经运行了');
  </script>
</body>
</html>
```

这个案例说明：  
**JavaScript 不是写给“想象”看的，是写给浏览器执行、再由你观察反馈的。**

---

## 2.4 初次报错怎么读？为什么不要怕报错？

新手学 JS，最常见的心理反应就是：  
“哎呀，怎么红了？是不是我写错了？”

其实不是。**报错不是敌人，是提示牌。**

浏览器报错通常会告诉你三件事：

1. **哪里错了**：哪个文件、哪一行  
2. **错了什么**：比如语法不对、变量没定义  
3. **可能怎么改**：有时会给出方向  

### 常见新手错误

#### 1）少写了符号

```javascript
alert('你好'
```

少了右括号，浏览器会提示你。

#### 2）变量名写错

```javascript
let name = '老赵';
console.log(nam);
```

`nam` 和 `name` 不一样，浏览器会说找不到这个变量。

#### 3）标签写错位置

比如 JS 太早执行，找不到页面元素。

### 读报错的三个步骤

1. **先看红字，不要慌**  
2. **看行号，找到位置**  
3. **从附近一小段代码开始查**  

很多时候，错误并不在报错那一行，而在它前后。

### 老赵提醒

别把报错当成“我不行”的证明。它更像是你骑车时车头歪了一点，系统提醒你：**“往回扶一扶。”**  
会报错，说明你已经开始和浏览器对话了，这其实是好事。

## 2.5 第一个小案例：点击按钮弹出提示

这一节我们做一个真正能互动的小例子：**点击按钮，弹出一句提示。**

### 需求

页面上有一个按钮，点一下后弹出“欢迎学习 JavaScript”。

### 实现步骤

#### 第一步：写 HTML

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="UTF-8">
  <title>按钮点击</title>
</head>
<body>
  <button id="btn">点我试试</button>

  <script src="main.js"></script>
</body>
</html>
```

#### 第二步：写 JS

**main.js**

```javascript
let btn = document.getElementById('btn');

btn.onclick = function () {
  alert('欢迎学习 JavaScript');
};
```

### 这段代码在干什么？

- `document.getElementById('btn')`：根据 `id` 找到按钮  
- `btn.onclick = ...`：给按钮加一个点击事件  
- `alert(...)`：弹出提示框  

你可以把它理解成：

- **按钮**是门铃  
- **onclick** 是“有人按门铃”  
- **function** 是门铃响了以后要做的事  

这就是网页交互最简单的样子：  
**用户操作 → 程序响应**

对新手来说，这一步特别重要，因为它会让你第一次感受到：  
“原来网页不是死的，它真的能听我指挥。”

## 2.6 从这个案例你要记住什么？

这个小案例虽然短，但已经包含了 JS 入门最重要的几个动作。

### 1）让 JS 先运行起来

不管你用内部脚本还是外部脚本，先保证浏览器能执行。代码不运行，后面都白搭。

### 2）让 JS 找到网页元素

通过 `id` 找到按钮，说明 JS 可以“认识网页上的东西”。这就像在房间里找开关，得先知道它在哪。

### 3）让元素响应用户操作

按钮一点击，程序就有反应，这就是交互的开始。后面你会继续学输入框、表单、提示框，都是在这个基础上往前走。

### 老赵提醒

先别急着追求复杂，先把“能点、能看、能响应”练熟。网页一旦开始听你指挥，JavaScript 就不再只是书上的符号了。

## 2.7 练习：把按钮效果变一变

学习编程最怕只看不练。你必须亲手改一改，才会真正熟。

### 练习 1：改提示内容

把弹窗内容改成：

- “今天开始学 JS！”
- “你已经成功点击按钮！”

观察效果是否变化。

### 练习 2：做两个按钮

做两个按钮：

- 第一个按钮点击后提示“早上好”
- 第二个按钮点击后提示“晚上好”

试着给它们分别设置不同的 `id`，再分别绑定点击事件。

### 练习 3：试试控制台输出

把 `alert` 改成：

```javascript
console.log('按钮被点击了');
```

然后打开控制台看看有没有输出。你会慢慢习惯“页面提示”和“控制台输出”这两种反馈方式。

### 练习 4：故意制造一个小错误

比如把按钮 `id` 写错，看看浏览器会怎么报错。目的不是捣乱，而是熟悉错误提示长什么样。以后你再遇到类似情况，就不会一脸懵。

# 第3章 第3章：变量与数据类型——给信息起名字、分清它是什么

## 开篇引入：为什么学变量，先学“装盒子”？

JavaScript 里的数据，就像家里散放的钥匙、零钱和便签纸：不用时随手一放，真要找就容易乱。**变量**，就是给数据准备一个盒子，再贴上标签。这样数据能被保存、重复使用，也更容易读懂。

比如网页里常见的用户昵称、年龄、是否登录，都会先放进变量里，后面的判断、显示、提示都要靠它们。

---

## 一、变量是什么：把数据装进盒子并贴标签

### 1.1 变量到底用来做什么？

变量主要做三件事：

1. 保存数据  
2. 重复使用数据  
3. 让代码更清楚

```javascript
let userName = "老赵";
let age = 18;
```

这里 `userName` 和 `age` 是变量名，右边是变量里存的值。可以把它理解成：左边是盒子名字，右边是装进去的东西。

### 1.2 赋值：把东西放进盒子里

给变量装数据，叫**赋值**。

```javascript
let score = 95;
```

这句代码表示：创建一个叫 `score` 的变量，并把数字 `95` 放进去。以后想用成绩，直接写 `score` 就行。

### 1.3 小案例：记录一位同学的信息

```javascript
let name = "小明";
let age = 16;
let isStudent = true;
```

这三行分别记录了名字、年龄和是否是学生。变量把零散信息整理得很清楚，就像把纸条分门别类放进抽屉里。

**老赵提醒：**  
变量名就像标签，越清楚，后面越省事。

---

## 二、let 与 const 的区别和使用场景

### 2.1 `let`：可以改的盒子

`let` 定义的变量，后面可以重新赋值，适合**会变化**的数据。

```javascript
let level = 1;
level = 2;
```

像等级、购物车数量、当前页码这类会变的值，常用 `let`。

### 2.2 `const`：不打算换内容的盒子

`const` 定义的变量，表示这个变量名对应的值**不能重新赋值**，适合**不打算变**的数据。

```javascript
const siteName = "全栈老赵";
```

你可以把它理解成“贴了封条的盒子”。

### 2.3 怎么选：看“会不会改”

- **以后还要改的，用 `let`**
- **确定不会改的，用 `const`**

```javascript
let age = 18;
const country = "中国";
```

如果拿不准，就问自己一句：**这个值后面还会换吗？** 会换，用 `let`；不会换，用 `const`。

### 2.4 常见误区

- 所有变量都用 `let`，容易忘记哪些数据不该改。
- 乱用 `const`，后面真要改时会报错。

**老赵提醒：**  
`const` 不是“更高级”，只是“更适合不变的数据”。写代码像整理抽屉，不是锁死，而是摆放合理。

---

## 三、字符串、数字、布尔值：三种最常见的数据

### 3.1 字符串：一串文字

字符串就是文字内容，通常写在引号里。

```javascript
let nickname = "小红";
let message = '你好，欢迎来到页面';
```

它常用来装名字、提示语、标题、输入内容这类信息。

### 3.2 数字：用来计算的值

数字就是数值本身，不需要引号。

```javascript
let price = 39;
let height = 168.5;
```

这里的 `39`、`168.5` 都是数字，可以参与计算。要注意：`"39"` 是字符串，不是数字。一个像“写在纸上的数字”，一个像“真的零钱”。

### 3.3 布尔值：只有两种答案

布尔值只有两个可能：

- `true`：真、是、成立
- `false`：假、不是、不成立

```javascript
let isLogin = true;
let isVip = false;
```

它适合表示是否登录、是否通过验证、是否有库存这类状态，就像开关灯，只有开和关两种情况。

### 3.4 三种类型的对比

| 类型 | 例子 | 用途 |
|---|---|---|
| 字符串 | `"老赵"` | 名字、文本、提示 |
| 数字 | `18` | 年龄、价格、数量 |
| 布尔值 | `true` / `false` | 状态判断 |

### 3.5 小案例：同时保存三类信息

```javascript
const userName = "老赵";
let age = 20;
let isLogin = true;
```

这里 `userName` 是字符串，`age` 是数字，`isLogin` 是布尔值。网页里常常就是这三类数据一起配合使用。

**老赵提醒：**  
先分清“这是什么”，再想“怎么用它”。类型搞明白，后面判断和交互才不会乱。

---

## 四、变量命名规则与命名习惯

### 4.1 命名规则：先别踩坑

变量名要注意：

1. 不能以数字开头  
2. 不能有空格  
3. 尽量别用关键词  
4. 尽量使用有意义的名字

### 4.2 命名习惯：让人一眼看懂

```javascript
let a = "张三";
let b = 18;
let c = false;
```

这种写法能跑，但看不出含义。更好的方式是：

```javascript
let userName = "张三";
let userAge = 18;
let isLogin = false;
```

这就是“看名字就知道在干什么”。

### 4.3 一个简单原则

本书先记住两个习惯：

- 变量名要有意义
- 英文单词之间常用驼峰写法，比如 `userName`、`totalPrice`

**老赵提醒：**  
好名字不是为了炫技，而是为了少犯糊涂。程序不会嫌名字长，怕的是你自己看不懂。

## 五、小案例：记录年龄、昵称和是否登录

### 5.1 场景说明

网页可能需要显示用户昵称、年龄和登录状态：

```javascript

let isLogin = true;
```

### 5.2 代码拆解

- `nickname`：字符串，保存昵称
- `age`：数字，保存年龄
- `isLogin`：布尔值，保存登录状态

如果年龄变了，可以改 `age`：


### 5.3 这个小案例告诉我们什么？

变量的作用，不只是“写代码时多打几个字”，而是：

- 让信息有地方放
- 让数据有名字可查
- 让后续判断和交互更顺手

这就是后面做按钮点击、表单校验、页面提示的基础。

# 第4章 第4章：运算符与类型转换——让数据会“计算”和“变身”

## 开篇引入：为什么变量写出来还不够？

前面我们学会了把数据放进变量里，但光“存起来”还不够。  
就像食材买回家，真正做成菜，还得会处理、会搭配、会下锅。  
在 JavaScript 里，**运算符**负责处理数据，**类型转换**负责把数据换一种“形态”继续使用。

这一章你要掌握的很简单：

- 让数据会“算”；
- 让数据会“比”；
- 让数据会“拼”；
- 让数据在需要的时候“变身”。

学完这一章，你就不只是会写变量了，而是能开始真正处理数据了。

---

## 一、算术运算符：先把“计算”这件事搞明白

算术运算符就是最像数学课的部分：加、减、乘、除、取余。

```javascript
let a = 10;
let b = 3;

console.log(a + b); // 13
console.log(a - b); // 7
console.log(a * b); // 30
console.log(a / b); // 3.333...
console.log(a % b); // 1
```

`%` 叫**取余运算符**，意思是“除完以后还剩多少”。

**生活化理解：**  
10 个苹果平均分给 3 个人，每人 3 个，还剩 1 个，这个“剩下的 1”就是余数。  
所以 `%` 常用在“分组”“轮到谁”“是否整除”这类场景。

```javascript
console.log(4 % 2); // 0
console.log(7 % 2); // 1
```

**老赵提醒：**  
算术运算符是拿来“算数”的，不是拿来“拼字”的。  
后面你会看到，`+` 有时候会悄悄变成拼接，这也是新手最容易踩坑的地方。

---

## 二、比较运算符：判断谁大谁小，谁成立谁不成立

比较运算符不返回具体数字，而是返回布尔值 `true` 或 `false`。  
你可以把它想成门口的保安：符合条件就放行，不符合就拦住。

```javascript
console.log(5 > 3);   // true
console.log(5 < 3);   // false
console.log(5 >= 5);  // true
console.log(5 <= 4);  // false
```

常见的比较运算符有：

- `>`：大于
- `<`：小于
- `>=`：大于等于
- `<=`：小于等于

### 等于和严格等于：别被“看起来一样”骗了

JavaScript 里，`==` 和 `===` 差别很大。

```javascript
console.log(1 == "1"); // true
console.log(1 === "1"); // false
console.log(1 === 1);   // true
```

`==` 会先帮你做类型转换，再比较；  
`===` 则更严格，**值相同，类型也要相同** 才算数。

**生活化比喻：**  
`==` 像先把大家换成同一种包装再比；  
`===` 像不仅要长得一样，还得是同一套包装。

**老赵提醒：**  
初学阶段，尽量优先用 `===` 和 `!==`，更稳，不容易被自动转换“偷袭”。

---

## 三、逻辑运算符：把多个条件串起来

当一个条件不够用时，就要靠逻辑运算符把多个条件拼成一条规则。

```javascript
console.log(true && false); // false
console.log(true || false);  // true
console.log(!true);          // false
```

它们可以这样理解：

- `&&`：两边都满足，才通过
- `||`：只要一边满足，就通过
- `!`：把结果反过来

**生活化比喻：**

- `&&` 像“既要有门票，又要有身份证”；
- `||` 像“有学生证或者会员卡，任意一个就行”；
- `!` 像“不是成年人”的反向判断。

```javascript
let isLogin = true;
let age = 20;

console.log(isLogin && age >= 18); // true
```

意思就是：**登录了，并且年龄满 18 岁，才满足条件。**

---

## 四、字符串拼接和数字运算：`+` 这个符号有两副面孔

`+` 很常见，但它不只会做加法。

### 1. 两边都是数字时，它是加法

```javascript
console.log(10 + 5); // 15
```

### 2. 只要有一边是字符串，它就可能变成拼接

```javascript
console.log("10" + 5);       // "105"
console.log("你好" + "世界"); // "你好世界"
console.log(1 + "2");        // "12"
```

这就像把两张卡片贴在一起，不是算成一个新数字，而是直接连成一串。

### 3. 为什么这点特别重要？

因为很多时候，输入框拿到的数据看起来像数字，其实是字符串。  
如果你直接拿来做加法，结果可能不是你想要的“计算”，而是“拼接”。

```javascript
console.log("20" + "30"); // "2030"
```

如果你本来想得到 50，就得先把它们转成数字。

**老赵提醒：**  
看到 `+`，先别急着以为一定是加法。  
先看看两边的数据类型，别让“拼接”冒充“计算”。

---

## 五、类型转换：让字符串变数字，让数字变字符串

类型转换，就是把一种数据类型换成另一种。  
新手最常遇到的场景有两个：

- 输入框拿到的是字符串，但你想参与计算；
- 算完后想把结果拼成提示文字显示出来。

### 1. 字符串转数字：`Number()`

```javascript
let price = "88";
let numPrice = Number(price);

console.log(numPrice); // 88
console.log(typeof numPrice); // number
```

如果字符串内容是合法数字，`Number()` 通常能转成功。  
如果不是数字，就会变成 `NaN`，意思是“不是一个合法数字”。

```javascript
console.log(Number("abc")); // NaN
```

### 2. 数字转字符串：`String()`

```javascript
let age = 18;
let text = String(age);

console.log(text); // "18"
console.log(typeof text); // string
```

当你要把结果显示给用户看时，字符串很常用。

```javascript
let score = 95;
console.log("你的分数是：" + score);
```

### 3. 布尔值：像开关一样简单

布尔值只有两种：

- `true`：真，开
- `false`：假，关

```javascript
let isLogin = true;
let hasCoupon = false;
```

它们在判断和流程控制里非常重要。  
你可以把布尔值想成电灯开关，不是亮就是灭。

### 4. 有些值会被当成“假”

在条件判断中，有些值会被当成 `false`，比如：

- `0`
- `""`
- `null`
- `undefined`
- `NaN`

这在后面写条件和表单校验时很常见。  
比如输入框里什么都没填，往往就是空字符串 `""`。

**老赵提醒：**  
从输入框拿到的数据，很多时候默认是字符串。  
如果后面要做加减乘除，先转成数字，不然很可能变成“拼接”。

## 六、小案例：计算购物总价并显示优惠结果

假设你要买两件商品：

- 书包：`88`
- 笔记本：`12`

商家规则：

- 总价满 `100` 元，打 `9` 折；
- 否则不打折。

### 1. 先算总价

```javascript
let bag = 88;
let notebook = 12;
let total = bag + notebook;

console.log("总价：" + total);
```

### 2. 再判断是否满足优惠条件

```javascript
if (total >= 100) {
  console.log("恭喜，享受9折优惠！");
} else {
  console.log("未达到优惠条件。");
}
```

### 3. 如果金额来自输入框，要先转数字

```javascript
let bag = Number("88");
let notebook = Number("12");
let total = bag + notebook;
```

如果不转成数字，`"88" + "12"` 可能会变成 `"8812"`，那就不是总价，而是把两个字符串硬贴在一起了。

### 4. 完整示例

```javascript
let bag = Number("88");
let notebook = Number("12");
let total = bag + notebook;

if (total >= 100) {
  console.log("总价：" + total + "，已满足优惠条件！");
} else {
  console.log("总价：" + total + "，还差一点点。");
}
```

这个例子里，你已经用到了：

- 运算
- 比较
- 条件判断
- 类型转换
- 字符串拼接

这就是 JavaScript 入门阶段最常见的一条完整链路。

# 第5章 第5章：条件判断——让程序学会“如果……就……”

编程最有意思的地方之一，就是让程序不再一股脑儿往下跑，而是学会“看情况办事”。你可以把它想成一个门卫：平时按规矩执行，一旦你告诉它“如果……就……”的规则，它就知道该放行还是拦住。比如：**如果**分数及格，**就**显示“通过”；**如果**年龄未满 18，**就**提示“未成年人”。这就是条件判断。

学会这一章后，你的代码就不再是一条直线，而是能根据不同情况走不同路线。

## 一、if / else：最基础的“如果……就……，否则……”

`if / else` 是最常见的条件判断，意思很简单：

- **如果条件成立**，执行这一段；
- **否则**，执行另一段。

```javascript
if (条件) {
  // 条件成立时执行
} else {
  // 条件不成立时执行
}
```

### 1. 条件到底是什么？

条件通常会得到 `true` 或 `false`，也就是“真”或“假”。  
你可以把它理解成一张通行证：

- `true`，门开了；
- `false`，门关着。

```javascript
let age = 20;

if (age >= 18) {
  console.log("你已经成年了");
} else {
  console.log("你还未成年");
}
```

这里程序先判断 `age >= 18` 是否成立。`age` 是 20，所以结果是 `true`，执行前面的代码。

### 2. 执行顺序很重要

条件判断的顺序就是“先看，再决定”：

1. 先判断 `if` 后面的条件；
2. 成立就执行 `if` 里的代码；
3. 不成立就执行 `else` 里的代码。

注意：**同一次判断里，只会执行一个分支**。就像在岔路口只能选一条路，不能两条都走。

### 小案例：下雨带伞

```javascript
let isRain = true;

if (isRain) {
  console.log("记得带伞");
} else {
  console.log("今天可以不带伞");
}
```

出门前看天气，下雨就带伞，不下雨就轻松出门。

### 老赵提醒

条件判断不是写复杂公式，而是先把规则想清楚：**什么情况下做什么**。想明白了，代码就好写。

---

## 二、多个条件判断：else if 怎么用？

现实里很多事情不只有“是/否”两种结果，而是有好几档。比如成绩可能是：

- 优秀
- 良好
- 及格
- 不及格

这时就要用 `else if`。

### 1. 基本结构

```javascript
if (条件1) {
  // 条件1成立
} else if (条件2) {
  // 条件1不成立，条件2成立
} else {
  // 前面的条件都不成立
}
```

### 2. 例子：按分数输出等级

```javascript
let score = 86;

if (score >= 90) {
  console.log("优秀");
} else if (score >= 80) {
  console.log("良好");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
```

程序是从上往下判断的，一旦某个条件成立，后面的就不再继续判断了。

### 3. 顺序为什么重要？

```javascript
if (score >= 60) {
  console.log("及格");
} else if (score >= 90) {
  console.log("优秀");
}
```

如果分数是 95，程序先看到 `score >= 60` 成立，就直接输出“及格”，后面的“优秀”不会再执行。  
所以多条件判断时，通常把**更严格、更具体的条件放前面**。

### 小案例：根据年龄判断提示语

```javascript
let age = 15;

if (age < 12) {
  console.log("你还是小朋友");
} else if (age < 18) {
  console.log("你是青少年");
} else {
  console.log("你已经是成年人了");
}
```

这个例子很适合练习“从上到下判断”的顺序。因为 `age < 12` 比 `age < 18` 更具体，所以要先写更小的范围。

### 老赵提醒

`else if` 就像路口上的指示牌，顺序一乱，车就容易开错。先想好分层，再写代码。

---

## 三、switch：适合“固定选项”的场景

`switch` 也是条件判断，但它更适合处理**一个变量对应多个固定值**的情况。比如星期几、菜单选项、等级编号、按钮选项。

### 1. 基本结构

```javascript
switch (变量) {
  case 值1:
    // 执行这里
    break;
  case 值2:
    // 执行这里
    break;
  default:
    // 都不匹配时执行
}
```

### 2. 例子：根据星期输出提示

```javascript
let day = 3;

switch (day) {
  case 1:
    console.log("星期一");
    break;
  case 2:
    console.log("星期二");
    break;
  case 3:
    console.log("星期三");
    break;
  default:
    console.log("不是 1~3 的数字");
}
```

### 3. `switch` 适合什么，不适合什么？

可以这样记：

- `if / else if`：更灵活，适合范围判断、复杂条件；
- `switch`：更像对号入座，适合多个明确的固定值。

比如判断分数是否达标，适合 `if`；而像下面这种固定编号判断，就很适合 `switch`：

```javascript
switch (menu) {
  case 1:
    console.log("查看资料");
    break;
  case 2:
    console.log("修改资料");
    break;
  case 3:
    console.log("退出系统");
    break;
  default:
    console.log("输入错误");
}
```

### 4. `break` 为什么不能忘？

`break` 的作用是“到这里就停”。  
如果忘了写 `break`，程序可能会继续往下执行别的 `case`，像小车没踩刹车一样一路冲过去。新手写 `switch` 时，最常见的错误之一就是漏写 `break`。

### 老赵提醒

`switch` 不是更高级，只是更适合某些场景。会选工具，比死记语法更重要。

---

## 四、条件判断中的常见写法与常见错误

刚学条件判断时，很容易踩几个坑，记住它们能少走弯路。

### 1. 别把赋值和比较弄混

```javascript
if (score = 60) {
  console.log("及格");
}
```

这里错了，因为 `=` 是赋值，不是比较。判断时要用“比较”的思路，不能把“给变量赋值”和“判断是否成立”混在一起。

### 2. 建议养成完整写法

```javascript
if (age >= 18) {
  console.log("成年");
}
```

有时少写花括号也能跑，但新手阶段最好写完整。这样结构清楚，不容易出错。

### 3. 先用中文把逻辑说一遍

比如先想清楚：

- 分数大于等于 60，及格；
- 否则，不及格。

中文想明白了，代码其实只是翻译。

### 4. 字符串比较要加引号

```javascript
let userType = "admin";

if (userType === "admin") {
  console.log("管理员");
}
```

字符串要加引号，不然程序会把它当变量看。

### 5. 布尔值可以直接判断

```javascript
let isLogin = true;

if (isLogin) {
  console.log("已登录");
}
```

如果变量本身就是布尔值，直接判断就行，不必绕一圈。

### 6. 先判断再写代码，别急着堆条件

如果一个判断已经够用，就不要硬塞很多层嵌套。对零基础读者来说，过深的嵌套就像在迷宫里转弯，容易把自己也绕晕。本章先把“如果……就……”练熟，后面再慢慢接触更复杂的组合。

### 检查清单

写条件判断前，先问自己：

- 我要判断什么？
- 成立时做什么？
- 不成立时做什么？
- 有几个分支？
- 用 `if` 还是用 `switch` 更合适？

---

## 五、小案例：根据分数输出等级

光看语法容易忘，真正能记住的是“拿来就能用”。

```javascript
let score = 73;

if (score >= 90) {
  console.log("A：优秀");
} else if (score >= 80) {
  console.log("B：良好");
} else if (score >= 60) {
  console.log("C：及格");
} else {
  console.log("D：需要努力");
}
```

### 拆解思路

1. 先确定分数范围；
2. 再把范围分层；
3. 从高到低依次判断；
4. 最后给出兜底结果。

你可以把它想成一排门，越靠前的门要求越高，符合哪个条件就走哪个门。  
这个例子以后也能直接用在网页提示里：比如输入分数后，页面自动显示对应等级。

### 老赵提醒

条件判断不是背答案，而是学会“分情况处理”。先分层，再写代码，思路就会很清楚。

# 第6章 第6章：循环——让重复工作交给程序来做

## 开篇引入：为什么程序最适合“重复劳动”

如果你要在网页上连续输出 10 次“你好”，最直接但最笨的办法，就是一行一行写：

```js
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
console.log("你好");
```

这能用，但代码又长又容易写错。就像你要给 10 个快递包裹贴标签，如果每份都手写一遍，不但累，还容易漏。循环的作用，就是把这种重复工作交给程序自己做。

在 JavaScript 里，循环就是“自动重复执行”的工具。只要条件还满足，程序就会一遍一遍执行同样的代码，直到该停的时候停下来。对新手来说，循环就是从“写一条条命令”，走向“让程序自己忙起来”的第一步。

---

## 一、为什么需要循环：重复任务不用手写很多遍

循环最常见的场景有三类：

1. **重复输出**：比如打印 1 到 5，或者重复提示三次  
2. **批量处理**：比如依次处理数组里的每个成绩  
3. **持续等待**：比如用户没输入正确内容，就继续提醒

你可以把循环理解成“工厂流水线”。一件件手工做，效率低；按统一流程批量处理，速度快，也不容易出错。

### 没有循环时的问题
- 代码很长，重复很多
- 修改麻烦，比如要把“重复 10 次”改成“重复 20 次”
- 容易漏写或写多

### 有循环后的好处
- 代码更短
- 逻辑更清晰
- 以后改次数更方便

**老赵提醒：**  
只要你发现自己在复制粘贴同一段代码，就该想一想：能不能用循环？

---

## 二、for 循环：最适合“次数明确”的重复

### 1. for 循环长什么样

```js
for (初始化; 条件; 更新) {
  // 需要重复执行的代码
}
```

它可以记成三个动作：

- **初始化**：先准备一个起点
- **条件**：检查还能不能继续
- **更新**：每次循环后让计数变化

例如打印 1 到 5：

```js
for (let i = 1; i <= 5; i++) {
  console.log(i);
}
```

这里的 `i` 就像“次数计数器”，从 1 开始，每次加 1，直到 5 为止。

### 2. for 循环适合什么场景

如果你已经知道要重复几次，`for` 最合适：

- 输出固定次数的提示
- 打印一组编号
- 遍历数组

### 3. 例子：输出 5 次“加油”

```js
for (let i = 1; i <= 5; i++) {
  console.log("加油");
}
```

如果以后想改成 8 次，只要把 `5` 改成 `8`，不用重写整段代码。

---

## 三、while 循环：最适合“条件满足就继续”的重复

### 1. while 循环长什么样

```js
while (条件) {
  // 重复执行的代码
}
```

意思很直白：**只要条件成立，就一直执行**。

比如：

```js
let count = 1;

while (count <= 3) {
  console.log("第" + count + "次提醒");
  count++;
}
```

这里先定义一个 `count`，然后每次循环后让它加 1，不然程序会一直跑下去。  
你可以把 `while` 理解成“先看情况，再决定要不要继续”。

### 2. while 和 for 的生活化区别

- **for** 像“我知道要发 5 张传单”，次数清楚，照着数就行
- **while** 像“门口还有人排队就继续发”，不是先数好总数，而是看条件还在不在

也就是说，`for` 更像“按次数办事”，`while` 更像“按情况办事”。

### 3. while 循环适合什么场景

`while` 更像“条件没达成，就一直等”：

- 用户没输入正确内容，继续提示
- 某个条件没有满足，持续执行
- 次数不固定，但需要一直等到某个结果出现

### 4. 例子：重复提示三次

```js
let i = 1;

while (i <= 3) {
  console.log("请认真检查内容");
  i++;
}
```

这个例子和 `for` 的效果差不多，但写法更像“先给一个起点，再慢慢往前走”。

### 5. for 和 while 怎么选

简单记：

- **次数明确**：优先用 `for`
- **条件驱动**：优先用 `while`

比如“输出 10 行内容”，用 `for` 很顺手；  
比如“直到用户输入正确密码为止”，`while` 更像这个任务的风格。

**老赵提醒：**  
`while` 最容易出问题的地方，是你忘了让条件变化。这样条件永远成立，程序就可能一直转下去。它就像电风扇一直开着却没人关，当然会停不下来。

---

## 四、循环中的计数、边界和停止条件

循环能不能正确运行，关键就看三件事：**计数、边界、停止条件**。

### 1. 计数：你现在走到第几步了

计数变量常见写法是：

```js
let i = 1;
```

它就像爬楼梯时的“台阶编号”，每走一步，编号就变一次。

### 2. 边界：从哪开始，到哪结束

例如：

```js
for (let i = 1; i <= 5; i++)
```

这里的边界就是 1 到 5。  
如果写成 `i < 5`，那就只会到 4。  
所以边界写错，结果就可能少一项或多一项。

### 3. 停止条件：什么时候该停

停止条件是循环最重要的安全阀。它告诉程序：到这里就别继续了。

比如：

```js
let i = 1;
while (i <= 3) {
  console.log(i);
  i++;
}
```

如果少了 `i++`，`i` 永远是 1，条件永远成立，循环就停不下来。

### 常见误区
- 忘记更新计数
- 边界写错
- 把 `<` 和 `<=` 搞混
- 循环条件始终为真

### 检查清单
在写循环前，先问自己：

1. 从几开始？
2. 到几结束？
3. 每次怎么变化？
4. 什么时候停止？

这四个问题能帮你减少大多数循环错误。

---

## 五、小案例：输出成绩列表

假设有一个成绩数组：

```js
let scores = [98, 87, 76, 90];
```

我们希望一个个打印出来：

```js
for (let i = 0; i < scores.length; i++) {
  console.log("第" + (i + 1) + "个成绩：" + scores[i]);
}
```

这里用了数组长度 `scores.length`，表示数组里有多少个元素。  
`i` 从 0 开始，因为数组下标通常从 0 起步。  
`i + 1` 是为了让显示出来的序号更符合人类习惯。

循环特别适合“挨个处理一批数据”，就像一篮子苹果，一个一个拿出来检查。

如果你想换成输出水果，也可以这样写：

```js
let fruits = ["苹果", "香蕉", "橘子"];

for (let i = 0; i < fruits.length; i++) {
  console.log("第" + (i + 1) + "个水果：" + fruits[i]);
}
```

你会发现，循环像一个勤快的小助手：你给它一串东西，它就挨个帮你处理。

# 第7章 第7章：函数入门——把常用动作打包成一个小工具

## 开篇引入：为什么代码也要“打包”
前面我们学了变量、判断和循环，已经能写一些基础逻辑了。但很快你会发现，很多代码会反复出现：打招呼、计算总分、判断年龄、输出提示，来来回回都差不多。

如果每次都重写一遍，不仅麻烦，还容易改漏、改错。代码就像桌上的工具，散着放又乱又不好找。**函数**就像一个小工具盒：先把常用动作装进去，需要时直接拿出来用，以后要改规则，也只改一处。

你也可以把它想成微波炉、洗衣机、遥控器：你不用每次都重新研究一遍怎么操作，按按钮就行。函数也是一样，**把一段功能包装好，反复使用**。

## 一、函数是什么：把一段功能包装起来反复使用
函数本质上就是一段**可以重复调用的代码块**。它像一个提前准备好的小程序，你告诉它什么时候工作，它就按规则执行。

函数的好处很实在：

1. **重复利用**：同样的事不用写很多遍。
2. **更好维护**：规则变化时，只改函数内部。
3. **更清楚**：复杂任务拆开后，代码更好读。

例如：

```js
function sayHello() {
  console.log("你好，欢迎学习 JavaScript！");
}
```

这段代码只是**定义**了函数，还没有执行。就像工具已经放进盒子里，只有真正拿出来用，它才会工作。

---

## 二、函数声明和调用：先做出来，再用起来
先记住两个动作：**声明**和**调用**。

### 1. 函数声明：先把函数“造出来”
基本写法：

```js
function 函数名() {
  // 函数体
}
```

例如：

```js
function sayHello() {
  console.log("你好！");
}
```

这里：
- `function` 表示定义函数
- `sayHello` 是函数名
- `()` 里以后可以放参数
- `{}` 里写要执行的内容

函数名就像盒子上的标签，写清楚才好找。

### 2. 函数调用：把函数“用起来”
写好后，要调用它才会执行：

```js
sayHello();
```

如果只写函数名，不加括号，它不会运行。就像拿着遥控器不按按钮，电视不会自己打开。

### 老赵提醒
函数声明是“把工具做出来”，函数调用是“把工具拿来用”。新手最常犯的错，就是只写了函数，忘了加括号。

---

## 三、参数和返回值：让函数会“收”和“送”
如果函数只会做固定动作，就不够灵活。要让它像真正的小工具，就要学会两件事：**接收外部数据**，以及**把结果带出来**。

### 1. 参数：让函数接收外部数据
有些函数要根据不同情况变化，这时就需要**参数**。

```js
function sayHello(name) {
  console.log("你好，" + name + "！");
}

sayHello("老赵");
sayHello("小明");
```

这里的 `name` 就是参数，像一个接收口，外面传什么，里面就用什么。它有点像炒菜时放的食材，同样是做菜，放什么料，结果就不同。

### 2. 返回值：把结果“带出来”
有些函数不只是做动作，还要给外面一个结果，这时用 `return` 返回。

```js
function add(a, b) {
  return a + b;
}

let result = add(3, 5);
console.log(result);
```

区分一下：
- `console.log`：把内容展示出来
- `return`：把结果交给外面继续用

可以把函数想成快递盒子，**参数**是放进去的东西，**return** 是最后送出来的结果。

### 3. 参数和变量有什么区别
新手常把参数和变量混在一起，其实它们有点像，但不完全一样：

- **参数**：函数门口负责接收数据的“接线员”
- **变量**：函数内部真正存放和处理数据的“储物格”

参数在函数里也能临时当变量用，但它只在当前函数中有效。

---

## 四、函数在拆分复杂任务中的作用：把大问题切成小块
刚学编程的人，最容易被“大任务”吓住。其实程序员做事，通常不是一下子解决大问题，而是把大问题拆成小问题。

比如“计算购物总价并显示优惠结果”，可以拆成：

1. 计算原价
2. 判断是否打折
3. 计算折后价
4. 输出提示

每一步都可以由一个函数来完成。这样做的好处是：

- 每个函数只管一件事
- 出错更容易找
- 后面复用更方便

例如：

```js
function calculateTotal(price, count) {
  return price * count;
}

function isAdult(age) {
  return age >= 18;
}
```

一个负责算价格，一个负责判断是否成年。  
这就是函数最实用的地方：**把复杂任务拆成很多简单动作盒子。**

### 小技巧：先问自己三句话
写函数前，先想清楚：

1. 输入是什么？
2. 输出是什么？
3. 能不能只做一件事？

如果一个函数什么都想管，最后往往会越写越乱。函数越专一，代码越清楚。

## 五、小案例：封装一个问候函数和一个计算函数
下面做两个最适合入门的小例子，先找手感，再谈复杂。

### 案例1：问候函数
需求：输入名字，输出一句欢迎语。

```js

  return "你好，" + name + "，欢迎来到 JavaScript 世界！";
}

let msg = greet("小明");
console.log(msg);
```

拆开看：

- 输入：名字
- 处理：拼接问候语
- 输出：完整句子

这个函数比直接写死一句话更灵活，因为它可以欢迎任何人。

### 案例2：计算函数
需求：输入价格和数量，返回总价。

```js
function getTotal(price, count) {

```

拆开看：

- 输入：单价、数量
- 处理：乘法计算
- 输出：总价

如果以后数量变了，只要改传入值，不用重写计算逻辑。  
这就像用计算器，不用每次重新发明一个，只要输入不同数字就行。

# 第8章 第8章：数组与对象——把一堆数据和一组信息组织起来

## 开篇引入：为什么我们需要“装东西的方式”？

前面学了变量、条件、循环、函数，接下来就会遇到一个现实问题：  
如果要保存的不是一个名字，而是一堆名字；不是一个价格，而是商品名称、价格、库存，怎么办？

这时候，JavaScript 里就需要两种常用的“收纳工具”：

- **数组**：像一排有顺序的盒子，用来放一串数据
- **对象**：像一个贴了标签的文件夹，用来整理一组信息

你可以把它理解成：

- 数组负责“**排队**”
- 对象负责“**贴标签**”

学会这两样，你就能开始处理网页里常见的数据，比如学生名单、商品列表、评论内容、购物车信息等。它就像学会整理房间：东西放对地方，代码才好写，也更好维护。

## 1. 数组是什么：一排有顺序的盒子

数组就是把多个数据放进一个容器里，而且这些数据**有顺序**。

```javascript
let fruits = ["苹果", "香蕉", "橙子"];
```

这里的 `fruits` 就像一排盒子：

1. 第一个盒子放“苹果”
2. 第二个盒子放“香蕉”
3. 第三个盒子放“橙子”

### 数组的特点

- 可以放多个值
- 有顺序
- 下标从 **0** 开始

所以：

```javascript
console.log(fruits[0]); // 苹果
console.log(fruits[1]); // 香蕉
console.log(fruits[2]); // 橙子
```

`length` 可以查看数组有多少项：

```javascript
let scores = [98, 85, 76];
console.log(scores.length); // 3
```

### 小案例

```javascript
let scores = [98, 85, 76];
console.log(scores[0]); // 98
console.log(scores.length); // 3
```

### 练习

1. 新建一个数组，放入 3 个你喜欢的食物。
2. 分别输出第 1 个和第 3 个元素。
3. 输出数组长度。

**老赵提醒：** 数组适合放“同一类东西”的列表，比如多个名字、多个分数、多个商品编号。

---

## 2. 数组常用方法入门：先学“增删查”，再学“截取”

数组不只是能存，还要会改。你可以把数组想成一排座位，方法就是帮你安排座位的工具。先记住最常见的几种：**加、删、查、截**。

### 2.1 push：往后面加一个

```javascript
let fruits = ["苹果", "香蕉"];
fruits.push("橙子");
console.log(fruits); // ["苹果", "香蕉", "橙子"]
```

像在队伍最后面加一个人。

### 2.2 pop：从后面删一个

```javascript
let fruits = ["苹果", "香蕉", "橙子"];
fruits.pop();
console.log(fruits); // ["苹果", "香蕉"]
```

像把队伍最后一个人请出去。

### 2.3 unshift：往前面加一个

```javascript
let fruits = ["香蕉", "橙子"];
fruits.unshift("苹果");
console.log(fruits); // ["苹果", "香蕉", "橙子"]
```

像在队伍最前面插入一个人。

### 2.4 shift：从前面删一个

```javascript
let fruits = ["苹果", "香蕉", "橙子"];
fruits.shift();
console.log(fruits); // ["香蕉", "橙子"]
```

像把队伍最前面的人移走。

### 2.5 slice：截取一段，不影响原数组

```javascript
let fruits = ["苹果", "香蕉", "橙子", "葡萄"];
let part = fruits.slice(1, 3);
console.log(part); // ["香蕉", "橙子"]
```

它适合“拿一段出来看看”，但不改原数组。

### 2.6 splice：删除、插入、替换都能做

```javascript
let fruits = ["苹果", "香蕉", "橙子", "葡萄"];
fruits.splice(1, 2);
console.log(fruits); // ["苹果", "葡萄"]
```

表示：从下标 1 开始，删除 2 个。

也可以插入：

```javascript
let fruits = ["苹果", "葡萄"];
fruits.splice(1, 0, "香蕉", "橙子");
console.log(fruits); // ["苹果", "香蕉", "橙子", "葡萄"]
```

### 2.7 includes：看看里面有没有

```javascript
let fruits = ["苹果", "香蕉", "橙子"];
console.log(fruits.includes("香蕉")); // true
console.log(fruits.includes("西瓜")); // false
```

像查名单：有没有这个东西。

### 小案例

做一个“购物清单”：

```javascript
let cart = ["牛奶", "面包"];
cart.push("鸡蛋");
console.log(cart.includes("牛奶")); // true
```

### 练习

1. 创建一个数组，练习 `push` 和 `pop`。
2. 用 `includes` 检查数组里是否有某个值。
3. 用 `slice` 截取数组的一部分。
4. 尝试用 `splice` 删除或插入一个元素。

**老赵提醒：** 先记住“增删查”这三类动作，数组就不再神秘了。方法不用一口气全背熟，先会用，再慢慢熟。

## 3. 对象基础：用键值对描述一个事物

如果数组像一排盒子，那么对象就像一个贴满标签的档案袋。

比如你要描述一个学生，不只是一个名字，还包括年龄、班级、成绩，这时对象最合适。

```javascript
let student = {
  name: "小明",
  age: 12,
  grade: "六年级"
};
```

每一项都是：

- **键**：`name`
- **值**：`"小明"`

这叫做**键值对**。可以把对象理解成“名字牌 + 内容”。

### 读取对象属性

```javascript
console.log(student.name); // 小明
console.log(student.age); // 12
console.log(student["grade"]); // 六年级
```

### 修改和新增属性

```javascript
student.age = 13;
student.hobby = "打篮球";
```

对象特别适合描述“一个完整的东西”。比如商品，不只是名字，还有价格、库存、是否上架等。

### 小案例

```javascript
let product = {
  name: "键盘",
  price: 199,
  inStock: true
};
```

### 练习

1. 创建一个对象，描述你自己：姓名、年龄、爱好。
2. 读取其中一个属性。
3. 修改一个属性，再输出查看。
4. 给对象新增一个属性，比如“城市”或“职业”。

**老赵提醒：** 数组更像“列表”，对象更像“说明书”。一个偏顺序，一个偏信息。新手先记住这个区别，后面就不容易乱。

## 4. 数组和对象的区别与组合使用：什么时候用谁？

很多新手会问：数组和对象到底怎么选？

### 判断标准

#### 用数组
当你要存的是一组同类数据，并且希望按顺序处理时，用数组。

```javascript
let names = ["张三", "李四", "王五"];
```

#### 用对象
当你要描述一个具体事物，里面有多种信息时，用对象。

```javascript
let user = {
  name: "张三",
  age: 20
};
```

### 组合使用

真实项目里，它们经常一起用。比如“学生名单”可以这样写：

```javascript
let students = [
  { name: "小明", age: 12 },
  { name: "小红", age: 13 },
  { name: "小刚", age: 12 }
];
```

这里是：

- 外层数组：管理多个人
- 内层对象：描述每个人的信息

这就像一个班级名单：一排学生卡片，每张卡片上写着姓名、年龄、成绩。

### 再看一个小例子：商品列表

```javascript
let products = [
  { name: "键盘", price: 199 },
  { name: "鼠标", price: 99 },
  { name: "耳机", price: 159 }
];

console.log(products[1].name); // 鼠标
console.log(products[1].price); // 99
```

这种写法在网页里很常见，比如商品展示页、通讯录、班级花名册。

### 练习

2. 用对象保存一个商品信息。
3. 用“数组 + 对象”保存 3 个学生的信息。

**老赵提醒：** 你可以把数组看成“排队的人”，把对象看成“每个人胸前挂的牌子”。两者组合起来，就能把复杂信息整理得很清楚。

## 5. 小案例：学生名单管理

# 第9章 第9章：DOM 入门——把代码和网页元素连起来

## 开篇引入：为什么学 DOM？

前面我们已经会写一点 JavaScript 了，但你可能会问：**代码写在那儿，网页怎么“动”起来？**

答案就是：**DOM**。

你可以把网页想成一间房子：HTML 是墙、门、窗这些结构，CSS 是装修风格，而 **DOM 就像一张“房间地图”**。JavaScript 顺着这张地图，就能找到按钮、文字、图片和输入框，然后对它们动手：

- 改文字
- 改颜色
- 改图片
- 读取输入框内容
- 响应按钮点击

这一步很关键。没有 DOM，JavaScript 就像拿着工具箱却找不到螺丝；学会 DOM，才算真正开始网页交互。

**老赵提醒：**  
先别急着背术语，你只要先记住：**DOM 是 JavaScript 和网页元素之间的桥梁。**

## 什么是 DOM：把网页看成一棵可操作的树

DOM 的全称先不用死记，你只要先明白：**浏览器会把网页解析成一棵树，JavaScript 可以顺着这棵树找到每个元素并操作它。**

### 1. 为什么说它像一棵树？

网页里通常有：

- `html`
  - `head`
  - `body`
    - `h1`
    - `p`
    - `button`
    - `img`

这种层层包含的关系，就像树干、树枝、树叶。你先把它理解成“网页结构图”就够了。JavaScript 不是直接去摸屏幕上的字，而是先找到树上的节点，再进行操作。

### 2. DOM 能做什么？

通过 DOM，JavaScript 可以：

- 找到某个元素
- 读取它的内容
- 修改它的内容
- 改变样式
- 修改属性
- 监听点击、输入等用户操作

比如，点一下按钮，标题变了；或者在输入框里输入名字，页面马上提示“欢迎你”。这些都属于 DOM 操作。

### 3. 一个最直观的理解

你可以把 DOM 想成“网页遥控器”。  
HTML 负责把东西摆出来，DOM 负责让这些东西**可以被程序控制**。

**老赵提醒：**  
别把 DOM 想得太神秘。你现在只要记住一句话：**DOM 就是 JavaScript 操作网页元素的入口。**

---

## 常见元素选择方式：id、class、标签名

### 这个问题先回答：JavaScript 怎么找到网页元素？

第一步不是改，而是**先找到**。就像你想擦桌子，得先知道桌子在哪儿。DOM 里常见的“找法”有三种：`id`、`class`、标签名。

---

### 1. 按 id 找：一对一，像身份证

`id` 通常是页面里唯一的，适合找一个确定元素。

```html
<h1 id="title">你好，JavaScript</h1>
```

```js
const title = document.getElementById('title');
```

这种写法就像拿身份证找人，目标明确。适合场景：

- 页面主标题
- 某个唯一按钮
- 某个唯一输入框

如果你知道“我就要找这一个”，那 `id` 往往最方便。

---

### 2. 按 class 找：一对多，像同一类标签

`class` 可以给多个元素使用，像“同一类商品贴同样的分类标签”。

```html
<p class="note">第一条</p>
<p class="note">第二条</p>
```

```js
const notes = document.getElementsByClassName('note');
```

这时拿到的是一组元素，不是单个元素。适合批量处理同类内容，比如把所有提示文字一起改样式。

---

### 3. 按标签名找：按类型抓一批

比如你想找到页面上所有 `p` 标签：

```js
const paragraphs = document.getElementsByTagName('p');
```

这种方式适合批量处理同类元素。对新手来说，最重要的不是背方法名，而是先分清：**你要找一个，还是找一组。**

**老赵提醒：**  
新手最容易犯的错，是把“单个元素”和“元素集合”搞混。先看清楚你拿到的是一个，还是一堆。换句话说，先别着急“下手改”，得先认清“你找到的是谁”。

---

## 修改文本、样式和属性的基础方法

### 找到了元素，接下来怎么改？

找到元素后，常见就是三件事：**改文字、改样式、改属性**。

---

### 1. 修改文本：让页面内容变一变

```js
const title = document.getElementById('title');
title.textContent = 'JavaScript 已经开始动起来了';
```

`textContent` 可以理解为“这个元素里显示的文字内容”。

**生活化比喻：**  
像给便利贴重新写字。贴纸还是那张贴纸，但上面的内容换了。

如果你想修改的是页面上能直接看到的文字，大多数时候就用它。

---

### 2. 修改样式：让页面看起来不同

```js
title.style.color = 'red';
title.style.fontSize = '24px';
```

这就像给房间换灯光、换墙色。页面本身没变，但视觉效果变了。

注意：这里是 JavaScript 临时改样式，适合小交互；大量样式设计还是交给 CSS。简单说，CSS 负责“装修风格”，JavaScript 负责“临时调整”。

---

### 3. 修改属性：比如图片地址、链接地址

```html
<img id="photo" src="a.jpg" alt="头像">
```

```js
const photo = document.getElementById('photo');
photo.src = 'b.jpg';
```

图片的 `src`、链接的 `href` 都是常见属性。你可以把属性理解成“这个东西身上的信息卡”。

**常见误区：**

- 文本内容改了，却以为图片地址也会自动变
- 把属性和显示文字混为一谈

文字是文字，属性是属性，这两件事不要混在一起。

---

## 获取输入框取值的基本方式

### 用户输入的内容怎么拿到？

网页交互里，输入框非常常见，比如输入姓名、密码、搜索关键词。

### 1. 输入框的值放在哪里？

输入框里用户写进去的内容，不在 `textContent` 里，而是在 `value` 里。

```html
<input id="nameInput" type="text">
```

```js
const input = document.getElementById('nameInput');
const name = input.value;
```

### 2. 最简单的区分

- `textContent`：看得见的文字
- `value`：输入框里的值

这就像：

- 招牌上的字，用眼睛看
- 盒子里装的内容，要打开才知道

如果拿错地方，代码就会“看起来没错，结果不对”。

### 3. 读取后能做什么？

```js
console.log(name);
```

也可以拿来做判断：

```js
if (name === '') {
  alert('请先输入姓名');
}
```

这就是把读到的数据拿来参与逻辑判断。很多网页功能，都是从这里开始的。

**老赵提醒：**  
输入框取值是表单交互的核心基础。先记住一句话：**输入框看 `value`，普通文字看 `textContent`。**

## 小案例：点击按钮改变页面文字或图片

### 怎么把“点击”变成“变化”？

下面我们做一个很典型的小交互：**点击按钮，改变标题文字和图片**。

### 1. HTML 结构

```html
<h1 id="title">欢迎光临</h1>
<img id="photo" src="a.jpg" alt="示例图片">
<button id="changeBtn">点击我</button>
```

### 2. JavaScript 代码

```js
const title = document.getElementById('title');
const photo = document.getElementById('photo');
const changeBtn = document.getElementById('changeBtn');

changeBtn.addEventListener('click', function () {
  title.textContent = '页面已经被我改过了';
  photo.src = 'b.jpg';
});
```

### 3. 这段代码在做什么？

可以拆成三步：

1. 找到标题、图片、按钮
2. 给按钮绑定点击事件
3. 用户一点击，就修改文字和图片

这就像先把遥控器、电视都准备好，再按下按钮让它们产生反应。

### 4. 你要真正理解的是“流程”

不是一上来就写复杂逻辑，而是：

- 先选中元素
- 再监听事件
- 最后执行修改

这就是网页交互的基本套路。

# 第10章 第10章：事件基础——让用户一点击，网页就回应

## 开篇引入：网页不是“摆设”，它要会回话

前面我们学了变量、判断、循环、函数，像是在学“怎么写句子”。但如果网页只会自己演示，不会理用户，那它就像一台关着门的自动售货机：东西摆得再整齐，别人也只能站在外面看。

**事件**，就是用户和页面之间的“对话”。  
你点按钮、输入文字、提交表单，网页都能收到信号，然后做出反应。学会事件，JavaScript 才真正从“会写代码”变成“能做交互”。

你可以把它理解成：网页原来只是“看板”，学了事件之后，它就开始“听得懂人话”了。用户一出手，页面马上回应，这才像真正的网页应用。

---

## 一、事件是什么：用户和页面之间的“对话”

你可以把页面想成一个很灵敏的服务员。用户一抬手，它就看见了；用户一点菜单，它就记住了；用户一按“确认”，它就开始行动。前端里的“事件”，本质上就是**某个动作发生了**，而我们要告诉网页：**发生之后，你该干什么**。

入门阶段先记住三类就够用：

- **点击事件**：用户点了按钮、链接、图片
- **输入事件**：用户在输入框里打字、删字
- **提交事件**：用户提交表单，准备把信息交出去

事件不是“发生了什么”这么简单，而是“**发生之后网页怎么回应**”。比如：

- 点击按钮后弹出提示
- 输入框里有内容就同步显示
- 提交表单前先检查内容是否为空

### 小案例：点击按钮说“你好”

用户点一下按钮，网页回应一句“你好”。这就是最简单的事件交互。看上去简单，但背后的思路很重要：**用户做动作，页面给反馈**。只要这个链路通了，后面的很多功能都能照着做。

---

## 二、事件绑定的基本方式：先告诉网页“谁来听”

事件不会自己生效，你得先把“监听”挂上去。  
这就像给门铃装上电池：门铃本身不会响，得先接好，别人按了才有反应。

常见做法是先拿到页面元素，再给它绑定事件。步骤可以记成三步：

1. 找到元素  
2. 绑定事件  
3. 写出响应动作

```html
<button id="btn">点我</button>
<p id="tip"></p>

<script>
  const btn = document.querySelector('#btn');
  const tip = document.querySelector('#tip');

  btn.addEventListener('click', function () {
    tip.textContent = '你刚刚点击了按钮';
  });
</script>
```

这里的 `addEventListener` 可以理解为：**给这个元素安排一个“值班员”**。只要用户触发了对应动作，这个值班员就会执行后面的代码。

### 为什么推荐这种写法

- 更清楚，容易读懂
- 可以给同一个元素绑定多个事件
- 不容易把 HTML 和 JS 混成一团

### 老赵提醒

> 先学会“给谁绑什么事件”，再去研究复杂写法。新手阶段，目标不是炫技，而是让页面先动起来。

---

## 三、点击、输入、提交：先认识最常用的三种事件

事件很多，但入门阶段先抓住三个就够了。它们就像厨房里最常用的三把刀：先会这几个，基本就能做菜了。

### 1. 点击事件：`click`

用户点按钮、链接、图标时触发。适合做：

- 弹窗提示
- 显示/隐藏内容
- 切换状态

```js
btn.addEventListener('click', function () {
  alert('按钮被点击了');
});
```

点击事件最适合做“立刻有反馈”的功能。用户点一下，页面马上告诉他“我收到啦”。

### 2. 输入事件：`input`

用户在输入框中输入、删除、粘贴内容时触发。适合做：

- 实时提示
- 字数统计
- 输入内容同步显示

```js
const input = document.querySelector('#name');
const show = document.querySelector('#show');

input.addEventListener('input', function () {
  show.textContent = input.value;
});
```

这里的 `value` 就是输入框当前的值。你可以把它理解成“这个盒子里现在装了什么”。

### 3. 提交事件：`submit`

用户提交表单时触发。适合做：

- 基础校验
- 防止空表单提交
- 提交前提醒

```js
form.addEventListener('submit', function (e) {
  e.preventDefault();
  alert('表单先别急着提交，我们先检查一下');
});
```

`preventDefault()` 的意思可以理解成“先别按默认流程走”。比如表单原本会刷新页面提交，但我们想先检查内容，就可以先拦一下。

### 小练习

1. 做一个按钮，点击后显示“我被点了”  
2. 做一个输入框，输入内容时把文字同步显示出来  
3. 做一个表单，点击提交后先弹出提示，不让页面刷新

## 四、简单按钮点击案例：点击前和点击后，页面真的变了

下面我们做一个完整的小案例：点击按钮后，提示文字改变。这个例子很适合零基础，因为它非常直观——**点之前是什么样，点之后变成什么样，一眼就能看出来**。

### 案例目标

- 页面上有一个按钮
- 有一段提示文字
- 点击按钮前：显示“当前状态：未开启”
- 点击按钮后：变成“当前状态：已开启”

```html
<button id="changeBtn">开启功能</button>
<p id="status">当前状态：未开启</p>

<script>
  const changeBtn = document.querySelector('#changeBtn');
  const status = document.querySelector('#status');

  changeBtn.addEventListener('click', function () {
    status.textContent = '当前状态：已开启';
  });
</script>
```

### 拆解一下

- `querySelector`：找到页面元素
- `addEventListener('click', ...)`：监听点击
- `textContent`：修改文本内容

你会发现，事件其实就是“**收到信号后，执行动作**”。用户按一下，页面就改一句话；用户再按一下，页面还能继续变。

### 再进一小步：切换状态

如果想更像开关，可以让按钮每点一次就切换一次状态：

```js
let on = false;

changeBtn.addEventListener('click', function () {
  on = !on;
  status.textContent = on ? '当前状态：已开启' : '当前状态：未开启';
});
```

这里用了布尔值 `true/false`。你可以把它想成灯的开关：不是亮，就是灭。`!on` 的意思就是把状态反过来。

## 五、把事件和 DOM 连起来：先找到元素，再让它动起来

很多新手一开始学事件时，会觉得它像一个“单独的知识点”。其实不是。**事件和 DOM 是连在一起的**：先用 DOM 把元素找到，再给这个元素绑事件，最后通过 DOM 改变页面内容。

你可以把这个过程想成“拿钥匙开门”：

- `querySelector` 是找门
- `addEventListener` 是告诉门“有人来按铃了”
- `textContent`、`value`、`style` 是开门后真正做的事

比如下面这个例子，点击按钮后把提示文字改掉：

```js
const btn = document.querySelector('#btn');
const tip = document.querySelector('#tip');

btn.addEventListener('click', function () {
  tip.textContent = '按钮已经生效';
});
```

如果没有 DOM，事件就没法找到目标；如果没有事件，DOM 只是静静躺着，不会自己变。两者配合起来，网页才会“听见人说话”。

## 六、事件处理中的常见注意点：别让网页“听错话”

事件很好用，但新手常会踩几个坑。

### 1. 元素没找到

如果选择器写错了，事件就绑不上。检查方法：

- ID 有没有拼错
- 标签是否真的存在
- 代码是否写在元素后面，或者是否等页面加载完再执行

### 2. 变量写错作用范围

有些变量定义在函数里，外面访问不到。简单记：**在哪里定义，就尽量在那里使用**。别把代码写得东一块西一块，不然自己回头看也容易迷路。

### 3. 表单提交导致页面刷新

如果处理表单时没写 `preventDefault()`，页面可能会直接刷新，前面的提示就一闪而过。第一次做表单校验时，这个问题很常见。

### 4. 一个元素绑定多个事件时要分清

点击、输入、提交是不同动作，不要把所有逻辑都塞到一个事件里。不然代码像一锅粥，自己看都费劲。

### 5. 先做最小功能

别一上来就想做“点击后自动计算、自动保存、自动弹窗、自动校验一整套”。新手更适合先做到：**点一下有反应**。先把最小闭环跑通，再慢慢加功能。

### 老赵提醒

> 事件处理最重要的不是写得多，而是写得准。先让网页“听懂用户”，再谈复杂逻辑。

---

## 七、简单表单校验与交互：提交前先看一眼

事件最实用的地方之一，就是做基础表单检查。比如用户注册时，至少要先判断用户名、密码、手机号是不是为空。

### 小案例：检查输入是否为空

```html
<form id="loginForm">
  <input type="text" id="username" placeholder="请输入用户名">
  <button type="submit">提交</button>
</form>
<p id="msg"></p>

<script>
  const form = document.querySelector('#loginForm');
  const username = document.querySelector('#username');
  const msg = document.querySelector('#msg');

  form.addEventListener('submit', function (e) {
    e.preventDefault();

    if (username.value.trim() === '') {
      msg.textContent = '用户名不能为空';
    } else {
      msg.textContent = '提交成功，用户名是：' + username.value;
    }
  });
</script>
```

### 这里学到什么

- `trim()`：去掉前后空格，避免用户只输入空格
- `if/else`：先判断，再决定提示什么
- `value`：获取输入框内容
- `preventDefault()`：阻止默认提交行为

这就是最基础的表单校验。像门卫检查证件一样，先看有没有填，再决定放不放行。你不用一下子做得很复杂，先把“空没空”检查好，就已经是一个有用的小功能了。

如果你愿意，还可以继续扩展：比如用户名长度太短就提醒、密码为空就提示、两个输入框内容不一致就告知用户。思路都一样，先取值，再判断，再反馈。

# 第11章 第11章：简单表单校验——让用户少填错、少走弯路

## 开篇引入：为什么表单校验这么重要？

表单就像门口登记表，用户每填一个框，系统就收一条信息。要是没人检查，名字可能没填、密码可能太短、手机号少一位，最后提交时拿到的就是一份“半成品”。

**表单校验**，就是在用户提交前先把明显错误拦下来。它不是找茬，而是提前提醒：

- 这里不能空着
- 这个长度太短
- 这个格式不对
- 你可能少写了一位

对新手来说，这一章很重要，因为它会把前面学过的 **变量、条件判断、函数、DOM、事件** 串成一个真正能用的小功能。

### 老赵提醒
表单校验不是为了刁难用户，而是为了让用户少走弯路。你写代码时，要像提醒的人，不是监考老师。

---

## 一、表单校验为什么重要：减少错误输入

表单校验的核心作用就一句话：**减少错误输入，减少返工**。

比如注册账号时，常见问题有：

- 用户名没填
- 密码太短
- 邮箱少了 `@`
- 电话号码多了空格

如果系统不提醒，用户提交后再被打回去，就会觉得麻烦，甚至直接离开。所以，校验不是多此一举，而是让网页更友好、更专业。

### 常见的基础校验目标
1. **不能为空**
2. **长度要合适**
3. **格式要基本正确**
4. **提示要清楚**

新手阶段不用把规则做得很复杂，先把最常见的错误拦住就够了。

### 老赵提醒
校验规则要像红绿灯：**简单、明确、直接**。别一下子搞太复杂，不然用户和你自己都会看晕。

---

## 二、输入框取值与空值判断：怎么知道用户填了什么？

做校验的第一步，不是判断对错，而是先把用户输入的内容拿出来。

### 1. 获取输入框的值

```html
<input type="text" id="username">
```

```javascript
const input = document.getElementById("username");
const value = input.value;
```

这里的 `value` 就是输入框里的内容。你可以把输入框想成一个小盒子，`value` 就是盒子里装的东西。

### 2. 判断空值

最常见的判断就是：用户有没有输入内容。

```javascript
if (value === "") {
  alert("用户名不能为空");
}
```

但用户可能只输入空格，比如 `"   "`。这时看起来有内容，实际上还是没填。通常先去掉前后空格：

```javascript
const value = input.value.trim();
```

`trim()` 的作用就是去掉字符串前后的空格。这样一来，用户只输入空格，也会被当成空。

### 小案例：检查用户名是否为空

```javascript
const input = document.getElementById("username");
const name = input.value.trim();

if (name === "") {
  alert("请输入用户名");
}
```

### 老赵提醒
很多新手会忘记 `trim()`，结果用户只输空格也被当成“填了”。这就像检查作业只看有没有字，不看是不是乱画的，当然不够稳。

---

## 三、常见校验规则：不能为空、长度限制、格式提示

表单校验不只是“空不空”，通常还会看这几类规则。

### 1. 不能为空

```javascript
if (name === "") {
  alert("用户名不能为空");
}
```

### 2. 长度限制

比如用户名至少 3 个字符，密码至少 6 个字符。

```javascript
if (name.length < 3) {
  alert("用户名至少 3 个字符");
}
```

`length` 可以理解为字符串的“长度尺子”，有几个字符就显示几。

### 3. 格式提示

有些字段不能只看长短，还要看样子对不对。比如邮箱通常要包含 `@`。

```javascript
if (email.indexOf("@") === -1) {
  alert("邮箱格式不正确");
}
```

再比如手机号：

```javascript
if (phone.length !== 11) {
  alert("手机号长度不对");
}
```

这个例子很适合入门，因为简单直接。真实项目里还会继续检查数字内容，但现在先把基本思路练熟更重要。

### 常见误区
- 只判断长度，不判断内容
- 只判断有没有填，不判断是否全是空格
- 提示语太笼统，比如“输入错误”

### 老赵提醒
校验规则要像路牌，**一眼看懂，一步到位**。提示越清楚，用户越不容易反复试错。

---

## 四、用 if / else 和函数实现基础校验：怎么把判断写得更清楚？

当校验规则变多后，如果把所有代码堆在一起，会很乱。这时候就该请出两个老朋友：**if / else** 和 **函数**。

### 1. 用 if / else 做判断

`if / else` 的意思很像日常说话：

- 如果满足条件，就做这件事
- 否则，就做另一件事

```javascript
if (name === "") {
  alert("用户名不能为空");
} else {
  alert("用户名已填写");
}
```

你可以把它理解成“左拐还是右拐”，代码会根据条件走不同路线。

### 2. 用函数封装校验逻辑

函数就像一个重复使用的小工具。比如：

```javascript
function checkUsername() {
  const input = document.getElementById("username");
  const name = input.value.trim();

  if (name === "") {
    alert("用户名不能为空");
    return false;
  }

  if (name.length < 3) {
    alert("用户名至少 3 个字符");
    return false;
  }

  return true;
}
```

这里有两个关键点：

- **函数声明**：`function checkUsername() {}`
- **返回值**：`return true` 或 `return false`

`false` 表示校验没通过，`true` 表示通过了。你可以把它理解成“通行证”：

- `true`：可以放行
- `false`：需要拦下

### 为什么要用函数？
因为你不想每次都重复写一大段判断。函数就像打包好的工具箱，需要时直接拿出来用。以后检查密码、手机号、邮箱，也可以照这个思路写。

### 老赵提醒
函数不是为了显得高级，而是为了让代码像一个整洁的抽屉：东西分好类，下次才好找。

---

## 五、小案例：用户名或密码的简单校验

下面做一个最实用的小例子：**点击按钮后，检查用户名和密码是否合格。**

### 页面结构

```html
<input type="text" id="username" placeholder="请输入用户名">
<input type="password" id="password" placeholder="请输入密码">
<button id="submitBtn">提交</button>
```

### JavaScript 代码

```javascript
function checkForm() {
  const username = document.getElementById("username").value.trim();
  const password = document.getElementById("password").value.trim();

  if (username === "") {
    alert("用户名不能为空");
    return false;
  }

  if (username.length < 3) {
    alert("用户名至少 3 个字符");
    return false;
  }

  if (password === "") {
    alert("密码不能为空");
    return false;
  }

  if (password.length < 6) {
    alert("密码至少 6 位");
    return false;
  }

  alert("校验通过，可以提交！");
  return true;
}

const btn = document.getElementById("submitBtn");
btn.addEventListener("click", checkForm);
```

### 这个案例做了什么？
- 用 DOM 找到输入框和按钮
- 用事件绑定监听按钮点击
- 用 `trim()` 去掉空格
- 用 `if` 逐步判断
- 用函数把校验流程装起来

这就是一个完整的小交互闭环。

### 老赵提醒
校验代码常见写法就是：**从上往下，一条一条检查，发现问题立刻返回**。这样清晰，也好排错。

**老赵提醒：** 学编程最怕“只看懂，不会做”。从这一章开始，学一个知识点，就想想它能在哪个小功能里用上。

## 这个小项目要做什么？

我们的留言板页面里有这些内容：

- 一个输入框，用来输入留言；
- 一个按钮，点击后提交；

如果你愿意，还可以把它改成**待办清单**：把“留言”换成“今天要做的事”，功能逻辑几乎一样。这个项目不复杂，但很适合练手，能把你前面学到的“变量、判断、循环、函数、数组、事件”都串起来。

## 先把要用的知识点捋一遍

### 1. 变量与数据类型

我们会用 `let` 保存会变化的内容，比如用户输入、消息数组；用 `const` 保存不会变的元素和规则，比如按钮、提示框、输入框。

这里会用到：

- **字符串**：用户输入的文字；
- **数字**：比如长度判断、条目序号；
- **布尔值**：比如“是否通过校验”。

可以把它理解成收纳盒：字符串放文字，数字放数量，布尔值放“是/否”的判断结果。

### 2. 条件判断

用 `if/else` 判断输入是否为空、长度是否合格。  
如果想把不同情况分开提示，也可以用 `switch` 做简单分类，比如空内容、太短、正常提交。

条件判断就像门卫看证件：符合条件就放行，不符合就拦下来。

### 3. 循环

如果要把消息列表逐条显示，就要用循环。`for` 和 `while` 都能派上用场。

循环的作用很像整理一盒彩色积木：一块一块拿出来检查，直到全部处理完。

### 4. 函数

把“获取输入”“检查内容”“显示提示”“添加列表项”分别写成函数。函数声明写起来很直白，像是在给每个小任务贴标签。

函数就像家里的分工：洗菜的人洗菜，切菜的人切菜，炒菜的人炒菜，厨房才不会乱。代码也是一样，拆开写更清楚，也更容易改。

### 5. 数组与对象

数组用来存放多条留言，方便统一管理；对象可以描述一条留言的细节，比如内容、时间、状态。

数组像排队的小朋友，对象像每个小朋友的身份证，里面写着名字和信息。

### 6. DOM 与事件

我们要通过 DOM 找到输入框、按钮、提示区，再通过事件绑定，让按钮“听话”。

用户点击按钮的时候，程序才开始运行。这就是网页真正“动起来”的地方。

## 第一步：先搭出页面骨架

先写 HTML，把输入框、按钮、提示区和列表放好。

```html

<p id="tip"></p>
<ul id="msgList"></ul>
```

## 第二步：用 DOM 找到元素并绑定事件

通过 `document.querySelector()` 把这些元素拿到手里。后面想改内容、清空输入框、更新列表，都得先找到它们。

```js
const input = document.querySelector("#msgInput");
const btn = document.querySelector("#sendBtn");
const tip = document.querySelector("#tip");
const list = document.querySelector("#msgList");
```

再给按钮加点击事件。用户一按，程序就开始工作。

```js
btn.addEventListener("click", function () {
  // 后面写处理逻辑

```

## 第三步：读取输入框值并做基础校验

输入框里的内容一般通过 `.value` 获取。读到之后，最好先用 `trim()` 去掉前后的空格，不然用户输入几个空格，也可能被误认为“有内容”。

常见校验可以先做这几个：

- 不能为空；
- 长度不能小于 2；
- 不能只输入空格。

```js
const text = input.value.trim();

if (text === "") {
  tip.textContent = "内容不能为空";
  return;
}

if (text.length < 2) {
  tip.textContent = "至少输入2个字";
  return;
}
```

这就像收快递：地址要写、收件人要对、内容不能乱来。先把基础条件过一遍，后面处理才稳。

## 第四步：把数据存起来，再渲染到页面上

校验通过后，我们把内容加入数组，再用循环重新显示列表。

```js
let messages = [];

messages.push(text);
tip.textContent = "提交成功";

list.innerHTML = "";
for (let i = 0; i < messages.length; i++) {
  list.innerHTML += `<li>${i + 1}. ${messages[i]}</li>`;
}
input.value = "";
```

这里的 `messages` 是数组；`if` 负责判断；`for` 负责循环渲染；`addEventListener` 负责绑定事件。你会发现，前面学过的内容已经开始连成一片了。

## 小案例：完整留言板代码

下面是一个可以直接看的完整版本，重点不是死记，而是看懂它们怎么配合。

```js
const input = document.querySelector("#msgInput");
const btn = document.querySelector("#sendBtn");
const tip = document.querySelector("#tip");
const list = document.querySelector("#msgList");

let messages = [];

btn.addEventListener("click", function () {
  const text = input.value.trim();

  if (text === "") {
    tip.textContent = "内容不能为空";
    return;
  }

  if (text.length < 2) {
    tip.textContent = "至少输入2个字";
    return;
  }

  messages.push(text);
  tip.textContent = "提交成功";

  list.innerHTML = "";
  for (let i = 0; i < messages.length; i++) {
    list.innerHTML += `<li>${i + 1}. ${messages[i]}</li>`;
  }

  input.value = "";
});
```

如果你想继续练，可以把 `messages` 改成对象数组，例如：

```js
messages.push({ text: text, time: "刚刚" });
```

这样以后还能扩展成显示时间、状态、是否已完成等信息。

## 调试思路：哪里出错，怎么找问题？

新手最常遇到的问题，不是不会写，而是“写了没反应”。这很正常，排查时按顺序来就行。

### 1. 先看元素有没有找对

选择器写错，后面全白干。比如按钮 id 明明是 `sendBtn`，你却写成 `#send-btn`，那就找不到元素。

### 2. 再看事件有没有绑上

按钮点了没反应，先检查 `addEventListener` 是否写对，括号和函数有没有漏掉。

### 3. 看输入值有没有取到

如果 `input.value` 一直是空，可能是变量拿错，或者你读取的不是那个输入框。

### 4. 最后看逻辑判断

有时不是代码报错，而是条件太严格。比如你想判断空字符串，却忘了去掉空格，用户输入几个空格也会被当成内容。

### 5. 必要时加输出检查

可以临时用 `console.log(text)` 看看取到的值是什么。  
这就像修水管时先开小水看看哪里漏，比盲猜靠谱得多。
