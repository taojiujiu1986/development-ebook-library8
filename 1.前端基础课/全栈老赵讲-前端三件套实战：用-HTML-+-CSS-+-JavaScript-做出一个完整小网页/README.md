# 第1章 第1章 先选一个能做完的小网页：明确目标、范围和成品样子

## 开篇引入：先别急着学，先把“做什么”定下来

很多新手一上来就忙着今天学一点 HTML、明天看一点 CSS、后天摸一点 JavaScript，知识点记了一堆，真打开编辑器还是不知道从哪儿开始。

所以这本书不走“先把知识学全再做项目”的路子。我们先做一个**小而完整**的网页。因为你真正要练的，不是单独某个语法，而是把 HTML、CSS、JavaScript 串起来，做出一个能看、能用、能改的小作品。

这一章先不写代码，先把目标、范围和成品样子定清楚。边界一旦明确，后面每一步都会轻松很多。

---

## 为什么先做小而完整的网页？

新手最常见的误区，就是总想着“等我都学会了，再开始做项目”。但前端很多能力，不是靠看懂，而是靠做出来。

小网页的好处很直接：

- **范围可控**：不会一上来就被复杂需求吓住。
- **结果清楚**：每一步做完，页面都会有变化，容易建立成就感。
- **方便练协作**：HTML 管结构，CSS 管样式，JS 管交互，正好一起上场。
- **便于复盘**：做完一个小项目，你才能知道自己到底卡在结构、样式还是交互。

你可以把它理解成：先学会做一盘完整的菜，再考虑做一桌宴席。对新手来说，先完成，再优化，比一开始就追求“大而全”更重要。

---

## 本书最终要做成什么样？

这本书最后不会带你做复杂大系统，而是完成几个**基础可用的小作品**。它们有一个共同点：打开能看，操作有反馈，逻辑讲得清，适合新手独立完成。

### 先做静态页面，站稳骨架

静态页面阶段，先把内容、排版和基本视觉效果做出来。比如个人介绍页，先放好头像、姓名、简介、技能标签和联系按钮。这个阶段的重点不是“炫”，而是把**结构搭起来**，让页面先像一个完整作品，而不是零散文字堆在一起。

### 再做半交互页面，让页面动起来

在静态页面基础上，再加一些基础操作，比如：

- 待办清单里点击按钮新增一条任务
- 登录页提交前做简单校验
- 商品展示页里点击按钮切换状态

这一步不追求复杂，只追求页面开始回应用户动作。也就是说，页面不是摆设，而是真的能对点击、输入这些行为做出反应。

### 最后形成可独立完成的小作品

到书末，你应该能独立做出一个小型静态或半交互网页。它不一定功能很多，但必须完整、清楚、可运行。新手阶段最怕的不是页面简单，而是简单的东西做不完整。

## 本书会做哪些示例页面？

### 个人介绍页：先练结构和排版

个人介绍页很适合入门，因为内容少、结构清楚，不容易迷路。你会练到：

- HTML 结构搭建
- CSS 基础布局与美化
- 文本、头像、按钮的基础排版

它的价值在于：先把“页面长什么样”这件事做明白。通常只需要头像区域、姓名标题、简介文字、技能标签和联系按钮，你要做的就是把这些内容按层次摆清楚。

### 待办清单：练 DOM 和事件处理

待办清单适合练基础交互。比如输入任务后点击添加，任务出现在列表里。这里会接触到：

- DOM 操作
- 事件处理
- 简单数据渲染

它能让你第一次真正感受到：JavaScript 不只是变量和判断，而是可以控制页面变化。重点不是功能多，而是把“输入—点击—显示出来”这个流程跑通。

### 简单商品展示页：练数据渲染和布局

商品展示页可以看成一个小型卡片列表页面。你可以先准备几条商品数据，再把它们渲染到页面上。这里重点是：

- 用结构承接数据
- 用样式统一卡片视觉
- 用简单循环把数据展示出来

这类页面特别适合练“数据 → 页面”的思路。你会慢慢理解，前端不只是手写元素，也可以把一组数据自动变成页面内容。

### 登录页：练表单提交前校验

登录页最适合练表单和校验。比如：

- 用户名不能为空
- 密码长度不能太短
- 点击提交前先检查输入是否合理

这一步会让你理解：交互不只是“点一下有反应”，还包括“提交前先判断对不对”。如果不先校验，用户点了提交才发现输入有问题，体验就会很差。

## 为什么按“先结构、后样式、再交互”做？

### 先结构：先把骨架立住

HTML 是页面骨架。先写结构，原因很简单：如果连内容块都没搭好，CSS 和 JS 都没有地方挂。

新手常犯的错，是一边写 HTML，一边急着调样式，最后页面结构乱了，改起来更痛苦。正确顺序应该是：

1. 先确定页面有哪些区域
2. 再用 HTML 把这些区域搭出来
3. 然后用 CSS 做美化
4. 最后加 JavaScript 做交互

这样做的好处是，每一步职责都清楚，不会一边改结构一边修样式，效率更高，出错也更少。

### 后样式：让页面看得顺眼

CSS 的任务是让内容更清楚、更舒服。先有结构，再上样式，你更容易判断：是内容组织不对，还是只是视觉不够好。

比如个人介绍页，先用 HTML 把信息块分好，再用 CSS 调字体、间距、颜色、圆角，这样修改起来很直观。反过来如果边写边调，常常会忘了自己到底是在优化内容，还是在修布局。

### 再交互：让页面真的“活”起来

JavaScript 负责响应点击、输入、提交等动作。如果前面结构和样式没定好，交互就会变成“边救火边写逻辑”。

按顺序做，问题少很多。你会更容易定位：是按钮没绑定事件，还是 DOM 选择器写错了，还是页面结构里压根没有对应元素。对新手来说，这种清晰度非常重要。

这就是从“学知识”走向“做页面”。以后你再看任何一个小项目，都会更容易判断自己该从哪一步开始。

# 第2章 第2章 先拆页面再动手：分析需求、画结构草图、定页面骨架

## 开篇引入：先别急着写代码，先把页面“想明白”

很多新手一拿到需求就急着打开编辑器，先堆几个 `div`，再补颜色，最后改来改去还是乱。老赵先给你一句实在话：**页面不是靠硬写出来的，是靠拆出来的。**

一个页面本质上是个小项目：有目标、有层级、有分工。你得先想清楚它展示什么、给谁看、重点在哪，后面 HTML 才知道怎么搭，CSS 才知道怎么排，JavaScript 才知道该管哪一块。

本章先不急着写 CSS 和 JS，先练最重要的习惯：**先结构、后样式、再交互**。这样 HTML 负责搭骨架，CSS 负责穿衣服，JavaScript 负责让它动起来，三者就不会互相打架。

这一章我们用**个人介绍页**做主案例，顺手看一下待办清单、简单商品展示页、登录页这几种页面怎么拆。学完后，你以后做别的小页面，也能按同一套思路来。

## 一、先从需求里拆出模块和功能点

### 1. 先问清楚这个页面要干什么

拿个人介绍页来说，需求不是一句“做个介绍页”就完了。你要先想：

- 这个页面给谁看？
- 想让用户看完后做什么？
- 页面里必须有哪些信息？
- 哪些内容只是展示，哪些以后可能要交互？

比如一个基础版个人介绍页，目标可能是：

- 展示头像和姓名
- 简单介绍自己会什么
- 提供几个入口按钮，比如“查看作品”“联系我”

需求一拆，页面轮廓就出来了。要是连目标都没想清楚，后面很容易变成“什么都想放，结果什么都不突出”。

### 2. 按“模块”拆，不要按“标签”拆

新手常犯的错，是上来就想“这里一个 `div`，那里一个 `p`”。  
正确方式是按模块拆：

- 头像区
- 标题区
- 自我介绍区
- 按钮区

每个模块都对应明确任务。这样做的好处是：**HTML 结构更清晰，后面 CSS 好写，JS 也知道该操作哪一块。**

比如头像区负责身份感，标题区告诉别人你是谁，简介区补充你做什么，按钮区负责引导用户下一步动作。模块一清楚，页面逻辑就顺了。

### 3. 一个页面拆模块，可以靠这三个判断

你可以用这三个问题判断一个内容是不是独立模块：

- 它是不是承担一个独立功能？
- 它是不是有自己的布局和样式需求？
- 它以后会不会单独变化？

如果三个问题里有两个答案是“是”，它大概率就该单独拆出来。

比如按钮区以后可能要换成“关注我”“下载简历”，那它值得单独成块；而一句辅助说明，如果只是补充信息，就可以并到简介区里，不必切得太碎。**新手最怕的不是拆得少，而是拆得乱。**

## 二、哪些内容放 HTML，哪些留给 CSS 和 JavaScript？

这部分很关键。很多新手页面乱，不是因为不会语法，而是不知道谁干什么。

### 1. HTML 负责什么？

HTML 负责**内容结构**，也就是“页面上有什么”。

比如个人介绍页里：

- 头像图片
- 姓名标题
- 简介文字
- 按钮
- 联系方式

这些都应该先用 HTML 搭出来。  
一句话：**HTML 是骨架，先把东西摆对位置。**

### 2. CSS 负责什么？

CSS 负责**视觉表现和布局**，也就是“页面长什么样”。

比如：

- 头像圆不圆
- 标题居中还是左对齐
- 卡片有没有阴影
- 按钮颜色是什么
- 模块之间间距多大

这些都属于 CSS 的事。记住：**先让结构出现，再让它变漂亮。**  
如果顺序反过来，先纠结颜色和阴影，最后结构一改，样式很容易跟着全乱。

### 3. JavaScript 负责什么？

JavaScript 负责**交互和动态变化**，也就是“页面会不会动”。

比如：

- 点击按钮后显示提示
- 切换关注状态
- 根据数据渲染不同内容
- 表单提交前先检查输入是否合法

如果页面只是静态展示，JS 可以少一点；如果要做半交互页面，JS 就负责把“变化”补上。

### 4. 老赵给你的分工口诀

- **HTML：有什么**
- **CSS：长什么样**
- **JS：会不会动**

先把这三件事分开想，写代码的时候就不容易乱。后面你做待办清单、登录页、商品卡片，都是这个逻辑。

## 三、页面草图怎么画，为什么草图能减少返工？

### 1. 草图不是艺术，是排版蓝图

很多人一听“画草图”就觉得要会画画。其实不是。  
草图不追求好看，只追求一件事：**把页面层级和位置先想清楚。**

你可以手绘，也可以直接写块状结构：

- 顶部：头像 + 姓名
- 中部：简介
- 底部：按钮

这就够了。草图的目的不是展示，而是给你自己定心。你先把脑子里的零散想法落下来，后面写代码时才不会东一块西一块。

### 2. 为什么草图能减少返工？

因为它能提前暴露问题。比如：

- 头像放左边还是上边？
- 标题和简介是上下排还是左右排？
- 按钮要不要并排？
- 哪些元素应该放在同一个卡片里？

如果这些问题不先想，你写到一半才发现布局不对，就要大改 HTML 和 CSS。  
草图的作用，就是把返工尽量拦在编码之前。

老赵提醒你一句：**代码改起来不怕，结构错了才麻烦。**  
结构错，样式跟着错；样式错，交互定位也容易出问题。

### 3. 草图要画到什么程度？

不用画很细，够用就行。建议至少包含：

- 每个模块的位置
- 模块之间的大致关系
- 哪些内容属于主视觉
- 哪些内容是辅助信息

你可以把它理解成：**先定房间格局，再买家具。**  
格局定好了，后面怎么摆都不会太离谱。

## 四、以个人介绍页为例，定页面骨架

现在我们拿一个完整一点的个人介绍页来拆。  
假设需求是：

- 有头像
- 有姓名和一句身份描述
- 有一段自我介绍
- 有两个按钮：查看作品、联系我

### 1. 页面骨架可以这样定

从结构角度看，它可以拆成一个主卡片，里面再分四块：

1. **头像区**：放图片  
2. **标题区**：放姓名、身份描述  
3. **简介区**：放一段介绍文字  
4. **按钮区**：放操作按钮

这时候你就已经知道 HTML 大概长什么样了。  
你甚至可以先不写代码，直接在脑子里想：外面一个容器，里面四个模块。这样一来，后面每个标签放哪儿，心里就有数。

### 2. 这个拆法为什么适合新手？

因为它简单、稳定、好扩展。  
以后你想加一句“我擅长什么”，它可以放进标题区或简介区；想加一个小标签，也能放在主卡片里。先把主结构定住，后面加内容才不会乱。

### 3. 这个阶段的阶段成果

到这里，虽然还没加样式，也没加交互，但你已经完成了一个重要阶段成果：

- 明确了页面目标
- 拆出了核心模块
- 画出了结构草图
- 定好了 HTML 骨架

这意味着你已经从“想到哪写到哪”，变成“先规划再实现”。

## 五、新手常见错误：边写边想、结构没定就开始加样式

### 1. 边写边想，最容易越写越散

新手常常是这样：

- 先写一个头像
- 觉得旁边空着，又加标题
- 然后发现标题下面太空，又加文字
- 最后按钮放哪都不顺眼

问题不是代码不对，而是**没有统一结构方案**。  
页面一旦没有方案，就会不停补洞，最后看起来像拼出来的，缺少整体感。

### 2. 结构没定就加样式，后面很容易重来

如果你一开始就先调颜色、阴影、边距，最后发现结构要改，样式基本都得跟着重做。  
所以老赵建议：**先把 HTML 结构搭稳，再统一做 CSS。**

这不是讲究流程，而是为了省时间。你越早定结构，后面越少返工。

### 3. 给新手一个简单检查点

每次写页面前，先问自己三件事：

- 这个页面的核心模块有哪些？
- 每个模块的作用是什么？
- 先放进 HTML 的内容有哪些？

如果这三件事还没答清楚，就别急着动手写样式。  
先把思路捋顺，再开始敲代码，效率反而更高。

## 六、把这套方法迁移到别的小页面

这套“先拆再写”的方法，不只适合个人介绍页。

### 1. 待办清单页

你先拆出：

- 输入框
- 添加按钮
- 任务列表
- 每条任务的删除或完成状态

这里的重点就是列表结构清楚，后面 JavaScript 再负责新增、删除、切换状态。

### 2. 简单商品展示页

你可以先拆成：

- 商品卡片容器

# 第3章 第3章 先把骨架搭起来：用 HTML 完成个人介绍页结构

## 开篇引入：先别急着写样式，今天只做一件事——把个人介绍页的“骨架”搭起来

前两章我们已经知道，HTML 负责结构，CSS 负责好看，JavaScript 负责动起来。这一章先做最关键的一步：**只用 HTML，把一个个人介绍页的内容层次搭出来**。

为什么先做这一步？因为很多新手一上来就想着居中、阴影、渐变、动效，结果页面看着像样，代码却乱。正确顺序永远是：

1. **先结构**
2. **后样式**
3. **再交互**

这一章我们就按这个顺序，做一个基础但完整的**个人介绍页**。做完后，你会得到一个已经分好区域、能看出层次的页面骨架。后面加 CSS 和 JS，就有基础可依。

记住一句话：**这一章不追求漂亮，只追求“内容摆对位置”**。页面骨架搭稳了，后面的工作才是在“装修房子”，而不是一边装修一边补地基。

---

## 一、HTML 基本骨架怎么组织？页面从哪里开始写起？

先回答一个最基础的问题：**HTML 文件到底从哪儿开始写？**

一个标准网页，先有最外层框架，再往里放内容。你可以把它理解成“房子先打地基，再砌墙，再摆家具”。

### 1. 基础页面结构

先把最基本的 HTML 结构写出来：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>我的个人介绍页</title>
</head>
<body>

</body>
</html>
```

这几行不是装饰，是网页起点：

- `<!DOCTYPE html>`：告诉浏览器这是标准 HTML5 页面
- `<html lang="zh-CN">`：声明页面语言
- `<head>`：放页面信息，不直接显示内容
- `<body>`：真正显示内容的地方

### 2. 为什么先写这个？

因为你后面所有内容，最终都得落到 `body` 里。新手常见错误是：直接写内容，却不知道自己写在什么层级里，结果标签套错、结构乱掉。**先搭骨架，就是先明确“页面从哪里开始、内容放哪里”**。

另外先把 `title` 写好也很实用。浏览器标签页显示的就是它，打开多个页面时一眼能认出来，也方便调试。

#### 阶段成果

到这里，你已经拥有了一个可打开的空白网页框架。

---

## 二、个人介绍页要分哪几块？先把层次拆清楚

今天这个案例是**个人介绍页**，它不需要太复杂，但必须层次分明。老赵建议你先按“头部、简介、信息区、操作区”来拆。

### 1. 页面分层路径

- **头部**：放名字、身份、头像或一句话介绍
- **简介**：说清楚自己是谁、在做什么
- **信息区**：列出技能、联系方式、兴趣
- **操作区**：放“联系我”“查看作品”这类动作

这样分的原因很简单：  
**先让读者一眼知道你是谁，再慢慢看你的信息，最后留一个能点击的出口。**

### 2. 对应到 HTML 结构

常见写法可以这样组织：

- `<header>`：头部区域
- `<main>`：主体内容
- `<section>`：每个独立内容块
- `<footer>`：底部收尾

这种结构的好处不是“高级”，而是**清楚**。以后你要给某个区域加样式、加按钮、加图片，定位会非常快。

## 三、把内容放进页面：先写出能看懂的骨架

下面我们直接把个人介绍页的内容搭出来。先别管样式，先把位置摆对。

```html
<body>
  <header>
    <h1>全栈老赵</h1>
    <p>前端学习路上的带路人</p>
  </header>

  <main>
    <section>
      <h2>关于我</h2>
      <p>我喜欢把复杂知识讲简单，带你一步一步做项目。</p>
    </section>

    <section>
      <h2>我的信息</h2>
      <ul>
        <li>擅长：HTML / CSS / JavaScript</li>
        <li>风格：讲清楚原理，更注重实战</li>
        <li>目标：帮新手串起前端三件套</li>
      </ul>
    </section>

    <section>
      <h2>联系我</h2>
      <a href="mailto:demo@example.com">发邮件联系</a>
      <button type="button">关注我</button>
    </section>
  </main>

  <footer>
    <p>© 2025 我的个人介绍页</p>
  </footer>
</body>
```

### 1. 为什么这样放？

- `header` 放最上面，因为它是门面
- `main` 放主体内容，因为它是页面核心
- 每个 `section` 表示一个独立块，方便阅读和扩展
- `footer` 放收尾信息，结构完整

### 2. 这一版完成后，你能看到什么？

打开页面后，你会明显看到几块内容：

- 顶部有标题和简介
- 中间有“关于我”
- 再往下是“我的信息”
- 最后是“联系我”和页脚

也就是说，**你已经完成了一个有层次的个人介绍页骨架**。哪怕它现在还不漂亮，至少结构已经站稳了。

#### 阶段成果

现在页面已经不是空白框架，而是一个**内容分区清楚、可继续做样式的个人介绍页骨架**了。

## 四、图片、链接、按钮怎么放？新手别把它们混了

这一部分很关键，因为后面做待办清单、登录页、商品展示页时，你也会反复用到这些元素。

### 1. 图片放哪里

如果你想加头像，通常放在头部区域最合适：

```html
<img src="avatar.jpg" alt="我的头像">
```

`alt` 一定要写。它有两个作用：

- 图片没加载出来时，能看到替代文字
- 让结构更完整，方便理解页面内容

老赵提醒你：**图片路径最容易出错**。很多时候不是标签错了，而是图片文件没放对位置，浏览器找不到。

### 2. 链接和按钮别混用

- `<a>`：用于跳转，比如作品页、邮箱、外部网站
- `<button>`：用于触发动作，比如关注、展开、切换状态

例如：

```html
<a href="https://example.com">查看作品</a>
<button type="button">关注我</button>
```

如果是“去别的地方”，用链接；如果是“点一下做动作”，用按钮。这个区别以后做交互时特别重要。

### 3. 文字内容怎么排更清楚

建议优先使用：

- 标题：`h1`、`h2`
- 段落：`p`
- 列表：`ul` / `li`

不要把所有内容都塞进 `div`。`div` 只是容器，**能用语义标签，就先用语义标签**。这样页面结构更清楚，后面 CSS 和 JS 也更好接手。

## 五、新手最容易踩的两个坑：层级乱、标签忘闭合

这一章不需要讲太多坑，抓住最常见的两个就够了。

### 1. 层级乱

有些同学会疯狂套 `div`，一层套一层，最后自己都看不明白。  
判断标准很简单：**这一层如果没有明确分组作用，就先别加。**

这不是“偷懒”，而是保持结构干净。小项目最怕的不是层少，而是层多还没用。

### 2. 标签没闭合

比如少写了一个 `</section>`，页面看起来就开始跑偏。  
老赵建议你：**写完一个小块就检查一次，不要攒到最后一起找错。**

最实用的习惯就是：

- 写一段
- 看一眼缩进
- 再写下一段

缩进不是装饰，是帮你看清标签关系的。

你以后不只会做个人介绍页。结构思路是通用的。

- **待办清单**：标题、任务列表、输入框和添加按钮
- **简单商品展示页**：商品标题、商品卡片、价格和购买按钮
- **登录页**：标题、账号密码输入框、登录按钮

你会发现，不管是什么页面，第一步都不是先调颜色，而是先把内容放进对的位置。  
这就是 HTML 的任务：**先把页面说清楚，再谈怎么变好看、怎么动起来。**

# 第4章 第4章 让页面先像个样子：用 CSS 做基础布局和视觉风格

## 开篇引入：先别急着“好看”，先让它“像个页面”

上一章我们已经把个人介绍页的 HTML 骨架搭起来了。现在页面就像刚砌好的毛坯房：有结构，但还没有门窗、家具和颜色。  
这时候轮到 CSS 出场了。

本章的目标很明确：**先把页面做出基础布局和视觉层次**。也就是说，让它至少具备这些感觉：

- 内容分区清楚，不是一坨字
- 页面居中，不会贴着浏览器边缘
- 标题、头像、简介、按钮各有层次
- 字体、颜色、间距统一、舒服

老赵先提醒你一句：**CSS 不是拿来先堆特效的，而是先把结构整理清楚，再谈美化。**  
所以这章你先别追求花哨，先把页面做到“看得懂、看得顺、看得舒服”。这个阶段的目标不是惊艳，而是可用。

## 一、先把 CSS 接到 HTML 上：样式从哪里开始写？

### 1.1 把样式单独放出来

常见做法是把样式写到单独的 `.css` 文件里，然后在 HTML 的 `<head>` 中引入：

```html
<link rel="stylesheet" href="./style.css">
```

这样做有两个好处：

1. **HTML 负责结构，CSS 负责外观**，分工清楚
2. **后面改样式更方便**，不会把内容和样式缠在一起

新手最容易犯的错，就是把样式直接塞进 HTML。短期看着省事，后面一改字号、布局或者主题，整页就容易乱。

### 1.2 样式先从全局开始

别一上来就盯着按钮、头像这些局部细节。更稳的做法是先写全局基础：

- `body`：背景、字体、整体基调
- 页面容器：最大宽度、居中方式、内边距
- 基础文本：标题、段落、链接的默认表现

这叫**先定大局，再修局部**。  
因为全局没统一，后面的模块就会各写各的，页面看起来就散。

### 1.3 本节阶段成果

做到这里，你已经完成了：

- CSS 文件成功连接到 HTML
- 页面有了基础字体和背景
- 样式开始统一管理整个页面

这一步不显眼，但很关键。它意味着页面已经从“只有内容”变成“有统一外观的网页”。

---

## 二、布局先做四件事：居中、分区、间距、对齐

### 2.1 为什么先做布局，不先调颜色

很多新手喜欢先调颜色、阴影、圆角，结果页面结构还是乱的。  
但真实开发里，**布局比美化更重要**。因为布局决定信息怎么被看见，视觉只是锦上添花。

个人介绍页可以按这个顺序做：

1. 页面整体居中
2. 内容分成几个区块
3. 每个区块内部再做对齐和间距

### 2.2 一个稳妥的布局思路

比如页面主体可以用一个 `card` 容器包起来：

- 外层负责居中
- 内层负责内容排版
- 标题、头像、介绍文案、按钮各占自己的位置

常见写法是：

- 页面外层：`display: flex; justify-content: center;`
- 容器：限制宽度 `max-width`
- 区块之间：用 `margin` 或 `gap` 拉开距离
- 内部对齐：根据内容决定居中还是左对齐

这样页面不会东倒西歪，内容也会有明确的落点。用户打开后，一眼就知道重点在哪。

### 2.3 留白不是浪费

新手常常觉得“挤”是因为内容太多，其实多数时候是**没有留白**。  
留白不是空着没用，而是让内容有呼吸感。比如：

- 标题和正文之间要有距离
- 图片和文字之间要有距离
- 按钮之间也要有距离

老赵提醒你：**如果元素全贴在一起，就算颜色再好看，也会显得很硬、很乱。**

### 2.4 本节阶段成果

这一步完成后，个人介绍页会从“散装文本”变成一个有秩序的卡片页面，读者能一眼看出标题、简介和操作入口。

这就是布局的价值：先把信息摆顺，页面才有继续打磨的基础。

## 三、用字体、颜色、背景、圆角、阴影做统一风格

### 3.1 先统一，不要乱加

个人介绍页最怕什么？怕每个元素都像来自不同网站。  
所以第一原则是：**统一基础风格**。

可以从这几个维度统一：

- 字体：全局统一系统字体
- 颜色：主色、正文色、弱化文字色不要太多
- 背景：页面背景保持干净
- 圆角：容器和按钮风格一致
- 阴影：轻一点就够，不要太重

### 3.2 这些样式各自干什么

- **字体**：决定阅读感
- **颜色**：决定重点和层次
- **背景**：决定整体气质
- **圆角**：让页面更柔和
- **阴影**：让卡片有一点“浮起来”的感觉

这些东西不是越多越好，而是要配合内容。  
比如个人介绍页更适合简洁、轻盈的风格，不适合满屏花哨渐变。你做的是“自我展示”，不是“视觉杂技”。

### 3.3 结合个人介绍页来看

一个好看的个人介绍页，通常会让用户先看到名字或标题，再看到简介，最后看到按钮或联系方式。  
要实现这个效果，不是靠堆很多颜色，而是靠：

- 标题字号更大
- 说明文字更柔和
- 按钮颜色更醒目
- 容器背景和页面背景有一点区分

也就是说，**风格统一，重点才会突出。**

### 3.4 本节阶段成果

完成这一部分后，页面不再只是“有内容”，而是开始“有气质”。  
这就是 CSS 的直接价值：**把结构变成可阅读、可感知的页面。**

## 四、个人介绍页的视觉层级：先让用户知道看什么

### 4.1 什么叫视觉层级

简单说，就是让用户知道“先看什么、后看什么”。  
在个人介绍页里，层级通常是：

- 第一层：姓名或主标题
- 第二层：一句核心介绍
- 第三层：详细描述
- 第四层：按钮或联系信息

### 4.2 怎么做出层级

最常用的办法就四个：

- **字号**：标题大，正文小
- **字重**：重点文字更粗
- **颜色**：重要内容颜色更深，次要内容更浅
- **间距**：层级之间留出呼吸感

不要把所有文字都写成一样大、一样粗、一样颜色，不然页面看起来整齐，但没有重点。

### 4.3 为什么要先统一基础风格

因为统一风格能让后面扩展更容易。  
比如后面你要做待办清单、商品展示页、登录页，如果已经有一套统一的：

- 页面宽度
- 卡片样式
- 按钮样式
- 字体和间距规则

那你后面的页面就能快速复用，不用每次从零开始试。

老赵给你一句实话：**CSS 的效率，不是写得快，而是改得稳。**

### 4.4 本节阶段成果

到这里，你的个人介绍页已经具备清晰的视觉层级，内容有重点、有节奏，开始像一个完整的小网页了。

### 5.1 选择器命名太乱

新手容易今天写一个 `.a`，明天写一个 `.box2`，后天又来个 `.redText`。

- 选择器优先级不清楚

- 全局样式和局部样式打架

有些页面内容没错，但就是不好看，原因通常不是颜色，而是：

- 段落太挤
- 模块之间没有距离
- 重点和次要信息没有区分

记住一句话：**好看的页面，很多时候不是“加了什么”，而是“留了什么”。**

### 5.4 快速检查清单

写完一轮 CSS 后，可以自查：

- 页面是否居中
- 内容是否分区明确
- 标题是否比正文更醒目
- 按钮是否一眼能看见
- 间距是否统一
- 颜色是否过多
- 有没有重复或冲突的样式

能按这个清单过一遍，页面基本就不会差得太离谱。

# 第5章 第5章 从静态到可点：给个人介绍页加上基础交互

这一章不追求复杂功能，只做最基础、最实用的交互，目标很明确：

- 理解 DOM，知道 JavaScript 为什么能控制页面元素
- 学会绑定按钮点击事件
- 学会通过切换文本、显示提示、展开信息做基础交互
- 学会把交互代码和 HTML、CSS 配合起来，不把三者写乱

你可以把这一章理解成：**让个人介绍页从“静态海报”升级成“能回应用户动作的小网页”**。

## 5.1 先看清楚：DOM 是什么，JavaScript 怎么碰到页面

先别急着写代码，我们先把思路捋顺。  
HTML 写出来后，浏览器会把它解析成一棵页面结构树，这就是 DOM。你可以把它理解成：**页面里每一个标签，都变成了 JavaScript 能找到、能修改、能监听的对象**。

所以 JS 不是直接去改 `.html` 文件，而是在运行时操作页面上的 DOM 元素。

### 这三件事先分清

- **HTML**：页面有什么
- **CSS**：页面长什么样
- **JavaScript**：页面会发生什么

比如个人介绍页里放一个“展开更多介绍”的按钮：HTML 先把按钮和隐藏内容准备好，CSS 负责默认显示和隐藏状态，JS 负责点击后把内容展开。

### 为什么要先理解这个

新手最容易犯的错，就是以为“写了 JS，按钮就会自己动”。其实不是，JS 要先找到页面上的元素，才谈得上操作。最基本的流程就四步：

1. 找到按钮
2. 找到要控制的内容
3. 绑定点击事件
4. 用户点击后修改文本、样式或状态

顺序不要乱，**先找到对象，再做动作**，这是前端交互的基本逻辑。

### 阶段成果

到这里你先记住一句话就够了：

> DOM 就是浏览器里的页面零件，JavaScript 通过它去找元素、改文本、切状态、接事件。

后面不管是待办清单、商品展示页，还是登录页，思路都是一样的。

---

## 5.2 先做一个最小交互：点击按钮，页面真的有反应

这一节我们不搞复杂功能，先做一个最小动作：**点一下按钮，页面有反馈**。  
这一步很重要，因为它能让你第一次感受到“页面不是死的”。

### 先准备一个简单场景

比如个人介绍页里放这几个元素：

- 一个“查看更多”按钮
- 一段默认收起的补充介绍
- 一个提示区域

这样点击后就有明确变化可看，不会点了半天看不出区别。

### 基本操作顺序

1. HTML 里把按钮和目标内容放好
2. CSS 里先写好默认样式，比如隐藏补充内容
3. JS 里找到按钮和内容
4. 给按钮绑定 `click` 事件
5. 用户点击后，改文本、切类名或显示提示

### 一个最常见的反馈方式

比如“查看更多”按钮：

- 初始时，补充介绍隐藏
- 点击后，补充介绍显示出来
- 按钮文字变成“收起介绍”

这就是最基础的页面反馈。用户一操作，页面就回应，这才算真正有交互。

### 输入-操作-预期结果

- **输入**：用户点击“查看更多”按钮
- **操作**：JS 切换内容区显示状态，并更新按钮文字
- **预期结果**：页面展开更多介绍，按钮文字变成“收起介绍”

这样看就很清楚，不容易写着写着迷路。

### 阶段成果

做到这里，你已经能让页面完成一个最小闭环：

**用户点击 → 页面变化 → 用户看到反馈**

这一步很小，但它是 JS 参与页面的第一道门。

## 5.3 三个基础动作：切换文本、显示提示、展开信息

个人介绍页内容不复杂，特别适合练这三种最基础的交互。它们都简单，但足够把“静态”变成“可点”。

### 1）切换文本

比如按钮文案在“展开介绍”和“收起介绍”之间切换。  
这类交互最适合练“状态”的概念。

为什么要这么做？  
因为按钮文字本身就是给用户看的状态提示。你点完以后，按钮还保持原样，用户就会怀疑自己刚才是不是点错了。

### 2）显示提示

比如点击“联系我”后，页面显示一句提示：  
“欢迎通过邮箱联系我”。

为什么要这么做？  
因为如果用户点了按钮却一点反应都没有，页面就会显得像坏了一样。哪怕只是一个轻量提示，也能告诉用户：系统已经收到操作了。

### 3）展开更多信息

比如简介区默认只显示前两行，点击后展开完整内容。  
这样做有两个好处：一是页面不会太挤，二是你能顺手练习“切换状态”。

为什么要这么做？  
不是所有内容都要一次性摆出来。适当收起来，页面更清爽，重点也更明显。

### 更稳的做法：用 class 切换状态

比起在 JS 里直接改一堆 `style`，更推荐你切换类名。比如：

- 默认是 `.info-collapsed`
- 点击后变成 `.info-expanded`

这样 CSS 负责效果，JS 只负责改状态。三件套的分工会更清楚，后面维护也轻松。

### 阶段成果

现在你的个人介绍页已经有了最基础的互动能力：

- 能点击
- 有反馈
- 能展开和收起
- 页面开始像一个真正的小网页

## 5.4 让 HTML、CSS、JS 各做各的事，不要写乱

这一点特别关键。很多新手不是不会写交互，而是一加 JS，整个项目就乱了。

### 记住这个分工

- **HTML**：放结构和语义
- **CSS**：放视觉和状态样式
- **JS**：放动作和状态切换

### 具体怎么配合

#### HTML 里先准备好“钩子”

也就是让 JS 容易找到的元素：

- 按钮
- 内容区
- 提示区
- 可展开区域

这些元素最好命名清楚，不然后面自己回来看代码，也得猜半天。

#### CSS 里先写好“状态类”

比如：

- `.hidden`
- `.active`
- `.expanded`

这些类不是装饰，而是专门给交互准备的。JS 只要负责切换类名，页面就会跟着变。

#### JS 里只做动作

JS 里主要做三件事：

- 绑定事件
- 切换类名
- 更新文字或提示

尽量不要在 JS 里写一大堆零散样式，比如 `style.color`、`style.fontSize` 一路改下去。  
短期看能跑，后面会很难维护。

### 一个完整流程

还是拿“展开介绍”举例：

1. HTML 里放好简介内容和按钮
2. CSS 里写好隐藏和展开状态
3. JS 监听按钮点击
4. 点击后切换类名
5. 按钮文字同步更新

这样逻辑、样式、结构都分得很开，后面要改效果，只改 CSS 就行。

### 阶段成果

这时你的代码结构应该已经比较清楚了：

- HTML 提供元素
- CSS 定义默认和变化状态
- JS 负责触发变化

这就是一个小型前端项目最基本的协作方式。

## 5.5 新手最容易踩的两个坑，先帮你挡一下

这一节老赵不多讲，直接说最常见、最值得排查的两个问题。

### 1）元素获取失败

如果按钮点了没反应，先看是不是根本没找到元素。常见原因就这几个：

- 选择器写错了
- `id` 和 `class` 搞混了
- 页面里压根没有这个元素

**检查方法**很简单：在控制台打印一下获取结果。  
如果是 `null`，说明 JS 没找到目标元素，后面的事件绑定当然也不会生效。

### 2）事件没绑上

元素找到了，但点击还是没反应，可能是事件没绑定成功。常见原因：

- 代码执行太早，元素还没加载出来
- 事件名写错了
- 绑到了错误的元素上

**解决思路**：  
确保脚本加载时页面元素已经存在，或者把脚本放到页面底部，或者等 DOM 加载完成后再执行。小项目里这类问题特别常见，代码本身不一定错，时机不对也会没反应。

### 老赵的调试顺序

按钮没动静时，按这个顺序查：

1. 元素有没有拿到
2. 事件有没有绑上
3. 函数有没有执行
4. 页面上的内容是不是本来就可见

这个顺序以后做任何前端交互都能用。

# 第6章 第6章 做一个更实用的页面：用待办清单练习列表结构和增删交互

## 开篇引入：这章我们做什么页面？

前面几章你已经分别接触了 HTML、CSS、JavaScript，但真正做页面时，它们一定是一起工作的。这一章，我们来做一个**待办清单页面**，把三件套真正串起来。

为什么选它？因为它简单、典型，刚好能练到几个最核心的场景：

- 有输入框，用户输入内容
- 有添加按钮，点击后把内容放进列表
- 有列表区域，内容是动态渲染的
- 有空状态，列表为空时要提示
- 还能继续加删除、完成这种基础交互

所以这一章不是让你背知识点，而是带你完整做一次页面：**先结构、后样式、再交互**。做完你会发现，很多小网页其实都是这个套路。

## 一、先拆需求：这个待办页到底要有哪些部分？

先别急着写代码。新手最容易犯的错，就是看到页面就开始堆标签，写到一半才发现结构不够用。

所以第一步是先拆需求。

这个待办清单页面，至少要有四块：

### 1. 输入框
用户在这里输入待办事项，比如“今晚复习 CSS”。

### 2. 添加按钮
输入完之后，点击按钮，把内容加入列表。

### 3. 列表区域
所有待办项都显示在这里。每一项最好包含：
- 文本内容
- 删除按钮
- 可选的“完成”状态

### 4. 空状态提示
如果列表里没有内容，要提示“暂无待办事项，快添加一个吧”。

#### 为什么要先拆需求？
因为页面不是先堆几个 `div` 再说，而是先明确功能，再决定结构。你先知道后面要支持什么交互，HTML 才不会写死，JS 也更容易接上去。

新手常见的问题是：一开始只想着“显示出来”，没考虑“以后怎么改”。结果后面要加删除、完成状态时，只能返工。先拆需求，就是为了避免这个坑。

---

## 二、HTML 结构怎么搭：为什么要给后续交互留空间？

这一章的 HTML 不追求花哨，重点是**语义清楚、结构好操作**。你可以把它理解成：先把房间隔出来，后面才好摆家具。

### 基本结构建议

- 一个外层容器
- 一个标题区
- 一个表单区：输入框 + 添加按钮
- 一个列表区：`ul` 或 `ol`
- 一个空状态提示区

从功能上看，这几个元素分工很明确：

- `form`：收集输入
- `input`：输入待办内容
- `button`：提交新增
- `ul`：承载所有待办项
- `li`：每一条待办内容
- `p` 或 `div`：空状态提示

### 为什么列表区域要用 `ul`？
因为待办清单本质上就是一个列表。用 `ul` 不只是像，更重要的是后续你要增删每一项时，对象会很明确：一条待办就是一个 `li`。这样 JS 处理起来更顺手，页面结构也更清晰。

### 为什么要给删除按钮和完成状态留空间？
很多新手一开始只写文本，等到后面想加删除功能时，才发现每一项都没有独立结构，只能硬改。  
所以建议你在每个 `li` 里预留两个区域：

- 文本区域
- 操作按钮区域

这样后面加“完成”“删除”都顺手，也更方便做样式对齐。

#### 阶段成果
到这里，页面还没加样式，但你已经完成了**可交互页面的骨架设计**。后续 JS 知道往哪儿塞内容，往哪儿找按钮，页面不会一团乱。

---

## 三、CSS 怎么写：如何把待办页做得清楚又耐看？

结构搭好了，接下来再做样式。这里的重点不是“炫”，而是“清楚”。

### 1. 先做整体布局
建议把内容居中，做一个卡片式容器：

- 页面背景浅一点
- 内容区白底
- 圆角 + 阴影
- 留足内边距

这样用户一眼就知道页面主体在哪，也更容易把注意力集中在输入和列表上。

### 2. 再做表单区
输入框和按钮最好横向排列：

- 输入框占主要宽度
- 按钮宽度固定
- 间距不要太挤

为什么这么做？因为这是常见的“输入 + 提交”场景。布局清楚，用户一看就知道怎么用。

### 3. 列表项要有层次
每个待办项建议左右分区：

- 左边显示文本
- 右边显示操作按钮

如果已经完成，可以给文字加删除线，或者降低透明度，让状态更明显。这样用户不用猜，状态一眼就能看出来。

### 4. 空状态不要忽略
空状态最好单独设计一下，不然列表为空时页面会显得“坏了”。比如可以用灰色小字提示：**“还没有待办事项，先加一条吧。”**

#### 老赵提醒
新手做样式最容易乱的地方，不是“丑”，而是“乱”：

- 间距不统一
- 按钮大小不一致
- 列表项没有对齐
- 完成状态和未完成状态看不出来

记住，待办页最重要的是**可读性**，不是装饰。你现在做的是一个工具页，重点是让人用得顺手。

#### 阶段成果
到这一步，你应该已经能看到一个像样的待办清单页面：输入框、按钮、列表、空状态都摆好了。虽然它还不会动，但已经有“页面”的样子了。

---

## 四、添加待办项：先输入、再点击、再渲染

接下来进入最关键的一步：让页面会动。这里我们先只做“添加”，别一口气把删除、完成、清空全塞进来，容易把逻辑写乱。

### 1. 先拿到页面元素
JavaScript 需要先找到：

- 输入框
- 添加按钮
- 列表容器
- 空状态提示

这是后面操作 DOM 的基础。可以把它理解成：先认门，再进屋。没有拿到元素，后面的添加、删除、渲染都无从谈起。

### 2. 处理添加动作
用户点击“添加”时，流程一般是：

1. 读取输入框内容
2. 去掉首尾空格
3. 判断是否为空
4. 如果为空，提示用户，不渲染
5. 如果不为空，创建新的待办项
6. 把新项插入列表
7. 清空输入框

### 3. 怎么渲染到列表？
最稳妥的思路是：把待办看成一条数据，再根据数据生成一个 `li`。

每条待办至少保留两个信息：

- 内容
- 是否完成

这样后面要切换状态、删除项目时，就不会只盯着页面上的文字，而是有一份清楚的数据可以操作。

#### 阶段成果
到这里，用户已经可以：

- 输入待办内容
- 点击添加
- 看到新待办出现在列表里

这就不是静态页面了，而是一个真正能用的半交互页面。

---

## 五、删除和完成：用事件处理管理每一条待办

有了添加，下一步就是管理单条待办。最常见的两个动作就是删除和完成。

### 1. 删除待办项
每条待办后面放一个删除按钮，点击后移除这条数据，并重新渲染列表。

### 2. 标记完成
点击某条待办文本或完成按钮，切换完成状态。常见表现是：

- 文本加删除线
- 字体颜色变浅
- 按钮状态变化

### 3. 事件处理思路
如果给每个按钮单独绑定事件，列表一多就麻烦。更稳妥的做法是：**给列表容器统一监听事件**，再根据点击目标判断是删除还是完成。

这样有两个好处：

- 新增的待办项也能自动响应事件
- 不需要每新增一次就重新绑定一次事件

这就是事件委托。它不是为了显得高级，而是为了更省事、更稳定。

#### 老赵提醒
很多新手在这里会把事件对象用乱：

- 不知道点到的是按钮还是 `li`
- 不知道怎么拿到当前元素
- 删除后发现点错地方也会触发

你要养成一个习惯：**先判断点击目标，再执行动作**。别一上来就直接删，先确认“我点的是谁”。

#### 阶段成果
到这里，待办页不只是能添加，还能管理每一条数据了。页面已经从“展示型”往“可操作型”迈了一大步。

---

## 六、常见问题压缩记：空状态、重复渲染、事件对象

待办清单看着简单，实际上特别容易踩坑，这里老赵帮你把最常见的三个问题收在一起。

### 1. 空状态
列表为空时，不要让页面只剩一片白。空状态的作用不是装饰，而是提醒用户下一步怎么做。显示它，页面才完整。

### 2. 重复渲染
如果你每次添加都直接把整段列表重新写一遍，却没处理好旧内容，可能会出现重复项。解决方法是：明确“数据源”和“渲染结果”，每次渲染前先清空再生成。

### 3. 事件对象
别把 `event.target` 和 `event.currentTarget` 搞混。前者是你真正点击的元素，后者通常是绑定事件的元素。如果你想做删除按钮判断，通常要看点击目标是不是按钮。

#### 阶段成果
把这三个坑提前避开，你的待办页才算真正稳定。不是“能跑”，而是“能用”。

---

## 结尾小结：这一章你真正学到了什么？

这一章我们不是单纯做了一个待办清单，而是完整走了一遍一个小项目的制作流程：

- 先拆需求，明确输入框、按钮、列表、空状态
- 再搭 HTML 结构，为后续交互留空间
- 然后写 CSS，把页面做得清楚、可用
- 最后加 JS，完成添加、删除、完成状态等基础交互
- 同时注意事件处理、重复渲染和空值判断这些细节

如果你能自己把这个待办页做出来，说明你已经开始具备把 HTML、CSS、JavaScript 串起来的能力了。这一步很重要，因为它意味着你不再是“只会单个知识点”，而是开始会做完整页面了。

### 本章最小可执行流程
你可以照着下面三步直接练：

1. 先搭出一个 `form + input + button + ul + 空状态提示` 的结构
2. 再把页面样式做成卡片布局，保证输入区和列表区清楚可见
3. 最后加添加、删除、完成三个基础交互，先跑通，再优化细节

### 练习建议
你可以在这个页面上继续加两个小功能：

1. 给每条待办加“完成时间”
2. 增加“清空全部”按钮

不用一口气做很多，先把一个完整小功能做稳，再扩展。  
这就是从“会写代码”到“会做页面”的关键一步。

# 第7章 第7章 让按钮和状态动起来：待办清单里的状态变化与细节反馈

## 开篇引入：这一章不再做“能用”，而是做“看得懂”

前面我们已经把待办清单的基础功能搭起来了，能新增、能删除、能显示任务。这一章不再重复功能本身，而是往前一步：**让页面把状态说清楚**。

真实页面里，最影响体验的不是功能少，而是用户点完之后不知道发生了什么。按钮能不能点、任务有没有完成、列表是不是空了、输入后能不能提交，这些都需要页面主动反馈给用户。  
所以这一章专门处理**按钮状态变化、完成状态切换、空状态提示、禁用状态和基础反馈**。做完之后，你的待办清单就不只是“能操作”，而是会“明确回应操作”。

这一章的阶段成果很明确：**列表不仅能动，而且用户一眼就能看出当前状态。**

---

## 一、先把状态规则定下来，页面才不会乱

新手最容易犯的错，就是写着写着边改边加，最后按钮、样式、数据互相打架。老赵建议你先把规则定清楚，再开始编码。

这一章的状态规则可以先定成几条：

1. **输入框为空**，添加按钮禁用  
2. **输入框有内容**，添加按钮启用  
3. **任务未完成**，显示“完成”  
4. **任务已完成**，显示“取消完成”  
5. **列表为空**，显示空状态提示  

这些规则本质上是在回答一个问题：**用户现在能做什么，页面应该怎么告诉他。**  
先定规则，再写 HTML、CSS 和 JavaScript，后面就不会乱。

---

## 二、完成/未完成状态怎么切换？核心就是改数据，不是只改表面

这一节是重点。记住一句话：**状态变化要先改数据，再让页面跟着变。**

### 1. 给任务加一个状态字段

每条待办项最好有一个布尔值，比如：

- `completed: false` 表示未完成
- `completed: true` 表示已完成

这样做的好处很直接：状态写在数据里，页面只是把它展示出来。以后要重新渲染、过滤任务，或者刷新页面，都更好处理。

### 2. 点击按钮后切换状态

用户点“完成”按钮时：

- 未完成就改成已完成；
- 已完成就改回未完成。

老赵提醒你，别只改按钮文字，也别只改颜色。**真正该变的是数据里的状态值。**  
正确顺序一般是：

1. 找到当前任务；
2. 反转 `completed`；
3. 重新渲染列表；
4. 顺手更新提示信息和按钮状态。

这样页面不会出现“看着变了，其实数据没变”的问题。

### 3. 用 class 带动样式变化

新手最容易把 JS 写成“手改样式属性”的工具，今天改字体色，明天改背景，后面代码会越来越乱。

更好的方式是：**JS 只负责加或删 class，CSS 负责定义状态样式。**

比如：

- 未完成：`todo-item`
- 已完成：`todo-item done`

任务完成时，JS 给元素加上 `done` 类；取消完成时再移除。  
CSS 统一写：

```css
.todo-item.done {
  opacity: 0.6;
  text-decoration: line-through;
}
```

这样结构、样式、逻辑就各归各位了。

---

## 三、按钮状态变化为什么重要？因为它是在给用户“提示”

很多新手会觉得按钮能点就行，其实不够。**按钮本身就是反馈。**

比如：

- 输入框没内容时，“添加”按钮禁用；
- 输入框有内容时，按钮恢复可点击；
- 任务已完成时，按钮文案变成“取消完成”；
- 任务没完成时，按钮显示“完成”。

这些变化不是为了好看，而是让用户不用猜。  
不是等用户点了报错才告诉他不行，而是在他操作之前就先提醒：**现在能不能做这一步。**

### 1. 禁用状态

输入框为空时，添加按钮应该是 `disabled` 状态。  
这样既避免提交空内容，也直接告诉用户：现在还不能提交。

### 2. 文案状态

按钮文案要跟状态走。  
如果任务已经完成，还写“完成”，用户会困惑。  
所以完成态最好改成“取消完成”，让按钮含义和当前状态一致。

### 3. 提示信息

完成操作后，可以在页面上给一句轻提示：

- 已添加
- 已完成
- 已取消完成
- 输入不能为空

这里不用做得太重，一个简单的文字区域就够了。

---

## 四、空状态和统一刷新：别让页面局部对、整体乱

这一节看起来小，但很像真实项目。

### 1. 列表为空时要有空状态

如果待办列表里什么都没有，页面不要只留一片空白。空白很容易让用户以为页面坏了。

更好的做法是显示一句提示，比如：

- “当前还没有待办事项，先添加一条吧。”

这样用户知道：不是出错了，而是还没数据。

### 2. 每次状态变化后都统一刷新

新手常见的坑，是只改了某一项，忘了更新其他区域。  
比如点了“完成”，只改这一条样式，却没同步空状态、按钮状态和提示信息，页面就会前后不一致。

更稳的做法是把更新拆成统一流程：

1. 更新任务数据；
2. 重新渲染列表；
3. 更新按钮启用/禁用状态；
4. 更新空状态提示；
5. 更新页面提示文字。

别把这些逻辑散在各个点击事件里。**一个操作，尽量对应一次统一刷新。**

---

## 五、新手最容易踩的坑：逻辑太绕，状态和样式分不清

这一节专门提醒你，避免写着写着把自己绕晕。

### 坑 1：判断写太多层

有些同学会把逻辑写成一大串嵌套判断：

- 先看输入框有没有内容
- 再看任务是不是完成
- 再看按钮能不能点
- 再看要不要显示提示

结果代码很长，自己也不好维护。

### 怎么改？

拆开。  
先处理输入状态，再处理任务状态，最后统一刷新页面。  
**一件事一段逻辑**，别把所有判断挤在一起。

### 坑 2：状态和样式混着写

“完成状态”不是“文字变灰”，真正的状态是数据里的 `completed`。  
样式只是它的表现。  
记住这个分工：

- **HTML** 管结构
- **CSS** 管外观
- **JavaScript** 管状态和行为

这个思路以后做个人介绍页、商品展示页、登录页，也都能继续用。

### 坑 3：只更新局部，不更新整体

点完按钮后，如果只改当前项，不刷新列表和提示，页面就会局部正常、整体混乱。  
所以状态一变，最好让相关区域一起同步。这样用户看到的才是一致的结果。

做到这里，你的待办清单已经不只是“能点一下”了，而是开始具备基础产品感：

- 输入框为空时，添加按钮会禁用；
- 输入有内容时，按钮会恢复；
- 任务能在完成/未完成之间切换；
- 完成状态会通过 class 联动样式；
- 列表为空时有空状态提示；
- 用户能清楚感知页面正在响应操作。

也就是说，这一章完成后，页面已经从“能跑”变成“能看懂、能反馈”。

## 复盘总结：这一章你真正掌握的是状态思维

这一章做的事情，看起来是按钮、文案、空状态这些小细节，但背后训练的是一个很重要的前端习惯：**让页面状态和用户动作保持一致。**

以后做任何小网页，都可以先问自己四个问题：

1. 用户现在能做什么？
2. 页面当前是什么状态？

# 第8章 第8章 做一个能看懂也能买的页面：商品展示页与简单数据渲染

## 开篇：这一章我们做什么

上一章我们练了页面的基础骨架、布局和一些简单交互。这一章往前走一步，做一个**商品展示页**。它不是只摆图片的静态页，而是一个能看懂、也能继续扩展成“能买”的页面。

我们要做的页面一般有三块：

- **标题区**：告诉用户这页卖什么、给谁看
- **筛选区**：比如“全部 / 热门 / 新品 / 低价”
- **商品卡片区**：真正展示商品内容

这一章重点不是做得花哨，而是训练一个关键能力：**用一份数据，批量生成页面内容**。这样以后你就不会一件商品写一套 HTML，十件商品复制十遍。那种写法短期能交作业，长期一定累。

这一章做完，你会得到一个阶段成果：**一个结构清晰、样式完整、可以用 JavaScript 渲染商品列表的展示页**。更重要的是，你会开始真正理解：页面很多时候不是“写出来的”，而是“数据渲染出来的”。

---

## 一、先想清楚：商品展示页到底长什么样

老赵先提醒你一句：**不要上来就写 div**。先想结构，再写代码。结构清楚了，HTML、CSS、JS 才能各干各的活。

### 1. 页面结构怎么拆

商品展示页按功能可以拆成三层：

- **头部标题区**：页面名称、简介文案
- **筛选操作区**：几个可点击的分类按钮
- **商品列表区**：一张张商品卡片

这样拆的好处很直接：标题区负责说明页面，筛选区负责告诉用户怎么找商品，列表区负责承载数据。

### 2. 为什么要这样拆

因为结构越清晰，后面越好维护。

- 标题区通常不频繁变
- 筛选区多半只是切换状态
- 商品区才是数据驱动重点

如果全塞进一个大容器里，后面一改样式或加交互就容易乱。新手最常见的错，就是“看起来差不多就行”，结果一加功能全崩。

### 阶段成果

此时你脑子里至少要有一张图：

- 上面是标题
- 中间是筛选按钮
- 下面是一组商品卡片

先有结构感，再动手。

---

## 二、商品卡片 HTML 怎么设计，才能方便重复渲染

这一节最关键：**卡片结构要标准化**。因为后面我们不是手写很多张卡片，而是让 JS 根据数据生成。

### 1. 卡片应该包含哪些内容

一张商品卡通常包括：

- 商品图片
- 商品名称
- 商品描述
- 价格
- 标签，比如“热卖”“新品”

这些内容就是数据要映射到页面上的字段。

### 2. HTML 结构要模板化

先写一个商品卡模板，大致包括：

- 外层卡片容器
- 图片区域
- 内容区域
- 标题、描述、价格、标签

重点不是复杂，而是**每张卡都长得一样，只有内容不同**。这样 JS 才能复制模板，替换里面的数据。

### 3. 为什么不能每个商品都单独写一套 HTML

因为会有三个问题：

1. **重复代码太多**，维护困难  
2. **数据和结构绑死**，一改要改很多处  
3. **扩展性差**，以后加商品很痛苦

老赵给新手一个判断标准：如果你发现“第二个商品和第一个商品结构几乎一样，只是文字和图片不同”，那就该考虑数据渲染了，而不是继续复制粘贴。

### 阶段成果

此时你应该已经准备好：

- 一个页面外壳
- 一个商品卡模板结构
- 一个能被重复生成的标准

---

## 三、用数组保存商品数据，再渲染到页面

这一步就是这一章的技术核心。我们把商品信息放进一个数组里，每一项代表一个商品对象。

### 1. 数据为什么要先放到数组里

因为页面内容本质上就是数据的展示。集中管理数据，后面就能统一处理：

- 取图片地址
- 取价格
- 取描述
- 取标签

以后商品增加、删除、修改，优先改数据，不用到处找 HTML。

### 2. 一个简单的数据结构应该长什么样

可以把每个商品设计成对象，字段比如：

- `name`：商品名
- `price`：价格
- `desc`：描述
- `img`：图片地址
- `tag`：标签
- `type`：分类

字段不要求绝对统一，但要保证**命名清楚、结构稳定**。新手常见问题是字段乱写，一会儿叫 `title`，一会儿叫 `name`，渲染时就容易找不到值。

### 3. 渲染的基本思路

渲染就是三步：

1. 遍历数组
2. 生成每个商品的 HTML 字符串
3. 把字符串放进商品容器里

你可以理解成：**数据是原料，模板是模具，渲染是批量生产。**

比如你手里有 4 条商品数据，就让程序循环 4 次，自动生成 4 张卡片。这样你后面要加到 10 条，也只是改数组，不用再补 6 份重复 HTML。

### 4. 为什么这样做比手写更好

因为它符合网页的真实工作方式：

- 数据变了，页面跟着变
- 页面结构统一，样式也统一
- 后期扩展商品很快

这就是最基础的“数据驱动视图”思路。先不用追求框架，先把这个逻辑弄明白。

### 阶段成果

此时页面已经不只是“写死的内容”，而是可以通过数组批量生成商品列表了。  
这一步完成后，你已经从“写页面”进阶到“管理页面内容”了。

## 四、图片、价格、描述、标签怎么映射到页面

这一节解决的是“数据怎么落到具体位置”。不用绕太多弯，我们直接把对应关系讲清楚。

### 1. 图片映射

图片一般放在卡片最上面，视觉上最先吸引人。你要确保：

- 图片地址正确
- 有统一尺寸
- 不要让不同图片把卡片高度顶乱

新手提醒：不要直接把原图塞进去不管尺寸，页面很容易一高一低，看起来很乱。最好给图片区域一个固定比例，避免布局跳来跳去。

### 2. 价格映射

价格是用户最敏感的信息，建议单独突出：

- 字号更大
- 颜色更醒目
- 小数位格式尽量统一

如果价格一个写“99”，一个写“99.00”，视觉上会显得不专业。小页面也要有统一感。

### 3. 描述映射

描述不要太长，适合简短说明：

- 适合谁
- 有什么特点
- 为什么值得看

描述太长会把卡片撑得过高，破坏版式。一般两三行以内更舒服，既交代信息，又不喧宾夺主。

### 4. 标签映射

标签是增强信息感的小组件，比如：

- 热卖
- 新品
- 限时

标签适合放在标题附近或图片角标。它不是堆信息，而是帮助用户快速判断，让人一眼知道这商品值不值得点。

### 阶段成果

你已经实现了从“对象字段”到“页面元素”的一一对应。  
这一步很重要，因为它决定了你的数据能不能稳定显示出来。

## 五、新手最容易踩的坑：别让重复代码拖住你

这一节老赵专门提醒你几个常见问题，记住关键的就行。

### 1. 不要把数据写死在 HTML 里

如果内容一多，你就会发现改一个价格要找半天，改一个图片还可能漏掉一处。正确做法是先定义统一数据格式，再按格式生成模板。这样数据和视图分开，后面才好维护。

### 2. 不要一上来就复制很多个卡片

如果你看到自己复制了三四个几乎一样的商品卡，就该停下来问一句：**我是不是应该用数组渲染了？**  
复制粘贴在学习阶段看似省事，真到后面维护时，改一处漏一处，最容易把自己绕晕。

### 3. 先结构、后样式、再交互

这章的顺序一定要稳：

**先结构、后样式、再交互。**

别反过来。很多新手一上来先写点击逻辑，最后发现根本没有标准结构可操作。页面都没搭好，交互当然也落不稳。

### 检查清单

完成这一章后，你可以自查：

- 页面是否有标题区、筛选区、商品区
- 卡片结构是否统一
- 数据是否放进数组管理
- 渲染是否通过循环完成
- 图片、价格、描述、标签是否都能正确显示
- 页面里是否还有大量重复 HTML

## 结尾小结：你这一章学到了什么

这一章我们做的是商品展示页，但真正学到的是**数据渲染思路**。

你现在应该明白了：

- HTML 负责搭结构
- CSS 负责做呈现
- JavaScript 负责把数据变成内容
- 数组是商品信息的统一来源
- 模板化卡片是批量渲染的基础

这一章完成后，你已经有能力把“一个个商品”变成“一个商品列表页面”。  
而且你不是靠手写重复结构，而是靠一份数据去生成页面，这才是前端真正开始“省力”的地方。

### 行动建议

你现在就可以动手做三件事：

1. 先画出商品页三块区域  
2. 写一个标准商品卡 HTML 模板  
3. 准备 4~6 条商品数据，用数组渲染出来  

如果你想再多练一步，可以把商品换成别的内容，比如：

- 个人介绍页里的几项技能

这样你会更快理解：**同样的渲染思路，换个场景也能用。**

记住老赵这句话：**别把商品页当成一堆图片摆放，应该把它当成“数据驱动的页面”。**  
你一旦建立起这个意识，后面做待办清单、登录页、个人介绍页，都会顺很多。

# 第9章 第9章 让页面更像产品：商品展示页的样式统一、排序与筛选反馈

## 开篇引入：这一章，我们把“能看”变成“像产品”

前面我们已经把商品展示页的基本内容搭起来了，但**能展示内容**和**像一个真正的产品页面**，差别还很大。很多新手做到这里，有卡片、有图片、有文字，就觉得完成了，其实还差“整齐感”“一致性”和“反馈感”。

这一章我们做三件事：

1. 把商品卡片做成**整齐统一的网格布局**；
2. 处理不同内容长度带来的**版式波动**；
3. 给**筛选、排序按钮**加上基础交互反馈，让页面看起来“会响应用户”。

老赵先提醒一句：这一章不追求复杂功能，重点是把页面的**节奏、一致性、反馈感**做出来。产品感，往往就是从这些细节里来的。

如果你前面已经把商品数据、基础卡片和按钮区搭好了，那这一章做完，你的页面就会从“能展示信息”明显往“像样的商品页”靠近。

---

## 一、先把商品列表排整齐：网格布局比一张张堆更像产品

商品页最怕的不是内容少，而是**排得乱**。卡片一会儿宽一会儿窄，一会儿挤一会儿空，页面就会像临时拼出来的列表，不像真正的商品陈列区。

所以这一章先做整体布局，再看单张卡片。商品列表容器推荐直接用 **CSS Grid**，它特别适合多个卡片均匀排列、自动换行的场景。

```html
<section class="product-list">
  <article class="product-card">
    <img src="..." alt="商品图片">
    <h3>商品名称</h3>
    <p>简短介绍文字</p>
    <div class="price">¥199</div>
  </article>
</section>
```

这里结构不复杂，但思路很重要：

- `section` 负责整个商品区域；
- `article` 表示每个商品卡片都是一个独立内容块；
- 图片、标题、描述、价格分开写，后面做样式和交互更顺手。

```css
.product-list {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}
```

这段的核心就是：**让卡片自动适配屏幕宽度**。屏幕宽就多排几列，屏幕窄就少排几列，不用写一堆媒体查询，页面也能保持基本稳定。

### 老赵提醒
新手很容易把卡片宽度写死，结果在窄屏上挤坏，在宽屏上又空得难看。记住，商品页做的是**整体节奏**，不是单张卡片的孤立美化。

#### 阶段成果
你已经把商品展示区从“堆内容”变成了**有秩序的网格布局**。

---

## 二、内容长短不一样时，怎么让版式还稳住？

商品页接入真实数据后，问题就来了：有的商品名短，有的描述长，有的价格旁边还带标签。单看每张卡没问题，放到一起就可能高低不齐，页面显得乱。

所以这里不要求内容完全一样长，而是要让**卡片内部的排版规则一致**。

### 1. 控制文字长度，别让一条描述撑坏整页

```css
.product-card h3,
.product-card p {
  margin: 0;
}

.product-card p {
  display: -webkit-box;
  -webkit-line-clamp: 2;
  -webkit-box-orient: vertical;
  overflow: hidden;
}
```

描述最多显示两行，超出部分省略。这样做不是“藏内容”，而是让卡片高度更稳定、视觉节奏更统一。标题太长时，也可以做单行省略，思路一样。

### 2. 用纵向结构保持内部顺序

```css
.product-card {
  display: flex;
  flex-direction: column;
  padding: 16px;
  border-radius: 12px;
  background: #fff;
}
```

卡片内部从上到下排，符合阅读顺序，也方便你统一管理间距。基础商品页先把“图、标题、描述、价格”这个节奏排顺，别一上来就追求复杂排版。

### 3. 让价格位置尽量稳定

```css
.product-card .price {
  margin-top: auto;
}
```

这个小技巧很实用。它能尽量把价格压到卡片底部，哪怕上面的描述长短不同，视觉上也会整齐很多。

### 老赵提醒
别只盯着一张卡片看，要站在“整排商品”的角度检查：这一排是不是齐？上下是不是乱跳？看起来是不是像一套页面，而不是一堆零件？

#### 阶段成果
现在商品卡片不只是“能显示内容”，而是已经有了**稳定、统一的版式节奏**。

---

## 三、筛选和排序按钮，不只是能点，还要让用户看得出有反应

很多新手写交互，只关注“点了以后数据变没变”，忘了按钮本身也要反馈。结果就是：页面逻辑在跑，但用户看不出来自己有没有点成功。

所以这一部分要做两件事：

1. **按钮有激活状态**；
2. **列表会跟着状态变化重新渲染**。

### 1. 先把按钮状态写清楚

```html
<div class="toolbar">
  <button class="filter-btn active" data-type="all">全部</button>
  <button class="filter-btn" data-type="hot">热销</button>
  <button class="filter-btn" data-type="new">最新</button>

  <button class="sort-btn" data-sort="price-asc">价格升序</button>
  <button class="sort-btn" data-sort="price-desc">价格降序</button>
</div>
```

这里用了 `data-*` 属性，意思很简单：按钮自己带着“身份信息”，JS 读取起来方便，代码也更清楚。

### 2. 用事件处理切换激活状态

```js
const filterButtons = document.querySelectorAll('.filter-btn');

filterButtons.forEach(btn => {
  btn.addEventListener('click', () => {
    filterButtons.forEach(item => item.classList.remove('active'));
    btn.classList.add('active');
  });
});
```

这段代码就是一个很典型的状态切换：**先清掉旧状态，再设置新状态**。新手最容易犯的错，就是只加不删，结果多个按钮都像被选中一样。

### 3. 用 CSS 把状态反馈做出来

```css
.filter-btn.active,
.sort-btn.active {
  background: #1677ff;
  color: #fff;
  border-color: #1677ff;
}

.filter-btn:hover,
.sort-btn:hover {
  background: #f5f5f5;
}
```

按钮一旦激活，颜色就变；鼠标移上去，也有一点反馈。这样用户点完之后，能马上知道“我刚才的操作生效了”。

### 4. 排序和筛选的核心思路

```js
products.sort((a, b) => a.price - b.price);
renderProducts(products);
```

排序不需要一开始就做得很复杂，先会用数组排序，再重新渲染列表就够了。这里其实已经把前面学过的知识串起来了：

- 事件处理：按钮点击；
- DOM 状态：`classList` 切换；
- 数据处理：`sort()`；
- 页面更新：`renderProducts()`。

这就是前端三件套一起工作的样子。

#### 阶段成果
你已经有了一个**会响应点击、会显示状态、会刷新列表**的基础商品工具栏。

---

## 四、把悬停、激活、切换这些细节统一起来

产品感最容易体现在细节上。页面如果只有功能，没有反馈，就会显得“硬”；如果反馈太乱，又会显得“吵”。所以这里要做的是：**统一体验**。

### 1. 卡片悬停，轻一点就够了

```css
.product-card {
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

.product-card:hover {
  transform: translateY(-4px);
  box-shadow: 0 8px 24px rgba(0, 0, 0, 0.08);
}
```

轻微上浮、阴影加深，这种反馈足够让用户感觉到“这是一张可关注的卡片”。别做太夸张，不然页面会显得浮躁。

### 2. 按钮按下时，也要有瞬间反馈

```css
.filter-btn:active,
.sort-btn:active {
  transform: scale(0.98);
}
```

这个变化很小，但很有用。用户按下按钮的那一瞬间，页面给出回应，交互感就出来了。

### 3. 把统一性放在前面

圆角、间距、字号、边框这些东西，尽量都统一。产品页不是拼贴画，所有模块都应该像来自同一套设计语言。你做得越统一，页面就越像真的产品。

#### 阶段成果
页面开始有了**可交互感、统一感和产品味**，不再只是静态堆内容。

## 五、新手最容易踩的坑：只看单个卡片，不看整体节奏

### 坑一：卡片自己挺好看，放一起就乱

### 坑三：内容长度不控制，页面像锯齿
解决办法很直接：

- 限制文字行数；
- 保持图片比例；
- 让价格区域位置稳定；
- 统一卡片内部节奏。

### 本章最小检查清单
做完以后，至少确认这几项：

- 商品列表是否能自动换行并整齐排列？
- 卡片高度是否尽量稳定？
- 筛选和排序按钮是否有激活状态？
- 鼠标悬停时页面是否有反馈？
- 整体视觉是否统一，而不是东一块西一块？

#### 阶段成果
如果这些都做到了，你的商品页就已经从“能用”升级成了**更像产品的页面**。

# 第10章 第10章 做一个最常见的页面：登录页结构、表单校验和提交前检查

这一章我们来做一个最常见、也最适合练手的页面：**登录页**。别看它简单，里面已经把前端最基础的一套流程串起来了：**HTML 负责结构，CSS 负责样式，JavaScript 负责交互，DOM 负责读写页面状态，事件负责接住用户操作**。

这一章的目标很明确：  
你要自己做出一个带有账号、密码、记住我、登录按钮和提示区的登录页，并实现**提交前校验**、**错误提示展示**、**按钮状态变化**。做完以后，你就不是只会写单个标签、单个样式、单个函数了，而是开始能把三件套串起来做一个完整小页面。

### 本章完成标准
读完并照着做完这一章后，你应该能独立做出一个**可提交前校验的登录页**：  
- 账号和密码都有输入框  
- 空值和长度错误会及时提示  
- 校验通过后按钮可用  
- 表单提交时不会直接刷新页面  
- 页面上能看到明确的反馈结果

## 一、先拆页面：登录页到底由哪几块组成？

做页面第一步，不是急着敲代码，而是先把页面拆明白。登录页虽然常见，但结构通常比较固定，我们可以拆成这几块：

1. **标题区**：比如“欢迎登录”
2. **账号输入区**
3. **密码输入区**
4. **记住我**
5. **登录按钮**
6. **提示区**

为什么要先这么拆？因为这样后面写 HTML 会很顺，每一块都对应一个功能，结构清楚，CSS 才知道怎么布局，JavaScript 也更容易找到目标元素。新手最怕的不是不会写代码，而是元素一多就乱了。

你可以先在脑子里画个草图：  
**上面一个标题，中间两个输入框，下面是“记住我”和登录按钮，最底下留一行提示文字。**

### 阶段成果
到这里，你已经有了页面的“脑图”。虽然还没写代码，但页面的结构和功能区块已经清楚了。

---

## 二、HTML 结构怎么写？为什么要先考虑填写顺序？

先写结构，再谈样式，这是新手最该养成的习惯。因为 HTML 决定页面骨架，骨架顺不顺，直接影响后面所有步骤。

基础结构可以这样写：

```html
<form id="loginForm" novalidate>
  <h1>欢迎登录</h1>

  <div class="form-item">
    <label for="username">账号</label>
    <input id="username" type="text" placeholder="请输入用户名或邮箱" />
  </div>

  <div class="form-item">
    <label for="password">密码</label>
    <input id="password" type="password" placeholder="请输入密码" />
  </div>

  <div class="form-extra">
    <label>
      <input id="remember" type="checkbox" />
      记住我
    </label>
  </div>

  <button type="submit" id="loginBtn" disabled>登录</button>
  <p id="tips" class="tips" aria-live="polite"></p>
</form>
```

这里有几个点要注意：

- `label` 和 `input` 最好用 `for` / `id` 关联，这样点文字也能聚焦输入框。
- 输入顺序要按用户填写顺序来：先账号，再密码，再选项，再按钮。
- 提示区要单独留出来，后面 JavaScript 只要改这个区域的内容，就能完成提示。
- `novalidate` 是先关掉浏览器默认校验，我们自己来做提交前检查。
- 按钮先写成 `disabled`，初始状态更符合“还没填完不能提交”的逻辑。

### 新手提醒
很多人一开始只想着“先把页面做得像”，结果元素摆得很散，后面写 JS 时找不到入口。**结构越清楚，交互越容易做。**  
还有一点，表单内容最好都放在 `form` 里，这样提交、校验、按钮行为才统一。

### 阶段成果
你现在已经完成了**页面骨架**。它可能还不漂亮，但它已经是一张完整的登录页结构了。

---

## 三、CSS 怎么美化？只做基础布局就够了

这一章的 CSS 不追求炫技，目标只有一个：让页面**清晰、整齐、像一个真实登录页**。

先做这几件事就够了：

1. 页面居中
2. 卡片化布局
3. 输入框统一宽度
4. 按钮颜色明确
5. 错误提示区预留空间

示例思路如下：

```css
body {
  font-family: sans-serif;
  background: #f5f7fa;
}

#loginForm {
  width: 320px;
  margin: 80px auto;
  padding: 24px;
  background: #fff;
  border-radius: 12px;
}

.form-item,
.form-extra {
  margin-bottom: 16px;
}

input[type="text"],
input[type="password"] {
  width: 100%;
  padding: 10px;
  box-sizing: border-box;
}

button {
  width: 100%;
  padding: 10px;
  background: #1677ff;
  color: #fff;
  border: none;
  border-radius: 6px;
}

button:disabled {
  background: #9bbcff;
  cursor: not-allowed;
}

.tips {
  min-height: 20px;
  color: #d93026;
  margin-top: 12px;
}
```

为什么这么写？

- `width: 320px` 让登录区域像一个独立卡片，视觉更集中。
- `box-sizing: border-box` 很重要，输入框加了 padding 以后不会把宽度撑破。
- `min-height` 给提示区预留空间，报错时页面不会突然上下跳动。
- `button:disabled` 让禁用状态更明显，用户一眼就知道现在不能提交。

基础样式不用多，关键是先把“页面像样”这件事完成。新手最容易犯的错就是一上来追求复杂视觉，结果布局乱、结构乱，后面交互也跟着乱。

### 阶段成果
现在页面已经不是“裸结构”了，而是一个**有卡片感、有层次感、有基本视觉秩序的登录页**。

---

## 四、提交前校验怎么做？先把规则定清楚

现在进入最关键的 JavaScript 部分。登录页最重要的不是“点按钮就提交”，而是**先检查用户填得对不对**。

提交前校验通常先做三类最基础的规则：

### 1. 不能为空
账号不能为空，密码不能为空。  
这是最基本的判断，空着提交没有意义。

### 2. 长度检查
账号至少 3 位，密码至少 6 位。  
这是一个非常适合新手练习的规则，逻辑简单，效果也明显。

### 3. 提示信息要明确
不要只写“输入错误”，而要告诉用户到底哪里错了，比如“密码至少 6 位”。  
用户看到具体提示，才知道该改什么。

示例逻辑如下：

```js
const form = document.querySelector('#loginForm');
const username = document.querySelector('#username');
const password = document.querySelector('#password');
const tips = document.querySelector('#tips');
const btn = document.querySelector('#loginBtn');

function updateButtonState() {
  const canSubmit =
    username.value.trim().length >= 3 &&
    password.value.trim().length >= 6;

  btn.disabled = !canSubmit;
}

function showTip(message, isSuccess) {
  tips.textContent = message;
  tips.style.color = isSuccess ? '#2e7d32' : '#d93026';
}

username.addEventListener('input', updateButtonState);
password.addEventListener('input', updateButtonState);

form.addEventListener('submit', function (e) {
  e.preventDefault();

  const u = username.value.trim();
  const p = password.value.trim();

  if (u === '') {
    showTip('账号不能为空', false);
    return;
  }

  if (u.length < 3) {
    showTip('账号至少 3 个字符', false);
    return;
  }

  if (p === '') {
    showTip('密码不能为空', false);
    return;
  }

  if (p.length < 6) {
    showTip('密码至少 6 位', false);
    return;
  }

  showTip('校验通过，准备提交', true);
});
```

这里为什么要用 `preventDefault()`？  
因为表单默认提交会刷新页面。我们现在是先做前端校验，所以要先拦住默认行为，再处理逻辑。这个步骤很关键，不然你还没来得及提示，页面就跳走了。

### 新手提醒
很多新手喜欢在用户点提交后，才统一弹一句“输入不合法”。这太晚了。更好的方式是：**尽早提示，减少用户反复试错**。  
前端校验不是为了“刁难用户”，而是为了帮用户更快地填对。

### 阶段成果
你已经让登录页具备了最基础的“判断能力”。它不再只是静态页面，而是会根据用户输入做出反应了。

---

## 五、错误提示怎么展示？按钮什么时候可用、什么时候禁用？

这一步是在校验基础上继续优化体验。

### 错误提示展示原则
- 提示要具体，不要含糊
- 提示要放在固定位置，避免页面乱跳
- 校验通过时，最好把提示改成成功信息

前面我们已经把提示区独立出来了，现在只要通过 `showTip()` 去更新内容就行。这样做的好处是，所有提示逻辑集中在一个地方，后面想改文案也方便。

### 按钮状态变化
按钮不是一定要一直可点。很多真实页面会根据输入情况控制按钮状态：

- 当账号或密码为空时，按钮禁用
- 当内容基本满足要求时，按钮启用

这样做的好处是，用户不用点了以后才知道不行，交互更自然。

我们在上面的 `updateButtonState()` 里已经做了这个判断：

- 账号至少 3 个字符
- 密码至少 6 位
- 满足条件后按钮才可点

`input` 事件的意思是：用户每输入一个字符，页面就立即响应。  
这样按钮状态会随着输入实时变化，页面就“活”起来了。

### 新手提醒
不要等到提交后才发现“不行”。很多时候，**提前禁用按钮 + 即时提示** 比“提交后报错”更友好，也更像真实产品。  
不过这一章我们只做基础版，不要把逻辑搞太复杂，先把“能用、好懂”做好。

### 阶段成果
现在你的登录页已经具备了两种交互能力：  
1. **即时反馈**  
2. **按钮状态控制**

这就是前端基础交互最常见的落地形式。

---

## 六、把整个流程串起来：为什么一定要按这个顺序做？

这一章你要记住一个固定流程：

1. **先结构**：把页面元素摆出来
2. **后样式**：让页面看起来整齐、清楚
3. **再交互**：加校验、加提示、加状态变化
4. **最后优化细节**：比如提示区、防止跳动、按钮禁用

为什么不能反过来？  
因为如果你一开始就写 JS，很容易不知道页面上该操作哪个元素；如果先追求样式，可能会把结构弄乱；而先结构后样式再交互，是最稳、最适合新手的开发顺序。

你可以把它理解成盖房子：

- 先打地基：HTML
- 再做外观：CSS
- 最后装开关和门锁：JavaScript

顺序对了，后面就顺。

### 检查清单
做完后，你可以自己检查这几项：

- 账号和密码输入顺序是否自然？
- `label` 是否能正确关联输入框？
- 空值、长度问题是否都有提示？
- 提示信息是否清晰？
- 按钮是否能根据输入状态变化？
- 提交时页面是否不会直接刷新？

如果这几项都能做到，说明你已经把一个登录页的基本逻辑跑通了。

## 结尾小结：你已经掌握了登录页的基础做法

这一章我们用登录页把前端三件套真正串了一次：

- **HTML**：负责结构，拆出账号、密码、记住我、按钮和提示区
- **CSS**：负责布局和视觉，让页面像一个完整的登录卡片
- **JavaScript**：负责提交前校验、错误提示和按钮状态变化
- **DOM + 事件**：把用户输入接进来，驱动页面反应

你会发现，登录页其实是一个非常适合新手练手的小项目，因为它不复杂，但很完整。它既能练结构，也能练样式，还能练一点最基础的交互逻辑。

接下来你完全可以把这一套思路迁移到别的页面，比如：

- 在**个人介绍页**里做一个简单联系表单
- 在**待办清单**里做输入校验和按钮状态
- 在**简单商品展示页**里加入搜索框和筛选按钮

### 本章行动建议
照着本章结构，自己独立做一遍登录页，并额外加上这两个小改动：

1. 给账号输入框加一个“请输入 3 位以上账号”的提示  
2. 当校验通过时，把提示区改成绿色成功信息

如果你想再往前走一步，可以继续试试：  
- 给“记住我”加上勾选状态保存  
- 当输入框为空时，给它加一个轻微高亮提示  

你只要把这一章真正做下来，前端里最常见的“表单结构 + 校验 + 交互”就已经入门了。

# 第11章 第11章 把三个例子串成方法：统一整理 HTML、CSS、JavaScript 的协作套路

前面我们已经分别做过个人介绍页、待办清单、简单商品展示页和登录页。你会发现，这几个页面虽然长得不一样，但落到手里，做法其实很像。

这一章老赵不再带你“再做一个新页面”，而是把前面的例子串起来，整理成一套**可复用的方法**。以后你拿到新需求，不用每次从零想，而是能先判断结构、再安排样式、最后加交互，稳稳做完一个小网页。

---

## 一、先统一理解：HTML、CSS、JavaScript 各管什么

这三个东西不是各干各的，而是一套配合关系，分工很明确。

- **HTML** 负责页面里“有什么”，也就是结构和内容
- **CSS** 负责页面“长什么样”，也就是布局和视觉
- **JavaScript** 负责页面“会不会动”，也就是交互和行为

你可以把它理解成：HTML 是骨架，CSS 是外观，JS 是动作。  
新手最容易犯的错，就是把这三件事混在一起写，最后页面能跑，但自己也说不清为什么这么写。记住一句话：**先把结构站稳，再去做样式，最后才接交互。**

---

## 二、把“先结构、后样式、再交互”变成固定模板

这个顺序不是口号，而是你以后做页面时最省力的流程。

### 1. 先写 HTML 结构

先别急着想颜色、圆角、阴影，先把页面需要的块列出来。  
比如登录页至少有：

- 标题
- 用户名输入框
- 密码输入框
- 登录按钮
- 提示信息区

待办清单至少有：

- 输入框
- 添加按钮
- 任务列表

这样做的好处很直接：你先得到一个清楚的骨架，后面的 CSS 和 JS 才知道该往哪里落。

### 2. 再写 CSS 样式

结构定了，样式才好安排。  
你知道哪里是标题、哪里是表单、哪里是列表，就能开始做版心、间距、对齐、字号层级和按钮状态。

为什么不能反过来？因为很多新手一上来先追求“好看”，结果样式越调越散，结构却没理顺。最后页面看着热闹，实际上很难维护。老赵提醒你：**样式是装饰，结构才是地基。**

### 3. 最后加 JavaScript 交互

JS 不是独立起飞的，它是建立在已有结构上的。  
比如你要给按钮加点击事件，前提是按钮已经在 HTML 里；你要做表单校验，前提是输入框和提示区已经准备好；你要做数据渲染，前提是页面里有容器接收这些内容。

所以，JS 最适合放在最后加。这样你调试时也更容易判断问题出在哪：是结构没搭好，还是样式没对上，还是事件逻辑写错了。

---

## 三、四个例子，其实是在练同一套能力

前面那几个页面看着不一样，但拆开以后，你会发现它们都在练同一个套路。

### 1. 个人介绍页：练“静态信息怎么摆清楚”

这个页面基本靠 HTML 和 CSS 就能完成。

- HTML 放头像、姓名、简介、技能列表
- CSS 做版心、排版、字号和间距

它训练的是：**如何把内容分组，让用户一眼看懂。**  
新手常见问题是把所有东西堆成一坨，结果信息都有了，但层次全没了。个人介绍页就是让你先学会“展示”，而不是急着写交互。

### 2. 待办清单：练 DOM 操作和事件处理

待办清单比介绍页多一步：用户要能输入、添加、完成、删除。

- HTML：输入框、按钮、列表容器
- CSS：表单布局、列表样式、完成状态样式
- JS：监听点击事件，新增任务，切换完成状态，删除任务

这个例子里最重要的是：**用户操作的是页面，JS 操作的是 DOM。**  
你点了“添加”，JS 才把输入内容变成一个列表项；你点了“完成”，JS 才给这一项加上状态。它不是在背语法，而是在练“事件触发后页面怎么变”。

### 3. 简单商品展示页：练数据渲染

商品展示页的重点，不是手写很多重复卡片，而是让数据自己生成页面内容。

- HTML：准备商品容器
- CSS：卡片布局、图片比例、文字层级
- JS：用数组把商品渲染出来

这个例子最适合理解“**数据 → 页面**”这件事。  
以后你再碰到文章列表、课程列表、活动列表，就不要一个个手敲，而是先想：能不能用数组和循环把它渲染出来？这就是从“写页面”迈向“用数据做页面”。

### 4. 登录页：练表单提交前校验和按钮状态变化

登录页最适合练“提交前先检查”。

- HTML：用户名、密码、按钮、提示区
- CSS：表单对齐、按钮样式、错误提示样式
- JS：监听提交、检查输入、控制按钮状态、展示提示信息

这个页面的核心不是炫技，而是让用户知道：**现在能不能提交，错在哪里。**  
比如用户名不能为空，密码不能太短，按钮在没填完时先禁用，输入正确后再允许提交。这个思路以后会一直用到别的表单页面里。

---

## 四、以后做新页面时，怎么直接套这套流程

老赵建议你以后做任何小网页，都按下面这个顺序来，别每次都从零发散。

### 第一步：先列需求
先回答三个问题：

- 页面是干什么的？
- 用户要做什么？
- 最终要有哪些区域？

比如登录页，就是输入、校验、提交；待办清单，就是添加、完成、删除。  
这一步的作用，是把脑子里的想法先整理成清单，避免写到一半发现少了功能。

### 第二步：再拆结构
把页面拆成几个块，先只管“有没有”，不管“漂不漂亮”。

比如登录页可以拆成标题区、表单区、提示区。  
待办清单可以拆成输入区、列表区。  
这样一拆，HTML 的骨架就很清楚了。

### 第三步：先做布局，再做细节
先把大位置摆好，再调颜色、边框、字号、间距。  
原因很简单：大结构不稳，细节调再多也没用。页面先站得住，再去讲好不好看。

### 第四步：最后加交互
等静态页面完整了，再接 JS。  
这样你更容易排查问题：按钮没反应，是没选到元素，还是没绑事件，还是结构本身就错了。

### 第五步：统一检查
最后看五件事：

- 结构是否清楚
- 样式是否统一
- 按钮有没有反馈
- 输入有没有校验
- 列表或数据有没有正确渲染

这五步走完，你就不是“凭感觉做页面”，而是在按流程做页面。

---

## 五、新手最容易踩的坑：每次都重新发明流程

这一段你一定要记住。

### 坑一：先写 JS，再补 HTML
这样最容易乱。因为元素都没定下来，JS 就没地方落。  
正确顺序一定是：先结构，再样式，最后交互。

### 坑二：只顾样式，不管结构语义
页面可能看着像了，但里面的层次是乱的。  
后面一加事件、加校验、加渲染，就会发现不好选元素，也不好维护。

### 坑三：每个页面都从头想
其实很多页面只是“展示、输入、列表、按钮、校验、渲染”这些模块的不同组合。  
你要做的是建立模板，不是每次重新造轮子。

### 坑四：不看阶段成果
新手最怕一口气闷头写，写到最后才发现全错了。  
所以每一步都要看到结果：先能看见结构，再能看见样式，再能点出交互。阶段成果就是你的安全绳。

## 六、复盘：一套方法，能通吃很多小页面

把前面的内容串起来，你就能得到一个稳定的前端小网页开发流程：

1. 先看需求，判断页面类型  
2. 用 HTML 搭结构  
3. 用 CSS 做布局和美化  
4. 用 JavaScript 做交互、校验、渲染

个人介绍页教你怎么展示信息，待办清单教你怎么处理用户操作，商品展示页教你怎么用数据生成页面，登录页教你怎么做表单校验和按钮状态。四个例子串起来，你学到的就不只是几个页面，而是一套能反复使用的方法。

### 本章阶段成果

到这里，你应该已经能把“做一个页面”拆成一套清楚的流程了。  
这很重要，因为真正的能力不是记住某个写法，而是你拿到新需求时，知道先做什么、后做什么、为什么这么做。

### 以后你可以直接照着做

下次练习新页面时，先别急着开编辑器，先写下这 5 件事：

- 页面要做什么
- 需要哪些结构
- 哪些地方交给 CSS
- 哪些地方交给 JS
- 最后要检查什么

你会发现，前端三件套不是分开学完就结束，而是要按流程配合起来用。  
**这一章你只要记住一句话：会写标签、会调样式、会加事件都不算完，真正重要的是把它们串成一套能复用的方法。**

# 第12章 第12章 收工前再检查一遍：调细节、排错误、复盘并完成你的第一个小作品

## 开篇：先别急着说“我做完了”

到这一步，你手里大概率已经有一个能看的小网页了：个人介绍页、待办清单、简单商品展示页，或者登录页。  
但老赵提醒你一句：**能跑，不等于做完；能看，不等于做好。**

收工前，咱们不再加大功能，而是把页面从“能用”拉到“像个作品”。这一章就做三件事：

1. 检查结构、样式、交互是否正常；
2. 排查常见问题；
3. 做最后一轮优化，然后复盘你到底学会了什么。

你可以把它当成交作业前的最后验收。很多新手就是卡在这一步：代码写完了，却没认真检查，结果一运行才发现按钮没反应、排版乱了、表单也不对。别急，咱们按顺序查，问题基本都能找到。  
**这一章的阶段成果很明确：把页面检查到结构完整、样式统一、交互可用，最后形成一个能独立展示的小作品。**

## 一、先按顺序做最后检查

检查页面别凭感觉，按这个顺序来：**HTML 结构 → CSS 外观 → JavaScript 交互**。  
顺序很重要，因为前一层有问题，后一层就容易误判。

### 1. 先看结构有没有缺块

打开页面后，先确认内容是不是都在：

- 标题是否显示
- 主要模块有没有漏掉
- 个人介绍页里头像、简介、按钮是否完整
- 待办清单里输入框、添加按钮、列表是否在
- 商品展示页里商品卡片是否正常渲染
- 登录页里用户名、密码、提交按钮是否齐全

**为什么先看结构？**  
因为 HTML 是底座。底座不完整，样式和交互都是补丁。先确认“页面该有的东西有没有”，再看“长得好不好看”。

老赵建议你养成习惯：每做完一个模块，就从上到下扫一遍。比如个人介绍页，先看标题、头像、简介、联系方式有没有按顺序摆出来；待办清单就先看输入框和列表区域是否完整。这样问题不会拖到最后一起爆。

### 2. 再看样式是否统一

重点看这几项：

- 间距是否一致
- 字体大小是否统一
- 按钮风格是否统一
- 卡片、表单、列表有没有对齐
- 页面是不是太挤，或者空白太多

**新手常见误区：**  
看到哪儿不好看就单独改哪儿，最后页面会变得东一块西一块。更好的做法是：先定基础样式，再局部微调。比如先统一字体、颜色、按钮圆角、卡片阴影，再去调某个模块的特殊样式。这样页面整体更像作品，而不是拼起来的作业。

如果你做的是简单商品展示页，还要重点看卡片是否整齐：图片大小有没有统一，商品名会不会乱换行，价格和按钮是否对齐。样式统一了，页面会立刻专业很多。

### 3. 最后测交互是否可用

逐个点、逐个试：

- 待办清单：能不能新增、删除、切换完成状态
- 登录页：点击提交前有没有校验
- 商品展示页：按钮状态会不会变化
- 页面事件：点击后有没有反应，输入后有没有反馈

**判断标准很简单：**  
用户照着操作一遍，结果和预期一致，就算通过。

比如你点待办清单的“添加”按钮，输入内容应该出现在列表里；你勾选任务，任务状态应该变化；你点登录页提交，如果用户名或密码为空，页面应该给出提示。别小看这些动作，它们就是 HTML、CSS、JavaScript 协作是否顺畅的直接体现。

## 二、常见问题排查：最后再核对一遍

这一节不讲大道理，直接给你一份能照着查的清单。很多新手不是不会写，而是卡在“为什么就是不对”。

### 1. 元素没显示，先查 HTML

常见原因有：

- 标签没闭合
- 内容写到错误层级里了
- 元素本身被删掉了
- 写了但没保存文件

**排查顺序：先看代码有没有，再看浏览器有没有。**

如果页面上少了某个模块，先别急着怪 CSS，先回到 HTML 里看结构是不是完整，父级容器在不在，内容是不是放错位置。新手最容易犯的错，就是元素明明写了，却因为层级或缩进乱了，看起来像“没显示”。

### 2. 样式不生效，先查选择器

比如你写了 `.btn {}`，但页面上按钮类名其实是 `button`，那 CSS 再写一百行也没用。

重点检查：

- 类名是不是拼错了
- 选择器是不是选对了元素
- CSS 文件有没有正确引入
- 后写的样式是不是覆盖了前面的样式

老赵提醒你，CSS 问题很多时候不是“不会写”，而是“没对上”。特别是做按钮状态变化时，常会出现基础样式写好了，但点击后加上的类名没有对应样式，结果看起来像“JS 没效果”。其实可能只是样式类没接上。

### 3. 事件没响应，先查 JS

比如按钮点了没反应，常见问题有：

- 获取元素时，选择器写错了
- 代码执行时，元素还没加载出来
- 事件类型写错了，比如把 `click` 写成别的
- 函数里报错了，但你没看控制台

**老赵提醒：**  
浏览器控制台不是摆设。遇到问题，先看报错信息，往往比盲猜快得多。  
控制台报错，通常说明 JS 执行链路断了；页面没显示，但控制台没报错，更多时候是 HTML 或 CSS 的问题。先分清这两类，排查会快很多。

如果你做的是登录页，提交按钮没反应，就去检查事件有没有绑定到按钮上；如果你做的是待办清单，新增功能没生效，就去看输入框取值是不是空的，或者列表渲染函数有没有报错。问题通常就在一两行代码里。

### 4. 数据渲染不对，先查数组和循环

如果你做了简单商品展示页，商品卡片没有渲染出来，或者内容乱了，那就重点看：

- 数据数组里有没有内容
- `map` 或循环有没有写对
- 拼接的 HTML 字符串有没有少标签
- 渲染函数有没有被调用

新手很容易把“数据有了”和“页面显示出来了”混为一谈。其实中间还差一步：**把数据放进 DOM**。  
只要这一层没接好，页面就会空着或者乱着。你可以先在控制台打印数据，确认数组确实有内容，再去看渲染函数是不是执行了。这样排查会更稳。

## 三、最后优化一点点，让它更像成品

这一轮不追求复杂，追求完整。

### 1. 做一个“保存—回看—修改”的动作

你可以按这个小流程收尾：

1. 保存所有文件；
2. 刷新浏览器回看页面；
3. 发现问题就改一处；
4. 再保存，再回看。

这个动作很普通，但特别重要。很多页面不是一次写坏的，而是改着改着忘了保存，或者改完没刷新。收尾时按这个流程走一遍，能少踩很多坑。

### 2. 补齐一点状态感

比如：

- 待办清单为空时，加一句“暂无待办事项”
- 登录页校验失败时，给出明确提示
- 商品展示页按钮点击后，改成“已加入”
- 个人介绍页把重点按钮放到更显眼的位置

这些都是小改动，但能让用户知道“发生了什么”。按钮状态变化、提示文案、空状态展示，都是前端最基础也最实用的细节。

### 3. 给自己留一个导出式收尾

如果你已经把页面文件整理好了，就把项目文件夹保存到一个固定位置，顺手备份一份。至少做到：

- 文件命名清楚
- HTML、CSS、JS 分开摆放
- 资源路径没乱
- 页面能正常打开

这一步不是技术炫技，而是让你的第一个小作品真的“收进文件夹”，而不是停留在浏览器里看一眼就算。

### 4. 检查不同状态下的页面表现

别只看“正常情况”，还要故意试试异常情况：

- 输入框不填内容会怎样
- 列表为空会怎样
- 长文本会不会把布局撑坏
- 按钮连续点几次会不会重复提交
- 图片加载失败时页面会不会太难看

这一步很像交作业前的“压力测试”。不是为了找茬，而是让页面更稳。新手最容易忽略的就是边界情况：平时点一下没问题，可一旦用户连续点击，或者输入超长内容，页面就露馅了。  
咱们现在做的是小作品，不要求多复杂，但至少要经得住正常使用。

- 我有没有在 JS 里正确获取 DOM？
- 我有没有在提交前做校验？
- 我有没有给按钮状态和空状态留反馈？

这些问题看起来琐碎，但它们就是前端新手进步最快的一条路。你每次复盘一次，下次就会少踩一次坑。
