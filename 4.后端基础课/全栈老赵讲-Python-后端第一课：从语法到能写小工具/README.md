## 老赵式实战习惯：先看目标，再拆步骤，边讲边练

赵老师做事有个固定习惯，老赵这里给你整理成一套好记、好用的方法框架，你后面每次写小程序都可以照着来：

**先看目标 → 再拆步骤 → 边讲边练 → 小步快跑 → 先排错再优化。**

这不是口号，是实操顺序。比如你想做一个“统计文本里高频词”的小工具，老赵不会上来就写几十行代码，而是先把这几个问题问清楚：

- 读入数据；

- 输出结果；

每次只解决一个小问题，不要一口吃成胖子。**小步快跑**，才是新手最稳的节奏。你写出来的不一定一开始就完美，但只要能跑、能改、能迭代，就已经走在正确路上了。

## 小步快跑怎么学：每章学一点、练一点、收一点

这本书不会要求你一次把所有知识吃下去。那样很容易累，也很容易忘。更适合新手的方法是：**每章学一点，马上练一点，最后收一点。**

这里说的“收一点”，就是把知识变成自己的东西，不要只看懂，要写出来。

### 你可以这样学：

- **学一点**：只抓本章最核心的 1～2 个概念；
- **练一点**：跟着敲一个最小例子；
- **收一点**：自己改一改，看看能不能跑通；
- **复盘一点**：写完以后问自己，输入、处理、输出有没有讲明白。

比如学字符串处理，不要一上来就追求“万能文本处理器”。先做几个最常用的动作就够了：

- 判断是否包含某个关键词；
- 把内容切分成列表；
- 替换掉某些字符。

学文件操作，也别急着写复杂目录扫描。先练最基本的：

- 读一个文本文件；
- 写一个结果文件；
- 看懂 `FileNotFoundError`。

学函数，也不要先研究高深设计。先问自己：**这段重复代码，能不能封装成一个函数？**只要你开始有这个意识，代码就会慢慢清爽，逻辑也会越来越清楚。

程序能力不是“突然开窍”的，而是一点点练出来的。

### 常用内置函数：别硬写，先看看 Python 有没有现成的

### 模块使用：别把所有代码堆在一个文件里

- 一个文件放数据处理；
- 需要时再引入标准库模块。

模块的好处很明显：代码更清楚、调试更方便、以后也更容易复用。你以后做小工具，最怕的不是功能少，而是全写在一个文件里，找半天也不知道哪里出了问题。

### 错误排查：程序跑不通，先别急着怀疑人生

新手写代码，十有八九会报错。这很正常。重要的不是“别报错”，而是“会看报错”。

赵老师的排错习惯很朴素：

1. 先看报错最后一行；
2. 再看报错发生在哪一行；
3. 想一想这一行的变量值是不是不对；
4. 从最小修改开始试。

很多问题其实不是逻辑大错，而是：

- 变量名写错了；
- 缩进乱了；
- 类型不对；
- 文件路径写错了。

程序员不是不犯错，而是知道怎么把错找出来。你每多解决一次报错，实际上都是在补自己的实战经验。

## 一、变量、类型、赋值和简单计算：先把数据装进去

### 1.1 变量到底是干什么的？

变量就是一个“带名字的盒子”。程序运行时，数据先放进去，后面需要的时候再拿出来。名字起得好不好，直接影响你后面看代码时的舒服程度。

```python
name = "老赵"
age = 18
score = 95.5
```

这里：

- `name` 存字符串
- `age` 存整数
- `score` 存浮点数

变量不只是保存数据，更重要的是：**让程序里的每一步都有中间结果可以接住。**  
比如做总价计算，就可以先把单价、数量分别放进变量，再算总价。这样代码更清楚，也更方便排错。

### 1.2 常见类型先认个脸

这一章先记住最常见的几种：

- `int`：整数
- `float`：小数
- `str`：字符串
- `bool`：布尔值，只有 `True` 和 `False`

先记一个实用判断：

- **要参与数学计算的，通常是数字类型**
- **要展示给人看、接收文本输入的，通常先按字符串处理**

后面你会反复遇到一个坑：`input()` 拿到的默认是字符串，就算你输入的是 `18`，它也还是 `"18"`。要参与计算，就得自己转类型。

### 1.3 赋值不是“等于”，而是“装进去”

新手最容易把 `=` 理解成数学里的“相等”。在 Python 里，`=` 更像是“把右边的值放到左边”。

```python
x = 10
x = x + 1
```

这不是说 10 等于 11，而是先算右边，再把结果放回 `x`。这个动作很常见，后面统计、累加、计数都靠它。

### 1.4 简单计算：先把加减乘除用顺

```python
a = 10
b = 3

print(a + b)
print(a - b)
print(a * b)
print(a / b)
print(a // b)
print(a % b)
print(a ** b)
```

这几个运算符要熟：

- `+` 加
- `-` 减
- `*` 乘
- `/` 除
- `//` 整除
- `%` 取余，常用于判断奇偶、分页、循环计数
- `**` 幂运算

#### 赵老师的实战习惯

老赵写小工具时，不喜欢一上来堆复杂表达式，而是先拆开：

```python
price = 30
count = 4
total = price * count
print(total)
```

这样写的好处很直接：

- 更容易看懂
- 更容易调试
- 后面改需求更轻松

**小工具里，能拆开就先拆开。**

## 二、输入输出怎么做：让程序和人对话

### 2.1 `input()`：把用户的话接进来

程序不只会自己算，还得能跟人交互。最基础的输入方式就是 `input()`。

```python
name = input("请输入你的名字：")
print(name)
```

要注意一个关键点：

> **`input()` 接收到的内容，默认都是字符串。**

所以：

```python
age = input("请输入年龄：")
```

此时 `age` 不是整数，而是字符串 `"18"` 这种形式。  
这就是为什么很多人第一次写“年龄 + 1”时会报错：不是不会算，而是把字符串当成了数字。

### 2.2 为什么输入后常常要转换类型？

因为年龄、数量、成绩通常要拿来计算。字符串没法直接做数学运算，所以要转成数字。

```python
age = input("请输入年龄：")
age = int(age)
print(age + 1)
```

更常见的写法：

```python
age = int(input("请输入年龄："))
```

如果输入的是小数，就用 `float()`：

```python
height = float(input("请输入身高："))
```

实战里记住一句话就够了：**凡是“看起来像数字、但来自输入”的值，第一时间想类型转换。**

### 2.3 `print()`：把结果清楚地展示出来

`print()` 是最直接的输出通道。新手常见问题不是不会用，而是输出不清楚。

```python
name = "老赵"
age = 18
print(name, age)
```

这能跑，但信息感一般。更推荐写得像人话一点：

```python
print("姓名：", name)
print("年龄：", age)
```

如果想让输出更整齐，就学会格式化输出。

### 2.4 格式化输出：把数据拼成完整句子

#### 方法一：f-string（推荐）

```python
name = "老赵"
age = 18
print(f"我叫{name}，今年{age}岁。")
```

这最直观，也最适合小工具场景。老赵建议优先用它。

#### 方法二：`.format()`

```python
print("我叫{}，今年{}岁。".format(name, age))
```

认识一下就行，先把 `f-string` 用顺手。

### 2.5 输出时的一个小习惯

别写这种：

```python
print("name", name, "age", age)
```

虽然能跑，但可读性一般。小工具里尽量输出得整齐：

```python
print(f"姓名：{name}")
print(f"年龄：{age}")
```

这样你排查问题时，一眼就能看出哪个字段有问题。

### 2.6 小练习

做一个最小交互程序：

1. 输入姓名
2. 输入年龄
3. 输出一句完整介绍
4. 再输出“明年你就 X 岁了”

注意第二步要做 `int()` 转换。先别追求漂亮界面，先把数据接对，把话说清楚。

## 三、常用内置函数：先把这几个用顺，效率会高很多

这一部分不让你死记函数表，而是先掌握最能帮你干活的几个。老赵的思路一直是：**先学最常用的，再在实战里补全。**

### 3.1 先记住“什么时候用、怎么用、常见坑”

你不需要一口气把所有内置函数背下来，先抓住三件事：

- **什么时候用**：看类型、做转换、统计长度、排序、生成序列
- **怎么用**：大部分函数就是“把数据丢进去，拿结果出来”
- **常见坑**：类型不对、字符串没转数字、结果是新对象却以为原地修改了

下面这几个，是你入门阶段最常碰到的。

### 3.2 `type()`：先看类型，再谈处理

```python
x = "18"
print(type(x))
```

它能帮你快速判断：

- 为什么这句不能算
- 为什么输入后还是字符串
- 为什么明明看着像数字，程序却报错

老赵排错时常做的一步就是：**先看类型，再看值。**

### 3.3 `len()`：数长度，字符串和列表都常用

```python
name = "Python"
print(len(name))
```

它能统计：

- 字符串长度
- 列表元素个数
- 字典键的数量

后面做文本处理、数据统计时会经常用到。

### 3.4 `int()`、`str()`：最常见的类型转换

```python
num = int("123")
text = str(456)
```

常见误区：

- 字符串直接拿去计算
- 数字直接拼接字符串时报错

比如：

```python
age = 18
print("年龄：" + age)
```

正确写法：

```python
print("年龄：" + str(age))
```

或者更省心一点：

```python
print(f"年龄：{age}")
```

你要养成习惯：**不同类型的东西要拼在一起时，先想清楚是不是需要转字符串。**

### 3.5 `list()`、`dict()`：把数据整理成容器

```python
a = list("abc")
print(a)
```

```python
b = dict(name="老赵", age=18)
print(b)
```

先把它们理解成“把数据整理成容器”。后面学列表和字典时你会更有感觉：程序里很多数据不是单个值，而是一组值、一份记录。

### 3.6 `sorted()`：排序，先记住“返回新结果”

```python
nums = [3, 1, 5, 2]
new_nums = sorted(nums)
print(new_nums)
```

它适合拿到一个新的排序结果，常用于展示前整理数据。  
**常见坑：**`sorted()` 返回的是新列表，原来的 `nums` 不会自动变。

### 3.7 `range()`：配合循环最常见

```python
for i in range(3):
    print(i)
```

输出的是 `0, 1, 2`。你现在先记住它是“生成一串数字”的工具，后面写循环会一直用到。

### 3.8 常用内置函数速查清单

先把这几个放进脑子里就够了：

- `type()`：看类型
- `len()`：看长度
- `int()`：转整数
- `str()`：转字符串
- `list()`：转列表
- `dict()`：转字典
- `sorted()`：排序
- `range()`：生成数字序列

它们不是摆设，是你写小工具时经常会顺手拿起来用的工具箱。

自己跑一遍：


重点不是只看结果，而是看“为什么这样”。建议你跑完后回答三个问题：

1. 哪一行返回的是类型信息？
2. 哪一行返回的是新列表？
3. 为什么 `"20"` 能转成数字，而 `"abc"` 不行？

这个动作很重要。你不只是要会用，还要慢慢建立“看到代码就能猜结果”的感觉。

## 四、怎么把零散语法变成可执行的小片段？

很多人卡住，不是因为不会单个语法，而是不会把它们串起来。老赵给你一个很实用的思路：**先做最小闭环。**

### 4.1 什么叫最小闭环？

一个最小闭环，通常只要三步：

1. 输入：拿到数据
2. 处理：对数据做一点变化
3. 输出：把结果打印出来

比如：

```python
name = input("请输入名字：")
length = len(name)
print(f"你的名字有 {length} 个字符")
```

这就是一个完整闭环。它不复杂，但它完整。很多小工具其实就是从这种结构慢慢长出来的。

### 4.2 写小片段的顺序：先人话，再代码

别先写代码，先用中文说清楚：

- 我要什么输入？
- 我要做什么处理？
- 我要输出什么结果？

比如“年龄明年加一”：

1. 输入年龄
2. 转成整数
3. 加 1
4. 输出结果

然后翻译成 Python：

```python
age = int(input("请输入年龄："))
next_age = age + 1
print(f"明年你就是 {next_age} 岁了")
```

这个顺序很关键。新手常常反过来，一上来就敲代码，敲到一半才发现自己根本没想清楚。

### 4.3 小步快跑，不要一口吃成胖子

新手最容易犯的错误是想一步写完所有功能，结果越写越乱。

老赵建议你这么做：

- 第一步：先让程序能跑
- 第二步：再让输出正确
- 第三步：再让格式好看
- 第四步：最后再考虑扩展

这就是**小步快跑**。每次只改一点，每次都确认能跑，这样出错了也容易定位。

### 4.4 代码组织的第一条经验：给变量起清楚名字

别图省事写：

```python
a = input()
b = int(a)
c = b + 1
```

能跑，但不好懂。更好的写法：

```python
age_text = input("请输入年龄：")
age = int(age_text)
next_age = age + 1
```

**变量名清楚，代码就已经成功了一半。**  
老赵写小工具时也很看重这一点：名字尽量让别人一眼知道它是什么。

### 4.5 错误排查：先别慌，按顺序看

新手报错很正常，别一看到红字就乱。老赵习惯按下面顺序查：

1. 看报错信息最后一行
2. 看报错指向哪一行
3. 看变量类型是不是对
4. 看括号、引号、缩进有没有问题
5. 把复杂表达式拆开测试

比如：

```python
age = input("请输入年龄：")
print(age + 1)
```

报错通常是因为 `age` 还是字符串。那就先查：

```python
print(type(age))
```

一查就知道问题在哪。**不会查错的程序员，只能靠运气；会查错的程序员，才是真的在掌控代码。**

### 4.6 赵老师的实战检查清单

老赵做小工具时，常会先过一遍这个小清单：

- 输入拿到了没有
- 类型转对了没有
- 中间变量有没有起清楚名字
- 输出是不是一眼能看懂
- 报错时能不能快速定位到一行

你也可以照着这个习惯来。别小看这几条，它们就是你以后写程序时的“护栏”。

## 一、字符串的基本操作：索引、切片、拼接、重复

### 1.1 字符串到底是什么？

字符串就是一串文本，比如：

```python
name = "Python"
text = "你好，老赵"
```

你可以把它理解成“按顺序排好的字符队列”。因为有顺序，所以才能做索引、切片这些操作。

先记住一句：**字符串是有位置的，每个字符都能被找到。**

---

### 1.2 索引：取某一个字符

字符串里的每个字符都有位置，从 `0` 开始。

```python
s = "Python"
print(s[0])   # P
print(s[1])   # y
print(s[-1])  # n
```

#### 记住两点

- 正向索引从 `0` 开始
- 负向索引从 `-1` 开始，表示倒数第一个字符

新手常见误区：

- 把第一个字符写成 `s[1]`
- 对空字符串取索引，直接报错

```python
s = ""
print(s[0])   # IndexError
```

#### 赵老师的实战习惯

处理用户输入前，先判断是不是空的：

```python
if s:
    print(s[0])
```

这就是“先防守，再进攻”。写小工具时，先想输入靠不靠谱，能少踩很多坑。

---

### 1.3 切片：截取一段内容

切片写法是：

```python
s[start:end:step]
```

注意：**左闭右开**，包含 `start`，不包含 `end`。

```python
s = "Python"
print(s[0:3])   # Pyt
print(s[2:5])   # tho
print(s[:3])    # Pyt
print(s[3:])    # hon
print(s[::2])   # Pto
```

#### 你可以这样理解

- `s[:3]`：从头截到第 3 个字符前
- `s[3:]`：从第 3 个字符开始，一直到最后
- `s[::2]`：每隔一个取一次

切片很适合做“截取前缀”“取中间内容”“按步长抽样”这类事。以后处理日志、文件名、日期字符串时，经常会用到。

#### 常见误区

- 以为 `s[0:3]` 会取 4 个字符
- 以为切片越界会报错，其实通常会自动容错

```python
s = "abc"
print(s[0:100])  # abc
```

切片比索引更安全，但别因为不报错就掉以轻心，范围还是要看对。

---

### 1.4 拼接和重复：把文本组织起来

字符串可以拼起来，也可以重复出现。

```python
first = "Hello"
second = "World"
print(first + " " + second)   # Hello World
print("ha" * 3)               # hahaha
```

#### 使用建议

- 简单拼接可以用 `+`
- 多个片段拼接，后面更推荐 `f-string` 或 `join`

#### 常见误区

字符串不能直接和数字相加：

```python
age = 18
print("年龄：" + age)   # TypeError
```

正确写法：

```python
print("年龄：" + str(age))
```

先记住：**字符串和数字不是一类东西，必要时要先转换。**

自己敲一遍：

```python

```

试着输出：

2. 最后一个字符
3. 前 6 个字符

## 二、常用文本处理方法：strip、split、join、replace、find、startswith、endswith

这一节是最实用的部分。  
你以后写小工具时，最常见的动作基本都能落到这些方法上：清理、拆分、拼接、查找、判断。

---

### 2.1 strip：去掉首尾空白

输入文本里最烦人的，就是前后多出来的空格、换行、制表符。

```python
s = "  hello \n"
print(s.strip())   # hello
```

`strip()` 默认去掉首尾空白字符，包括空格、换行 `\n`、制表符 `\t`。

#### 什么时候一定要用？

- 处理用户输入
- 读取文件每一行
- 比较文本前先清理一下

#### 误区

`strip()` 只去掉首尾，不会清理中间空格。

```python
s = "a  b"
print(s.strip())   # 还是 "a  b"
```

如果要处理中间多个空格，可以先 `split()` 再 `join()`。

---

### 2.2 split：按规则切开

`split()` 的意思是“按某个分隔符把字符串拆成列表”。

```python
line = "name,age,city"
parts = line.split(",")
print(parts)   # ['name', 'age', 'city']
```

不传分隔符时，默认按空白字符切：

```python
text = "Python  backend  beginner"
print(text.split())
# ['Python', 'backend', 'beginner']
```

#### 记住

- `split()` 的结果是**列表**
- 它适合处理结构化一点的文本

#### 赵老师的小习惯

不确定一行文本长什么样，先打印原始内容：

```python
print(repr(line))
```

这样能看到隐藏的换行和空格，排错很有用。

---

### 2.3 join：把列表拼回字符串

`join()` 和 `split()` 是一对搭档：`split()` 负责拆，`join()` 负责拼。

```python
parts = ["Python", "backend", "tool"]
result = "-".join(parts)
print(result)   # Python-backend-tool
```

#### 使用场景

- 把拆开的文本重新组装
- 统一输出分隔符
- 生成日志、标题、报告行

#### 误区

`join()` 的对象必须是字符串列表。

```python
items = ["a", 1, "c"]
print(",".join(items))   # 报错
```

要先转成字符串：

```python
items = ["a", 1, "c"]
print(",".join(map(str, items)))
```

---

### 2.4 replace：替换文本

`replace()` 的意思是“找到了就换掉”。

```python
s = "Python 2 is old"
print(s.replace("2", "3"))   # Python 3 is old
```

你还可以连续替换多个内容：

```python
s = "a,b,c"
print(s.replace(",", " | "))
# a | b | c
```

#### 误区

`replace()` 默认会替换所有匹配项，不是只替换一次。  
如果只想替换前几个，可以传第三个参数：

```python
s = "a,a,a"
print(s.replace("a", "b", 2))   # b,b,a
```

---

### 2.5 find：查找位置

有时候你不一定要替换，只想知道某个内容在哪儿。

```python
s = "hello python"
print(s.find("python"))   # 6
print(s.find("java"))     # -1
```

#### 返回值怎么理解

- 找到：返回首次出现的位置
- 找不到：返回 `-1`

这比 `index()` 更稳，因为 `index()` 找不到会报错。  
新手写小工具时，`find()` 更适合做判断。

```python
if s.find("python") != -1:
    print("找到了")
```

#### 常见问题

大小写不同会影响结果：

```python
text = "Learn Python"
if text.lower().find("python") != -1:
    print("包含 python")
```

---

### 2.6 startswith / endswith：判断开头和结尾

这两个方法在过滤文本时特别好用。

```python
filename = "report.txt"
print(filename.endswith(".txt"))   # True
print(filename.startswith("re"))    # True
```

#### 常见用途

- 判断文件类型
- 判断一行是不是标题
- 判断链接、路径、日志前缀

如果要忽略大小写，先统一转成小写：

```python
name = "README.MD"
print(name.lower().endswith(".md"))
```

---

### 2.7 一次把常用动作串起来

很多实际场景里，你不会只用一个方法，而是按顺序组合起来。

比如有一段文本：

```python
line = "  Python,Backend,TOOL  "
```

我们先清理，再拆分，再统一格式：

```python
parts = line.strip().split(",")
items = [item.strip().lower() for item in parts]
result = " | ".join(items)
print(result)
```

输出：

```python
python | backend | tool
```

这个流程很常见，后面处理文件每一行、网页抓下来的标题、日志里的字段，基本都能这么做。

---

## 三、格式化字符串的实战写法：f-string 为主

字符串不只是“拆和改”，还要把结果输出得像样。  
这时候，格式化就派上用场了。

老赵这里主推 **f-string**，因为它简单、直观、好读。

---

### 3.1 为什么推荐 f-string？

```python
name = "老赵"
age = 18
print(f"{name}今年{age}岁")
```

这比老式拼接舒服得多。

#### 好处

- 代码短
- 可读性强
- 能直接写表达式

```python
x = 3
y = 5
print(f"{x} + {y} = {x + y}")
```

以后写调试信息、结果提示、命令行输出，基本都会用到它。

---

### 3.2 实战中怎么用？

很多时候，你需要输出一行说明文字或者结构化结果。

```python
title = "Python入门"
price = 39.9
print(f"书名：{title}，价格：{price:.1f}元")
```

这里的 `:.1f` 表示保留 1 位小数。  
你先不用背太多格式，先记住：**f-string 不只是拼文本，还能控制输出格式。**

#### 常见场景

- 日志输出
- 报表行
- 命令行提示
- 调试打印

#### 一个实用建议

写小工具时，输出最好“像样一点”，不是为了好看，是为了排错方便：

```python
print(f"已处理文件：{filename}")
print(f"共找到 {count} 条记录")
```

比只打数字更清楚。

---

### 3.3 和字符串处理结合起来

比如处理一行原始输入：

```python
raw = "  python backend  "
clean = raw.strip().title()
print(f"标准结果：{clean}")
```

先整理，再展示。  
很多时候，程序不只是给机器看，也是给人看。输出清楚，排查也轻松。

---

## 四、字符串处理中的常见坑：空格、换行、大小写、编码概念入门

这一节很重要。  
很多新手不是不会方法，而是**忽略了脏数据**。

---

### 4.1 空格和换行：看不见，但很要命

你以为两个字符串一样，其实不一样。

```python
a = "hello"
b = "hello "
print(a == b)   # False
```

文件读出来的每一行，通常自带换行符：

```python
line = "Python\n"
print(line == "Python")   # False
```

所以比较前先做：

```python
line = line.strip()
```

#### 赵老师提醒

凡是用户输入、文件读入、网页抓取的文本，先默认它不干净。  
先清洗，再判断，这是习惯。

---

### 4.2 大小写：比较前先统一

字符串比较默认区分大小写：

```python
print("Python" == "python")   # False
```

如果想做不区分大小写的比较，先统一成小写：

```python
a = "Python"
b = "python"
print(a.lower() == b.lower())  # True
```

#### 常见用途

- 处理用户指令
- 判断关键词
- 检查文件扩展名

#### 推荐顺序

1. `strip()` 去空白
2. `lower()` 统一大小写
3. 再判断 `startswith()`、`endswith()`、`find()`

这套顺序很稳，适合直接照着用。

---

### 4.3 编码概念入门：知道有这回事就够了

你现在不用深挖编码细节，但至少要知道：**字符串是文本，文件和网络传输时会涉及编码/解码**。

后面读写文件时，中文乱码之类的问题，常常就和编码有关。  
先记住一句：

> 如果字符串显示异常，或者保存后打开不对，先想想编码是不是出了问题。

这就是一个新手应该有的排查意识。

---

## 五、一个简明检查表：字符串清洗前先看这几项

后面你写文本小工具时，遇到问题别乱猜，先按这个表检查。

| 检查项 | 常见现象 | 处理方法 |
| --- | --- | --- |
| 前后空格 | 比较结果不对 | `strip()` |
| 行尾换行 | 文件内容看着一样却不相等 | `strip()` 或 `rstrip()` |
| 大小写不一致 | `find()`、`startswith()`、`endswith()` 结果不稳定 | 先 `lower()` |
| 分隔符不统一 | `split()` 后字段数量不对 | 先确认原始文本 |
| 中间多空格 | 输出不整齐 | `split()` 后再 `join()` |
| 编码异常 | 中文乱码、保存后打开不正常 | 检查读写编码 |

你先不用背太多原理，先养成习惯：**先看原始文本，再做处理，再看输出。**

## 六、练习：清洗一段杂乱文本并输出标准结果

这一节做个小练习，目标很明确：**把一段乱文本清洗成统一格式并输出。**

---

### 6.1 题目

给你一段原始文本：

```python
raw = "  python , Backend,TOOL  "
```

要求输出成：

```python
python | backend | tool
```

你要做的事：

1. 去掉首尾空格
2. 按逗号拆分
3. 去掉每个元素前后的空格
4. 统一转成小写
5. 用 ` | ` 重新拼接

---

### 6.2 解题思路

这个题不难，关键是把字符串处理串起来。

#### 第一步：去掉首尾空格

```python
raw = raw.strip()
```

#### 第二步：拆成列表

```python
parts = raw.split(",")
```

#### 第三步：逐个清洗

```python
clean_parts = []
for item in parts:
    clean_parts.append(item.strip().lower())
```

#### 第四步：拼接输出

```python
result = " | ".join(clean_parts)
print(result)
```

---

### 6.3 完整代码

```python
raw = "  python , Backend,TOOL  "

raw = raw.strip()
parts = raw.split(",")

clean_parts = []
for item in parts:
    clean_parts.append(item.strip().lower())

result = " | ".join(clean_parts)
print(result)
```

输出：

```python
python | backend | tool
```

这段代码很短，但已经包含了字符串处理的完整套路。  
后面你写更复杂的文本工具，很多时候就是在这个基础上叠加。

---

### 6.4 再进阶一点：顺手封装成函数

老赵一直强调一个习惯：**能复用的逻辑，先收进函数里。**

```python
def clean_text(line):
    parts = line.strip().split(",")
    cleaned = []
    for item in parts:
        cleaned.append(item.strip().lower())
    return " | ".join(cleaned)

print(clean_text("  python , Backend,TOOL  "))
print(clean_text("  Hello , WORLD ,  Test "))
```

这就是很典型的小工具思路：输入一行，输出标准结果。  
你现在不只是会写一段代码，而是在开始写一个可复用的处理能力。

# 第4章 列表和字典上手实战：把数据装进合适的容器

## 开篇引入：先别急着写程序，先想“数据放哪儿”

很多新手学 Python，最容易卡住的地方，不是 `if`、`for`，也不是函数，而是：**明明知道有列表和字典，却不知道什么时候用哪个。** 结果就是需求一来，变量越写越多，代码越写越散，后面想加功能也不好加。

老赵给你的实战思路很简单：**先别急着写流程，先把数据摆对。**

程序本质上就三步：

1. 拿到数据
2. 处理数据
3. 输出结果

如果一开始数据结构选错了，后面函数、文件、异常处理都会跟着难受。相反，只要你先把“数据该放哪儿”想明白，代码就会顺很多。

你可以把列表和字典理解成两种最常见的收纳盒：

- **列表**：适合装一串有顺序的数据
- **字典**：适合装“名字 + 内容”这种成对数据

这一章不只讲“怎么用”，更重要的是讲清楚：**数据该放哪、为什么放这里、放进去之后怎么处理。** 你把这个意识建立起来，后面写小工具就会越来越像样。

---

## 一、列表：一串数据怎么管

### 1. 列表是什么，适合装什么？

列表（`list`）是有顺序的容器，可以理解成排队的队伍，数据一项接一项放进去，前后顺序固定。

```python
scores = [90, 85, 76, 100]
names = ["小明", "小红", "老赵"]
```

列表最适合放这类数据：

- 一组成绩
- 一串名字
- 一批待办事项
- 一批文件名
- 一组采集到的文本行

如果数据强调“顺序”或“一批同类内容”，通常先想到列表。

### 2. 列表的增删改查

先记住最常用的操作，边敲边熟。

#### 增加

```python
todo = ["吃饭", "写代码"]
todo.append("睡觉")
todo.insert(1, "喝水")
```

- `append()`：加到最后
- `insert()`：插到指定位置

#### 删除

```python
todo.remove("吃饭")
todo.pop()
todo.pop(0)
```

`remove()` 按值删，删第一个匹配项；`pop()` 默认删最后一个，传索引就删指定位置。

#### 修改

```python
todo[0] = "认真写代码"
```

列表下标从 0 开始，`0` 是第一个元素，`-1` 是最后一个元素。

#### 查询

```python
print(todo[0])
print(todo[-1])
print(todo[0:2])
```

切片表示取一段数据，先会用就行。

### 3. 遍历列表：不要一个个手工取

```python
for item in todo:
    print(item)
```

如果还想拿到索引：

```python
for i, item in enumerate(todo):
    print(i, item)
```

`enumerate()` 是很实用的内置函数，既能拿内容，又能拿位置，写菜单、打印序号、定位错误时都很好用。

### 4. 练一把：把一组任务打印成清单

```python
tasks = ["整理文档", "回消息", "提交代码"]

for i, task in enumerate(tasks, start=1):
    print(f"{i}. {task}")
```

这个套路很常见：列表负责存数据，遍历负责处理数据，`enumerate()` 负责加序号。

### 5. 再练一把：做个简单统计

```python
days = [30, 25, 40, 35]
total = sum(days)
print("总时长：", total)
print(max(days))
print(min(days))
```

这里用到了 `sum()`、`max()`、`min()` 这些常用内置函数。像“求总和、最大值、最小值”这种事，能直接用内置函数就别自己硬写循环，短，也不容易错。

### 6. 常见误区

- 以为列表只能放数字，其实什么都能放
- 分不清 `append()` 和 `insert()`
- 用 `remove()` 时不知道它删的是“值”不是“下标”
- 遍历时总想着手写索引，代码不易扩展
- 只会取值，不会修改和删除，列表很快就乱

老赵的建议是：**列表不要只会“看”，还要会“动”。**

---

## 二、字典：一对一地存信息

### 1. 字典是什么，为什么实用？

字典（`dict`）可以理解成“查表工具”，通过**键（key）**找**值（value）**。

```python
person = {
    "name": "老赵",
    "age": 30,
    "city": "杭州"
}
```

字典适合存这些信息：

- 用户资料
- 配置参数
- 一条记录的各项字段
- 关键词统计结果
- 接口返回的结构化数据

如果说列表像“排队”，那字典就像“标签柜”，更适合保存“一个对象的多个属性”。

### 2. 字典的增删改查

#### 查询

```python
print(person["name"])
print(person.get("name"))
print(person.get("phone", "未填写"))
```

直接按键取值很方便，但键不存在会报错；`get()` 更稳，能给默认值。

#### 新增和修改

```python
person["job"] = "程序员"
person["age"] = 31
```

键不存在就是新增，键已存在就是修改。

#### 删除

```python
del person["city"]
person.pop("age")
```

不确定键在不在时，最好先判断，或者用更安全的写法。

### 3. 字典怎么遍历？

遍历键：

```python
for key in person:
    print(key)
```

遍历值：

```python
for value in person.values():
    print(value)
```

遍历键和值：

```python
for key, value in person.items():
    print(key, value)
```

`items()` 很重要，实战里经常用，因为你通常既想看键，也想看值。

### 4. 练一把：打印个人信息卡片

```python
profile = {
    "name": "小李",
    "age": 24,
    "hobby": "读书"
}

for key, value in profile.items():
    print(f"{key}: {value}")
```

这个练习把“数据结构 + 遍历 + 输出”串起来了。

### 5. 再练一把：安全读取配置

```python
config = {
    "host": "127.0.0.1",
    "port": 8000
}

host = config.get("host", "localhost")
debug = config.get("debug", False)

print(host)
print(debug)
```

真实项目里，配置项不一定齐，`get()` 能帮你减少很多“键不存在”的报错。后面写命令行小工具、读配置文件时，你会经常用到这个思路。

### 6. 常见误区

- 把字典当列表用，强行用下标访问
- 键写错了还不知道
- 不会用 `get()`，一遇到缺失键就报错
- 遍历时只会拿键，不知道 `items()` 更方便
- 以为字典也有固定位置，其实它更强调映射关系

---

## 三、列表和字典各自适合解决什么问题

这一节最关键。很多程序不是“不会写”，而是“放错地方”。

### 1. 什么时候优先用列表？

你关心的是：

- 有顺序
- 一组同类数据
- 需要批量遍历
- 需要按位置取数据

比如：

- 今日待办列表
- 文件名列表
- 所有用户输入内容
- 采集到的文章标题列表

这类数据的共同点是：它们是“成串出现”的。你更关心“有多少条、每一条是什么”，而不是每一条叫什么名字。

### 2. 什么时候优先用字典？

你关心的是：

- 一个对象有哪些属性
- 根据名字快速查找
- 需要键值对应关系
- 一条记录包含多个字段

比如：

- 用户信息：姓名、年龄、城市
- 商品信息：名称、价格、库存
- 配置项：路径、开关、模式

这类数据的共同点是：它们不是一串无名数据，而是“一项内容对应一个标签”。

### 3. 一个很实用的判断标准

你可以问自己两个问题：

1. 我是在处理“一串东西”，还是“一个东西的多个字段”？
2. 我更需要按顺序拿，还是按名称找？

- 一串东西 → 列表
- 一个东西的多个字段 → 字典

这个判断不用死记，做几个小练习就会越来越清楚。

### 4. 老赵的实战习惯

老赵写程序时，会先画数据结构，再写功能。比如做一个记录工具，他会先想：

- 多条记录放列表
- 每条记录用字典
- 记录里有时间、内容、标签
- 再决定怎么保存、查询、输出

这样写出来的代码不容易乱。你如果一上来就急着写功能，常常会写到一半才发现数据不够放，最后返工。

赵老师这儿有个很固定的习惯：

- **先看目标**：这个工具到底要干啥
- **再看数据**：一串还是一条记录
- **先画结构**：列表、字典、还是嵌套结构
- **再写最小版本**：先跑通，再加功能
- **最后查错误**：先看类型、键名、索引，再改逻辑

记住这句话：

> 不是先写代码，再想数据；而是先想数据，再写代码。

## 四、嵌套结构的入门：列表里放字典，字典里放列表

真实项目里，数据很少是单层的。列表和字典经常会嵌套使用。

### 1. 列表里放字典：最常见的记录方式

```python
books = [
    {"title": "Python 入门", "price": 59},
    {"title": "数据分析实战", "price": 69},
    {"title": "爬虫小工具", "price": 49}
]
```

列表负责多条记录，字典负责单条记录的字段。

遍历时：

```python
for book in books:
    print(book["title"], book["price"])
```

### 2. 字典里放列表：一个类别对应一组内容

```python
person = {
    "name": "老赵",
    "skills": ["Python", "SQL", "Linux"]
}
```

访问时：

```python
print(person["skills"][0])
```

这种结构适合“一个对象 + 多个子项”的场景，比如爱好、标签、子任务。

### 3. 为什么嵌套结构很重要？

因为真实世界的数据本来就是分层的：

- 一个用户有多个订单
- 一个订单有多个商品
- 一个商品有多个标签
- 一个任务清单有多个子任务

只会单层结构，程序很容易卡住。学会嵌套之后，你会开始接近“能做小工具”的阶段。

### 4. 练一把：统计课程与标签

```python
courses = [
    {"name": "Python基础", "tags": ["语法", "入门"]},
    {"name": "文件操作", "tags": ["实战", "工具"]},
]

for course in courses:
    print(course["name"])
    for tag in course["tags"]:
        print(" -", tag)
```

### 5. 再练一把：整理一个简单记录

```python
records = [
    {"date": "2025-03-01", "topic": "变量与输入输出", "minutes": 40, "done": True},
    {"date": "2025-03-02", "topic": "字符串处理", "minutes": 55, "done": True},
    {"date": "2025-03-03", "topic": "列表和字典", "minutes": 60, "done": False}
]
```

输出时可以这样写：

```python
for item in records:
    status = "已完成" if item["done"] else "未完成"
    print(f"{item['date']} | {item['topic']} | {item['minutes']} 分钟 | {status}")
```

这就是很典型的“列表装多条，字典装字段”的用法。后面你做学习记录、读书笔记、商品清单、简单库存，都能套这个思路。

## 五、练习：用列表和字典整理一份简单记录数据

这一节咱们直接做一个小练习，目标是：**整理一份学习记录，并能查看、统计、追加。**

### 1. 先设计数据结构

```python
records = [
    {"date": "2025-03-01", "topic": "变量与输入输出", "minutes": 40},
    {"date": "2025-03-02", "topic": "字符串处理", "minutes": 55},
    {"date": "2025-03-03", "topic": "列表和字典", "minutes": 60}
]
```

先把数据放进去，再谈功能。老赵一直强调：**先把样子摆出来，再去加工。**

### 2. 输出所有记录

```python
for item in records:
    print(f"{item['date']} | {item['topic']} | {item['minutes']} 分钟")
```

这是在练“遍历 + 格式化输出”。

### 3. 做一个简单统计

```python
total = 0
for item in records:
    total += item["minutes"]

print("总时长：", total)
```

也可以用内置函数：

```python
total = sum(item["minutes"] for item in records)
print("总时长：", total)
```

### 4. 找出学习最久的一天

```python
max_record = records[0]

for item in records:
    if item["minutes"] > max_record["minutes"]:
        max_record = item

print("学习最久的一天：", max_record)
```

这是“先假设一个结果，再循环更新”的思路。以后找最大值、最小值、最新记录时都能用。

### 5. 新增一条记录

```python
new_item = {"date": "2025-03-04", "topic": "函数组织代码", "minutes": 45}
records.append(new_item)
```

一个真正有用的小工具，不只是能看，还要能增、能查、能统计。

### 6. 只看某个主题

```python
for item in records:
    if item["topic"] == "列表和字典":
        print(item)
```

这类过滤操作以后很常见。比如你想看某个标签下的笔记，或者只看“已完成”的任务。容器选对了，筛选逻辑就很顺。

## 六、错误排查：列表和字典最常见的坑怎么找

写数据结构程序，报错很常见。别怕，先学会查。新手最容易犯的错，不是不会写，而是写错了不知道错在哪。

### 1. 下标越界

```python
items = ["a", "b"]
print(items[2])
```

会报错，因为最大下标是 `1`。

排查方法：

- 先看列表长度 `len(items)`
- 再确认索引是否越界
- 记住下标从 0 开始

### 2. 键不存在

```python
person = {"name": "老赵"}
print(person["age"])
```

会报错，因为没有 `age` 这个键。

排查方法：

- 用 `get("age")`
- 或者先判断 `"age" in person`

如果经常处理不完整数据，`get()` 会比直接取值稳很多。

### 3. 类型搞混了

比如把字符串当列表改，或者把字典当成可以用数字下标访问的对象。遇到这类问题，先打印：

```python
print(type(data))
```

老赵的实战习惯之一就是：**先看类型，再看内容，再看流程。**

很多报错不是逻辑问题，而是你以为它是某种类型，实际上不是。

### 4. 调试小习惯

养成这个顺序：

1. 先打印变量值
2. 再看 `type()`
3. 再看长度 `len()`
4. 再看关键字段是否存在
5. 最后再判断逻辑分支

这比盲目改代码有效得多。新手常常一报错就乱改，结果只是键名拼错了，或者索引多写了 1。

# 第5章 用函数把代码收起来：从一坨脚本变成能维护的程序

## 开篇引入：为什么你现在最该学函数

前面我们已经碰过变量、字符串、列表、字典、文件读取这些基础语法。问题也开始显现：当你真的想做一个小工具时，代码往往不再是三五行，而是一整套流程——读取数据、清洗文本、统计结果、输出文件、处理异常。  
一开始你可能觉得“能跑就行”，但写着写着就会发现：代码越来越长，重复越来越多，改一个地方要翻好几处，最后连自己都看不懂。

这时候，**函数**就该上场了。

老赵做程序，最看重的不是代码堆得多，而是**能不能收得住**。会用函数，说明你开始有了“拆任务、收重复、理流程”的意识。程序不再是一坨脚本，而是一个能维护、能扩展、能复用的东西。

这一章我们就干一件事：  
**把零散语法整合成函数，把一段脚本整理成能维护的小程序。**

别把函数想得太高深，它就是帮你把代码从“临时拼起来”变成“以后还能继续用”。这一步很关键。后面学文件操作、标准库、异常处理、命令行程序，你都会不断用到函数。可以说，函数就是你写工具的骨架。

这一章老赵还是老规矩：**先看目标，再拆步骤，小步快跑，边敲边看结果。** 不要想着一口吃成胖子，我们就把一段重复脚本慢慢收起来，收成几个清清楚楚的小函数。

## 一、函数定义、参数、返回值和作用域：先把最基本的骨架搭起来

### 1. 什么是函数，为什么要用它？

函数就是一段可以反复调用的代码块。你可以把它理解成一个小机器：

- 你给它输入：参数
- 它内部处理：函数体
- 它把结果交出来：返回值

比如“去空格、转小写、统计长度”这类操作，如果直接复制粘贴，后面很难维护；写成函数后，以后想改逻辑，只改一处就行。更重要的是，函数能把一个大任务拆成几个小动作，这是新手从“会写语句”走向“会组织程序”的关键一步。

### 2. 函数的基本结构

```python
def clean_text(text):
    text = text.strip()
    text = text.lower()
    return text
```

这里最关键的是：

- `def`：定义函数
- `clean_text`：函数名
- `(text)`：参数
- 缩进里的代码：函数体
- `return`：返回结果

调用时：

```python
result = clean_text("  Hello Python  ")
print(result)
```

原来分散的处理步骤，现在被收进一个小盒子里。以后只要看到 `clean_text()`，你就知道它是在干“文本清洗”这件事。

### 3. 参数和返回值怎么理解？

参数就是函数接收的输入，表示“这次处理的对象是什么”。

```python
def add_prefix(text):
    return "【笔记】" + text
```

这里 `text` 就是参数。传什么进去，函数就处理什么。

返回值是函数处理完给你的结果。  
通常比“只打印不返回”更灵活，因为你拿到结果后还能继续处理：

```python
def count_words(text):
    return len(text.split())

n = count_words("hello python world")
print("单词数：", n)
```

函数最实用的地方就在于：**处理和使用可以分开**。  
函数内部负责把事情做完，外面负责决定结果怎么用。这样写出来的代码，才方便后面组合、测试和复用。

### 4. 作用域：变量在哪儿生效？

函数内部定义的变量一般只在函数内部可用，这叫局部变量。

```python
def demo():
    msg = "hello"
    print(msg)
```

函数外部定义的变量叫全局变量。新手阶段尽量少依赖它，因为它会让代码更难排错。

```python
prefix = "【笔记】"

def add_prefix(text):
    return prefix + text
```

这种写法看起来省事，但外部一改 `prefix`，函数行为也跟着变。  
**老赵的习惯是：优先让函数吃参数、吐结果，少碰外部状态。** 这样更独立，也更好复用。

你可以先记住一个很实用的判断：  
**函数里能搞定的，就别老去依赖外面的变量；需要外面的数据，就尽量通过参数传进来。** 这样后面出问题时，好查得多。

---

## 二、把重复代码拆成函数：不是为了好看，是为了少出错

### 1. 什么时候该抽函数？

不是所有代码都要立刻拆。可以按这几个标准判断：

- 重复出现两次以上
- 逻辑能清晰描述成一个动作
- 以后可能要改
- 一段流程太长，影响阅读

比如这类文本处理：

```python
text = text.strip()
text = text.lower()
text = text.replace("，", ",")
text = text.replace("。", ".")
```

就很适合抽成一个函数。

### 2. 拆函数前先问三个问题

老赵建议你看到一坨代码时先问：

1. 这段代码在干什么？
2. 输入是什么？
3. 输出是什么？

比如：

```python
text = input("请输入一句话：")
text = text.strip()
text = text.lower()
print("处理后：", text)
```

可以拆成：

- 获取输入
- 清洗文本
- 输出结果

拆完后，程序意图更清楚。以后要把“手动输入”改成“从文件读”，也不用推翻重写。

### 3. 一个从脚本到函数的重构例子

先看原始脚本。它能跑，但一长就很难改：

```python
text = input("请输入文本：")
text = text.strip()
text = text.replace(" ", "")
text = text.lower()

print("长度：", len(text))
print("内容：", text)
```

如果以后你还想加“保存到文件”“统计关键词”，这段脚本会越来越乱。  
我们把它拆一拆，先把“清洗”和“展示”分开：

```python
def process_text(text):
    text = text.strip()
    text = text.replace(" ", "")
    text = text.lower()
    return text

def show_text_info(text):
    print("长度：", len(text))
    print("内容：", text)

text = input("请输入文本：")
cleaned = process_text(text)
show_text_info(cleaned)
```

这一下就清楚了：

- `process_text()` 只负责整理文本
- `show_text_info()` 只负责输出信息
- 主流程只负责把它们串起来

这就是函数最大的价值：**把一段容易乱的脚本，变成几块职责分明的小积木。**

### 4. 职责边界要收紧

函数不是越大越省事，反而是越大越容易出问题。一个函数里如果同时干了太多事，后面你会很难判断错误到底出在哪一步。

不好的写法：

```python
def process():
    text = input("输入：")
    text = text.strip()
    result = text.lower()
    print(result)
```

它同时做了输入、处理、输出，后面很难复用。

更好的方式：

```python
def normalize_text(text):
    return text.strip().lower()

def main():
    text = input("输入：")
    result = normalize_text(text)
    print(result)
```

`normalize_text()` 只负责清洗，`main()` 负责串流程。  
这样出问题时，你也更容易判断是输入、处理还是输出出了问题。

记住一句话：**一个函数最好只做一件事，而且这件事要能用一句话说清楚。**  
如果你说不清它到底干啥，那大概率就是职责有点散了。

---

## 三、函数命名、参数设计和职责控制：让函数一看就懂

### 1. 函数命名要像“动词+对象”

函数名最好直接告诉别人它做什么：

- `clean_text`
- `load_data`
- `parse_line`
- `save_report`

尽量少用 `deal()`、`do_sth()`、`func1()` 这种看不出含义的名字。  
名字清楚，代码就好读，自己回头看也不容易懵。

### 2. 参数设计：少而明确

参数只传函数真正需要的东西。比如：

```python
def write_report(filename, content):
    with open(filename, "w", encoding="utf-8") as f:
        f.write(content)
```

一个管文件名，一个管内容，清楚直接。  
如果参数多到十几个，通常说明函数职责已经混乱了，应该考虑拆分。

### 3. 别把“暂时方便”写成“以后麻烦”

有些新手写函数时喜欢图快，直接把各种外部变量都拿进来用。短时间看着省事，后面一改就全乱。  
更稳的思路是：**能通过参数传进来的，就别藏在外面；函数返回的结果，也尽量别只靠打印。**

比如下面这个函数就比较稳：

```python
def format_title(text):
    return text.strip().title()
```

它输入明确，输出明确，任何地方都能复用。

### 4. 赵老师的实战习惯：先分三层，再动手写

老赵写小工具时，通常先分三层：

- **输入层**：从哪儿拿数据
- **处理层**：怎么处理数据
- **输出层**：结果怎么展示或保存

这样以后把“输入”从手动输入换成文件读取，改动会很小；排错时也能快速定位，不会整段程序一起乱。

你可以把这个习惯当成一个固定动作：  
**先想输入，再想处理，最后想输出。**  
只要这个顺序不乱，后面的代码组织一般不会太差。

---

## 四、用函数组织一个小脚本：把程序搭成“主流程 + 工具函数”

### 1. 先有结构，再填细节

新手常见的问题是想到哪写到哪，最后主流程乱成一团。  
更稳的写法是先搭结构：

- `main()` 负责主流程
- 其他函数负责具体任务

### 2. 一个小脚本的标准骨架

```python
def normalize_text(text):
    return text.strip().lower()

def count_chars(text):
    return len(text)

def show_result(text):
    print("处理后文本：", text)
    print("字符数：", count_chars(text))

def main():
    text = input("请输入一段文本：")
    cleaned = normalize_text(text)
    show_result(cleaned)

if __name__ == "__main__":
    main()
```

这个结构里：

- `main()` 是入口
- 其他函数各管一件事
- `if __name__ == "__main__":` 可以让文件既能直接运行，也能被导入

你现在不用急着完全吃透导入机制，但要先把这个写法记住。以后工具拆成多个文件时，会经常见到。

### 3. 为什么要有 main()？

因为程序一复杂，入口清楚很重要。  
你以后调试、扩展、复用时，先看 `main()`，就知道程序从哪儿开始跑。  
而且它也方便你单独测试某个函数，不必每次都把整个程序跑一遍。

### 4. 代码组织的基本思路

老赵建议你按这个顺序写：

1. 先定功能目标
2. 再拆成几个动作
3. 每个动作对应一个函数
4. 用 `main()` 串起来
5. 最后补异常处理、文件操作

**小步快跑，先通再优。** 这比一开始追求“写得很高级”更重要。

这也是赵老师比较固定的实战习惯：  
**先跑通最小版本，再补边界情况，再考虑复用。**

## 五、练习：把前面学过的文本处理或数据整理逻辑封装成函数

这一部分最重要，别只看，要敲。

### 练习目标

做一个最基础的文本整理小工具，功能如下：

- 去掉首尾空格
- 统一成小写
- 压缩多余空格
- 统计字符数
- 统计单词数
- 输出处理结果

### 第一步：先写核心函数

```python
def clean_text(text):
    text = text.strip()
    text = text.lower()
    text = " ".join(text.split())
    return text

def count_chars(text):
    return len(text)

def count_words(text):
    if not text:
        return 0
    return len(text.split())
```

`split()` 会把连续空白当成分隔符，`" ".join(...)` 会把单词重新拼成规范字符串。  
这就是最常见的“整理乱文本”思路，后面处理日志、笔记、抓取内容时都用得上。

### 第二步：写展示函数

```python
def show_report(original, cleaned):
    print("原始文本：", original)
    print("整理后文本：", cleaned)
    print("原始字符数：", count_chars(original))
    print("整理后字符数：", count_chars(cleaned))
    print("整理后单词数：", count_words(cleaned))
```

把“算结果”和“看结果”分开，后面如果你想改成写文件，只改这一层就行。

### 第三步：写主流程

```python
def main():
    text = input("请输入一段文本：")
    cleaned = clean_text(text)
    show_report(text, cleaned)

if __name__ == "__main__":
    main()
```

先别追求花样，先让程序完整跑起来。输入一句简单的话，比如：

```text

```

看看输出是否符合预期。

## 六、错误排查：函数写对了，为什么还是报错？

会写函数只是开始，会排错才算真能用。

### 1. 最常见的几类问题

#### 问题一：忘记 `return`

```python
def add(a, b):
    result = a + b
```

这段函数没有返回值，外面拿到的是 `None`。  
正确写法：

```python
def add(a, b):
    return a + b
```

如果结果总是 `None`，先检查有没有写 `return`。

#### 问题二：变量名写错

函数内部叫 `cleaned_text`，外面却写成 `clean_text`，这种错误很常见。排查时先看变量名是否统一。

#### 问题三：参数数量不匹配

```python
def hello(name):
    print("Hello", name)

hello("Tom", "Jerry")
```

定义一个参数，调用时却传了两个，必然报错。

#### 问题四：作用域混乱

以为函数里定义的变量外面也能直接用。  
记住：**先看变量在哪定义，再看在哪访问。**


这不是土办法，而是很实用的定位手段。很多时候程序不是坏了，只是你不知道它跑到哪一步了。

## 一、文件的打开、读取、写入和关闭：先把最基本动作做对

### 1. 为什么文件操作重要？

很多实用小工具，输入和输出都不是人手敲在屏幕上，而是来自文件。比如：

- 清洗日志
- 统计文本出现次数
- 批量整理资料
- 读取配置文件
- 保存处理结果

也就是说，**文件是程序和真实世界之间的接口**。  
如果你只会在内存里玩变量，程序还停留在演示阶段；一旦能从文件读数据、加工后写回文件，小工具才真正开始“干活”。

---

### 2. 打开文件：`open()` 是入口

文件操作的第一步是打开文件：

```python
f = open("data.txt", "r", encoding="utf-8")
```

这里先记住三个点：

- `"data.txt"`：文件名或路径
- `"r"`：打开模式，表示只读
- `encoding="utf-8"`：指定编码

常见模式先熟这几个：

- `"r"`：读
- `"w"`：写，**会覆盖原文件**
- `"a"`：追加写，写到文件末尾
- `"x"`：新建文件，文件已存在就报错
- `"rb"` / `"wb"`：二进制读写

老赵建议你先把这几个模式记成一张小抄：

- **读**：`r`
- **写覆盖**：`w`
- **追加**：`a`

新手最容易踩的坑就是：本来想往原文件后面补内容，结果用了 `w`，一下把原内容清空了。所以写文件前先想清楚：**我是要覆盖，还是要追加？**

---

### 3. 读取文件：读整段、读一行、读多行

#### 读全部内容

```python
f = open("note.txt", "r", encoding="utf-8")
content = f.read()
print(content)
f.close()
```

`read()` 会一次性把整个文件读进来，适合小文件，不适合特别大的文件。

#### 按行读取

```python
f = open("note.txt", "r", encoding="utf-8")
line = f.readline()
print(line)
f.close()
```

`readline()` 每次读一行，适合日志分析、文本清洗这类逐行处理场景。

#### 读取所有行

```python
f = open("note.txt", "r", encoding="utf-8")
lines = f.readlines()
print(lines)
f.close()
```

`readlines()` 会返回一个列表，每个元素是一行文本，行末通常带 `\n`。

你可以自己试试：

```python
with open("note.txt", "r", encoding="utf-8") as f:
    lines = f.readlines()
    print(len(lines))
    print(lines[0])
```

这样能直观看到：文件读出来后，到底是一个长字符串，还是一个字符串列表。

---

### 4. 写入文件：保存结果别只靠打印

很多人刚学 Python 时，习惯把结果都 `print()` 出来。  
这当然没错，但打印只是“看见结果”，不等于“保存结果”。真正的小工具，得把结果写到文件里。

```python
f = open("result.txt", "w", encoding="utf-8")
f.write("Hello Python\n")
f.write("这是第一行\n")
f.close()
```

`write()` 写的是字符串，所以要注意两点：

- 写入内容必须是字符串，数字要先转成字符串
- `"w"` 模式会覆盖原文件

比如：

```python
score = 98
with open("result.txt", "w", encoding="utf-8") as f:
    f.write("分数：")
    f.write(str(score))
    f.write("\n")
```

如果你想一行一行输出，可以这样：

```python
lines = ["苹果", "香蕉", "橙子"]
f = open("fruits.txt", "w", encoding="utf-8")
for item in lines:
    f.write(item + "\n")
f.close()
```

这就是很典型的“列表转文本文件”。

---

### 5. 关闭文件：别偷懒

`close()` 的作用是告诉系统：这个文件我用完了，可以释放资源了。  
如果忘记关，短程序可能表面上看不出问题，但习惯不好，项目大了就容易出毛病。

**老赵的习惯：凡是能用 `with`，就尽量不用手动 `close()`。**  
因为人会忘，机器最诚实，`with` 更稳。

## 二、`with` 语法与文件操作习惯：让文件自动收尾

### 1. 为什么推荐 `with`？

文件操作最怕两件事：

- 中间报错，文件没关
- 自己写了太多 `close()`，代码又长又乱

`with` 的好处是：**即使中间出错，文件也会自动关闭**。  
这是写 Python 小工具时非常重要的习惯。

---

### 2. 基本写法

```python
with open("note.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)
```

写入时也一样：

```python
with open("result.txt", "w", encoding="utf-8") as f:
    f.write("处理完成\n")
```

老赵一直强调：**先把基本动作做对，再谈花活。**

---

### 3. 赵老师的实战习惯

老赵做小工具时有几个习惯，你可以直接照着学：

1. **先看目标，再动手写代码**  
   先搞清楚输入是什么，输出是什么，别一上来就敲代码。

2. **能用 `with` 就不用手动 `close()`**  
   这样更稳，也更省心。

3. **先小文件调通，再处理大文件**  
   小步快跑，先把最小闭环跑通。

4. **先打印中间结果，再写入文件**  
   先确认逻辑没问题，再保存结果。

5. **文件操作和业务逻辑分开写**  
   读、处理、写，尽量拆开，排错才轻松。

老赵特别看重最后这一条。  
不要把“读取、处理、保存”全写成一坨。后面一报错，你都不知道是读文件错了，还是处理逻辑错了，还是路径错了。把结构拆开，才方便一步一步查。

建议按这个顺序组织代码：

- 先定义输入输出路径
- 再读取文件
- 再处理内容
- 最后写入结果

这样结构清楚，排查也轻松。

```python
with open("input.txt", "r", encoding="utf-8") as f:
    content = f.read()

with open("copy.txt", "w", encoding="utf-8") as f:
    f.write(content)
```

这段代码没做加工，但它能帮你建立一个重要直觉：  
**程序不只是显示数据，还能把数据稳定保存下来。**

## 三、文本文件编码与常见读写问题：为什么明明写了却乱码？

### 1. 编码是什么？

编码可以理解为：**字符和字节之间的翻译规则**。  
文本文件看起来是字，计算机存的是字节。读写时如果翻译规则不一致，就会乱码。

最常见的情况是：

- 文件本来是 UTF-8
- 你按其他编码去读
- 结果就乱了

---

### 2. 为什么总建议显式写 `encoding="utf-8"`？

因为它能减少很多环境差异带来的问题。

```python
with open("data.txt", "r", encoding="utf-8") as f:
    text = f.read()
```

这样做的好处：

- 代码更稳定
- 在不同电脑上更一致
- 以后排查问题更方便

如果不写编码，程序会使用系统默认编码。  
在自己电脑上可能没事，换个环境就报错。这个坑在文件工具里很常见。

---

### 3. 常见问题和判断思路

#### 问题一：打开文件时报编码错误

常见表现：

- `UnicodeDecodeError`
- 读出来一堆怪字符

判断思路：

1. 先看文件是不是 UTF-8
2. 再看代码里是否写了正确的 `encoding`
3. 如果文件来源复杂，先用编辑器查看编码

#### 问题二：写入后文件打不开

可能是：

- 文件被别的程序占用
- 路径写错了
- 输出内容不是字符串
- 没指定正确编码

#### 问题三：内容少了或多了换行

这通常和 `\n` 有关。  
你写一行时，最好明确加换行：

```python
f.write("第一行\n")
```

如果写出来的文本都挤在一行里，先别怀疑 Python，先看看自己有没有漏写换行。

---

### 4. 常见误区

- 误区 1：只要能打开就行，编码不用管  
  不对，编码不管，后面早晚踩坑。

- 误区 2：`read()` 最方便，所以所有文件都整块读  
  不对，大文件适合逐行处理。

- 误区 3：写文件一定是追加更安全  
  不对，是否覆盖要看你的需求。

老赵建议你把“编码”“换行”“读法”当成文件操作的三大基本功。很多问题其实不是难，而是细节没对上。

---

## 四、路径和文件名的基本处理思路：别被路径绊住脚

### 1. 路径为什么总让新手头疼？

因为很多人写文件时只会写：

```python
open("a.txt")
```

一旦文件不在当前目录，就找不到了。  
所以你必须知道：**文件名只是最简单情况，实际项目里经常要处理路径**。

---

### 2. 相对路径和绝对路径

#### 相对路径

相对当前运行目录来写：

```python
with open("data/input.txt", "r", encoding="utf-8") as f:
    text = f.read()
```

#### 绝对路径

直接写完整路径：

```python
with open("D:/work/python/data/input.txt", "r", encoding="utf-8") as f:
    text = f.read()
```

新手阶段建议：

- 能用相对路径就先用相对路径
- 但要知道“当前目录”不一定等于脚本所在目录

这个坑很常见。你明明觉得文件就在脚本旁边，结果程序运行时却报找不到文件，通常就是当前工作目录不一样。

---

### 3. 推荐使用 `pathlib`

处理路径时更推荐 `pathlib`，因为它更直观。

```python
from pathlib import Path

p = Path("data") / "input.txt"
print(p)
```

`/` 在 `Path` 里表示拼接路径，读起来更自然。

读取文件：

```python
from pathlib import Path

path = Path("data") / "input.txt"
with path.open("r", encoding="utf-8") as f:
    text = f.read()
```

写文件：

```python
from pathlib import Path

out = Path("output") / "result.txt"
with out.open("w", encoding="utf-8") as f:
    f.write("done\n")
```

你先记住一句话：  
**路径不是为了难你，而是为了告诉程序“去哪找文件、往哪存结果”。**

---

### 4. 处理路径和文件名的几个注意事项

这一小节老赵给你收成一个统一的注意事项清单，后面做文件工具时就按这个思路来：

- **输入文件和输出文件先写清楚**
- **输出目录不存在时先创建**
- **文件名尽量简单、稳定、可读**
- **路径拼接优先用 `pathlib`**
- **不要把路径写死在代码里太深的位置**

例如，输出目录不存在，程序就会报错。  
所以很多工具会先检查目录，再写文件：

```python
from pathlib import Path

out_dir = Path("output")
out_dir.mkdir(exist_ok=True)
```

这行的意思是：目录不存在就创建，存在就算了。

很多时候程序失败，不是处理逻辑错了，而是输出路径根本不存在。  
路径这件事，看起来小，实际上特别影响小工具能不能稳定运行。

## 五、练习：读取一个文本文件并输出处理后的新文件

下面做一个真正能用的小练习：  
**读取一个文本文件，把每一行前后的空白去掉，过滤空行，然后保存到新文件。**

这个练习把前面学的东西都串起来了：

- 文件读取
- 字符串处理
- 列表组织
- `with`
- 路径
- 写入结果
- 错误排查

这就是老赵说的“小步快跑”：别一上来就想做大项目，先把一个小闭环跑通。

---

### 1. 任务目标

输入文件 `input.txt`，内容可能像这样：

```text
  hello python  

  老赵讲课  
Python后端入门
```

输出到 `output/cleaned.txt`，结果变成：

```text
hello python
老赵讲课
Python后端入门
```

也就是说，我们要：

- 去掉每行前后空格
- 删除空行
- 保存处理后的内容

---

### 2. 拆解步骤

#### 第一步：读取文件
用 `with open(..., "r")` 把文件内容按行读出来。

#### 第二步：逐行处理
对每一行做 `strip()`，去掉首尾空白。

#### 第三步：过滤空行
如果这一行清理后为空，就跳过。

#### 第四步：保存结果
把整理后的内容写入新文件。

你会发现，这其实就是一个很标准的小工具流程：

**输入 → 处理 → 输出**

以后你做任何文本类工具，很多时候都能套这个结构。

---

### 3. 完整示例代码

```python
from pathlib import Path

input_path = Path("input.txt")
output_dir = Path("output")
output_path = output_dir / "cleaned.txt"

output_dir.mkdir(exist_ok=True)

cleaned_lines = []

with input_path.open("r", encoding="utf-8") as f:
    for line in f:
        text = line.strip()
        if text:
            cleaned_lines.append(text)

with output_path.open("w", encoding="utf-8") as f:
    for item in cleaned_lines:
        f.write(item + "\n")

print(f"处理完成，结果已保存到：{output_path}")
```

这段代码不长，但已经有了一个小工具的完整骨架：

- 路径定义
- 目录创建
- 文件读取
- 文本清洗
- 结果写回
- 处理完成提示

### 4. 这个小工具怎么复用？

别小看这个练习，它已经是一个能复用的文本处理底座了。  
你可以把它直接改成这些场景：

- 清洗日志文件
- 去掉文档中的空白行
- 统一整理导出的文本
- 过滤无效记录
- 保存处理后的备份文件

只要输入还是文本，处理逻辑还能保持“逐行清洗”的风格，这个小工具就能继续用。  
这就是小工具的价值：**先做一个能跑的版本，再慢慢加功能。**

### 5. 补上失败场景：文件不存在、编码不匹配怎么办？

真正的小工具不能只在理想环境里跑。文件操作最常见的失败场景，至少要想到两个：

#### 场景一：文件不存在

如果 `input.txt` 没放对位置，程序会报 `FileNotFoundError`。  
这时候不要直接崩掉，最好给用户一个明确提示。

可以先做一个简单判断：

```python
from pathlib import Path

input_path = Path("input.txt")
if not input_path.exists():
    print(f"找不到输入文件：{input_path}")
    raise SystemExit
```

这样用户一看就知道问题在哪，不用猜。

#### 场景二：编码不匹配

如果文件不是 UTF-8，读取时可能报 `UnicodeDecodeError`。  
你可以先用统一编码读取，如果失败，再提示用户检查文件编码：

```python
try:
    with input_path.open("r", encoding="utf-8") as f:
        text = f.read()
except UnicodeDecodeError:
    print("文件编码可能不是 UTF-8，请检查后重试。")
    raise SystemExit
```

这就很像做真实工具的思路：**先发现问题，再给出可理解的提示。**

## 六、错误排查清单：文件工具出问题，先查这几项

文件类小工具出错时，老赵一般按这个顺序排：

1. **文件是否存在？**  
   输入文件名对不对，当前目录对不对。

2. **路径是否正确？**  
   是相对路径还是绝对路径，输出目录建了没有。

3. **编码是否一致？**  
   读写是不是都用了 `utf-8`。

4. **内容是不是字符串？**  
   `write()` 不能直接写数字和列表。

5. **有没有处理换行？**  
   `\n` 加没加，结果会不会挤成一行。

6. **异常有没有提示清楚？**  
   出错时不要只报一串英文，最好告诉用户该检查什么。

这个排查顺序很实用。  
你以后写小工具，只要把这几项养成习惯，很多低级错误都能提前躲开。

## 一、常见错误类型：语法错误、运行错误、逻辑错误

先别急着学 `try`，先把错误分清。不同错误，处理方式完全不一样。

### 1. 语法错误：代码连门都没进

语法错误就是 Python 看不懂你的代码，程序根本启动不了。比如少了冒号、括号没配对、缩进乱了：

```python
name = input("请输入名字")
if name == "赵老师"
    print("你好")
```

这里 `if` 后面少了冒号，Python 会直接报错。  
这类错误通常是：

- 程序还没真正跑起来就报错
- 提示出错行，但真正问题有时在上一行
- 常见原因是冒号、括号、引号、缩进这些基础细节

**老赵习惯：**
- 先看报错最后一行
- 再看箭头指向的位置
- 先检查冒号、括号、缩进、引号
- 不要急着怀疑逻辑，先把基础语法过一遍

新手最容易踩的坑，往往就是少一个右括号、引号没闭合。写完一小段，顺手检查一遍格式，能省很多时间。

### 2. 运行错误：代码能启动，但跑着跑着炸了

运行错误也叫异常。程序语法没问题，但执行到某一步出问题了。比如：

```python
num = int(input("请输入数字："))
print(10 / num)
```

如果用户输入 `0`，就会报除零错误；如果输入 `abc`，`int()` 会转换失败。

常见运行错误有这些：

- `ZeroDivisionError`：除以 0
- `ValueError`：值不符合要求，比如把字母转成整数
- `FileNotFoundError`：文件找不到
- `TypeError`：类型不对，比如字符串和数字混着算

它们的共同特点是：

- 程序可以启动
- 运行到某一步才崩
- 往往和外部输入、文件、网络、环境有关

真实程序里，用户输入不受你控制，文件也不一定一直存在。你要接受一个现实：**不一定是你的代码写错了，有时候只是输入不符合预期。**

### 3. 逻辑错误：程序不报错，但结果不对

这个最阴。程序能跑完，输出也出来了，但结果不符合预期。比如把加法写成减法、把排序方向弄反了。

```python
prices = [12, 25, 8]
total = 0
for p in prices:
    total = total - p
print(total)
```

它不会报错，但结果明显不对。

逻辑错误的特点：

- 程序执行正常
- 没有红字报错
- 但结果和你的目标不一致

这类问题最重要的办法不是硬猜，而是通过输入输出对照、打印中间变量、逐步验证来发现。**程序跑通只是第一步，结果正确才算真的做成。**

## 二、先记住一个统一的排错流程：看报错、缩小范围、逐段验证

后面你遇到什么错，都先别慌。老赵给你一个很实用的排错顺序，先照着走。

### 第一步：先看报错

报错信息不是来吓人的，它其实是在给你线索。至少要关注：

- **错误类型**：比如 `ValueError`、`TypeError`
- **出错位置**：哪一行、哪一段
- **最后一行提示**：通常最关键

比如：

```python
print(int("abc"))
```

它会告诉你是 `ValueError`。这说明不是语法错，而是转换失败。  
看到这个，就应该想到：输入值不合法，或者类型转换前没有做检查。

### 第二步：缩小范围

别一上来怀疑整份代码。程序一长，最忌讳“全局怀疑”。老赵的习惯是：

- 先把一部分代码注释掉
- 或者先只跑一个函数
- 把大程序拆成几个小段逐个检查

比如你写了一个文本统计工具，结果总数不对，那就先打印中间结果：

```python
print(words)
print(len(words))
```

如果 `words` 本身就不对，那问题在分词；如果 `words` 对了但统计错了，那问题在统计逻辑。

### 第三步：逐段验证

不要等写完再测，要边写边测。  
比如写一个处理文件的小工具，可以按这几步来：

1. 先确认文件能打开
2. 再确认内容能读出来
3. 再确认字符串处理没问题
4. 再确认统计逻辑正确
5. 最后再加异常处理

每完成一步，就跑一次。  
这就是老赵常说的：**小步快跑，别一口吃成胖子。**

### 第四步：多用打印调试

对新手来说，`print()` 是最朴素也最管用的工具。

```python
print("读到的原文：", text)
print("切分后的列表：", words)
print("当前计数：", count)
```

等你定位到问题，再决定怎么改。  
记住：**先让程序说话，再让程序正确。**

## 三、try、except、else、finally 怎么用

异常处理的核心，就是把“可能出问题的地方”包起来。出问题时不要让程序直接死掉，而是给一个兜底方案，让程序更稳一点。

### 1. `try` 和 `except`：最基本的兜底

最常见的结构就是这样：

```python
try:
    可能出错的代码
except:
    出错后的处理
```

比如：

```python
try:
    num = int(input("请输入数字："))
    print(10 / num)
except:
    print("输入有问题，程序先结束了。")
```

这段代码能兜底，但太粗糙。它不管什么错都用一句话处理，用户还是不知道到底哪里错了。

更好的方式，是针对不同错误分别处理。

```python
try:
    num = int(input("请输入数字："))
    print(10 / num)
except ValueError:
    print("你输入的不是数字，请重新输一个整数。")
except ZeroDivisionError:
    print("0 不能拿来做除数，请换一个非 0 的数字。")
```

这样就清楚多了。  
**能指定类型就别一把抓。** 这样更容易排错，也更利于给用户明确提示。

你可以把它理解成：

- `ValueError` 是“格式不对”
- `ZeroDivisionError` 是“数值本身不合要求”

不同情况分开处理，程序就更像真正可用的小工具，而不是碰一下就倒的练习题。

### 2. `else`：没出错时再执行

`else` 的意思是：**如果 `try` 里面没出错，就执行这里。**

```python
try:
    num = int(input("请输入数字："))
except ValueError:
    print("输入不是数字。")
else:
    print("转换成功，结果是：", num)
```

这个写法把“正常流程”和“异常流程”分开了，代码更清楚。  
以后写稍微长一点的程序时，这个思路特别有用：**正常逻辑放在 `else` 里，错误处理放在 `except` 里。**

### 3. `finally`：不管有没有错都执行

`finally` 适合做收尾工作，比如关闭文件、释放资源、打印结束信息。

```python
try:
    f = open("data.txt", "r", encoding="utf-8")
    content = f.read()
except FileNotFoundError:
    print("没找到 data.txt 这个文件，检查一下文件名和位置吧。")
finally:
    print("这一轮程序执行结束。")
```

如果你已经用 `with open(...)` 管理文件，很多时候不需要手动写 `finally` 去关文件。但你要知道它的存在和用途。  
它的价值在于：**不管中间发生什么，最后都能收个尾。**

## 四、如何给用户更友好的报错提示

新手写程序，常见问题不是“没报错”，而是“报错太吓人”。用户看不懂一堆英文和堆栈信息，自然不知道怎么改。一个真正能用的小工具，不只是会算结果，还要会“说人话”。

### 1. 把技术错误翻译成人话

比如原始报错可能是：

- `ValueError: invalid literal for int() with base 10: 'abc'`

这个信息对程序员有用，但对普通用户太硬了。我们更希望它变成：

```python
try:
    age = int(input("请输入年龄："))
except ValueError:
    print("年龄要输入数字，比如 18，不要输汉字或字母。")
```

这样用户一下就明白了：不是程序坏了，而是输入方式不对。

**原则：**
- 说清楚错在哪
- 说清楚应该怎么改
- 语气别吓人

### 2. 提示要具体，不要空话

不要只说：

```python
print("输入有误")
```

太笼统了，用户看完还是不知道怎么做。

更好的写法是：

```python
print("输入有误，请输入一个整数，比如 1、2、3。")
```

如果是文件名，也可以说得更具体一点：

```python
print("没找到文件，请确认文件名是否正确，文件是否真的在当前目录里。")
```

你可以把提示当成“用户说明书”的一部分。提示写得越清楚，用户越容易自己解决问题，程序也越像成熟工具。

### 3. 给用户一个重新输入的机会

这才像一个实用小工具，而不是一次性玩具。

```python
while True:
    try:
        age = int(input("请输入年龄："))
        break
    except ValueError:
        print("请输入数字，不要输入汉字或字母。")
```

错了就提醒，用户改对了再继续。  
如果你做的是命令行小工具，这个思路尤其重要，因为用户经常会输错，程序不能一出错就结束，要尽量稳住。

## 五、练习：给一个“前面学过的小程序”加上异常处理

这次咱们不用搞陌生场景，就拿前面学过的**输入和计算**来练。这样你更容易把异常处理和已有知识接上。

### 任务目标

做一个“输入年龄，判断是否成年”的小程序。  
要求：

- 用户输入年龄时，不能直接崩
- 输入不是数字时，给出友好提示
- 输入合法后，输出成年或未成年
- 最好允许用户重新输入，直到填对为止

### 版本一：没有异常处理

```python
age = int(input("请输入年龄："))
if age >= 18:
    print("你已经成年了。")
else:
    print("你还未成年。")
```

这段代码的问题很明显：

- 输入 `abc` 会报错
- 用户体验很差
- 程序一错就停

### 版本二：加上异常处理

```python
while True:
    try:
        age = int(input("请输入年龄："))
    except ValueError:
        print("年龄要输入数字，比如 18。")
    else:
        if age >= 18:
            print("你已经成年了。")
        else:
            print("你还未成年了。")
        break
```

### 这段代码怎么理解

- `while True`：让程序一直等用户输入，直到成功为止
- `try`：把可能出错的地方包起来
- `except ValueError`：处理“不是数字”的情况
- `else`：没有错误时执行判断
- `break`：成功后退出循环

这个写法比最初版本长一点，但换来的好处很明显：**程序稳了，用户也不会被吓跑。**

### 再往前走一步：把提示写得更像人话

```python
while True:
    text = input("请输入年龄，输入 q 退出：")

    if text.lower() == "q":
        print("好的，程序结束。")
        break

    try:
        age = int(text)
    except ValueError:
        print("年龄要输数字，比如 16、18、25。")
    else:
        if age >= 18:
            print("你已经成年了。")
        else:
            print("你还未成年。")
        break
```

这就更像一个小工具了：  
用户输错了，能重新来；用户不想玩了，也能退出。你已经开始具备把输入、判断、异常处理、循环组织起来的能力了。

## 一、日期时间处理：`datetime` 到底能干什么？

### 1.1 先记住一个核心：时间数据最好先转成 `datetime`

很多时候，时间不是“字符串”这么简单。比如：

- `2025-01-03 09:20:15`
- `2025/01/03`
- `2025年1月3日`

这些都只是文本。**如果你要比较大小、计算相差几天、加减时间，最好先转换成 `datetime` 对象。**

因为字符串适合展示，不适合做时间运算。比如“2025-10-01”和“2025-2-01”如果直接按字符串比较，结果未必符合直觉；转成日期对象后，Python 才知道谁早谁晚、差几天、加一小时该怎么处理。

常用写法：

```python
from datetime import datetime

now = datetime.now()
print(now)
print(type(now))
```

`now` 是当前日期时间对象，不是普通字符串，但它可以继续做运算。

### 1.2 时间戳、格式化日期和日期计算

#### 1）时间戳是什么

时间戳一般是从某个固定起点开始计算的秒数，适合机器处理、排序和比较；格式化字符串适合人阅读。

```python
from datetime import datetime

now = datetime.now()
ts = now.timestamp()
print(ts)
```

反过来，也可以把时间戳变回日期时间：

```python
from datetime import datetime

dt = datetime.fromtimestamp(1735860000)
print(dt)
```

#### 2）格式化日期

把日期时间对象变成我们想要的文本形式，靠 `strftime()`：

```python
from datetime import datetime

now = datetime.now()
print(now.strftime("%Y-%m-%d %H:%M:%S"))
print(now.strftime("%Y年%m月%d日"))
```

先记几个常用格式符就够了：

- `%Y`：四位年份
- `%m`：月份
- `%d`：日期
- `%H`：24 小时制小时
- `%M`：分钟
- `%S`：秒

记住：

- `strftime`：把对象变成字符串
- `strptime`：把字符串变成对象

#### 3）解析字符串日期

如果拿到的是字符串，可以用 `strptime()` 转回对象：

```python
from datetime import datetime

s = "2025-01-03 09:20:15"
dt = datetime.strptime(s, "%Y-%m-%d %H:%M:%S")
print(dt)
```

这在日志处理、时间筛选里很常见。

#### 4）日期计算

`datetime` 最大的价值之一就是能算：

```python
from datetime import datetime, timedelta

today = datetime.now()
tomorrow = today + timedelta(days=1)
print(tomorrow)
```

你可以加天、加小时、减分钟。  
这比自己拼字符串可靠得多。

### 1.3 常见误区

- 直接拿字符串比较日期大小，格式不统一时容易错。
- 把时间当普通文本处理到底，一旦涉及加减、排序、统计就该转对象。
- 格式化和计算混在一起。先计算，再格式化，思路更清楚。

老赵建议你做时间处理时，脑子里先过一遍流程：  
**输入字符串 → 解析成对象 → 运算 → 格式化输出**。

### 1.4 动手练习

先敲这三个小练习：

1. 打印当前时间，格式为 `2025-01-03 09:20:15`
2. 写一段代码，输出明天的日期
3. 把字符串 `"2025-12-31 23:59:59"` 解析成日期对象

如果还想多练一步，把“今天、明天、三天后”的日期都打印出来。

## 二、标准库中的实用模块：`os`、`pathlib`、`random`、`re` 怎么入门？

这一节不追求一次学透，而是先建立“模块思维”：**不同的问题，找不同的标准库**。

### 2.1 `os`：和系统、环境、文件路径相关

`os` 适合做基础系统操作，比如：

- 获取当前工作目录
- 判断文件是否存在
- 拼接路径
- 列出目录文件

```python
import os

print(os.getcwd())
print(os.listdir("."))
```

写小工具时，这类能力很常用，因为你经常要知道程序跑在哪、文件放在哪、路径对不对。

### 2.2 `pathlib`：更现代的路径处理方式

如果说 `os.path` 是传统路线，那 `pathlib` 更推荐。它的好处是：**路径对象化，读起来更自然**。

```python
from pathlib import Path

p = Path("data")
print(p.exists())
print(p.is_dir())
print(p.name)
```

拼路径也更直观：

```python
from pathlib import Path

p = Path("data") / "note.txt"
print(p)
```

这比手写 `"data/note.txt"` 更稳，也更适合跨平台。

> 赵老师这里有个实战习惯：**凡是和文件、目录有关的事，先用 `pathlib` 想一遍。**  
> 因为它更直观，也更不容易把斜杠写乱。

### 2.3 `random`: 随机抽样、随机数、打乱顺序

`random` 很适合做：

- 随机抽一个结果
- 随机数模拟
- 打乱列表顺序

```python
import random

print(random.randint(1, 10))
print(random.choice(["苹果", "香蕉", "橙子"]))
```

打乱列表：

```python
import random

nums = [1, 2, 3, 4, 5]
random.shuffle(nums)
print(nums)
```

做抽奖、随机练习题、任务分配时都能用上。

### 2.4 `re`：简单文本匹配和提取

`re` 是正则表达式模块，新手不用一开始就钻太深，先记住：

**当文本有固定模式时，`re` 可以帮你提取内容。**

比如找出文本中的数字：

```python
import re

text = "订单号是A123，金额是45元"
nums = re.findall(r"\d+", text)
print(nums)
```

结果是：

```python
['123', '45']
```

再比如判断一个字符串里有没有邮箱样式：

```python
import re

s = "test@example.com"
print(re.search(r".+@.+\..+", s))
```

先会用最基础的搜索和提取就够了。`re` 适合做模式匹配，不适合替代所有字符串操作。

### 2.5 模块使用的基本套路

记住这四步：

1. 先 `import`
2. 看模块能解决什么问题
3. 用最小例子跑通
4. 再放进你的程序里

老赵建议你每次只学一个小功能，**小步快跑，跑通再扩展**。模块就是拿来边用边熟的。

## 三、什么时候优先用标准库，而不是自己写？

### 3.1 判断标准：优先用标准库的场景

下面这些情况，通常先看标准库：

- 时间日期处理：`datetime`
- 路径、目录、文件系统：`pathlib` / `os`
- 随机选择：`random`
- 文本模式提取：`re`

判断标准很简单：

1. 这是个通用问题吗？
2. 自己写会不会更容易出错？
3. 现成工具能不能让代码更清楚？

如果能让代码更短、更稳、更易维护，就优先用。

### 3.2 什么时候可以自己写

不是说所有东西都交给标准库。以下情况可以考虑自己封装：

- 你的业务规则非常特殊
- 你要把多个标准库能力组合起来
- 你要做一个小工具，需要统一入口

也就是说，**标准库解决“基础能力”，你自己负责“业务组合”**。

比如：时间怎么显示交给 `datetime`；文件怎么保存交给 `pathlib`；但“保存到哪儿、是否追加、标题怎么生成”，这些就是你的业务逻辑。

### 3.3 老赵的实战习惯：先找标准库，再拆成函数

你可以把赵老师的做法记成一套固定动作：

1. 先列需求
2. 先问：有没有现成标准库能解决
3. 用最小代码验证模块是否可用
4. 把业务部分拆成函数
5. 每完成一步就跑一次，确认没坏

这个顺序很重要。它不是“写完再看”，而是“边写边验”。  
对新手来说，**先确认标准库可用，再做组合，是最稳的路线**。

真正花时间的不是造轮子，而是把轮子装到车上。

## 四、代码组织思路：别把所有代码都堆在一起

很多新手程序越写越乱，不是因为语法不懂，而是**没有组织思路**。

### 4.1 一个简单的小程序结构

你可以按这个顺序组织代码：

1. 导入模块
2. 定义常量
3. 定义函数
4. 写主流程
5. 入口控制

例如：

```python
from datetime import datetime
from pathlib import Path

def format_time():
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

def save_text(path, content):
    path.write_text(content, encoding="utf-8")

def main():
    print(format_time())

if __name__ == "__main__":
    main()
```

好处很直接：

- 逻辑清楚
- 方便调试
- 以后容易扩展

### 4.2 函数拆分的原则

函数不是越多越好，而是要满足一个原则：

**一个函数只做一件事。**

比如：

- 一个函数负责生成时间字符串
- 一个函数负责拼接记录内容
- 一个函数负责保存文件
- 一个函数负责读取文件

这样后面排错时就不会满屏找问题。

### 4.3 先小后大，别一口气写完

很多人学会几个模块后，马上想做“大而全”的程序，结果一运行就一堆报错。更稳的做法是：

- 先写一个能输出时间的小程序
- 再加文件保存
- 再加随机提示
- 再加文本处理

每一步都能跑通，你就会越来越有底气。

## 五、错误排查：新手最需要的不是“永不报错”，而是“知道怎么找错”

### 5.1 先看报错信息，不要第一时间删代码

Python 报错其实很诚实。你要重点看：

- 报错类型
- 报错行号
- 最后一行提示

常见错误：

- `NameError`：变量或函数没定义
- `TypeError`：类型不对
- `FileNotFoundError`：文件找不到
- `ValueError`：值格式不对

看到报错先别慌，通常只是某个地方没对上。

### 5.2 排错三步法

老赵推荐你固定用这个流程：

#### 第一步：缩小范围
先判断问题是在输入、处理，还是输出阶段。

#### 第二步：打印关键中间值
比如：

```python
print("debug:", value)
```

先把问题定位出来。

#### 第三步：验证最小样例
把复杂程序拆成最小可运行例子，确认是模块用错了，还是自己的逻辑错了。

这三个动作很朴素，但很管用。高手不是“不报错”，而是“报错后很快知道该看哪里”。

### 5.3 常见排错点

- 路径写错了
- 文件编码不一致
- 字符串和日期对象混用了
- 正则表达式写得太贪心
- 函数参数顺序弄反了

养成“先小样例，再组合”的习惯，排错速度会快很多。

## 六、练习项目：做一个带时间标记的小记录器

现在把前面的东西串起来，做一个真正能用的小工具：**输入一段文字，自动加上当前时间，保存到文本文件里。**

它能练到什么？

- 变量与输入输出
- 字符串拼接
- `datetime` 时间处理
- `pathlib` 文件路径
- 文件读写
- 函数组织
- 异常处理
- 命令行小程序雏形

### 6.1 功能需求

最小版本很简单：

1. 用户输入一段内容
2. 程序自动加上当前时间
3. 保存到 `records.txt`
4. 每次运行都追加一条记录

这个需求不复杂，但非常适合练“把零散语法拼成完整程序”。

### 6.2 代码实现

```python
from datetime import datetime
from pathlib import Path

FILE_PATH = Path("records.txt")

def get_time_str():
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

def build_record(content):
    time_str = get_time_str()
    return f"[{time_str}] {content}\n"

def save_record(record):
    with FILE_PATH.open("a", encoding="utf-8") as f:
        f.write(record)

def main():
    print("请输入你要记录的内容，直接回车结束：")
    content = input("> ").strip()

    if not content:
        print("没有输入内容，程序结束。")
        return

    record = build_record(content)

    try:
        save_record(record)
        print("记录成功：")
        print(record)
    except Exception as e:
        print("保存失败：", e)

if __name__ == "__main__":
    main()
```

### 6.3 这段代码的结构你要看懂

#### 1）`FILE_PATH`
把文件路径放到常量里，后面改文件名不用到处找。

#### 2）`get_time_str()`
只负责生成时间字符串。

#### 3）`build_record(content)`
只负责拼装一条记录。

#### 4）`save_record(record)`
只负责写文件。

#### 5）`main()`
负责控制流程，相当于程序入口。

这就是最基础的代码组织思路。**别一上来把所有逻辑都堆在 `main()` 里。** 那样虽然也能跑，但一复杂就很难维护。

### 6.4 这个小工具怎么继续复用

别把它只当成“练习题”，它其实是个很好的小工具骨架。你后面可以很自然地加功能：

- 改成按日期分文件保存
- 记录标题和正文两部分
- 加一个随机提示语，帮助你每天想记录什么
- 把内容再做一点简单文本提取，比如提取关键词
- 把输入方式改成命令行参数，做成真正的小命令

这样一来，这个记录器就不只是“记一条文字”，而是能慢慢长成一个可复用的小助手。  
它以后可以嵌进笔记工具、日志工具、学习打卡工具，甚至是一个简单的命令行记录程序里。

### 6.5 一个更实用的小升级：先判断，再保存

如果你想再往前走一步，可以给它加两个小检查：

- 文件不存在时自动创建
- 输入内容为空时直接退出

这样程序就更稳，也更像一个真正能用的小工具。

## 一、命令行程序的基本结构：先把主流程想明白

先别急着上复杂框架。命令行小程序最常见的骨架就是：

1. **输入**：从用户那里拿到数据  
2. **处理**：对数据做判断、清洗、计算、转换  
3. **输出**：把结果打印出来，或者保存成文件

这就是一个最小闭环。

比如做一个“文本词频统计”小工具，流程可以是：

- 输入：文件路径，或者用户粘贴的一段文本
- 处理：去掉标点、统一大小写、拆分单词、统计次数
- 输出：打印前 10 个高频词，或者保存结果

所谓“小工具”，不是功能一定很多，而是**流程清楚、入口明确、输出稳定**。

### 1.1 先别追求“大而全”，先追求“能闭环”

新手最容易犯的错，就是一上来想把功能做全：菜单、配置、日志、数据库、图形界面，全都想要。结果写到一半卡住，连最基本的输入输出都没通。

赵老师的实战习惯是：**先写最小可运行版本**。也就是先问三个问题：

- 这个工具最少要接收什么输入？
- 中间最少要做什么处理？
- 最少要给什么输出，才算有用？

只要这三步能连起来，程序就已经活了。后面再慢慢加功能，才不会把自己绕晕。

### 1.2 代码结构建议：主流程放前面，细节拆函数

一个简单命令行程序，建议这样组织：

- `main()` 负责主流程
- `parse_input()` 负责读取和整理输入
- `do_work()` 负责核心处理
- `show_result()` 负责输出结果
- `if __name__ == "__main__":` 作为入口

你不一定非得记住这些名字，但要记住这个思想：**主线清楚，细节分开。**

好处很直接：

- 后面改功能时，不会把整段代码搅成一锅粥
- 出错时更容易定位问题，到底是输入错了，还是处理错了

#### 动手练习

先写一个最简单的程序：

- 让用户输入一个名字
- 程序输出：`你好，XXX！今天也继续加油。`

然后把它改成函数版本：

- `get_name()`
- `greet(name)`

别小看这个练习，它是在训练你把“零散语法”变成“完整流程”。

## 二、参数设计：位置参数、可选参数和默认值

一个小工具如果只能靠你在代码里改变量，那还不算真正可用。它应该尽量能让用户**在运行时传入参数**。

这里先不急着上复杂参数解析库，先把“参数”三种最常见的思路讲清楚：**位置参数、可选参数、默认值**。

### 2.1 什么是位置参数？

位置参数就是：**按顺序传入，顺序不能乱。**

比如：

```python
def add(a, b):
    return a + b
```

调用时：

```python
add(3, 5)
```

这里 `3` 和 `5` 的位置很重要，顺序换了，结果就变了。  
放到命令行里也类似：

```bash
python tool.py input.txt
```

这里 `input.txt` 就像位置参数，告诉程序你要处理哪个文件。

位置参数适合：

- 必须传的信息
- 位置固定、调用简单的场景

但参数太多时，顺序一乱就容易出错，所以新手做工具时，位置参数通常只保留最关键的一两个，比如输入文件、关键词、模式名。

### 2.2 什么是可选参数？

可选参数就是：**给也行，不给也行**，程序要有默认行为。

比如：

- 默认处理当前目录
- 默认输出到屏幕
- 默认显示前 10 条结果

这时函数默认参数就派上用场了：

```python
def greet(name="朋友"):
    print(f"你好，{name}！")
```

这种写法很适合小工具：用户不填也能跑，想精细控制时再多传一点参数就行。

### 2.3 默认值为什么适合小工具？

因为默认值能显著降低使用门槛。你可以把它理解成“懒人友好模式”：

- 用户什么都不填，也能跑
- 用户想精细控制，再额外传参数

这就是好工具的基本气质：**先能用，再好用。**

一个常见原则是：**默认值尽量选最常见、最安全、最不容易出错的选项。**

比如：

```python
def report(name, level="普通"):
    print(f"{name} 的等级是：{level}")
```

只传 `name` 时，程序也能正常工作；需要更具体信息时，再传 `level`。

#### 常见误区

- 误区一：参数越多越专业  
  其实不是，参数多只会让新手更怕用。
- 误区二：默认值随便写  
  默认值应该是最常见、最安全、最不容易出错的选择。
- 误区三：位置参数和可选参数不区分  
  结果调用时混乱，后面自己都看不懂。

#### 动手练习

试着写一个函数：

```python
def report(name, level="普通"):
    ...
```

要求：

- 只传 `name` 时，默认等级是“普通”
- 传了 `level` 时，按传入的显示
- 再试着换几个调用顺序，体会“位置”和“默认值”的区别

这个练习看着简单，但它在帮你建立一个很重要的意识：**工具不是写给自己看代码的，是写给未来使用者看的。**

## 三、交互式输入与批处理输入：程序该怎么“接待”用户？

一个命令行工具，常见有两种输入方式：

1. **交互式输入**
2. **批处理输入**

这两个概念一定要分清，不然后面你会反复纠结“到底让用户敲什么”。

### 3.1 什么是交互式输入？

交互式输入就是程序跑起来以后，一步一步问你：

- 请输入文件名
- 请输入关键词
- 是否覆盖原文件？
- 是否继续？

优点是：

- 适合新手
- 提示清楚
- 误操作少

缺点也明显：

- 慢
- 不适合重复执行很多次
- 自动化能力弱

最常见的写法就是：

```python
name = input("请输入你的名字：")
print("你好，", name)
```

交互式输入最重要的不是“问”，而是“问得清楚”。你问得越模糊，用户越容易输错。

### 3.2 什么是批处理输入？

批处理输入就是：**一次把参数给全，程序直接干活。**

比如：

```bash
python tool.py notes.txt python
```

程序看到这些参数后，直接去处理 `notes.txt`，找 `python` 相关内容，不再一项一项问你。

优点是：

- 快
- 适合自动化
- 适合重复执行

缺点是：

- 对初学者不太友好
- 参数少了容易报错
- 对输入格式要求更高

### 3.3 新手阶段怎么选？

赵老师的建议很简单：

- **练习时先用交互式输入**
- **做工具时尽量兼容批处理输入**
- **默认优先让程序“傻瓜可用”**

也就是说，你可以先让程序能问答式运行，再逐步扩展到命令行参数模式。这样学习节奏最稳。

#### 动手练习

设计一个“待办事项小程序”的输入方式：

- 交互式：让用户一次输入任务内容、截止日期、优先级
- 批处理式：一行命令传入任务内容和可选参数

比较一下两种方式，你会更直观地感受到“可用性”和“效率”的区别。  
做完这个练习，你就会明白：输入方式不是随便选的，它直接决定工具是“玩具”还是“真能用”。

## 四、提示信息、帮助信息和使用体验：别让用户猜

很多新手写出来的程序，自己会用，别人不会用。原因很简单：程序没有“说人话”。

一个命令行程序，最基本的用户体验包括：

- 启动后知道要做什么
- 出错时知道哪里错了
- 不知道怎么用时能看到帮助信息

### 4.1 提示信息要明确

比如这句就太空：

```python
input("请输入：")
```

用户不知道该输入什么、格式是什么、能不能空着。更好的写法是：

```python
input("请输入待处理的文件路径，例如 data.txt：")
```

提示信息最好包含三样：

- 输入什么
- 格式是什么
- 给个例子

这样用户少猜，你也少排错。

### 4.2 帮助信息是小工具的门牌

一个可以反复使用的小工具，最好有简单的帮助说明。哪怕你暂时还没上正式参数解析，也可以自己约定一个 `--help` 思路，或者在启动时打印使用说明。

比如：

```python
print("用法：python tool.py [文件名] [关键词]")
print("示例：python tool.py notes.txt Python")
```

这类信息很朴素，但特别实用。它像门牌，告诉别人：这个工具怎么进、怎么用、从哪开始。

如果以后你给工具加更多参数，也可以继续扩展成更完整的帮助信息，比如：

- 这个参数是必填还是可选
- 没传参数时默认干什么
- 输入文件格式是什么
- 输出结果会保存到哪里

### 4.3 错误提示要像人话

不要只打印：

```python
print("Error")
```

这等于没说。应该尽量告诉用户：

- 哪里错了
- 为什么错了
- 怎么改

例如：

```python
print("文件不存在，请检查路径是否正确。")
```

你还可以进一步告诉用户建议的检查方法：

- 先看文件名有没有拼错
- 再看是不是当前目录下没有这个文件
- 如果是绝对路径，确认路径格式是否正确

#### 赵老师的实战习惯

老赵写小工具时，最先补的不是功能，而是这三样：

1. 入口提示  
2. 错误提示  
3. 使用示例

因为这三样决定了一个工具“像不像工具”。

## 五、练习：实现一个命令行小工具的基础框架

下面我们来做一个真正能落地的最小框架。这个工具先不追求复杂，目标是：

- 接收一个文本文件名
- 接收一个关键词
- 统计文件中关键词出现的次数
- 输出结果
- 出错时能提示用户

### 5.1 先画出流程

先别写代码，先想流程：

1. 读取输入
2. 检查参数是否齐全
3. 读取文件
4. 处理文本
5. 输出结果
6. 捕获异常

这一步很重要。程序一旦卡住，大多数不是语法问题，而是**流程没想清楚**。老赵很喜欢先在纸上或者脑子里过一遍流程，再敲代码，这样不会东一榔头西一棒子。

### 5.2 代码骨架示例

```python
def count_keyword(text, keyword):
    return text.lower().count(keyword.lower())

def main():
    print("=== 关键词统计小工具 ===")
    filename = input("请输入文件名：").strip()
    keyword = input("请输入关键词：").strip()

    if not filename or not keyword:
        print("文件名和关键词都不能为空。")
        return

    try:
        with open(filename, "r", encoding="utf-8") as f:
            text = f.read()
    except FileNotFoundError:
        print("文件不存在，请检查路径。")
        return
    except UnicodeDecodeError:
        print("文件编码读取失败，可能不是 UTF-8。")
        return

    count = count_keyword(text, keyword)
    print(f"关键词“{keyword}”出现了 {count} 次。")

if __name__ == "__main__":
    main()
```

这个例子很小，但已经包含了很多实战要素：

- 函数组织代码
- 字符串处理
- 文件读取
- 异常处理
- 用户提示
- 基础输出

这就是“从语法到小工具”的关键一步。

### 5.3 这段代码体现了什么思路？

#### 1）主流程和功能拆开

`main()` 负责流程，`count_keyword()` 负责统计。这样后面你想换成统计词频、统计行数，都比较容易改。

#### 2）先检查输入，再做处理

不要一上来就读文件。先判断输入是否为空，能避免很多低级错误。  
这就是典型的“小步快跑”：先保证最基本的输入合法，再继续往下走。

#### 3）异常不是可有可无

新手经常把异常当成高级内容，其实不是。对工具来说，异常处理就是基本防护，不写反而不专业。

### 5.4 进阶一步：让工具更像工具

你可以继续给这个小工具加三个小功能：

- 如果没有输入关键词，默认统计“Python”
- 支持统计结果写入新文件
- 增加一个简短的使用说明

比如：

```python
print("用法：")
print("1. 输入文件名")
print("2. 输入关键词")
print("3. 程序返回出现次数")
```

这一步不在于“做得多”，而在于让工具逐渐具备可复用性。一个工具如果只能跑一次，那只是练习；如果你下次还能拿来改、拿来扩展，那它就真正开始像工具了。

## 六、赵老师的实战习惯：写工具时先盯住这四件事

到这里，我们把一个命令行工具的基本思路串起来了。为了让你以后自己写项目时不乱，老赵这里把实战习惯再帮你收一遍，做成一个固定清单。

### 6.1 先看目标，再拆步骤

先问自己：这个工具到底要干什么？不要一上来就写代码，先把目标说清楚。目标越清楚，后面拆步骤越稳。

- 参数有没有传对
- 路径对不对

- 输出有没有按预期生成

能跑通，再谈优化。

这个方法不花哨，但特别管用。你以后做任何小工具，基本都能按这套来。

# 第10章 处理真实数据：简单文本处理或轻量爬取实战

# 第 10 章 处理真实数据：简单文本处理或轻量爬取实战

前面我们已经把变量、字符串、列表、字典、函数、文件、异常这些基础动作练得差不多了。接下来就进入一个关键阶段：**开始碰真实数据**。

真实数据和练习题里的“标准答案”不一样，通常有这些特点：

- 格式不整齐
- 有多余字符
- 可能有缺失值
- 读取会失败
- 结果不一定能直接用

所以这一章老赵不绕弯子，直接做两类最常见的事：

1. **文本处理**：从原始文本里提取关键信息  
2. **轻量爬取**：按“请求 → 解析 → 清洗”的流程拿到可用数据

真正能干活的程序，往往不是“会很多语法”的程序，而是**能把脏数据处理成结构化结果**的程序。  
这一章继续保持老赵的节奏：**小步快跑，先跑通，再优化。**

---

## 一、先把路子想明白：真实数据处理的固定流程

不管你处理的是日志、公告、表格文本，还是网页内容，老赵建议你先按这个顺序来：

1. **明确目标**：你到底想提取什么？
2. **看原始数据**：它长什么样，哪里稳定，哪里会变？
3. **先过滤，再拆分**：先找目标行，再拆字段
4. **清洗字段**：去空格、去换行、去杂字符
5. **结构化保存**：转成列表、字典或字典列表
6. **加异常处理**：别让一条坏数据把程序带崩

这个顺序很重要。很多新手一上来就急着“写解析”，结果连输入长什么样都没看清。赵老师的实战习惯是：**先打印原始数据，再写处理逻辑**。先观察，后动手，代码会稳很多。

---

## 二、文本处理场景：从原始文本中提取关键信息

### 2.1 真实文本长什么样？

日志、通知、公告、聊天记录、订单文本，常常长这样：

```text
2024-06-01 09:10 用户A 登录成功
2024-06-01 09:12 用户B 登录失败
2024-06-01 09:15 用户A 下单 2 件
2024-06-01 09:20 用户C 登录成功
```

你要做的，不是“看懂句子”，而是把它变成程序能处理的结构，比如：

- 哪些记录是登录成功？
- 哪些用户出现次数最多？
- 哪些时间段最活跃？
- 提取日期、用户名、动作、结果等字段

文本处理的核心目标就是：**从自然文本里拆出结构化信息**。

老赵平时会先问四个问题：

1. 数据按什么分隔？
2. 每一行是不是差不多长？
3. 哪些字段稳定，哪些字段会变？
4. 最终要的是筛选、统计，还是导出？

先把这四个问题想清楚，代码就不会乱。

---

### 2.2 文本处理的基本套路是什么？

记住一个固定流程就够了：

#### 第一步：读取原始文本
可以来自字符串、文件、网页响应。

#### 第二步：按行、按词、按分隔符拆分
常用方法：

- `split()`
- `split(',')`
- `strip()`
- `replace()`

#### 第三步：筛选目标内容
比如只保留包含“登录成功”的行。

#### 第四步：提取字段
通过分割、查找、切片把日期、用户名、动作拆出来。

#### 第五步：转成可用结构
比如列表、字典、字典列表。

这套流程以后处理成绩单、日志、聊天记录、商品信息，都能套上。

---

### 2.3 一个小例子：提取“登录成功”的用户名

```python
logs = """
2024-06-01 09:10 用户A 登录成功
2024-06-01 09:12 用户B 登录失败
2024-06-01 09:15 用户A 下单 2 件
2024-06-01 09:20 用户C 登录成功
"""

lines = logs.strip().split("\n")
success_users = []

for line in lines:
    if "登录成功" in line:
        parts = line.split()
        if len(parts) >= 4:
            user = parts[2]
            success_users.append(user)

print(success_users)
```

输出：

```python
['用户A', '用户C']
```

这里注意几点：

- `strip()` 去掉首尾空白和多余换行
- `split("\n")` 按行拆分
- `if "登录成功" in line` 是最实用的过滤方式
- `split()` 默认按空白分隔，适合规整文本
- 加 `len(parts) >= 4`，可以避免格式不完整时报错

真实项目里，**先过滤，再拆分，再判断长度**，程序会稳很多。

---

### 2.4 常见误区

#### 误区 1：一上来就想写“万能解析器”
先处理一种稳定格式，再慢慢扩展。别急着一步到位。

#### 误区 2：忽略空行和异常行
真实文本里经常有空行、格式错乱行、缺字段行。  
如果默认每一行都有 4 个字段，程序就容易崩。

#### 误区 3：结果直接拿来用，不做清洗
像 `" 用户A "`、`"用户A"`、`"用户A\n"` 看起来一样，程序里可不一样。  
所以清洗是必须动作。

赵老师的实战习惯是：**原始数据不要信，先打印出来看一眼。**

---

### 2.5 练习：做一个简单文本整理器

准备一份混乱文本：

```text
张三, 89
李四, 76
王五, 92
李四, 81
```

目标：

- 去掉空格
- 提取姓名和分数
- 找出所有分数大于等于 80 的人

思路：

1. 按行拆分
2. 每行按逗号拆分
3. 去掉空格
4. 把分数转成整数
5. 根据分数筛选

如果愿意，再加一个统计功能：  
同一个人出现多次时，保留最高分或最后一次分数。

这类练习不追求花哨，追求的是你能不能把“看起来乱”的数据，拆成“程序能用”的数据。

## 三、轻量爬取思路：请求、解析、清洗的基本流程

### 3.1 轻量爬取到底在做什么？

这里说的“轻量爬取”，不是写复杂爬虫，而是理解最基本的流程：

1. **请求**：把网页内容拿回来
2. **解析**：从 HTML 或文本里找出你要的内容
3. **清洗**：把杂乱信息处理成可用数据

你先把这个流程理解清楚就够了。很多时候，你不是要爬整个网站，只是想拿到一个列表、一段标题、一串价格、几条公告。

说白了，就是：**把网页当成一份特殊格式的文本来处理。**

---

### 3.2 请求阶段：先把内容拿到手

练习时可以先理解为：程序向目标地址要数据，拿回一大段文本。

```python
import requests

url = "https://example.com"
resp = requests.get(url, timeout=5)
print(resp.status_code)
print(resp.text[:200])
```

几个重要点：

- `requests.get()` 发起请求
- `timeout=5` 防止卡死
- `status_code` 判断是否成功
- `text` 是网页文本内容

赵老师的习惯是：**先看状态码，再看内容，最后再谈解析。**  
不要一上来就找标签，结果其实请求早失败了。

如果 `status_code` 不是 200，先确认是不是网络问题、地址写错了，或者页面本身不允许访问。

---

### 3.3 解析阶段：找到你真正关心的字段

如果返回的是 HTML，你通常不会把整页都保存，而是找标题、链接、价格、时间等字段。

常见思路有两种：

#### 方法一：字符串处理
适合结构简单、目标明确的场景。

#### 方法二：借助解析工具
比如用 `BeautifulSoup` 定位标签。

本章重点不是让你马上成为网页解析高手，而是明白：  
**解析的本质，就是把原始文本变成你要的字段。**

先训练自己做“提取 + 清洗 + 结构化”的动作，网页解析也就没那么吓人了。

---

### 3.4 清洗阶段：把抓回来的内容变干净

清洗很重要，常见动作有：

- 去掉 `"\n"`
- 去掉多余空格
- 过滤空字段
- 处理非法字符
- 去重

例如：

```python
title = "  Python 入门指南\n"
clean_title = title.strip()
print(clean_title)
```

批量处理时可以配合列表推导式：

```python
titles = ["  标题A\n", " 标题B ", "标题C  "]
clean_titles = [t.strip() for t in titles]
print(clean_titles)
```

赵老师经常提醒：**数据清洗不是附加步骤，而是核心步骤。**  
真正让结果可用的，不是你抓到了什么，而是你整理成什么样。

---

## 四、网络请求或数据读取中的异常与重试意识

### 4.1 为什么真实数据总会出错？

因为真实环境不稳定，可能出现：

- 网络超时
- 页面不存在
- 格式变化
- 文件编码不一致
- 某一行缺字段
- 请求被临时拒绝

所以写程序时，心态要变一下：  
**不是“会不会出错”，而是“出了错怎么处理”。**

这就是从“写练习代码”走向“写工具代码”的分水岭。

---

### 4.2 基本异常处理怎么写？

最常见的是 `try...except`：

```python
try:
    num = int("abc")
except ValueError:
    print("转换失败：不是合法数字")
```

数据处理中，异常处理最常见的用途有两个：

1. 防止程序直接崩掉
2. 给错误留出修复空间

比如读取每一行数据时，某一行格式不对，就跳过它：

```python
lines = ["张三,89", "李四,not_a_number", "王五,92"]

for line in lines:
    try:
        name, score = line.split(",")
        score = int(score)
        print(name, score)
    except Exception:
        print("这行有问题，已跳过：", line)
```

先别纠结异常类型是否够细，新手阶段更重要的是养成习惯：  
**不要让一行坏数据拖垮整个程序。**

---

### 4.3 重试意识：一次失败不代表永远失败

轻量爬取或读取接口时，第一次失败可能只是临时波动。可以做简单重试：

```python
import requests
import time

url = "https://example.com"

for i in range(3):
    try:
        resp = requests.get(url, timeout=5)
        resp.raise_for_status()
        print("请求成功")
        break
    except requests.RequestException as e:
        print(f"第 {i+1} 次失败：{e}")
        time.sleep(2)
```

先记住这个动作：

- 失败了先别慌
- 看清楚报错类型
- 允许有限次数重试
- 重试之间稍微暂停

这是很实用的工程思维。做小工具不怕问题，怕的是你没给程序留恢复机会。

---

### 4.4 排错时先看什么？

赵老师的顺序一般是：

1. 先看报错行号
2. 再看报错类型
3. 打印关键变量
4. 检查输入格式
5. 缩小范围，单独跑一小段

数据处理里，别一上来就整段猜。最有效的方法往往是：

```python
print(repr(line))
print(parts)
print(type(score))
```

`repr()` 在排查空格、换行、不可见字符时很好用。很多“我明明写对了”的问题，最后都是某个多余空格、一个换行符，或者字段顺序不对。

## 五、把抓到或处理到的数据转成可用结构

### 5.1 为什么一定要结构化？

因为“看见了”不等于“能用”。  
真正可用的数据，通常会变成这些结构：

- 列表：适合一组记录
- 字典：适合一条记录
- 字典列表：适合多条结构化记录

比如一批日志可以整理成：

```python
[
    {"time": "2024-06-01 09:10", "user": "用户A", "action": "登录成功"},
    {"time": "2024-06-01 09:12", "user": "用户B", "action": "登录失败"},
]
```

这样后面筛选、统计、导出都方便。  
这一步就是从“文本思维”切换到“数据思维”。

老赵建议你以后看到一段原始内容，先别急着写代码，先想：**我最后要把它整理成什么结构？**

---

### 5.2 从文本到结构的转换方式

假设原始文本是：

```text
2024-06-01 09:10 用户A 登录成功
2024-06-01 09:12 用户B 登录失败
2024-06-01 09:20 用户C 登录成功
```

可以整理成字典列表：

```python
raw = """
2024-06-01 09:10 用户A 登录成功
2024-06-01 09:12 用户B 登录失败
2024-06-01 09:20 用户C 登录成功
"""

records = []

for line in raw.strip().split("\n"):
    parts = line.split()
    if len(parts) < 4:
        continue
    record = {
        "date": parts[0],
        "time": parts[1],
        "user": parts[2],
        "result": parts[3]
    }
    records.append(record)

print(records)
```

这里几个判断很关键：

- `len(parts) < 4`：防止字段不够
- `continue`：跳过坏数据
- 字典保存字段名：后续处理更直观

以后无论做日志分析、文本提取，还是简单网页内容整理，这一套都能用上。

---

### 5.3 数据结构选型的小原则

#### 用列表：关心“顺序”和“批量”
比如每条记录、每个标题、每个分数。

#### 用字典：关心“键值对应”
比如用户名对应分数、类别对应统计值。

#### 用字典列表：关心“多条结构化记录”
这是最常见的数据处理中间态。

老赵的习惯是：  
**先用字典列表把数据装起来，再考虑统计、筛选、导出。**  
不要一开始就把逻辑全揉在一起，不然代码会越来越难改。

## 六、实战项目：做一个日志整理小工具

这一节我们把前面学到的东西串起来，做一个真正能复用的小工具雏形。目标很简单：**输入一份原始日志，输出清洗后的记录、成功次数统计，并保存结果文件。**

### 6.1 任务设计

假设你有一份原始数据：

```text
2024-06-01 09:10 用户A 登录成功
2024-06-01 09:12 用户B 登录失败
2024-06-01 09:15 用户A 下单 2 件
2024-06-01 09:20 用户C 登录成功
2024-06-01 09:25 用户A 登录成功
```

任务是：

1. 提取所有“登录成功”的记录
2. 统计每个用户登录成功次数
3. 把结果保存到文件中
4. 遇到格式错误行，不要让程序崩掉

这几个目标很贴近真实场景：先筛选，再统计，再落盘。

---

### 6.2 一个参考实现思路

```python
raw = """
2024-06-01 09:10 用户A 登录成功
2024-06-01 09:12 用户B 登录失败
2024-06-01 09:15 用户A 下单 2 件
2024-06-01 09:20 用户C 登录成功
2024-06-01 09:25 用户A 登录成功
"""

success_records = []
user_count = {}

for line in raw.strip().split("\n"):
    try:
        parts = line.split()
        if len(parts) < 4:
            continue

        date = parts[0]
        time = parts[1]
        user = parts[2]
        action = parts[3]

        if action == "登录成功":
            record = {
                "date": date,
                "time": time,
                "user": user,
                "action": action
            }
            success_records.append(record)
            user_count[user] = user_count.get(user, 0) + 1

    except Exception as e:
        print("处理失败，跳过：", line, e)

print("登录成功记录：", success_records)
print("统计结果：", user_count)
```

这段代码已经有了一个小工具该有的样子：**输入、处理、输出**。

它体现了几个很实战的点：

- 用 `try...except` 保底
- 用字典保存统计结果
- 用 `get()` 简化计数逻辑
- 先筛选，再统计，再输出

---

### 6.3 把结果保存下来，才算真正有用

程序跑完如果什么都不留，还是不够实用。真实的小工具，通常都要把结果写进文件，方便后面查看、复用、发给别人。

```python
with open("success_records.txt", "w", encoding="utf-8") as f:
    for item in success_records:
        line = f'{item["date"]} {item["time"]} {item["user"]} {item["action"]}\n'
        f.write(line)
```

这样你就把内存里的结果变成了一个可复用文件。  
后面要继续分析、分享、备份，都很有用。

如果你愿意，还可以再补一份统计文件：

```python
with open("user_count.txt", "w", encoding="utf-8") as f:
    for user, count in user_count.items():
        f.write(f"{user}: {count}\n")
```

这一步很重要，因为它把“处理结果”变成了“可交付结果”。  
老赵一直强调：**程序不只是跑完，还要留下成果。**

---

### 6.4 这个小工具能复用到哪里？

这个日志整理小工具虽然简单，但它的思路可以直接复用到很多场景：

- 课堂签到记录整理
- 简单后台日志筛选
- 活动报名名单统计
- 聊天记录关键词提取
- 文本报表的快速清洗

你看，它不是只为这一份样例数据服务，而是能换输入、换规则、换输出格式。  
这才叫“可复用”。

---

### 6.5 赵老师的实战检查清单

写完后，按下面这张表检查：

- 能不能正确分行？
- 遇到空行会不会崩？
- 字段不够时是否跳过？
- 是否只保留目标数据？
- 统计是否准确？
- 输出文件是否能正常打开？
- 有没有多余空格和换行？

这张清单就是你以后做真实任务时的“验收模板”。  
以后你写任何小工具，都可以拿它来对照一下，看看是不是少了哪一块。

## 七、小结：把“会语法”变成“能处理数据”

这一章做的事，表面上是文本处理和轻量爬取，实际上是在训练一种重要能力：  
**把零散语法组合成真实工作流**。

你要记住这条主线：

- 先把数据拿进来
- 再拆分、筛选、清洗
- 然后转成结构化结果
- 最后保存、统计、输出

这就是老赵常说的“小步快跑”：

- 先做能跑的版本
- 再加异常处理
- 再补结构化输出
- 再做重试和文件保存

不要一开始就想把所有功能做满。  
真正靠谱的小工具，往往是一步一步长出来的。

## 一、模块和导入的基本用法：为什么要拆文件？

先回答一个最常见的问题：**为什么不能所有代码都写在一个 `.py` 文件里？**

能写，但不推荐。功能一多，文件就会越来越乱：配置混在业务逻辑里，读文件、处理数据、打印结果全挤在一起。以后想改一个小地方，也得在一大坨代码里翻来翻去。

所以我们要学会把代码拆成模块。这里的**模块**，就是可以被导入和复用的 Python 文件。你可以理解为：一个文件只负责一类事情，最后再拼起来。

### 1.1 最基础的导入方式

假设你有一个文件叫 `utils.py`，里面写了一个函数：

```python
def greet(name):
    return f"你好，{name}！"
```

另一个文件 `main.py` 可以导入它：

```python
import utils

print(utils.greet("老赵"))
```

这叫“导入模块后，用模块名.函数名”。

如果你只想导入某个函数，也可以：

```python
from utils import greet

print(greet("小王"))
```

两种写法都能用，但新手阶段老赵更建议你先用 `import utils`。原因很简单：**更清楚，不容易撞名，也方便看出函数来自哪里**。

### 1.2 什么时候用哪种方式？

简单判断就行：

- **只用少量函数**：可以 `from xxx import yyy`
- **要用很多东西**：直接 `import xxx` 更清楚
- **新手阶段**：优先 `import xxx`，少出错

你现在追求的不是“写法高级”，而是“代码稳”。

### 1.3 常见误区

#### 误区 1：文件名随便起
别把自己的文件命名成 `random.py`、`datetime.py`、`json.py` 这种和标准库重名的名字，不然导入时会很混乱。你明明想用系统自带模块，结果导入了自己写的同名文件，排错会很痛苦。

#### 误区 2：导入后乱用全局变量
模块之间尽量通过函数传参、返回值交互，不要到处靠全局变量“隔空传话”。全局变量短期省事，长期就是埋雷。

#### 误区 3：导入时执行了一堆代码
模块顶层代码会在导入时执行，所以如果你把正式运行流程也写在顶层，别人一导入就开始跑程序了。这个问题后面会靠 `main` 入口解决。

### 1.4 动手练习

建两个文件：

**`tools.py`**
```python
def format_title(text):
    return f"*** {text.strip()} ***"
```

**`app.py`**
```python
import tools

print(tools.format_title("  今日清单  "))
```

先把这个跑通。别嫌简单，模块化的第一步就是让你不怕“拆文件”。只要你能把一个函数放进单独文件，再成功导入出来，说明你已经迈出第一步了。

## 二、如何拆分功能：配置、数据处理、输出、主入口

接下来是核心问题：**一个小工具到底该怎么拆？**

老赵建议你按四层来想：

1. **配置**：参数、路径、开关、固定规则
2. **数据处理**：清洗、筛选、统计、转换
3. **输出**：打印、写文件、生成结果
4. **主入口**：把流程串起来

这套拆法不复杂，但很实用。

### 2.1 配置层：把会变的东西集中起来

比如日志分析小工具里的文件路径、输出文件名、关键词列表，都属于配置：

```python
LOG_FILE = "app.log"
OUTPUT_FILE = "result.txt"
KEYWORDS = ["error", "warning", "timeout"]
```

为什么要这样做？

- 以后改路径不用翻代码
- 规则清楚，读起来一眼明白
- 后面可以顺手升级成命令行参数

新手常见问题是把各种值直接写进函数里，短期能跑，但需求一变就得满文件乱改。把配置统一放出来，是很值得养成的习惯。

### 2.2 数据处理层：一段函数只干一件事

比如从文本里找关键词，可以写成一个函数：

```python
def count_keywords(lines, keywords):
    result = {k: 0 for k in keywords}
    for line in lines:
        text = line.lower()
        for k in keywords:
            if k in text:
                result[k] += 1
    return result
```

这个函数只负责“统计”，不管文件读写，也不管最终怎么展示。这样做的好处很明显：

- 代码更容易测试
- 出错时更容易定位
- 后续换输入来源也不用改它

老赵的实战习惯就是：**函数职责越单纯，越好维护**。如果一个函数里又读文件、又处理、又输出，那说明它已经“胖”了，该拆。

### 2.3 输出层：把结果变成人能看懂的东西

处理完数据后，输出可以是打印，也可以是写入文件：

```python
def format_result(stats):
    lines = []
    for key, value in stats.items():
        lines.append(f"{key}: {value}")
    return "\n".join(lines)
```

输出层的原则是：**把内部数据结构转换成外部可读格式**。字典适合程序处理，但用户未必喜欢直接看字典；整理成一段字符串，才更像工具输出。

### 2.4 主入口：流程总指挥

主入口负责：

- 读配置
- 读文件
- 调用处理函数
- 输出结果

它不该塞太多细节，只做调度。

### 2.5 怎么判断拆得对不对？

你可以用这个标准检查：

- **配置**是不是都集中在一起？
- **处理函数**是不是尽量纯粹，只做一件事？
- **输出函数**是不是只负责展示或保存？
- **主入口**是不是像流水线一样把它们串起来？

如果一个函数里既读文件又统计又打印，那基本就是“该拆了”。

## 三、main 入口和脚本组织方式：为什么要写 `if __name__ == "__main__"`？

这句很多新手都背过，但未必真懂。老赵给你讲人话版。

### 3.1 它解决什么问题？

当你把一个 Python 文件既当“模块”又当“脚本”时，会出现一个问题：

- 直接运行这个文件时，要执行主流程
- 但被别的文件导入时，不应该自动执行主流程

这时就要用：

```python
if __name__ == "__main__":
    main()
```

### 3.2 这句怎么理解？

你可以理解成：

- **自己运行自己**：执行 `main()`
- **别人导入你**：别急着跑主流程

也就是说，导入和运行要分开。这样文件才既能独立执行，也能被别人拿来复用。

### 3.3 推荐的脚本组织方式

一个入门小项目，可以这样拆：

```text
project/
├── app.py          # 主入口
├── config.py       # 配置
├── io_utils.py     # 文件读写
├── processor.py    # 数据处理
└── formatter.py    # 结果格式化
```

这不是唯一标准，但很适合新手。它的好处是：一眼就能看出每个文件负责什么，不会把所有东西塞进一个大文件里。

### 3.4 `main()` 应该写什么？

`main()` 里面只放流程，不放细节：

```python
from io_utils import read_lines, write_text
from processor import count_keywords
from formatter import format_result
from config import LOG_FILE, OUTPUT_FILE, KEYWORDS

def main():
    lines = read_lines(LOG_FILE)
    stats = count_keywords(lines, KEYWORDS)
    text = format_result(stats)
    write_text(OUTPUT_FILE, text)
    print(text)

if __name__ == "__main__":
    main()
```

这就是很标准的小工具主入口风格。像不像一条生产线？输入进来，经过处理，最后变成结果。程序写到这个程度，已经开始有“工具感”了。

### 3.5 赵老师的实战习惯：一套固定的检查法

老赵写项目时有几个习惯，你可以直接学：

- **先看目标，再拆步骤**：先弄清楚这个工具最终要输出什么
- **先写主流程，再补细节**：先搭骨架，后填肉
- **先跑通，再优化**：不要一开始就追求完美
- **每拆一个模块，就立刻测试一次**：别等最后一起爆雷
- **先观察输入，再决定清洗方式**：数据长什么样，处理方法就怎么选
- **出错先定位，再修改**：先看报错文件和行号，别瞎改

这套方法其实就一句话：**小步快跑，随时确认方向没歪**。

## 四、把函数、文件、异常、标准库整合起来：怎么让程序更像“工具”？

到这里，你已经知道怎么分文件了。真正关键的是：**怎么把前面学过的知识放进一个完整的小工具里？**

我们用一个适合新手的例子：**统计文本中的关键词并输出结果**。

### 4.1 文件操作：把输入和输出串起来

先写 `io_utils.py`：

```python
def read_lines(path):
    with open(path, "r", encoding="utf-8") as f:
        return f.readlines()

def write_text(path, text):
    with open(path, "w", encoding="utf-8") as f:
        f.write(text)
```

这里你会看到：

- `with` 负责自动关闭文件
- 读取用 `readlines()`
- 写入用 `write()`

`with open(...)` 基本就是最稳妥的写法，能少犯“忘记关闭文件”的错。

### 4.2 异常处理：别让程序一报错就崩掉

文件不存在、编码不对、权限不足，这些都很常见。小工具不需要硬扛，应该把错误处理好。

```python
def safe_read_lines(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return f.readlines()
    except FileNotFoundError:
        print(f"文件不存在：{path}")
        return []
    except UnicodeDecodeError:
        print(f"文件编码有问题：{path}")
        return []
```

这里的思路很实用：

- 能预判的错误，提前处理
- 出错后给用户明确提示
- 不要直接把一长串报错扔给普通用户

异常处理不是为了掩盖错误，而是为了让程序出问题时也能说人话。

### 4.3 标准库：别什么都自己造轮子

小工具开发里，标准库特别好用。比如：

- `os` / `pathlib`：处理路径
- `sys`：获取命令行参数
- `datetime`：处理日期时间
- `collections`：做统计
- `re`：做文本匹配
- `json`：读写结构化数据

例如，可以用 `datetime` 给输出加个时间戳：

```python
from datetime import datetime

def add_header(text):
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    return f"生成时间：{now}\n\n{text}"
```

这样一来，输出结果不只是“有内容”，还知道是啥时候生成的。很多实用小工具都会需要这种细节。

### 4.4 常用内置函数别忘了

你前面学的很多内置函数，现在正好派上用场：

- `len()`：统计长度
- `sum()`：求和
- `max()` / `min()`：找最大最小
- `sorted()`：排序
- `enumerate()`：带索引遍历
- `zip()`：并排处理数据
- `any()` / `all()`：判断条件
- `str()` / `int()` / `float()`：类型转换

比如处理列表时：

```python
items = ["apple", "banana", "pear"]
for idx, item in enumerate(items, start=1):
    print(idx, item)
```

这些内置函数不花哨，但很常用。很多时候你不是不会写，而是忘了 Python 其实已经帮你准备好了。

### 4.5 判断一个小工具有没有“成型”

看这几个点：

- 输入有来源：文件、命令行、用户输入
- 处理有逻辑：函数拆分清楚
- 错误有提示：不会一崩到底
- 输出有结果：打印、写文件、生成报告
- 能重复使用：换个文件也能跑

如果这些都具备了，恭喜你，已经不是“写几行练习题”了，而是在做真正的小工具。

## 五、练习：把一个散乱脚本改成模块化小项目

下面进入本章重点：**动手重构**。

### 5.1 先看一个散乱脚本

假设你现在有这样一段代码：

```python
file = "notes.txt"

try:
    with open(file, "r", encoding="utf-8") as f:
        lines = f.readlines()
except:
    print("读取失败")
    lines = []

count = 0
for line in lines:
    if "Python" in line:
        count += 1

print("包含 Python 的行数：", count)
```

这段代码能跑，但问题很多：

- 文件名写死了
- 读取、统计、输出混在一起
- 异常捕获太粗糙
- 不方便复用
- 不利于后续扩展

这就是很多新手最常见的写法：能用，但不耐用。我们接下来把它整理一下。

### 5.2 重构目标

把它改成一个模块化小项目，目标是：

- 配置独立
- 读取独立
- 统计独立
- 输出独立
- 主流程清晰

### 5.3 第一步：拆配置

**`config.py`**
```python
INPUT_FILE = "notes.txt"
TARGET_WORD = "Python"
```

### 5.4 第二步：拆文件读取

**`io_utils.py`**
```python
def read_lines(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return f.readlines()
    except FileNotFoundError:
        print(f"找不到文件：{path}")
        return []
```

### 5.5 第三步：拆数据处理

**`processor.py`**
```python
def count_target_lines(lines, target):
    count = 0
    for line in lines:
        if target in line:
            count += 1
    return count
```

### 5.6 第四步：拆输出格式

**`formatter.py`**
```python
from datetime import datetime

def build_result(count, target):
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    return f"统计时间：{now}\n包含 {target} 的行数：{count}"
```

### 5.7 第五步：写主入口

**`app.py`**
```python
from config import INPUT_FILE, TARGET_WORD
from io_utils import read_lines
from processor import count_target_lines
from formatter import build_result

def main():
    lines = read_lines(INPUT_FILE)
    count = count_target_lines(lines, TARGET_WORD)
    result = build_result(count, TARGET_WORD)
    print(result)

if __name__ == "__main__":
    main()
```

### 5.8 重构后，你得到什么？

你会发现它比之前强很多：

- 改文件名只改 `config.py`
- 统计逻辑只看 `processor.py`
- 输出样式只改 `formatter.py`
- 主流程一眼就能看懂
- 以后想加“输出到文件”，直接再写个函数就行

这就是模块化的价值：**小功能各司其职，后面扩展不费劲**。更重要的是，你开始有能力把“能跑的代码”整理成“能维护的代码”了。

### 5.9 再往前走一步：让它真正能复用

如果你想把这个小工具用到不同文本上，下一步可以做两件事：

1. 把 `INPUT_FILE` 和 `TARGET_WORD` 改成命令行参数
2. 把结果同时打印到屏幕和文件里

这样它就不只是一个练习脚本，而是一个可以反复拿来用的小工具了。比如以后你要检查日志里某个词出现了多少次、统计笔记里某个关键词的行数，都能直接拿来改一改就跑。

## 六、错误排查：模块化后怎么找问题更快？

很多人一拆模块就慌了：报错变多了，看不懂了。其实恰恰相反，模块化以后，排错更容易，因为问题范围缩小了。

### 6.1 老赵的排错顺序

你可以按这个顺序来：

1. **先看报错信息**
2. **确认报错发生在哪个文件哪一行**
3. **检查导入名是否正确**
4. **检查函数参数是否传对**
5. **检查文件路径、编码、内容格式**
6. **先打印关键中间值，再继续缩小范围**

不要一出错就乱改。先定位，再动手，效率会高很多。

### 6.2 常见问题清单

#### 问题 1：导入失败
先看文件名、路径、模块名有没有写错。很多时候只是一个字母拼错了，或者文件没放在正确目录里。

#### 问题 2：函数找不到
检查是不是拼写错了，或者函数没定义在当前模块里。Python 对名字很认真，差一个字母都不认。

#### 问题 3：结果不对但不报错
这类最常见。建议加临时打印：

```python
print(lines[:3])
print(count)
```

调试阶段，多打几个 `print()` 很正常。先把数据看见，比猜强。

#### 问题 4：文件打开失败
重点看路径、当前工作目录、编码。很多“文件明明在那儿却读不到”的问题，其实不是文件没了，而是你运行程序的目录和你以为的不一样。

### 6.3 一个实战习惯：先做最小验证

别一上来就跑完整项目。先验证最小环节：

- 能不能导入模块？
- 能不能读到文件？
- 函数是不是返回了正确类型？
- 输出格式是不是对的？

这就是“小步快跑”的真正含义：**每一步都确认没问题，再往下走**。这样一旦出错，你马上知道是哪一层出了问题。

## 一、先别急着写代码：怎么确定小工具需求并拆分功能？

很多新手写程序失败，不是不会语法，而是**一上来就冲进代码里，脑子里没有结构**。老赵的习惯是：先把“这工具到底解决什么问题”说清楚。

### 1.1 先用一句话说清楚工具目标

我们拿一个适合新手练手的项目：**日志小助手**。  
它的作用很简单：

- 读取一个文本文件
- 统计指定关键词出现次数
- 输出统计结果
- 记录生成时间
- 文件不存在或内容有问题时，能提示错误

这类工具的好处是：

- 功能不大，适合新手完成
- 能串起文件、字符串、字典、函数、异常、日期时间
- 后续也容易扩展，比如支持多个关键词、输出到新文件、按日期分类

它不算复杂，但足够接近真实工作里的小脚本、小工具，正适合拿来练手。

### 1.2 拆功能时，用“输入→处理→输出”三步法

老赵很常用这个拆分方式，几乎适合所有小工具。

#### 输入

- 从用户这里输入文件路径
- 输入要统计的关键词

#### 处理

- 打开文件，读取内容
- 按行或按文本处理
- 统计关键词出现次数
- 生成结果字典

#### 输出

- 打印统计报告
- 可选：把结果写入新文件
- 输出当前日期时间，方便追踪

先把流程想清楚，再写代码。  
**不要先写代码，再补功能；先把流程画出来，再动手。**

老赵写程序时，经常先在脑子里过一遍：

> 先拿到什么，再判断什么，最后输出什么？

这个习惯很实用，能帮你把“我好像都会一点”变成“我知道怎么开始”。

### 1.3 赵老师的实战习惯：先拆清单，再开工

老赵写小工具时，会先列出这几项：

- 需求一句话
- 输入有哪些
- 输出是什么
- 中间要处理什么
- 哪些地方可能出错

比如本项目可以写成：

```text
需求：统计文本文件中关键词出现次数，并输出时间戳报告。
输入：文件路径、关键词
处理：读取文件、统计次数、整理结果
输出：控制台报告 / 可选写入结果文件
风险：文件不存在、编码错误、空内容、关键词为空
```

这一招很稳。你先把“做什么”和“怎么拆”写下来，代码就不是一团雾了。  
**小步快跑不是乱跑，而是每一步都跑得很稳。**

## 二、从输入到处理再到输出：一个小工具怎么完整跑起来？

下面开始把思路变成代码。先别追求漂亮，先追求**能跑**。  
做项目最怕的不是代码不够高级，而是写了半天，连第一版都没跑通。

### 2.1 第一个版本：先把流程打通

先做最小可运行版本：

```python
file_path = input("请输入文本文件路径：").strip()
keyword = input("请输入要统计的关键词：").strip()

with open(file_path, "r", encoding="utf-8") as f:
    text = f.read()

count = text.count(keyword)

print("统计结果")
print(f"关键词：{keyword}")
print(f"出现次数：{count}")
```

这个版本已经能用，但还很粗糙。它体现了完整流程：

- 输入
- 读取
- 处理
- 输出

对新手来说，这一步很重要。很多人总想着“我要先设计得很完整”，结果迟迟不下手。其实写程序最怕的不是不优雅，而是**根本没跑起来**。

### 2.2 为什么要先做“粗版本”

因为新手最容易掉进一个坑：  
**总想一步写成完美程序，结果每一步都没跑通。**

老赵建议你这样做：

1. 先写最短路径，确保能跑
2. 再加异常处理
3. 再整理函数
4. 再加文件输出
5. 最后再优化体验

这就是小步快跑。每次只改一点，每次都验证结果。  
你每完成一个小版本，就相当于给自己打了一个“可运行”的确认点。

### 2.3 把流程做得更清楚一点

现在我们把结果做得更像一个小工具，而不是一段练习代码：

```python
from datetime import datetime

file_path = input("请输入文本文件路径：").strip()
keyword = input("请输入要统计的关键词：").strip()

with open(file_path, "r", encoding="utf-8") as f:
    text = f.read()

count = text.count(keyword)
now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")

print("=" * 40)
print("关键词统计报告")
print(f"生成时间：{now}")
print(f"文件路径：{file_path}")
print(f"关键词：{keyword}")
print(f"出现次数：{count}")
print("=" * 40)
```

这里已经用到了日期时间模块。  
**标准库不是“考试知识点”，而是让工具像工具的关键。**

一个真正的小工具，往往不只是“算出结果”，还要能留下“结果记录”。生成时间就是很典型的实战需求：以后你打开报告，知道它是什么时候生成的，不会拿错版本。

## 三、怎么把字符串、列表、字典、函数、文件、异常、日期时间、模块串起来？

这一节是本章的核心。很多人学过这些知识，但不会“串联”。  
其实方法很简单：**每个知识点都服务于一个明确的任务。**

### 3.1 字符串：负责清理和判断

字符串处理最常见的用途就是：

- `strip()` 去掉首尾空白
- `split()` 拆分文本
- `count()` 统计次数
- `replace()` 替换内容
- `lower()` / `upper()` 统一大小写

例如，如果你想让关键词统计不区分大小写，可以这样做：

```python
text = text.lower()
keyword = keyword.lower()
count = text.count(keyword)
```

这个小改动很实用。现实里的文本输入经常大小写混杂，如果不统一处理，统计结果很容易不准。

### 3.2 列表：负责保存多条数据

如果你想统计多个关键词，而不是一个词，就需要列表。

```python
keywords = input("请输入多个关键词，用逗号分隔：").strip().split(",")
```

然后遍历列表：

```python
for kw in keywords:
    kw = kw.strip()
    print(kw, text.count(kw))
```

这里你把“字符串拆分”和“列表遍历”连起来了。  
新手最需要练的，就是这种组合操作。单个知识点都不难，难的是**把它们连成一条线**。

### 3.3 字典：负责保存“名称→结果”的对应关系

统计类程序天然适合用字典：

```python
result = {}
for kw in keywords:
    kw = kw.strip()
    result[kw] = text.count(kw)
```

字典的好处是：

- 可以快速按关键词查结果
- 结构清晰
- 便于后续写入文件或导出

如果说列表像一个“名单”，那字典更像“姓名对应成绩表”。小工具里凡是“名字对应数值”“字段对应值”的场景，字典通常都很顺手。

### 3.4 函数：负责把代码分块

当代码开始变长，函数就必须上场。  
老赵的原则很直接：**一个函数只做一件事。**

例如可以拆成三个函数：

```python
def read_text(file_path):
    with open(file_path, "r", encoding="utf-8") as f:
        return f.read()

def count_keywords(text, keywords):
    result = {}
    for kw in keywords:
        kw = kw.strip()
        if kw:
            result[kw] = text.lower().count(kw.lower())
    return result

def print_report(file_path, result):
    from datetime import datetime
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    print("=" * 40)
    print("关键词统计报告")
    print(f"生成时间：{now}")
    print(f"文件路径：{file_path}")
    for kw, count in result.items():
        print(f"{kw}：{count}")
    print("=" * 40)
```

这样做的好处很明显：

- 结构清楚
- 便于调试
- 以后想换成统计别的内容，只改某个函数

函数化不是为了“显得高级”，而是为了让代码更好维护。你后面再学别的项目，比如文本清洗、文件整理、命令行工具，都会反复用到这种思路。

### 3.5 文件与异常：让工具真正可用

文件操作最常见的问题就是：

- 文件路径错了
- 文件编码不对
- 输入为空
- 关键词没有填

所以要用异常处理兜底：

```python
try:
    text = read_text(file_path)
except FileNotFoundError:
    print("文件不存在，请检查路径。")
except UnicodeDecodeError:
    print("文件编码读取失败，可能不是 UTF-8。")
except Exception as e:
    print(f"发生未知错误：{e}")
```

新手常见误区是把异常当成“高级内容”，能不用就不用。其实不对。做工具时，异常处理是基础能力。没有异常兜底，程序就像没穿鞋出门。  
你以后写任何跟文件、网络、用户输入有关的程序，都会遇到异常。早点学会它，后面会轻松很多。

### 3.6 日期时间和模块：让结果更像“正式产物”

日期时间不是装饰，而是帮助你追踪结果来源。

```python
from datetime import datetime
now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
```

你可以把它写进报告里，也可以写进输出文件头部。  
以后你查日志、看报告、做版本对比时，这个信息很有用。

而模块使用的意义也很直接：当一个脚本越来越长，最好的办法就是拆模块。  
例如你可以拆成：

- `main.py`：程序入口
- `tools.py`：放读取、统计、打印相关函数
- `config.py`：放固定配置

这就是最基本的模块化思路。  
**程序不是写成一坨就完事，而是要按职责分工。**

你现在可能只写一个文件，但脑子里要先有“以后可以拆开”的意识。这样你从一开始就不是在堆代码，而是在搭结构。

## 四、调试、修正和优化：怎么让工具真正能用？

能写出来，不代表能稳定使用。  
真正的工具，往往是在不断排错、修正、优化中长出来的。

### 4.1 先学会看报错，不要怕报错

老赵的经验是：**报错不是敌人，是提示。**

你看到错误时，先做三件事：

1. 看报错类型
2. 看报错行号
3. 看这行代码周围在干什么

例如：

- `FileNotFoundError`：路径错了
- `ValueError`：输入格式不对
- `UnicodeDecodeError`：编码问题
- `NameError`：变量没定义

刚开始看报错会有点懵，这很正常。你不用一下子看懂所有内容，只要先抓住关键词，定位大概问题就行。慢慢你会发现，报错信息其实是在“告诉你哪里不对”。

### 4.2 常见调试步骤

#### 第一步：打印关键变量

```python
print(file_path)
print(keyword)
print(text[:100])
```

先看输入是不是对的，再看读取出来的内容是不是对的。很多问题其实不是代码逻辑错，而是数据本身没按预期进来。

#### 第二步：缩小问题范围

先注释掉不重要的部分，只保留核心逻辑。  
如果最小版本能跑，再一段段加回来。

#### 第三步：逐步验证

- 文件能不能读到？
- 内容是不是空的？
- 关键词有没有被正确拆分？
- 字典结果是不是对的？

#### 第四步：给边界情况做保护

比如关键词为空时：

```python
if not keyword:
    print("关键词不能为空")
    return
```

这个判断看起来简单，但非常有用。因为真实用户输入并不总是乖乖配合的。写工具，不能只假设“用户一定输入正确”。

### 4.3 一个更稳一点的完整版本

把前面的内容整合起来，下面就是一个可以直接跑、也方便后续扩展的小工具版本：

```python
from datetime import datetime

def read_text(file_path):
    with open(file_path, "r", encoding="utf-8") as f:
        return f.read()

def count_keywords(text, keywords):
    result = {}
    text = text.lower()
    for kw in keywords:
        kw = kw.strip()
        if kw:
            result[kw] = text.count(kw.lower())
    return result

def print_report(file_path, result):
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    print("=" * 40)
    print("关键词统计报告")
    print(f"生成时间：{now}")
    print(f"文件路径：{file_path}")
    for kw, count in result.items():
        print(f"{kw}：{count}")
    print("=" * 40)

def save_report(file_path, result, output_path):
    now = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    with open(output_path, "w", encoding="utf-8") as f:
        f.write("=" * 40 + "\n")
        f.write("关键词统计报告\n")
        f.write(f"生成时间：{now}\n")
        f.write(f"源文件：{file_path}\n")
        for kw, count in result.items():
            f.write(f"{kw}：{count}\n")
        f.write("=" * 40 + "\n")

def main():
    file_path = input("请输入文本文件路径：").strip()
    raw_keywords = input("请输入多个关键词，用逗号分隔：").strip()
    output_path = input("请输入报告输出文件名（可直接回车跳过）：").strip()

    if not file_path:
        print("文件路径不能为空")
        return
    if not raw_keywords:
        print("关键词不能为空")
        return

    keywords = raw_keywords.split(",")

    try:
        text = read_text(file_path)
        result = count_keywords(text, keywords)
        print_report(file_path, result)

        if output_path:
            save_report(file_path, result, output_path)
            print(f"报告已保存到：{output_path}")

    except FileNotFoundError:
        print("文件不存在，请检查路径。")
    except UnicodeDecodeError:
        print("文件编码读取失败，建议确认是否为 UTF-8。")
    except Exception as e:
        print(f"发生未知错误：{e}")

if __name__ == "__main__":
    main()
```

这个版本已经很像一个真正的小工具了。  
它有：

- 明确入口
- 清晰函数划分
- 输入校验
- 异常处理
- 日期时间输出
- 可选保存结果

### 4.4 优化的目标不是“更炫”，而是“更可靠”

新手常常会把优化理解成“写得更高级”。其实不是。  
优化的优先级一般是：

1. 先保证能跑
2. 再保证不容易挂
3. 再保证好读
4. 最后才考虑更方便、更美观

例如你还可以继续加：

- 支持多个文件统计
- 支持按行统计
- 支持关键词高亮
- 支持命令行参数传入
- 支持把结果整理成更漂亮的文本报告

但这些是后续扩展，不是今天的第一目标。  
今天最重要的是：你已经有了一个能完整跑起来的成品，而且它的结构是可扩展的。

## 五、复盘项目结构与后续扩展方向：这次你到底学会了什么？

做完一个工具之后，别急着关掉窗口。  
老赵最看重的一步是：**复盘。**  
因为复盘决定你下次能不能更快独立完成另一个项目。

### 5.1 这个小工具的结构是什么？

你可以把它总结成下面这个思路：

- `main()` 负责流程调度
- `read_text()` 负责读取文件
- `count_keywords()` 负责处理数据
- `print_report()` 负责输出结果
- `save_report()` 负责保存结果
- `try...except` 负责兜底异常
- `datetime` 负责生成时间信息

这就是一个完整的小工具结构。  
你以后做别的项目，也可以按这个模板套：

> 输入 → 校验 → 处理 → 输出 → 异常兜底 → 复盘优化

这套思路比“我会多少语法”重要得多。因为真正写程序时，你面对的不是语法题，而是一个实际任务。

### 5.2 这次你真正练到的能力

不是单独某个语法，而是下面这些组合能力：

- 能把需求拆成步骤
- 能从输入到输出搭流程
- 能把字符串、列表、字典串起来
- 能用函数组织代码
- 能用文件和异常让工具可用
- 能用标准库补足实战需求
- 能发现问题并定位问题

这才是从“会一点语法”走向“能写程序”的关键一步。  
换句话说，你这次不是在背知识点，而是在训练“把知识点变成结果”的能力。

### 5.3 这个小工具可以复用到哪些真实场景？

这不是只给你做练习看的，它有现实用途。比如：

- 分析文章里某些词出现了多少次
- 快速检查一批文本日志中的关键词
- 给培训材料、说明文档做基础统计
- 对客服记录、会议纪要做简单文本扫描
- 作为后续“文本处理工具箱”的底座

也就是说，你今天写出来的，不只是一个示例，而是一个**能继续改、能继续用**的小工具雏形。

### 5.4 后续可以怎么扩展

如果你想继续练，下面这些方向很适合做二次升级：

#### 方向一：结果写入文件

把统计报告保存成 `.txt` 文件，方便以后查看。

#### 方向二：支持命令行参数

#### 方向三：支持多文件统计

#### 方向四：支持简单爬取后的文本处理
